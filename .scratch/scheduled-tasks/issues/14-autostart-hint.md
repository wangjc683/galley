# 14: 可靠性前提引导 — 自启缺失的条件式 footer

Status: done
PRD: ../PRD.md（决策 14；原开放问题 6）

## 背景

定时任务「静默不跑」的最大缺口：开机自启默认关，重启电脑后 Galley
不在，任务整天丢弃且无痕。原 footer 只有一句被动免责声明。关窗驻留
后台默认开，不构成常见缺口。

## 定案（JC 2026-07-30 认可 agent 方案）

- **条件式 footer**：仅当「自启未开 && 存在至少 1 个启用任务」时，
  footer 变为警示行 + 行内一键「设为开机自动启动」；解决后自动变回
  静态说明。空状态不推销自启。
- 这是**情境提示**而非把 Settings 搬进功能 dialog：出现在「配置正在
  破坏眼前功能」的确切时刻和地点；先例是 Settings 通知权限缺失的
  就地提示。新建首个任务后回列表页立即可见，天然覆盖首次创建时机。
- 行内直接 `enable()` 而非跳转 Settings（一次点击 vs 三次导航）；
  按钮文案沿用 Settings 同款词「开机自动启动」保证知情。
- 不覆盖「关窗驻留后台」被关的情况（用户显式选择过，默认开）。
- 已拒绝的更重选项：创建首个任务时弹确认框（多余模态）；静默自动
  开启自启（改登录项不告知是坏公民）。

## 实现

- 纯 GUI：`ScheduledTasksDialog` 打开时 `isEnabled()`（插件已接入，
  Settings → 通用同款）；查询失败（浏览器 dev / 插件缺失）保持
  unknown → 静态 footer，绝不误报。一键走 `enable()` + 复查，错误
  文案复用 `settings.general.launchAtLoginError`（同一操作同一措辞）。
