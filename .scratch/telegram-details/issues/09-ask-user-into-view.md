## 问题

票 06 之后工作台发出后不跟随。跑的途中 ask_user 问你、而内容已超出一屏时，问题出在可见区域以下，不会被拉进来，只能靠侧栏「等你回复」和回到底部的脉冲发现。问题会卡住这一轮，没看到就一直等着。

## 规则

- 只工作台（主对话照旧，一行不走新逻辑）。
- ask_user 的提问块一出现（`pendingAskUser` 从无到有，或换了一个新问题），量它是否完整落在可见区域内（扣掉输入框与回到底部按钮占的地方）：
  - 已完整可见：不动（常见情况：live 窗口高度有限，问题多半落在留白里）。
  - 没完整露出：用票 04 的滚动函数滚到它完整可见——问题块的下缘停在可见区域底边之上（留白的量你定，参照对话区 `py-6` 的 24px）；问题块高过可见区域时，改为它的上缘停在锚线（`USER_MSG_ANCHOR_TOP_PX`）。减少动态效果时瞬时。
- **你正往上翻着读更早的内容时不动**：确定的判断，不猜。以「这一轮你发出的那条停靠位置」为界：视口在它之上（你往上翻过了它）就不动；在它或它之下（停着、或在读这一轮的过程与回复）就滚。写进 Comments 你最后用的判断式。
- 滚过去之后照旧不跟随（票 06 的语义不变）；你自己滚到内容末尾或点回到底部才挂上跟随。
- 一轮里多次提问，每一个新问题都按同一规则。
- Supervisor / CLI 发起、你没在界面里发出的那一轮：照今天的跟随规则（票 06 没改它们），不受本票影响；确认一下这一轮里提问出现时的表现与今天一致。

### 实现（2026-10-16，子代理，分支 `td-scroll`，从 main `ce14d696` 快进后接着做）

提交：`4912d7af`（代码与测试）；文档与本节另一个提交。

**做了什么**

- `gui/src/lib/live-tail.ts`：`askUserRevealTop`（在不在视野里、滚到哪）、`scrolledAboveRound`（往上翻过没有），留白的新方法 `reveal(question, round, key)`。
- `useStickyScroll.ts`：一个跟着 `pendingAskUser` 的 effect。新问题出现后，下一帧调 `reveal`，之后 600ms 内每帧再看一次。只有留白存在、而且这一轮不跟随时才调；主对话在最前面就返回。
- `animate-scroll.ts`：结束原因多一种 `displaced`（别的代码挪了 `scrollTop`），和 `interrupted`（你自己滚的）分开。追底与已有的用法都不受影响，只改了一个测试的期望值。

**「往上翻过」的判断式**

`userMsgParkOffset(这一轮最后一条你的消息, 容器上缘) > USER_MSG_ANCHOR_TOLERANCE_PX`（8px）就不动。

- 「这一轮最后一条你的消息」是 DOM 里最后一个 `user-msg` / `user-msg-reply`，也就是你发的那条，或你回答上一个问题的那条。
- 它在自己的停靠线下面超过 8px，就是视口在它的停靠位置之上（你往上翻过了）。
- 停在线上、或在它下面读这一轮的过程与回复，就滚。
- 容差同 ⌥↑ / ⌥↓ 与问题轨。停靠线全由 `userMsgParkOffset` 取，没有另算，票 07 / 08 对它的改动会自然跟上。
- 排队的消息在底部发出时（票 06：视口不动，留白挪到它下面），视口在它的停靠位置之上，所以这一轮里问你也不动。你多半还在读上一轮的回答，和票 06 的理由一致。

**留白取值**

- 「完整露出」：上缘不高于视口顶，下缘不低于回到底部按钮那一条，底下 48px（按钮 `bottom-4` 16px + 圆 32px）。
- 滚到时下缘停在那一条之上 24px（`py-6`），即视口底上 72px。
- 内容到头、滚不到那么高时，停在内容末尾。此时下缘在视口底上 44px（`py-6` 24 + 提问块 `my-5` 20）；在底部按钮也不出现，不会压住。
- 提问块高过这段空间（视口 − 72 − 32）时，上缘停在锚线 32px。

**600ms 的再看**

问你之后这一轮马上停下，上面那段会按「没在跑」重画，问题会挪位。所以出现后 600ms 内每帧再算一次：位置变了就改瞄，已经露出就不动。

- 期间你滚轮、触控板、按键滚动，或按 ⌥↑ / ⌥↓、点问题轨、点回到底部，就交给你，不再管。
- 被别的代码挪了（`displaced`，比如 Chromium 的滚动锚定）不算你，照样改瞄。

**滚过去之后照旧不跟随**

这次滚动途中、以及停在它放下的位置时，留白不把「到了内容末尾」当成你要跟随。你滚开再自己滚回末尾，或点回到底部，才挂上。

**Supervisor / CLI 那一轮的表现确认**

那一轮来源是 `external`，票 06 让它回到「在底部就跟」，不受本票影响。Chrome harness 实测：

- 在底部：步骤落下时跟到底，问题出现后照旧跟到底，问题完整露出（视口底上 44px）。
- 往上读着 500px：问题出现后 `scrollTop` 不变。

两种和票 06 之前一样。

**JC 真机验收**

1. 工作台里发「先问我要哪个城市，再查天气」这类会中途问你的任务。问题出现前把回复撑过一屏（或往下读着），问题出现时滚到它完整露出，下面留出回到底部按钮的位置。
2. 问题出现前往上翻到更早的内容：问题出现时视口不动。
3. 滚过去之后它接着长（你回答后的新一轮除外）不拉视口。回答后照票 06：你的回答停到顶上。
4. 一轮里问两次：第二个问题同样处理。
5. 问题很长（超过一屏）：它的开头停在顶上。
6. 减少动态效果：瞬时。
7. 主对话里问你：照旧（贴底）。
8. 可选：Supervisor / CLI 发起、会问你的一轮：同今天。

**风险**

- 600ms 窗口内，若有不经滚轮、按键、按住滚动条的滚动方式（比如 Windows 的中键自动滚动），会被当成「别的代码挪了」而再改瞄一次。很少见。
- 排队那条在底部发出的那一轮里问你，按判断式不动（视口在它的停靠位置之上），只靠侧栏「等你回复」与按钮提示。按规则如此，真机若觉得应滚，改判断式的界即可。
- 子任务卡片等其它「要你看见」的东西仍不拉进视野（只处理了提问）。
