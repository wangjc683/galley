# 07 引用改成输入框上方的一条，气泡里把引用单独画出来

Status: merged（2026-10-16 合入 main，`fcde201e`，合并提交 `f3e315af`；等 JC 真机验收与切档裁决）

来源：[PRD](../PRD.md) 裁决 3a（2026-10-16，JC 真机试了票 02：「『引用』后在输入框可以显示出引用的文字，但是这个引用文字的显示 UI 我觉得不好看，有点简陋」；讨论后：「按你推荐」）。只改 GUI 与文档，不碰 Rust。两边都上。
接在票 02 后面（改它的做法）；切换器部分与票 05 的切换器合用一颗 pill（见下）。

## 问题

- 输入框是纯文本框，引用就是一行行 `> ` 字符（票 02 的做法），没有样式。
- 发出去后你的气泡也是这几行 `>`：气泡按纯文本显示（`MessageUser.tsx:344`，`whitespace-pre-wrap`），不渲染 Markdown。

## 裁决（JC：「按你推荐」）

1. **方向 A**：引用不进输入框的文字，在输入框卡片内、文字上方单独一条（与图片条、排队条同一层）；发出时才拼成 Markdown 引用。没选 B（只改气泡，输入框照旧简陋）、C（输入框改富文本，等于重写输入框：输入法、粘贴折叠、文件引用都建在纯文本框上）。
2. **可以叠多段**：每段一行、各带 ×；对 AI 问「这两处什么意思」很自然。
3. **气泡里画在哪：切换器真机比**，推荐「气泡外、上方」（杏沙是人的声音，`conversation.md:59`；引用的是助理的话，放进你的气泡会混两种声音；ChatGPT 放在气泡外），对照「气泡内顶部」（Telegram）。输入框里那一条的样子也进同一个切换器。
4. **不做点引用跳回原文**：要跳得记住来源消息（改库、碰 Core）；按文字匹配是猜（选中的文字与 Markdown 原文常对不上）。

## 要做

### 输入框

- `ComposerHandle.quote(selected)` 改为往「引用列表」里加一段（不再改文字）。每段存选中的原文（`selection.toString().trim()`），格式化留到发出时。
- 引用条放在输入框卡片内、文字上方。与图片条、排队条的上下次序你定（原则：离文字最近的是和这条消息最相关的），写理由。每段一行：样子按切换器的档（见下），右侧一个 ×（aria-label「移除引用」/「Remove quote」），悬停整行时 × 才显还是常显你定。
- 叠多段：上限你定（建议 3–5，满了怎么办写清：拒绝并提示，还是替换最早的一段）。
- 点「引用」后：聚焦输入框，光标在文字末尾，输入框里已有的字、粘贴折叠、文件引用、图片一样不动。
- **发出**：消息文字 = 各段 `markdownQuote`（`lib/composer-quote.ts`，保留票 02 的格式化规则）用空行连起来 + 空行 + 你打的字；发出后引用条清空。只有引用、没有字也没有图时，发送键不亮（一段引用不是一句话）。在跑时按 Enter 排队、ask_user 的回答、`/btw`：都按同一规则拼，逐个确认。
- **草稿**（票 01）：引用列表随草稿一起存、一起恢复，重开后引用条还在。localStorage 里今天存的是纯文字：改成能放引用的格式，读到旧的纯文字值要照样认（向后兼容）。
- 票 02 的 `textWithQuote`（往文字里拼引用）不再用于点「引用」：删掉还是留给别处用你定，不留死代码。

### 气泡

- 新的纯函数（放 `lib/`）：从消息文字开头认出引用块——开头连续的 `>` 行，几个引用块之间可以隔空行——拆成「几段引用 + 你的话」。只认开头；正文中间的 `>` 照旧当普通文字。你手打的以 `>` 开头的消息也会画成引用，这是 Markdown 本来的意思，接受。
- `MessageUser` 把引用画出来，你的话照旧在气泡里。两档（切换器）：
  - **D1 气泡外、上方（推荐，默认）**：一段一行，淡色小字（字号、墨色你定，比气泡正文低一到两档）+ 左侧细竖线，靠右、宽度上限同气泡 `min(80%, 560px)`，每段最多两行、超出省略；离气泡的距离你定（参照助手同侧连发 4px）。
  - **D2 气泡内顶部**：气泡里先一块引用（左竖线、比气泡底深或浅一档的底、正文低一档的字，最多三行省略），下面是你的话。
  - 引用被省略时，点一下原地展开全文、再点收起（可选，你定；不做就用 tooltip 给全文）。
- 长消息折叠（6 行或 500 字）只算你的话，不算引用。
- 工作台的悬停复制照旧复制原文全文（含 `>` 引用）。只有引用、没有你的话的消息（手打的）：只画引用。

### 其他显示你消息文字的地方

grep 所有拿用户消息文字做预览的地方（侧栏助手卡片「你：…」、排队条、问题轨 tooltip、⌘K / ⌘F 结果……），预览里显示你自己的话、不显示 `>`；搜索结果要不要连引用一起搜、一起显示你定（原则：能搜到就要看得出命中在哪）。逐处写进 Comments。

**取舍（票里「你定」的）**

- **与图片条、排队条的次序**：排队条照旧在框外上方；框内从上到下是图片条、引用条、输入。发出的消息是「引用，然后你的话」，引用排在离文字最近的地方，读起来就是这句话的开头；图片在气泡里本来也画在文字下面，它是附件，不是这句话在说的那一句。
- **× 何时显**：悬停那一行才显（同附件条的 ×），隐藏时占位，不跳。
- **上限 3 段**：建议是 3–5，取最小。C1 每段可到两行，3 段一行的框高约 134px、3 段两行约 185px（不带引用是 48px），再多就压对话了；「这两处什么意思」的场景 2 段就够。满了**拒绝并提示**（toast：「最多引用 3 段，先移除一段再引用」），不替换最早的一段，替换会悄悄丢掉你选过的。同一段再引用一次不重复加。
- **只有引用、没有字也没有图**：发送键不亮、Enter 不发。有图没字时发出的就是引用块（不再补「请看这张图片。」，那句只在完全没字时补）。
- **`/btw`**：按「引用 + 空行 + 你的话」拼会把 `/btw` 挤到后面，桥（`runner/workbench_bridge.py` `dispatch_command`）和 GA（`btw_cmd._strip_cmd`）都只认开头的 `/btw `，侧问就变成了主任务。所以 `/btw` 例外：`/btw ` 留在最前，引用接下一行，问题再空一行（`/btw \n> 引用\n\n问题`）；GA 去掉 `/btw` 后拿到的是「引用 + 问题」。拆的时候认这个形状，气泡里照样画引用、正文是「/btw 问题」。
- **草稿存盘格式**：没有引用的草稿照旧存成纯文字（与票 01 一样，旧数据、旧测试都不动）；有引用的存成 `{"galleyDraft":2,"text":…,"quotes":[…]}`。读的时候只有以 `{"galleyDraft":2` 开头且能解析的才当 JSON，其余（含解析失败的）一律当纯文字，所以旧的纯文字值照样认。只有引用的草稿也算草稿（存、恢复、侧栏「草稿：[引用]」）。
- **`textWithQuote`**：删了（见上）。
- **省略的引用**：做了点击原地展开、再点收起。只在真被截断时才是按钮（`ResizeObserver` 量 `scrollHeight > clientHeight`，在回调里 setState，不在 effect 里同步 setState）；没截断的就是普通文字。D1 两行、D2 三行；输入框里的 C1 两行、C2 一行，用原生 `title` 给全文（输入框里不做展开，× 已经在那一行）。
- **D1 / D2 的字号、墨色、距离**：都用 `--conversation-echo-size`（标准 13px，正文 15px，低两档；小、大字号跟着变）。D1 `ink-muted` + 2px `line-strong` 竖线，整列与气泡同一个上限 `min(80%, 560px)`、宽度取最宽那段（几段的竖线对齐；最初各自靠右时竖线参差，改了）、段间 2px、离气泡 4px（同侧连发间距）。D2 `ink-soft`、正常字重、`brand-strong` 10% 的底 + 45% 的竖线、`rounded-sm`，块间 4px、离你的话 6px。引用都不能选中（是它的话，原处可选）。回复里 Markdown 引用的样式（3px brand 竖线 + 斜体）不变；这里有意不用斜体（中文是假斜体），竖线细一档。
- **搜索**：Core 的 FTS 照旧搜全文，引用里的字也搜得到（不碰 Rust 也改不了）。你的消息的命中片段里，以 `>` 开头的行画成灰字、前面一条竖线，看得出命中在引用里；片段从一行中间开始时认不出，当你的话显示。
- **逐处预览**（grep 过 `role === "user"` 与 `.content` 的用处）：侧栏助手卡片「你：…」只取你的话，只有引用时写「[引用]」；草稿同理。问题轨悬停取你的话（没有就取引用）。排队条取你的话（没有就取引用），「取回编辑」时引用回到引用条、你的话回到输入框。⌘K / ⌘F 见上。会话标题由 Core 从第一句话取（Rust，没碰），第一句不会带引用：引用要先有对话。ask_user 候选的勾选（`lib/ask-user-candidates.ts` 比对回答全文）遇到带引用的回答不打勾，本来就不是点候选，对的。侧栏会话行的摘要是 GA 的每轮小结，不是你的原话，不受影响。
- **其他**：幽灵文字（下一步建议）有引用时不出；`prefillText`（ask_user 候选「填入」、题词预填）换掉整份草稿，引用随图片一起清。连点两次「引用」在同一帧里也都加得上（按当前列表函数式更新）。
