## 现状

- 两边正文同一套变量（`gui/src/lib/conversation-font-size.ts`，标准档 `--conversation-body-size` 15px、`--conversation-body-leading` 1.7、`--conversation-block-gap` 12px；小档 13.5 / 1.65 / 10.5，大档见文件）。
- 助理气泡的 Markdown 正文（`MarkdownView.tsx:222, 303, 311`）与你的气泡（`MessageUser.tsx:350`）都读这三个变量。
- 主对话的气泡把行宽收到栏宽 88% 再减 28px 内边距（`AssistantParts.tsx` `ASSISTANT_BUBBLE_MAX`、`BUBBLE`）：760 栏约 641px，一行约 42 个汉字。

## 要做

- **只主对话**：在主对话的对话列上（不是全局）覆盖这三个变量，你的气泡与助理的气泡（含问候、提问、子任务叫醒那一轮的回复）一起变。工作台一个像素不动。输入框（`--conversation-composer-size`）不动。逐个列出主对话里还有谁读这三个变量（过程卡片、子任务卡片、引用块……），各自跟不跟你定，写理由；原则是「气泡里的正文」跟，气泡外的小字不跟。
- **按字号档各一组**，⌘= / ⌘− 照常生效。标准档的值如下；小档、大档按标准档与现有档位的比例推，段距守住 `conversation-font-size.ts` 注释里「段距约为行框 0.47」的规矩（写出你算的表）：

  | 档 | 字号 | 行高 | 段距 | 说明 |
  |---|---|---|---|---|
  | V0 | 15px | 1.7 | 12px | 现状 |
  | V1 | 15px | 1.55 | 10.5px | 只收行距（主会话倾向） |
  | V2 | 14px | 1.6 | 10.5px | 降一档字号 |
  | V3 | 14px | 1.5 | 9.5px | 降字号再收行距，对照 |

- 气泡的内边距、圆角、宽度上限、连发 4px 间距都不动。标题、代码、表格的字号不动（主对话少见，看完再说）。
- 依据：Telegram Web A 在 macOS 上正文默认 15px、行高 1.3125（`src/global/initialState.ts:98`、`src/components/middle/message/Message.scss`）；我们与它的差距在行距。中文需要比拉丁字更多的行距，1.31 对中文太挤，1.5–1.6 是中文界面常见范围。

### 2026-10-16 实现（子代理，分支 `td-density`，提交 `ba56d1bd`）

**切换器**：主对话里才有的一颗 pill（portal、`pointer-events: auto`，顶栏下、离右缘 12px），闭合写「临时 · 气泡 V0」，点开四档，每档标出当前字号档下的「字号 / 行高 / 段距」，⌘= / ⌘− 后标签跟着变。存 localStorage `galley.tmp.tdDensity`（try/catch），默认 V0。代码在 `gui/src/components/conversation/td-density/`，拆法写在 `td-density.ts` 头注释；接入点只有 MainView 两处（pill，对话列的 class 与 style），都标 `TEMP variant switcher (telegram-details 10)`。

段距 ÷ 行框：推出来的六格在 0.465–0.479；票给的标准档 V1、V3 是 0.452，照票未改。

**怎么只动气泡**：主对话的对话列带上 `--bubble-body-size / -leading / -gap`，再用一组 class 只在气泡上重新声明那三个变量：助理气泡（`data-role="assistant-bubble"`，回复、问候、它的提问（答完的与在问的）、子任务叫醒那一轮的回复）三个都换；你的气泡（`data-role^="user-msg"`）换字号与行高（它没有段落）。Chrome 里读到：V2 时对话列、时间条、输入框照旧 15px / 1.7 / 12px，两种气泡 14px / 1.6。

**主对话里还有谁读这三个变量，跟不跟**：

- 跟：助理气泡里的 Markdown 正文（段落、列表、引用块的字与行高；标题、代码块、表格的上下间距是段距的倍数，也跟）；你的气泡正文。
- 不跟（气泡外，或气泡里的另一种字）：过程卡片（行与点开的那一步）、子任务卡片、在跑时那一行、时间条、提问下面的候选、整段平铺的运行（中止、出错、步数上限）与 `/btw`（工作台的画法）、协议失败的说明框；气泡里的标题、代码、表格字号（各有自己的变量）；你气泡顶上的引用（`MessageQuotes`，自己的字号与行高）。思考预览、流式正文、工作台的折叠间距也读这些变量，但主对话不画它们。
