# 更新连得上：跟系统代理 + 加速地址

日期：2026-11-19
来源：GitHub issue #33（请求给应用内更新加 GitHub 反代加速）；JC 当日裁决

## 问题

应用内更新要连两个 GitHub 域名：更新清单在 `raw.githubusercontent.com`，安装包在
`github.com/.../releases/download/`。连不上 GitHub 的用户分两类，各缺一条路：

1. **有代理，但更新器用不上。** 更新器的 HTTP 客户端只读环境变量里的代理，不读系统代理设置：
   `tauri-plugin-updater` 2.10.1 依赖 reqwest 0.13 且关掉默认特性，`system-proxy` 没开
   （`cargo tree -e features -i reqwest@0.13.3` 只有 `json`、`stream`、rustls）；没有这个特性，
   `hyper-util` 的 `Builder::from_system` 只走 `from_env`。从 Dock / 开始菜单启动的应用没有
   `HTTPS_PROXY`，所以代理软件的「系统代理」模式到不了更新器，只有 TUN 模式生效。
2. **没有代理。** 只能靠一个转发 GitHub 的地址。

## 裁决（2026-11-19）

1. 两条都做：票 01 让更新器跟系统代理，票 02 加「更新加速地址」设置。
2. 加速地址由用户自己填，**不带预设**，默认留空即关闭。理由：公共反代域名常换，预设会烂在已发出的
   版本里，也等于替第三方设施背书。
3. 设置放「通用 → 应用行为」，在 `自动下载更新` 下面，同样存 pref。「关于」页是版权页，不放输入框；
   「关于」页更新出错时，错误块在「手动下载」旁加一个链接跳到这项设置。
4. 形态是一个输入框，留空即关闭，不另加开关。填的是前缀，Galley 把它拼在原地址前面
   （`<前缀>/<原地址全文>`），清单与安装包两处都拼。只收 `https://`。
5. 失效规则：检查更新先走加速地址，失败再直连；下载只走加速地址，失败就报错并写明地址，不自动改直连
   （连不上 GitHub 的用户否则要多等一轮超时）。
   2026-11-19 当日改：下载也回退直连，原因见 devlog（`docs/devlog/2026-11-19-update-proxy.md`「下载也回退直连」）。
6. 自建镜像（第二端点）不做。已进 `docs/devlog/deferred.md`「更新连不上：自建镜像与 PAC」。启动信号：有用户在系统代理确实生效、或填了加速地址后仍然更新失败。

## 已核实的事实

- 拼接格式对 issue 点名的两家公共反代都成立（2026-11-19 实测）：清单经反代取回与直连逐字节相同；
  Windows 安装包经其中一家整包下载，大小与 SHA-256 和直连一致。
- 反代装不进 Galley 没签过的包：安装包用编译进应用的 minisign 公钥验签（`Update::download` 里校验）。反代能看到
  IP 与版本号，能不给更新。**2026-11-19 更正：原文「换不了包」「不能给假包」说满了，它能把旧版的真包当新版推过来，
  见票 [03](./issues/03-downgrade-through-the-prefix.md)。**
- 更新器的端点列表遇到「返回 200 但不是 JSON」会直接报错、不试下一个端点（`updater.rs` 里
  `res.json().await?`），所以票 02 的回退由 Galley 自己做两次检查，不靠端点列表。
- `hyper-util` 0.1.20 读系统代理时，macOS 不读例外列表，Windows 的 `ProxyOverride` 里 `<local>`
  与 `127.*` 这类写法不生效，也没有回环地址自动绕行。票 01 因此给「测试模型」补回环直连。
  **这一条 JC 未裁，不要可撤。**

## 影响面

- 内置与外置运行时相同；引擎进程零变化；CLI 契约不动；没有新 IPC 命令；没有迁移。
- 票 01 的特性开在 Core 与更新器共用的 `hyper-util` 上，Core 自己的三处请求（测试模型、对话图片、
  ChatGPT 登录）也开始跟系统代理。这是想要的方向：引擎一侧的 Python `requests` 默认就跟系统代理。
