# 侧栏顶部快捷入口压缩

Status: done

2026-09-28 与 JC 讨论。起因：侧栏顶部四行（新对话 / 搜索 / 定时 / 项目）里只有新对话
高频，其余三个很多时候不常用，这个布局下空间浪费。

## 现状与约束

- 四行各约 36px（`py-2` + 13px 行），加 `py-1` 共约 152px；会话行 `min-h-[48px]`，
  这块约占三条会话的位置（`SidebarQuickActions.tsx`）。
- `docs/design/layout-and-chrome.md` §4.2「Quick Actions 靠顶部：New Chat / Search /
  Project Review 是最高频入口」——前提被 JC 的用法推翻，定案后要改。
- JC 本机数据（workbench.db 只读）：项目 0 个、定时任务 0 个；搜索没有打点。社区用法
  未知，所以降级、不藏。
- 必须保住：定时徽标（只在有待处理事项时出现，夜里失败要一眼可见，08-13）；项目按钮
  按下态（开启后时间线整体换成 Project Review，要一直看得出模式）。
- 不能碰：常驻搜索框（palette 是既定裁决）；悬停一律瞬时、不做滑动高亮（08-13）；
  鼠标优先（07-05）。

## 方案（线稿见讨论）

- **A 一行（推荐，默认）**：新对话保留文字，搜索 / 定时 / 项目缩成同一行右侧三个图标。
  省约 108px。快捷键进悬停提示；定时徽标缩到图标右上角；新建项目「＋」移到 Project
  Review 的分组标题右侧（命令面板已有「新建项目」，零项目空态 CTA 不变）。窄宽度下
  新对话也缩成只剩「＋」。
- **A2 一行·搜索带字**（2026-09-28 追加）：JC 平时搜索主要点侧栏那一行，不按 ⌘K，所以
  搜索是他第二个高频入口。同 A 一行，但搜索保留文字：`＋ 新对话   ⌕ 搜索   ◷² ▭`；
  窄宽度先去掉搜索的文字，再去掉新对话的文字。
- **B 两行**：新对话一行；搜索 / 定时 / 项目三个带字小按钮挤第二行。省约 72px。窄宽度
  退成只剩图标。
- **E 底栏**：顶部只留新对话；三个图标移到底部，与归档同一行。项目按钮离它改变的列表远，
  徽标离视线远，底栏要常驻。

## 待真机裁决（临时切换器）

现状 / A / A2 / B / E，默认 A。默认宽度和最窄宽度各看一遍。

纯界面改动，外置 / 内置两种运行时模式一致。

## 真机第一轮（2026-09-28）

- JC：「一行」最舒服。现状 / 一行·搜索带字 / 两行 / 底栏落选。
- JC 提出新对话的文字是否也降为提示、做成一行四个按钮，新对话在视觉层级上最优先。
  讨论结论：去字不省高度（「一行」已是一行），换来的是各宽度、各语言一致；丢掉的是文字这个
  最强的主次信号，以及「新对话 · 项目名」（主区空状态「在 X 里交代什么？」兜底）。主次靠
  颜色 / 粗细 / 位置 / 外框补；排除杏沙填充（Submit 是全局唯一杏沙 CTA，`conversation.md:534`）
  和杏色浅底（那是按下 / 选中的语言，和项目按钮开启态撞）。候选：I1 纯图标、I2 加号套中性
  细描边框。
- 英文：「New conversation」112.8px（Inter 500 13px 实测），「New chat」58.8px，「新对话」39px。
  JC 定用 **New chat**（句首大写，与英文界面一致）。这打破英文稿「不引入 chat」
  （`docs/archive/english-copy-draft.md:86–87`）：按最小改法，**创建对话的动作标签**在英文里
  统一叫 New chat（侧栏、侧栏项目版、顶栏、命令面板、快捷键说明五处），名词仍是
  conversation；英文稿规则随之改写。
- **不截断规则**：新对话的动作文字要么完整显示，要么只剩加号；项目版只截项目名。门槛按语言：
  中文 198px，英文约 220px（198 − 39 + 58.8 ≈ 218）。
