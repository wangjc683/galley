# 回答操作栏减噪

Status: done

2026-09-28 与 JC 讨论。起因：回答下方的操作栏（复制、保存 | ↑5k ↓314 ⊙<1%）
「有的时候有点吵，但是长答案的时候又还好」，JC 提议改成悬停才显示。

## 旧裁决（对齐，不盲翻）

- 常显是 V0.1 按试用反馈定的：只在悬停时出现，用户得到处找（`MessageActions.tsx`
  顶部注释；`docs/design/conversation.md`「常驻可见（不 hover-only）」）。针对的是
  复制、保存能不能被发现。
- token 行 2026-06-25 加（`6437162e`），没有 devlog 记为什么常显。
- run-fold 领土划分：Footer = 机器成本（token、上下文）+ 复制 / 保存；耗时归折叠头。
- 同日反证：用户消息的悬停时间被 JC 砍掉，「有点吵，也没有必要」——悬停浮现在
  JC 这里本身算吵。

## 数据（workbench.db 只读，截至 2026-09-23）

- 每轮最终回答 397 条：<50 字 67（17%）、50–150 字 38（10%）、150–400 字 61、
  400–1000 字 107、≥1000 字 124（31%）。约 27% 的回答只有一两行，操作栏体量和
  回答相当——解释了「短答案吵、长答案还好」。
- 上下文占用 168 条：<1% 45、1–10% 65、10–30% 34、30–50% 11、50–80% 7、≥80% 6。
  65% 在 10% 以下，≥50% 只有 8%。历史回答上的读数是过期状态。

## 方案

- A 整条悬停才显示：读长答案时鼠标停在答案上，栏基本一直在，进出会闪；推翻 V0.1。
- B 最新一条常显、历史悬停：往回翻干净、上下文读数只在最新一条；最新短答案仍吵，
  历史照样闪。
- **C 常显但只留图标（推荐，JC 同意推进）**：复制、保存、仪表三个细线图标；
  token 与上下文收进仪表图标的悬停提示；上下文 ≥50% 时百分比常显，作为提醒。
  代价：看 token 多一次悬停。
- D 按答案长度分：同一组件随内容变行为、阈值拍脑袋，不推荐。
