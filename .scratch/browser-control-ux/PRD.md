# 浏览器控制 UX 一轮

Status: ready-for-agent

来源：2026-10-04 顶栏打磨讨论延伸。JC 定位：真实浏览器控制是 Galley 最大的卖点之一。

## 依据

- 用量（`workbench.db` 只读查询，2026-10-04）：135 个会话中 61 个用过浏览器（45%）；
  `web_execute_js` 622 次 + `web_scan` 262 次，是 `code_run`（274）的三倍多，所有工具第一。
- 状态只在启动时检测一次（`useBrowserControlStartupEffect.ts`），之后不刷新；Chrome 没开时
  每次启动挂 35 秒「浏览器控制 · 检测中」；检测会在网页里执行脚本并临时占用 18765／18766。
- 对话里浏览器步骤看不出网站：`ToolCallout.tsx` 读 `query` / `url` 参数，GA 的 `web_scan`
  没有这两个参数；结果里其实带 `metadata.active_tab` + `tabs[]`，`web_execute_js` 结果带 `tab_id`。

## 裁决（JC，2026-10-04）

1. 状态走 **S‑b 浏览器桥常驻**：内置模式下 Core 托管一个常驻 TMWebDriver master 进程，
   会话走上游已支持的远程客户端模式，删掉每次启动的检测。
2. 未连接时的语气从黄色「待修」改成「待解锁」（改 05-27 的 warning 规约）。
3. 顶栏浏览器控制、渠道两个图标：常显；**点灯**（在线＝细线轮廓＋淡填充，不在线＝空心）；
   点击弹 popover（从没设置过时直达设置）。浏览器灯：亮＝Chrome 开着且插件连着。
4. 不做暂停开关。
5. 插件上架 Chrome 应用商店 / Edge 加载项：暂缓（见 deferred.md）。
