# 04 飞书补充：标题转粗体、插队时引用原话

Status: needs-dogfood

来源：票 [03](./03-feishu-conversation-ux.md) Comments「交 JC 定」五条，JC 2026-10-21「飞书那几项，按你推荐推进」：

1. 表格：照现在转成列表，不用卡片原生表格（IM 入口层本来就不让出表格；原生表格 5 行分页、每个组件最多 4 张，手机上看不全）。**不用改。**
2. 标题：转成粗体行，同 Telegram（`tgapp.py` 的 `_rewrite_markdown`）。卡片的一级标题 26px，手机上太大，IM 入口层也不让出标题。**要改。**

5. 「过程」面板与汇报卡片的样子：等 JC 真机看过再定，真机反馈追加到本票。

  **实施偏差**（各附理由）
  1. 标题的粗体行前后各补一个空行，自成一段（Telegram 不补）：卡片 Markdown 的单个回车文档写「可能会被忽略」，标题原本是独立一块，不补的话 `## 结论\n正文` 改完可能和下一行并成「**结论** 正文」。代价：标题和正文之间多一行空白。
  2. 汇报也计入「插进来的消息」：Telegram 的汇报走 Bot HTTP 直发，没记进 `_last_message_ids`，那边汇报夹在中间时回答不引用；飞书这边记了，汇报夹在你的消息和回答之间时，引用才看得出回答对应哪句。
  3. 进来的消息在权限闸门之前就计数（Telegram 在 `ALLOWED` 检查之后）：群里别人 @ 机器人，那条也落在了会话里，算插进来的消息。

  6. 停止回执实际上几乎总是引用：`/stop`（或 `/new`、`/continue N`）本身就落在被停的那条之后。Telegram 有状态消息时是把状态消息原地改成回执、不引用，没有状态消息时才走同一条规则；飞书没有状态消息，所以总在后一种。
