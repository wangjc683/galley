# 助手：你只跟一个人说话

Status: active（2026-10-15 地基与 D1–D5 已裁，名字已定；2026-10-16 第一步「闭环」合入，待 JC 真机验收与一周试用）

来源：2026-10-15 JC 提出。主对话已经定了 IM 向的对话体验，也是未来手机端的主要入口，但定位和产品设计的核心「总感觉差那么一点东西」；
JC 想到的是：它是之前 Supervisor SOP 的进一步延伸。模型能力往上走，用户除了自己一个个项目、一个个会话地聊天、布置任务、与 AI 结对工作，
还可以有一个 Supervisor、幕僚长、管家、助理、副手、「教父边上的律师和军师」，替用户统管大大小小的任务：查看、新建和管理所有普通会话，
管理、配置和改变 Galley 本身；用户不再考虑会话管理、上下文管理、项目管理、多任务进展管理，只需要像和一个真人通过 IM 聊天；
它为你新开会话和项目，为你编写提示、验收成果，为你整理和汇总，也记着你日常生活的提醒和事务。
JC 要的是一个扎实坚固的核心理念，让桌面、本机全能助手、Galley、未来的手机端，以及之后的 UI / UX 与交互设计都有地基。

本文是 [主对话 PRD](../main-chat/PRD.md) 与 [移动端产品定义](../mobile-product/PRD.md) 的上层；产品层改动在这里裁，下游只记实现。
devlog：[助手带团队](../../docs/devlog/2026-10-15-assistant-runs-the-team.md)。

## 一句话

**你只跟一个人说话；它替你带一支团队，事事给你交代。**

## 诊断：差的那一点是闭环

主对话的样子已经像一个「人」（IM 画法、助手卡片、头像，主对话 PRD 裁决 60–79），角色上还是**前台**：接话、做小事、把大活转出去，之后就不管了。

- **派完就放手。** 入口层原话是「告诉用户在路上了，卡片显示进度，用户问起再查」（`core/src/managed_prompt.rs:300-301`）；
  主对话 PRD 裁决 9 定的是不往对话里注入汇报轮。活交出去以后，盯卡片、判断结果靠不靠谱的人是你。
- **不碰 Galley 的配置。** 「What Only The User Changes In Galley」（`core/src/managed_prompt.rs:89`）。
- **记不住在办的事。** 事项账本撤了（主对话 PRD 裁决 49），跨段只剩查历史和 GA 记忆。

JC 列的职责（开会话、写提示、验收、汇总、记事）它只做了前两件，缺的是派出去之后那一半：回来验收、给你交代、记住答应过的事。前台和负责人的差别就在这里。

## 不是新方向，是两条线合一

1. **名字里就写着。** README「为什么叫 Galley」：人在 GUI 推进工作，Supervisor Agent 通过 CLI 管理团队，桌子是同一张（`README.zh-CN.md:225`）。
   宪法 Product Shape 也是「一个助手不够时扩成一支团队，人和 agent 都是一等操作者」（`AGENTS.md:15-16`）。
2. **Supervisor 当初为什么没用起来。** 到 10-06，`galley-im/*` 身份开的会话是 0，IM 里的真实请求都是小事，agent 自己就做了
   （`docs/devlog/2026-10-06-im-entry-layer-phone-first.md:10-12`）。它一直在门外：用户得自己找一个 agent、把 SOP 复制进去；而那时交给它的活也小到用不着管理。
3. **JC 每天都在用这个形态。** 他给 Claude Code 定的规矩，读起来就是一份幕僚长授权书：

| JC 给 Claude Code 定的规矩 | 换到 Galley 的助手 |
|---|---|
| 给 2–4 个选项加明确推荐；「按建议推进」就自主执行到底 | 要拍板的事带推荐来问，授权之后自己跑完 |
| 结论带推理链与可核实依据 | 交代要带证据 |
| 改完跑检查，别只声称已改 | 验收看证据，不转述子任务的说法 |
| 能自己点的自己点，我只做扫码 / 授权，写动作先问 | 三级授权（裁决 3） |
| 执行票派子代理，主会话只留讨论、票面、验收、提交 | 重活派出去，主对话只放判断和关系 |
| 暂缓进 deferred，裁决进 devlog | 记录是做事的副产品（裁决 5） |

所以要做的不是再给主对话加功能，而是请门外的 Supervisor 进门、坐到主对话的位置上：**Supervisor 线和主对话线合成一条**。SOP 也不退场，它变成助手自己的岗位手册。

## 地基展开

- **为什么是现在。** 模型越强，瓶颈越从「AI 能不能干」移到「人管不管得过来」：能派的活越来越多，人能同时盯的会话不会变多。
  今天重度用 AI 的人多半在给 AI 当项目经理；Galley 把这个经理的活也交给 AI，人只留下说话和拍板。
- **和「Less harness. More model.」不冲突，是它推到编排层。** 怎么拆、提示怎么写、结果够不够好，全交给模型判断。Galley 只造三样：
  - **手**：派活标签与 CLI，它操作团队的方式；
  - **账**：库里的记录，会话、项目、提醒、定时任务，一件跨天的事就是一个项目；
  - **办公室**：工作台，团队干活的地方。

  不造替模型想的流程，不在后台替你花钱。
- **底线：不用管，但随时看得见、接得过来。** JC 原话是「完全不再考虑会话管理」；改成这句，因为它用你的登录态在你的浏览器里下单，看不见你就不敢放手，办公室是信任的来源。
- **各端的位置。** 桌面 = 办公室，也是和它说话的地方；手机 = 只和它说话（核心价值仍是它能用你登录态的真实浏览器干活，见 [移动端产品定义](../mobile-product/PRD.md)）；
  IM 渠道 = 打给它的另外几条线；CLI = 它的手，也是外部 agent 的手。
- **比喻。** 内部设计拿「幕僚长」当尺子：秘书不带团队，军师不管执行，管家偏家务；幕僚长是带团队、授权有边界、替你过滤、对结果负责，也敢说不。
  对外它仍然只叫 Galley（主对话 PRD 裁决 64），这个词不进界面文案。

## 一天的样子

> 早上你在手机上说：「下周三去上海、周五回，看看高铁和外滩附近的酒店。」它：「好，我让人去查，十分钟左右。」对话里多一张在跑的卡片。
>
> 十分钟后它来消息：「查好了：周三早上 8 点那班二等座 553；酒店最合适的是 X，离外滩 600 米，680 一晚。要订吗？订票会用你电脑上登录着的 12306。」
> 这是它对过日期和价格截图之后的结论，不是把子任务原文转给你。
>
> 你：「订。」12306 要短信验证码，子任务停下来问；它判断这只能你来，问你一句，你回了数字，它转过去。
> 「订好了……都放进了『上海出差』项目。周二晚上 8 点提醒你带身份证？」你：「好。」提醒落成一条记录，看得见、撤得掉；周二 20:00 它来找你。
>
> 桌面工作台里多了「上海出差」项目和三个会话，想看怎么做的、想接手哪个都行，不想管就不用管。

## 裁决（JC，2026-10-15）

JC：「按你的建议次序推进」。以下六条都取推荐档，次序见下文「次序」。

1. **地基**：「你只跟一个人说话；它替你带一支团队，事事给你交代。」助手对结果负责，工作台是团队的办公室，Galley 只造手、账与办公室。
   措辞与宪法 Product Shape 要不要补「团队由助手本人带」，等本文稳了再拿给 JC（见待定）。
2. **D1 闭环：派出去的活，回来由助手负责。** 子任务完成或提问时，Core 叫醒助手一轮。它对照派活说明看结果，不够就打回给子任务，够了用一两句告诉你；
   子任务的提问先到它，它知道答案的替你答，涉及钱、对外、不可逆的转给你。卡片照旧显示状态，通知跟着它的消息走。
   - 没选：B 只在完成时叫醒、提问照旧直接找你；C 维持主对话 PRD 裁决 9（卡片加通知，不叫醒）。
   - 代价：每个子任务多一两次主对话调用，都因你交代的事而起，不是后台花费。
   - 先例：IM 渠道的 supervisor 一直这么做，委派的会话跑完就给 IM 那边注入一轮汇报（`runner/im_reporter.py:3-6`）。
3. **D2 授权：三级。**
   - 自己做，做完告诉你怎么撤：读一切；开、续、停它派的会话；建项目、归档、移动、改名；给它派的会话选模型；设你同意过的提醒。
   - 先问：对外（发消息、邮件、下单付款）；删除；往你自己开的会话里写；新建每天花钱的定时任务；改默认模型。
   - 只能你来：API Key、渠道登录、浏览器插件、运行环境、更新、重置主对话。它备好要填的内容，告诉你在哪。
   - 没选：B 只读加派活，再加 D1 的验收；C 除凭证外全放开。
   - 依据：会话与项目的 CLI 写操作 10-06 就明确不在禁止之列（`docs/devlog/2026-10-06-runtime-prompt-self-description.md:50-51`），助手只是没被告知；
     「配置只归用户」挡的是定时任务这类当时没有手、模型会假装做了的配置（galley#31「说已设置、其实不会执行」，同文件 `:28-29`），给了真的 CLI 命令就能挪。
     凭证留给你是原则：Key 经过模型就发给了模型服务商；运行环境和重置等于锯它自己坐的树枝（重置本来就不进 CLI，主对话 PRD 裁决 59）。
   - 授权只给助手；它派出去的子任务照旧守今天的边界，专心干活。
4. **D3 开口：只在欠你一个交代时。** 派出去的活有了结果或需要你、你同意过的提醒到点、定时任务跑完。不发主动建议。
   主对话 PRD 裁决 16 要的「提醒不再是必须事先设定的闹钟」改由**当场承诺**来做：它在对话里听到「周三要交材料」，当场说「周二晚上提醒你」，并落成记录。
   - 没选：B 加主动建议卡片（OpenMuse 的 Ideas），后台定期生成；C 只在你问时说话、不做提醒。
   - 理由：确定式规则，你能预期它什么时候出声；推断发生在你眼前的对话里而不是后台，裁决 49 拆账本的两条理由（后台替用户花 token、GA 记忆之外另起一套）都不碰。
5. **D4 记事：记录是做事的副产品。** 在办的事就是它派的子任务、建的项目、答应的提醒、定时任务，本来就在库里。
   每段开头由 Core 从库里确定式地拼几行「在办的事」放进上下文，不调模型；手册要求它把你提到的、有时间或有后续的事当场落成记录。「你是谁、你的习惯」照旧靠 GA 记忆。
   - 没选：B 维持今天，只靠 GA 记忆加查历史；C 把账本请回来。
   - 效果与边界：找回裁决 49 承认失去的「没人提起时也想得到」的一部分；只覆盖落成了记录的事，只说过一嘴的仍要靠查历史。
6. **D5 一个人：原则现在定，实现后排。** 对口只有一个，以后的设计都按这个走；实现排在桌面闭环之后，到时再和 iOS 排先后（[deferred](../../docs/devlog/deferred.md)「IM 渠道并入主聊天」的 L2）。
   - 没选：B IM 渠道长期各是一个独立的它（共享长期记忆、对话分开）。
   - 理由：今天每个渠道是独立进程、各养一个 agent（`docs/devlog/2026-10-12-main-chat-concept-review.md:63`），在微信里交代的事主对话里的它不知道，和「只跟一个人说话」直接冲突；
     但并入要重新解释 Rule 4、改 IM 进程，不该抢在闭环前面。
7. **名字：专名 Galley，角色词「助理」，名字后面不挂职位**（JC 同日：「1，A；2，首句问候……；3，都按你推荐改」）。
   - 分三层：专名（你在跟谁说话）就是 Galley，不变（主对话 PRD 裁决 64）；角色词（它是你的什么）中文「私人助理 / 助理」、英文 personal assistant / assistant；内部用语照旧（主对话、助手卡片、main chat）。
   - 没选「Galley Supervisor」：Supervisor 在 README、Agent API 与「智能体接入」里指接进来的外部 agent（`via=supervisor`，`README.zh-CN.md:170`），文案规范只留在集成语境（`docs/copy-language-guidelines.md:190`）；英语里它是上级、监工，方向对团队那一侧准、对用户那一侧反了。Supervisor 留作技术角色：操作 Galley 团队的 agent，内置的那一个就是 Galley 本人。
   - 没选「Chief of Staff / 幕僚长」作名字：最准，但是公司与政府的职位、冷，个人用户身边多半没有；只在说明里当一次比喻。没选「管家」（中文软件里被系统清理工具占了：电脑管家、手机管家）、「大副」（比喻叠一层，Galley 本是船上的厨房），其余（总管、特助、秘书长、参谋长、师爷、军师、副手）见 devlog。
   - 「助理」不选「助手」：助手是帮手、偏工具，助理是替你打理事务、对你负责的人，正是裁决 1 的「负责人」；移动端产品定义本来就通篇用「助理」。「带一支团队」由句子说，不进名词。
   - **侧栏卡片取 A**：名字行只写「Galley」，不挂「Galley · 助理」（IM 会话列表不写职位；英文「Galley · Assistant」113px 加时间，1280 窗口的默认侧栏会挤掉时间），不改名「Galley 助理」（读成功能名），顶栏身份行静止时也不写角色（裁决 64）。它是谁由问候的第一句说：问候第一次打开时就是卡片第二行（主对话 PRD 裁决 65）。
   - **问候**（JC 定稿中文，删掉了原句「不用再想是开新对话还是接着哪个旧的」）：「你好，我是你的私人助理。以后有什么事，直接在这里跟我说就行。费时间的活我派出去办，办完回来告诉你。」英文：「Hi, I'm your personal assistant. Whatever comes up, just tell me here. Longer jobs I'll hand off, and come back to you when they're done.」
     开头不重复「Galley」（卡片上名字就在正上方）：中文开头一句 144px，1280 窗口默认侧栏的第二行（169px）也整句放得下；带名字要 195px。末句用「派出去」不用「安排人」：子任务是 AI 对话，不是真人。已建出的主对话里那一条不变，新建与重置后才是新版。
   - 跟着改：关于页副标题「极简 harness 的本地全能 AI 助理」、渠道里「Galley 是私人助理」、⌘K 关键词加「助理」、文案规范与设计文档。GitHub 仓库 About 与 README 是对外的，另问 JC。
8. **第 1 步「闭环」执行定稿**（JC 同日：「按建议推进」）：
   - **打回最多两次**（Q1 选 A）：只算助手主动发进子任务的消息，回答子任务的提问不算；上限写在叫醒消息里由模型遵守，Core 不硬拦，你开口让它再试照发。
     没选：一次（「先补证据、再补一处细节」就得来找你）、不设上限（助手追求完美、子任务卡在同一处，两种循环都没刹车）、按时间或花费（要先量，规则一句话说不清）。先例：Supervisor SOP「第一波不完整时，同一项目里最多再开 1–2 个后续会话」。
   - **打回时不出声**（Q1 附带选甲）：助手那一轮的回复写约定标签 `<no-reply/>`，界面不画、不通知、不置未读；返工的信号挪到卡片上，在跑那一行前面加「第 N 轮 · 」，点进子任务看得到它打回时说了什么。替你回答子任务的提问同样不出声。
     先例：IM 汇报的 `SKIP_REPORT`（`runner/im_reporter.py`）。没选：每次返工说一句并通知（乙，等于每个返工都弹一次；JC 的惯例是嫌吵就换通道，不删信号）。
   - **叫醒不留痕迹**（Q2 选 A）：叫醒是一条隐藏的系统消息，界面只画它的回复，它自己点名是哪件事。没选：灰色系统行（B，和它那句话重复、撞时间条的样式）。
     换成「交代带卡片」（C，回复下面挂同一张子任务卡片）的信号：试用一周里有两三次往上翻找卡片，或问它「哪个」「在哪看」；手机上往上翻更贵，iOS 界面开工时再定。
   - **机制**：子任务一次运行结束时（完成、提问、出错、停在步数上限、没派出去；被停掉的不算），Core 叫醒主对话一轮。主对话空闲就立刻；在跑就等这一轮结束、你排队的消息先发；它在等你回答时不发（这时发任何消息都会被当成那个问题的回答）。
     发之前重读现状（又跑起来的、问题已被你在卡片上答掉的、已被你接手的丢掉），几件合成一次。叫醒行 `created_via='system'`、`supervisor='galley-report'`，回放时压成一行。送不出去（派发失败，或到达时它在等你回答）就退回子任务自己的通知；平时通知跟着助手的消息走。
   - **助手手册**：内嵌在 Core、随主对话写进内置状态目录（照 IM 写 SOP 的先例），入口层要求第一次用 Galley 写命令前先读；写命令带 `--supervisor=galley-assistant`；不许用 `session wait` 一类会卡住主对话的命令。外部 agent 用的 SOP 不动。
   - **票**：主对话票 [29](../main-chat/issues/29-subtask-wake-core.md)（Core 叫醒）、[30](../main-chat/issues/30-assistant-manual-and-entry-layer.md)（入口层、手册、真模型评测）、[31](../main-chat/issues/31-subtask-wake-gui.md)（界面）。

## 重量

按「提新机制先量定位重量」写清三样：

- **上游**：GA 没有「管理用户看得见的会话」这一层，它的子代理是文件式、你看不见（主对话 PRD 裁决 25 已不用）。这是 Galley 自己 CLI 平台的延伸，不是平行重做 GA。

## 反方

1. **需求还没被证明。** `subtask_dispatches` 0 行；主对话 10-14 重置后 JC 说了 5 句；9 月以来工作台多是一到四句的生活查询。闭环的价值要真有活派出去才显现。
   对冲：没活可派时它退化成今天的好助手，不亏；第 1 步做完就量每周派几次、打回几次、JC 还会不会去盯卡片。
2. **验收可能走过场。** JC 和 Claude Code 那套能成立，一半靠写代码有测试和 diff 可验；Galley 的主场是浏览器和生活事务，没测试可跑。
   对策：派活说明要求交回证据（确认号、截图路径、链接），助手核对证据在不在，核不了就明说「没核实到」。结构照搬，验收标准要另写。
3. **两个操作者撞车。** 你和它同时动一个会话。规则：它只往自己派的会话里写，你开的除非你开口。
4. **裁决 6 落地前，「一个人」在 IM 上是破的。**
