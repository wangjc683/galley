# 02 工作台折叠头后面一行一步，中途提问留在外面

Status: open

来源：[工作台对话 PRD](../PRD.md) 裁决 6（2026-10-16，JC：「按你推荐，P1，不用切换器」「按建议推进」）。只改 GUI 与文档，不碰 Rust。
与票 [01](./01-speaking-grammar.md)（你的话在右、时间居中、一步的回复不画折叠头）并行，两张都会动 `Conversation.tsx` 与 `conversation.md`；01 先合，合进 main 后主会话会通知你把 main 合进本分支、解冲突。

## 目标

工作台里点开折叠头，看到的是助手过程卡片那种一行一步，点一行原地展开那一步原来的样子；中途提问和你的回答不再折进去。在跑时的样子不变，助手的对话逐像素不变。

## 背景：为什么不是 09-16 否掉的那一刀

deferred「过程区密度」B「全面单行合并」2026-09-16 真机否过（`0270ff56`，已 revert；JC：「太密集后，单个步骤的阅读体验其实变得更差了」），重开条件是「只能以阅读形态本身更好为由，且要同时解决同行两个披露 caret 的问题」。本票不是 B：B 把工具标签挤进 summary 那一行；这里一行只有一句话与对象，工具标签收进点开，整行是唯一的点击目标、没有 caret，单步点开后与今天的阅读形态一样。这一形态 JC 已在助手里真机验收（主对话票 22）。实现时守住这几条，别让一行里长出第二个可点的东西。

## 一、折叠头后面一行一步

- **范围**：落定运行的折叠头（`RunFoldHeader` / `RunFoldSection`）点开后的内容；live 头「已完成 N 步」点开后的内容。**不在范围**：live 窗口（最近完成的一步 + 在跑那一行）、没有回答的运行（中止、出错、停在步数上限）的整段平铺、`/btw`。规则一句话：折叠头后面的一律一行一步，不在折叠头后面的照原样。
- **每一行照助手过程卡片**（`docs/design/conversation.md`「过程卡片」）：那一句话 + 浅色对象（网站、文件名）；去掉序号、工具名与参数、箭头、竖线、收口那一步、只做了提问的那一步（同一步还跑了别的工具时这一行留着）；有细节的行点开原地展开（旁白、工具 `ToolCallout`、推理与开场白，工具在推理前）。数据与规则用现成的：`lib/assistant-process.ts`（`assistantProcessSteps`、`assistantStepObjects`）、`lib/step-heading.ts`、`lib/browser-site.ts`。
- **组件共用，不复制**：把 `AssistantProcessCard.tsx` 里的行与列表（`ProcessSteps`、`ProcessStepRow`、`StepDetail`）抽成两边共用的部件，参数化差别（有没有数字行、有没有行数上限与内滚、宽度）。助手卡片逐像素不变。
- **工作台的差别**：
  - 容器同助手的卡片（hairline `border-line`、`rounded-md`、`bg-app`，不加投影、不抬升），宽度撑满栏（工作台回复是满栏散文，卡片与它对齐）；
  - **没有数字行**（折叠头已经写了步数、用时、工具计数；token 与上下文照旧在回复的悬停行里）；
  - **不设行数上限、不内滚、没有渐隐**：工作台读过程是正事，p90 11 步、最多 52，嵌套滚动是负担。
- **间距与分隔**：卡片与折叠头、与下面回复的间距你定，参照今天折叠区的节奏（`RunFoldSection` 的 `-mt-2.5` 折叠数学、折叠头 `mb-2.5`）。展开后卡片与回复之间不画 StrongHr：卡片的边框已经把「行动」和「结论」分开，再加一道全宽线是两层分隔。写进 Comments。
- **动画**：开合照今天的 `RunFoldSection` / `ExpandSection`；点一行展开细节照助手卡片。
- **键盘**：行照助手卡片的披露控件语法（`role="button"`、Tab 可达、回车 / 空格、`aria-expanded`；没有细节的行不是按钮）。今天工作台的步骤标记行能 Tab 到，不能退步。
- **live 头点开的运行**：落定后照旧开着（`foldOverrides`，「completion is not a reason to take it away」），内容从 live 时的一行一步到落定的一行一步，不跳、不重挂载。

## 二、中途提问与你的回答留在外面

- 今天提问块与你的回答是运行的成员，落定后跟着折进折叠头后面（`run-groups.ts`：「Reply to the pending ask_user — stays inside the run」；`Conversation.tsx` 的 `sectionOwner`）。改为：落定后按时间顺序留在对话里、在折叠头之前（折叠头是回复的眉头，要贴着回复）：

  你的消息 → 提问块（回显）→ 你的回答 → 折叠头 → 回复

  多次提问的运行，每一组提问与回答都按时间顺序留在外面。助手对话是同一条规则（`linePlan.question`），可参照。
- **只改画在哪里**：运行的分组、步数（照旧算提问那一步）、用时、token、问题轨的 replySet、`askUserReplyContent`、`chosenCandidateIndex`、侧栏「第 N 步」都不变。
- 在跑时（提问还没答、或答完接着跑）照今天。
- 01 合入后，你的回答是右侧气泡、提问块在左，这里的顺序要在那个画法下看一遍。
- 库里同期 `ask_user` 只有 7 次，罕见；规则照样要一句话说得清，测试要覆盖。

## 验收

- 跑这几项：`pnpm --dir gui typecheck`、`pnpm --dir gui lint`、`TZ=UTC pnpm --dir gui test`，再用 `TZ=America/Los_Angeles` 全量跑一遍；`git diff --check`；全角标点自查（扫新增行）。gui 只格式化自己改的 hunk，新文件可以整篇格式化。
- **测试**至少覆盖：工作台点开折叠头是一行一步、没有数字行、没有上限（20 步全显示）、点一行展开细节；live 头点开同样，落定后保持打开；没有回答的运行照旧平铺原步骤区；中途提问与回答落定后在折叠头之前、按时间顺序（含两次提问）；步数与用时不变；助手卡片不变。
- **反向检查**：改坏几处，确认测试会挂；恢复后逐字节一致。例如：工作台卡片带上 8 行上限、提问又折进去、没有回答的运行也变一行一步、助手卡片多出或少了数字行。
- **逐像素**：助手对话（过程卡片收起与展开、在跑、在问你；浅色与深色）与开工时的 main 一致。
- **量**：同一批轮次（2、9、20、50 步）点开后的高度，改前改后各量一次，写进 Comments（参照主对话票 22 的量法）。
- **自查截图**（Chrome harness，不进仓库）：工作台多步运行收起与点开、点开一步的细节、20 步以上、live 头点开、带提问的运行（一次、两次）、中止与出错的运行、外置运行时；浅色与深色、中英文、默认窗口与宽松档；出总览图。
- **JC 在 tauri dev 里走一遍**：
  1. 打开一个有多步回复的工作台会话，点开折叠头，看每步一行、点一行能看到原来的工具与细节；
  2. 找一个步数多的（10 步以上），看全部列出、不在卡片里滚；
  3. 新问一句会调几次工具的问题，在跑时点开「已完成 N 步」，看跑完后还开着、样子不跳；
  4. 找一个它中途问过你的会话，看提问和你的回答在外面、折叠头贴着回复；
  5. 打开助手，点一条回复的「过程」，看助手卡片没变。
