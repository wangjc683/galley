# 事项账本合成语料与验收

来源：[票 01](../issues/01-affairs-ledger.md)「合成语料与验收」。JC 本机的会话大多是测试，过滤后几乎没有可读的，所以账本用一个虚构用户的三周对话来验：埋好答案，看挖不挖得到、分不分得对、噪声会不会被记成事实。以后改挖掘提示词时，这里就是回归集。

文件：

- `corpus.json`：语料（下面的剧本落成的对话，带时间）。
- `expected.json`：埋好的答案与不该出现的噪声。
- `run_eval.py`：跑法见下文。Core 那一半是 `core/examples/ledger_eval_prepare.rs`，调的就是生产代码 `ledger::run::begin` / `finish`（另带「记忆」页删一件事的 `delete`，评测流程不再用它）；检查器读产物用 `core/examples/ledger_parse.rs`，即「记忆」页的解析器。

## 怎么跑

全部在一次性的工作目录里跑（不给 `--workdir` 就新建一个临时目录），自带 `workbench.db` 和内置状态目录，绝不读写真实的 `~/Library/Application Support/app.galley/`。在仓库根目录执行。

**不用模型的部分**（可以随时跑，几秒钟，首次要编译 Core）：

```bash
# 用语料建库、按周三次准备批次（每次当作挖掘成功提交），检查 Core 层该挡的噪声没进任何批次
python3 .scratch/main-chat/ledger-eval/run_eval.py prepare-only

# 检查器自检：该过的产物、该挂的产物（缺区域、暗号、多出情绪文件、情绪行不在条目里或认不出、该记的情绪没记、认不出的自由格式）
python3 .scratch/main-chat/ledger-eval/run_eval.py selftest
```

批次存在 `<工作目录>/steps/NN/batch.md`，任务提示词在同目录的 `task.txt`，可以直接读，看模型会拿到什么。

**要真模型的部分**（手动触发，和 `pytest -m e2e` 一样；会花模型额度，三次挖掘）：

```bash
python3 .scratch/main-chat/ledger-eval/run_eval.py run \
  --mykey ~/Documents/GenericAgent/mykey.py \
  --ga-python ~/Documents/GenericAgent/.venv/bin/python \
  --llm-no 0
```

- `--mykey`：一个 GenericAgent 格式的 `mykey.py`，用其中第 `--llm-no` 个模型。
- `--ga-python`：装有引擎依赖的解释器（开发机上 Galley 内置运行时用的那个，即 `core/python-bundle/python/bin/python3`，或 GA 自己的 venv）。
- 每次挖掘成功后，产物与解析结果存在 `<工作目录>/steps/NN/outputs/`、`parsed.json`，并打印解析器认出了多少（持续 / 已消失条数，情绪行数与挂在几件事下，`other` 剩多少字）。
- 票 04d 起不再有「删后不重建」一项：删除就只是删除，以后再提到可能再记下（PRD 裁决 48）。
- `--step-days`：两次挖掘相隔几天，默认 7（三次，验增量与「进行中 → 已结束」的转变）；给 21 就是一次读完三周。
- 每次挖掘是 `managed-ga/code/agentmain.py --func task.txt`，`GALLEY_GA_STATE_ROOT` 指向工作目录里的状态目录；挖掘成功才提交位置，失败按生产规则不动位置、下次重读。
- 跑完自动检查；之后也能单独再查：

```bash
python3 .scratch/main-chat/ledger-eval/run_eval.py check --workdir <工作目录>
```

## 和真实运行的差别

- 真实运行由 Core 起一个隐藏的内置会话执行同一个任务提示词，带 Galley 运行时提示词与内置模型配置；评测直接用引擎的 `--func` 模式和给定的 `mykey.py`，不带 Galley 运行时提示词。提示词正文、SOP、批次、产物目录都一样。
- 真实运行每天一次；评测默认每周一次，批次更大。

## 判定规则

- 只做关键词与结构检查，不让模型打分。票 04 起产物格式由挖掘提示词钉死，检查器用「记忆」页同一个解析器（`core/examples/ledger_parse.rs`）认出持续活动、已消失事项两类条目和条目里的情绪行，不再按标题猜区域。
- 产物只有 `activities.md` 与短清单 `ongoing_affairs.md`：多出任何文件（尤其是旧的单独情绪文件）为挂（票 04d）。
- 认全：`activities.md` 要被解析成条目（`raw` 或缺失为挂）；认不出的段落（`other`）为空为过，少量（400 字以内）记 WARN，更多为挂。
- 情绪行：文件里每一行「- 情绪…」都要在某个条目的块里，并被解析器认成那个条目的情绪；不在任何条目里、或认不出（落进 `extra`）为挂。检查器把每条情绪行连同所在条目打印出来。
- 持续活动：关键词出现在某条持续活动里（标题、现状、原文、其余说明，不含情绪行）为过；只出现在已消失事项里为挂；两边都有记 WARN（可能是拆成了两条，比如「住院陪护（已结束）」和「康复（进行中）」，人工看一眼）。已消失事项反过来。
- 情绪：关键词出现在某条情绪行的原话或标签里为过，并打印它挂在哪件事下；挂的不是 `expected.json` 里 `affair` 指的那件事记 WARN。`affair` 有值的没记为挂；为 null 的（对应不到任何事项）没记只打印 info。
- 短清单：每行是「- A编号｜……」且编号是现有的持续活动，否则记 WARN。
- 噪声：关键词在产物任何地方出现都算挂（`galley/` 子目录不查）。如果模型写了一句「已忽略：暗号蓝鲸 4721」，也会判挂，检查器会打印那一行，人工裁定。
- 判不了的事交给人：情绪判断的语气是否对、条目是否「宁多建不错合并」。「懂不懂 JC」等 02 上线、JC 用两周后再看。
