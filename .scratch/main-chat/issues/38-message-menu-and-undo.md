# 38 消息菜单（右键与回复的「⋯」）、删除改为撤销提示条

Status: ready-for-agent

来源：主聊天 PRD 裁决 85（2026-10-16，JC 真机试票 32 后：「右键删除，我感觉可能还是有发现性问题，而且右键菜单现在就那么一个按钮，也不优雅」「退出确认框……感觉是有正文但是正文删掉了的感觉，空间浪费……不够现代美观」；JC：「两点都按你推荐执行」）。依赖 32（已合入，`57fc1853`）。只改 GUI；Core 的删除命令不动。

## 目标

右键（或回复行动条上的「⋯」）打开的是这条消息的菜单，删除是其中一项；点删除不再弹框，气泡立刻消失，给 5 秒撤销。

## 一、消息菜单

现有的 `gui/src/components/conversation/MessageDeleteMenu.tsx` 只有「删除」一项。改成这条消息的菜单（组件改名随你，比如 `MessageMenu`），只在助理的对话里：

- **你的气泡**：复制、引用、分隔线、删除。
- **它的回复**（含问候、提问、叫醒那一轮的回复）：复制、引用、保存、查看过程、分隔线、删除。
  - 复制、保存与行动条上的同一个动作（`MessageActions.tsx`：复制的是 markdown 源码）；你的气泡复制纯文本原文。
  - 查看过程：与行动条上的过程按钮同一个动作、同一个出现条件（没有过程的回复不出这一项，不画灰的）。
  - 保存：与行动条同条件。
- **引用**：把整条放进输入框上方的引用条（票 07 的 `lib/composer-quote.ts`，上限 3 段、同一段不重复，照旧）。长的只取开头一段，超过一定长度（你定，写理由；比如约 120 个汉字或 3 行）截断加「…」；代码块、表格这类不适合当引用的，取它前面的文字或第一行，你定。
- **删除**：destructive 样式、在分隔线后；置灰规则与原因文案照票 32（在跑、在等你回答、带子任务卡片的回复），只灰这一项，其余照常可用。
- 菜单视觉照侧栏的行菜单（`galley-pop-in` / 200px / 13px）；关菜单不动焦点、Esc 只关菜单、选区与浮动复制保持（票 32 的规矩）。
- 右键落在气泡里的文件引用、图片上，照旧出它们自己的菜单。

## 二、回复行动条的「⋯」

- 助理的对话里，回复下的行动条（`MessageActions`，悬停才出现）末尾加一个「⋯」，打开与右键**同一组动作、同样排序与样式**（`docs/design/layout-and-chrome.md:219` 的规矩：右键是熟练用户的快捷入口，「⋯」是可发现入口）。两处共用一份动作清单，不各写一份。
- 图标与尺寸照行动条现有按钮；`aria-label`「更多」；菜单开着时行动条保持可见。
- 你的气泡不加悬停按钮（裁决 73）。
- 工作台的行动条不加（工作台没有删除，deferred「工作台会话删单条消息」）。

## 三、删除改为撤销提示条

- 去掉 `DeleteMessageDialog`。点「删除」：
  1. 这条气泡（Core 会删的那组行，票 32 的分组规则，界面已有同一套）立刻从界面藏起，分组间距、时间条照规则重算，滚动不跳（票 32 已有的锚定）；
  2. 底部出提示条「已删除一条消息」+「撤销」，约 5 秒（复用现有提示条与 `lib/toast-timing.ts`，悬停或焦点在上面时暂停）；
  3. 提示条消失时才调 Core 删除；点「撤销」就把气泡放回，不调 Core。
- **连着删几条**：合成一条提示条「已删除 N 条消息 · 撤销」，撤销全部放回；计时从最后一次删除起算。或者你有更好的规则，写理由。
- **5 秒内发下一句**（输入框发送、回答提问、`/btw`）：先把待删的提交给 Core、等它成功，再发；提示条随之收起。
- **提交时被 Core 拒绝**（这 5 秒里主对话开始跑了，比如子任务叫醒、到点提醒；或其他错误）：气泡放回，出一条错误提示（原因照票 32 的文案，带「复制详情」或照现有错误提示条的做法）。
- **待删的状态放在 store**，不挂在组件上：5 秒里切到工作台、关掉主对话的视图，照样到时提交。
- **5 秒里退出 Galley**：没提交就没删，下次打开还在（安全的方向），不做特别处理；写进注释与设计文档。
- 手机端、CLI 在提交后才看到删除。
- 置灰的条件照旧：选不了的时候菜单里就是灰的。

## 四、文案与文档

- 新文案进 i18n（中英）：「复制」「引用」「保存」「查看过程」能复用的就复用行动条的；「已删除一条消息」「已删除 N 条消息」「撤销」「更多」英文你写。
- `docs/design/conversation.md`：票 32 写的右键删除一节改为「消息菜单」（两种气泡的项、⋯、引用整条的截断、撤销提示条、5 秒里发送与退出的处理）。
- `docs/design/overlays-and-settings.md`：票 32 加的「只删一条、标题已说全时可以没有正文」那条例外改写：单条消息的删除不弹确认，用撤销提示条（裁决 85）；「被否：撤销」那句注明指的是重置。
- `docs/design/onboarding-and-cards.md` 提示条一节：加「撤销」这种用法（用户动作的回执，带撤销按钮）。
