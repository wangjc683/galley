## 目标

主对话把要跑很久的活派给子任务，自己不被占住；子任务在主对话里是一张卡片，需要你时浮到你面前，你在里面说过话它才算你的对话。

## 已定的五点（JC 2026-10-13）

1. 一条回复里每个 `<subtask>` 标签一个子任务、一张卡；拆不拆由模型决定。不做「多个活合成一张卡」。
2. 子任务是一个普通对话：派活说明作为它的第一条用户消息，照普通对话跑（不是 Goal）。
3. 卡片第一版四种状态各一行：在跑（与侧栏副行同源的「第 N 步 · 在做什么」）/ 在问你（卡片里直接答）/ 完成（一行结果 +「打开」）/ 失败（原因 +「打开」）。不做浏览器「已看 3 / 7」与网站图标。
4. 通知：子任务在问你一律通知；完成只在跑了 2 分钟以上时通知；出错一律通知（与侧栏「等你回复 / 出错时挂出」同一原则）。
5. 定时任务改卡片拆到 06b，本票不做。

## 范围

**Core（Rule 5：业务在 Core）**

- **数据**：会话记父会话（主对话）与「是否已升级为普通对话」；另记「哪条回复派了哪个子任务」（含没派出去的：原因），卡片按它找到自己的子任务。迁移照规矩补六处手写列表（core/tests 四处、cli/tests 两处），回报你选的表结构与理由。
- **解析与派活**：只在内置运行时的主对话里，一轮结束、回复落库时，Core 取出最终回复里的全部 `<subtask>…</subtask>`，每个开一个子任务：内置运行时的普通会话，父会话是主对话，来源标成子任务（`origin.via` 的新值，回报叫法），标题取说明的第一行，说明作为第一条用户消息发出、立即开跑。
  走 Core 现有的建会话加发送路径，参照定时任务 `core/src/scheduler.rs` 的 `fire`。标签正文为空、没闭合或建会话失败：记为没派出去并带原因，不重试。其他会话里出现这个标签不派活。
- **标签不进正文**：落库与流式显示都不带 `<subtask>` 标签，照 `<next-suggestion>`、`<goal-status>` 的过滤（`core/src/turn_persistence/derive.rs:77`、`:102`，GUI 的 `cleanPartialContent`）。说明本身跟着子任务存。
- **回放**：主对话回放时（含票 11 带过去的几轮），派过活的那条回复在末尾补一行 `[subtask <子会话 id>: <标题>]`，没派出去的补 `[subtask not started: <原因>]`，模型日后能按编号用 CLI 查（`session show <id>`）。说明正文不回放。
- **升级**：用户从界面（含手机）在子任务里发出一句话，它就升级为普通对话，此后照其他对话处理。CLI、supervisor、定时任务的发送不算。
- **通知**：按上面第 4 点；沿用现有通知路径（`gui/src/lib/notify.ts` 等，回报落在 Core 还是 GUI 与理由），iOS PRD 裁决 17「回复完成只认人发起的轮次」对子任务按本票例外处理（主聊天 PRD「设计约束」已写）。
- **CLI / Agent API 只做加法**（Rule 3）：会话 JSON 加父会话与是否已升级两个字段；`sessions list` 的默认结果不变（子任务照样列出）。新字段写进 `docs/agent-api/`。
- **手机端**：远程会话列表与侧栏一致，不列没升级的子任务（先例：票 10 拆掉前的挖掘会话过滤在 `core/src/remote/*`）；卡片在手机上的渲染留给 iOS 07。

**入口层的派活条款**

- 接在入口层（`MAIN_CHAT_ENTRY_LAYER`，`core/src/managed_prompt.rs`）后面，原文用 `.scratch/main-chat/entry-layer-eval/dispatch-clauses.md` 的 T 段，再加一句：用 Galley 的子任务，不用记忆里的文件式子代理（`memory/subagent.md`；对照里模型会主动去读它）。
- 字节上限跟着调并写明理由；`docs/managed-ga-runtime/prompt-composition.md` 的入口层一节、条款台账、回归清单（大活派出去、快活自己做、派完不守着）同步改。

**界面**

- **卡片**：派活的那条回复下面，一个子任务一张卡，按上面第 3 点。在问你时卡片里直接回答，复用现有 ask_user 的回答组件与发送路径；没派出去的卡写明原因，没有「打开」。状态实时（订阅现有运行状态事件）。卡片不进模型上下文。
- **打开子任务**：在主区打开，顶栏标题前一段面包屑「主对话 ›」，点它回主对话；侧栏选中仍停在主对话行（「选中行必在侧栏里」，`docs/design/layout-and-chrome.md`）。
- **侧栏**：没升级的子任务不进任何分区（置顶、项目、时间桶、其他来源、更早）；子任务在问你、出错时，状态汇到主对话行（裁决 30）。⌘K 能搜到子任务，打开时同样是面包屑形态。升级后照普通对话进「其他对话」。
- **设计**：动手前读 `docs/design/` 的对话区、会话行、状态色与卡片相关章节，查禁令（「不要 / 有意 / 分叉」）；卡片与面包屑写进设计文档。视觉合入后由 JC 在 tauri dev 里看，子代理不开 tauri dev。

**外置运行时零变化**（没有主对话）。

## 不做

- 定时任务改卡片（06b）、浏览器「已看 3 / 7」、多活合成一张卡、手机端卡片渲染（iOS 07）、派活失败自动重试。

## 验收

- Rust：一条回复多个标签各开一个子任务；空标签、没闭合、建会话失败各记为没派出去；子任务的父会话、来源、标题、第一条消息正确并开跑；回放补行（派出、没派出）且说明不回放；升级规则（界面发送升级、CLI 发送不升级）；通知判定（在问你、2 分钟门槛、出错）若落在 Core；其他会话与外置运行时不派活；CLI 新字段。
- vitest：流式与落库都不显示标签；卡片四种状态与没派出去；卡片里回答 ask_user；面包屑与侧栏选中；侧栏不列没升级的子任务、升级后列出；通知判定若落在 GUI。
- `cargo test --manifest-path core/Cargo.toml --workspace`（本机时区与 `TZ=UTC`）；`pnpm --dir gui typecheck`、`lint`、`exec vitest run`（本机时区与 `TZ=UTC`）；六个门禁脚本；`git diff --check`。
- 写清给主会话的真机复现步骤：在主对话里交代一件大活（如「把下载文件夹里的 PDF 按内容分类」），看到卡片在跑；子任务问你时卡片里能答；完成后「打开」看到完整过程、面包屑能回来；在子任务里说一句话后它进侧栏。
- 格式化只动自己的文件或 hunk（core 不是 rustfmt-clean，gui 不是 prettier-clean）。

## Comments

2026-10-13 实现回报（Opus 子代理，基于 `62c68552`，三个提交：Core 与入口层、界面、文档）：

- **表结构（迁移 048）**：`sessions` 加 `parent_session_id`（指向主对话，`ON DELETE SET NULL`）与 `promoted_at`（用户第一次在里面说话的时间，空 = 没升级）；新表 `subtask_dispatches`，主键 `(parent_session_id, turn_index, ordinal)`，一行一个标签，按回复里的顺序：`session_id`（没建出会话时为空）、`title`、`failure`（`empty` / `unclosed` / `start_failed`，CHECK 限定）、`failure_detail`、`created_at`。回复就是 `msg_{主对话}_{turn_index}_assistant` 那一行，卡片按它挂。
  理由：父会话与升级是会话自己的事实，CLI 要读，所以进 `sessions`；「哪条回复派了哪个子任务、没派出去为什么」是一次派活的记录，一个标签一行，主键同时挡住同一条回复派两次。六处手写迁移列表与 `db_migrations.rs` 都补了。
- **`origin.via` 的新值叫 `subtask`**：子任务会话与它的第一条消息（派活说明）都是 `{"via":"subtask"}`。`created_via` 的 CHECK（006、007、021）只认四个值，加第五个要重建 `sessions` 和 `messages`，正是 021 / 023 / 033 预检要防的外键级联删除风险，所以库里存成 `system` + 保留的 supervisor 标签 `galley-subtask`，读回时（会话、消息、原始消息行）一律还原成 `subtask`、不带 supervisor。Agent API 文档里 `Origin.via` 加上这个值（稳定标识集合，新增不算破坏）。
- **派活**（`core/src/subtask.rs`）：队列 drain 任务收到主对话的 `RunComplete` 时，在把下一条排队消息交出去之前，读主对话最新一条可见回复；是最终回答（没有真实工具调用，以 `ask_user` 结束的不算）、里面有 `<subtask>`、还没有记录的，先在进程内认领，再放到后台去派。每个标签并发处理：
  - 空标签记 `empty`，没闭合的记 `unclosed`（标题取它已写的第一行），都不建会话、不重试。
  - 有说明的：建会话（内置运行时、父会话 = 主对话、来源 `subtask`、标题 = 说明第一行去掉 `#`、`-`、`**` 之类的 markdown 记号后按派生标题的规则截断、用主对话当前选的模型），第一条消息就是说明，与会话在同一个事务里写入；随即广播 `session-created-external`（via `subtask`）与 `user-message-persisted`（`pending`），写记录并广播 `subtask-dispatched`（卡片这时就出现），然后照 Core 发送的做法起跑：占运行闸、共用路径起 runner、发出 `user_message`，再广播 `dispatched`。
  - 建会话失败：记 `start_failed`、没有 `session_id`；会话建好了但 runner 没起来：记录改成 `start_failed` 带原因（保留 `session_id`，可以打开），消息广播为 `persisted_only`，再广播一次 `subtask-dispatched`。
  - 其他会话（包括外置运行时的会话）里的标签只是文字，不派活。
  - 没有走 `session.new` 的 socket 路径：它不占运行闸、也不能带父会话和新来源；也没有直接调 `send_user_message`：那样记录要等 runner 就绪（几秒）才能写，卡片会晚出现。
- **标签不进正文**：Core 的派生（`turn_persistence/derive.rs`）与 GUI 的 `ga-output-cleaning.ts` 同步改：完整的 `<subtask>…</subtask>` 从最终回答、preamble、ask_user 参数里去掉；没闭合的连同后面全部截掉；流式时按未闭合标签截断、标签名写到一半也截。共享黄金用例加了 3 条，两边逐字节一致。库里 `content` 原样保留（派活要读）。
- **回放**：主对话的 runner 拿回历史时（当前段与票 11 带过去的几轮都算），助手行去掉 `<subtask>` 块，派过活的那条回复末尾空一行后每个标签一行：

- **真机复现（主会话在 tauri dev 里做）**：
