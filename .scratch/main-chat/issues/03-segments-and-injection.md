# 03（C）切段、注入与主聊天入口层提示词

Status: needs-triage

来源：主聊天 PRD 裁决 18、20、27（2026-10-12）。依赖 01（账本有内容）、02（主聊天存在）。对外必须与 04 同版。

## 目标

用户看到一条完整的主聊天；模型每次只拿当前一段的上下文，外加身份、全局记忆和事项清单，所以没人提起时它也能联想到相关的事。

## 范围

- **切段规则（确定式）**：上一轮结束后空闲超过 N 小时，下一条消息开新段。N 待定，真机调。手动收束话题的说法待定。
- **段末**：确定触发一次记忆整理（今天靠模型自觉，140 个会话 3 次，`docs/ga-baseline.md:75`）与账本增量（01 的挖掘对这一段跑一次）。
- **段首**：Core 让 runner 以新上下文起，不回放旧段（02b 起回放由 Core 控制）；注入身份、全局记忆、事项清单。库里的时间线不动，界面照常显示整条。
  注入的事项清单要小：进行中的事项，不是所有聊天的摘要。可以考虑写进 GA 每 10 步重读的记忆文件（`ga.py:605`），让长段里也保持新鲜。
- **查主聊天历史的工具**：只读，内置运行时专用；管「你问起时找得到」。
- **主聊天入口层提示词**：进 Galley 现有分层（准入规则、字节预算、条款台账、回归清单，`docs/managed-ga-runtime/prompt-composition.md`），起点是 10-06 IM 入口层。
  写：长期助理的身份与连续性；情绪的使用规则（可以为做事引用，不单独评论，PRD 裁决 20）；何时开旁聊 / 派子任务；主动开口的分寸；记什么、不记什么。
- **IM L0**：IM 入口层也带事项清单（`core/src/managed_prompt.rs` `im_supervisor_prompt`）。
- 旧材料（10-09 窗口预算调研，仍可参考）：GA 超过 `context_win × 3` 字符从最早整段丢（`managed-ga/code/llmcore.py:107-131`），
  较早轮次工具输出截头尾（`:48-66`），缓存标记（`:959-967`），`trim_keep_rate` / `cut_msg_interval` 按会话读。

## 验收

- 按轮看 `telemetry_json` 的 `contextUsedChars`：每段从小开始，不再一路涨到整窗（`.scratch/main-chat/baseline-snapshot.py --session <id>`）。
- 跨段问上周聊过的事能接上；没提起时也能在相关话题里联想到（JC 实感）。
