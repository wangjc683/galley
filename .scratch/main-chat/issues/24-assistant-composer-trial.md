# 24 主对话的输入框试验：现状 / 一行式

Status: ready-for-agent

来源：主聊天 PRD 裁决 71（2026-10-15，JC：「按你推荐的 A，其余照调整推进」）。依赖 22。只改 GUI，不碰 Rust。

## 目标

主区开着助手时，输入框可以在两档之间切换，在 tauri dev 里真机比：**现状**（今天的卡片加提示行）与**一行式**。比完按赢家另开票定稿、撤掉切换器。裁决 71 已经定下的三件（按 Enter 直接排队、主对话不显示提示行、占位文字「发消息…」）不进切换器，直接做；其中提示行与占位文字随一行式出现，现状档保持今天的样子，好对照。

## 生效范围

- 只在主区开着助手时（`MainView` 的 `isMainChat`，同票 20 的门）。工作台的会话、从助手点开的子任务、外置运行时，两档下都与今天完全一样。
- 新对话的空状态输入框（居中那个）不动。

## 一、切换器（临时）

- 照票 19 的做法：一个常驻、可点的小 pill（放哪你定，不挡对话与输入框），两档「现状 / 一行式」，选择存 `localStorage`（键名带 `galley.tmp.` 前缀），默认「一行式」。头部注释写清删除步骤；试验代码单独一个目录或文件，名字带 trial。
- pill 上加一个「演示在跑」开关：只换输入框的显示，画出在跑时的样子（停止键、输入框上方的队列条里两条假的排队消息），不写 store、不发消息、不调模型；演示时点停止、点队列条都不做事。用来比在跑时两档的样子。

## 二、一行式（只在一行式档）

```
┌──────────────────────────────────────────────────────────┐
│ ＋  发消息…                     gpt-6.1-sol · 默认   (↑)  │
└──────────────────────────────────────────────────────────┘
```

- 一条：最左 ＋（同今天的 ＋ 菜单），中间输入，右边模型短语（今天的 `LLMPill` + `EffortPill`，「模型 · 强度」整个短语原样），最右发送 / 停止。
- **输入**：起一行，随内容长高，约 8 行后在框里滚动（行数你定，写进 Comments）。长高时 ＋、模型短语、发送键贴底对齐（同 Claude.ai、Telegram）。
- **高度**：一行时约 48px（量了写进 Comments）。圆角、底色、边框、杏沙 focus ring 照今天的输入卡片；圆角要不要随一行式调（比如更圆），你定，截图里要有。
- **附件条**（图片缩略图）、**幽灵文字**（下一步建议）、**拖放浮层**、**草稿**都照旧可用：附件条放在输入上方、框内；幽灵文字照旧在输入里。今天「按 → 填入」那句提示若在提示行里，一行式下换个位置或做法（比如幽灵文字末尾一个安静的 →），你定，写进 Comments。
- **模型短语的弹层**向上开、右对齐；运行中照旧封锁换模型、强度照旧可点。
- **宽屏**（1200 栏）下照旧满栏宽；小窗口（960 × 600）下模型短语过长时截断模型名，不挤掉发送键。
- **不显示提示行**（裁决 71 第 3 条）。今天提示行可能出现的六种（`gui/src/lib/composer-hint.ts`）：`dragToReferenceHint`、`enterHint`、`newlineHint`、`queueEnterHint`、`mainChatBusyEnterHint`（随下一节删掉）、`stoppingQueueHint`。前五种在主对话里都不说；`stoppingQueueHint`（停止中且有排队）回答「我发的丢没丢」，要换个位置说：比如队列条的标题在停止中改说这句，你定，写进 Comments。
- **占位文字**：主对话里「继续…」改为「发消息…」（en「Message…」，新文案键）；在问你时的「回复上方提问」照旧；在跑时也写「发消息…」，不写 `/btw`（`/btw` 的功能照旧可用）。占位文字在两档里都改（它不是形态），但现状档的提示行照旧。

## 三、按 Enter 直接排队（两档都生效，不进切换器）

- 主对话在跑时按 Enter，与普通会话一样直接排队（进输入框上方的队列条），不再弹「排队 / 开新对话 / 继续编辑」三选一（票 02）。
- 删掉 `MainChatBusyChoice` 与只为它存在的分支、文案键、`mainChatBusy` 参数与 `mainChatBusyEnterHint`；不再有人用的就删。带图的消息在跑时照普通会话的规则处理（今天普通会话怎么拦，主对话就怎么拦）。
- 设计文档里写着三选一的地方（grep「排队 / 开新对话」「开旁聊」「mainChatBusy」，中英都搜）：这张是试验票，文档留给定稿票改；只在 Comments 里列出要改的位置。

## 不做

- 模型挪进顶栏菜单（裁决 71 第 2 条已否）。
- 排队的消息挪进对话、显示成气泡（裁决 71 第 6 条，晚点再谈）。
- 工作台、子任务、空状态的输入框；外置运行时；手机端。

## 验收

- 跑这几项：`pnpm --dir gui typecheck`、`pnpm --dir gui lint`、`TZ=UTC pnpm --dir gui test`，再用 `TZ=America/Los_Angeles` 全量跑一遍；`git diff --check`；全角标点自查（扫新增行）。gui 只格式化自己改的 hunk，新文件可以整篇格式化。
- **测试**（试验测试单独一个文件，定稿时并进正式测试）：
  - 只在主对话生效：普通会话、子任务在两档下与今天逐字节一致。
  - 一行式：一条里有 ＋、输入、模型短语、发送；没有提示行；占位「发消息…」；在问你时「回复上方提问」；停止中且有排队时那句状态出现在新位置。
  - 现状档：今天的卡片与提示行（占位文字已换）。
  - 直接排队：主对话在跑时 Enter 进队列，不出三选一；普通会话照旧。
- **反向检查**：改坏几处，确认测试会挂；恢复后逐字节一致。例如：普通会话也变一行式、一行式又出提示行、主对话又弹三选一、停止中排队的那句丢了。
- **逐像素**：工作台的会话、子任务、外置运行时、空状态的输入框，与开工时的 main 比，静止、在跑、在问你，浅色与深色，要全部一致。
- **自查截图**（Chrome harness，可以复用会话草稿目录里 `s22/harness/` 的脚本，复制到新目录再改，不进仓库）：两档各一套：
  - 空闲、输入了三行、输入很长（滚动）、带两张图、幽灵文字、在问你、演示在跑（停止键 + 队列条）、停止中且有排队、模型弹层打开；
  - 浅色与深色、中英文、默认窗口、小窗口与宽屏；出总览图。截完把 harness 从工作树删掉。
- **JC 在 tauri dev 里比**：
  1. 打开助手，用 pill 在两档之间切，空闲时比；
  2. 打几行字、拖一张图进去，看长高和附件条；
  3. 打开「演示在跑」，比停止键与队列条；
  4. 真发一句要跑一会儿的话，跑的时候再按 Enter 发一句，看它直接进队列；
  5. 点模型短语，看弹层的位置；
  6. 选赢家。
