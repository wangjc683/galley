# 77 新段带过去的「一轮」按用户的一句分，不按 turn_index

Status: needs-dogfood（2026-10-22 合入 `e3767d1f`；主会话机器验收：rebase 到 main 后 `TZ=UTC cargo test --workspace` 1209 条全过；代理另跑本机时区全量、改过的三个文件 `rustfmt --check`、`git diff --check`。代理用本机数据备份核对：段首 27 的窗口带上了 20、26 两个答案。`CARRY_MAX_CHARS` 由 6,000 改为 8,000，依据见裁决 125）

来源：[主聊天 PRD](../PRD.md) 裁决 125 第 2 条（2026-10-22，JC 真机走查票 75：「我看说在执行一个任务是我没有得到答案的 NBA 的一个什么，可是主对话前面关于 NBA 的问题我明明都已经有收到回复？」；主会话诊断后推荐，JC：「按你推荐，开始修巡看功能」）。只改 Core。修的是票 11（裁决 50，2026-10-13，`b9c1eef8`）起就有的错。

## 为什么

新段开头带上段首之前最近 3 轮（`core/src/session_runner/carry.rs`）。`CarriedWindow::from_rows`（`carry.rs:88-125`）按 `turn_index` 把「用户的一句」和「回复」配成一轮，模块注释也这么写（`carry.rs:14-18`）。但一次运行每走一步占一个 `turn_index`，只有第一步和用户的话同号，最终答案落在后面没有用户行的号上，被当成不完整的轮丢掉。

真机证据（主对话，10-21 21:26 开新段，`main_chat_segments` 起点 27）：

- turn 12：「和我聊聊哲学背景……」一步答完 → 完整带过去。
- turn 13：「新赛季 NBA 你对西部怎么预测……」+ 第一步「我先查一下西部阵容和最新预测……」；14–19 只有步骤；20 是答案。
- turn 21：「东部呢？」+「东部我先核对……」；22–25 步骤；26 是答案。

带过去的三轮是 12、13、21，两个答案都丢了。模型派子任务时写「此前助手两次只说会查阵容与预测，却没有实际交付」，逐字对得上。10-22 09:00 的巡看又开了一段（起点 37），带过去的又只有各轮第一步，它在第 3 步写「发现 NBA 预测子任务已完成但尚未汇总」，读了主对话才改口。每天早上的巡看几乎总是新段的第一轮，这个错每天都会碰上。

`SqliteGalley::main_chat_carry_from`（`core/src/db/main_chat.rs:508-532`）挑「同号上有助理行的用户行」，也是按同号配的。

## 要做的

1. **一轮的定义**：一句用户行（`is_conversation()` 的用户行：叫醒行算，问候不算），加上它之后、下一句用户行之前的全部助理行；至少有一行助理行才算完整。读到的行里排在第一句用户行之前的助理行（例如用户那句被删掉的回复，票 32）不算一轮，照旧不带。合并方式与重放一致（`replay.rs` 的 `merge_into`：同一角色的相邻内容以空行相接）。`said_at` 取这一轮最后一行助理行的 `created_at`。`turn_index` 字段取用户行的号。
2. **读取起点**：`main_chat_carry_from` 改成与第 1 条同一个定义（段首之前最近 `CARRY_TURNS` 句后面跟着助理行的用户行里最早那句的号），读进来的行要覆盖这几轮的全部步骤。两处定义写在注释里互相指向。
3. **一句用户行回答 `ask_user`**：那句回答本身是一句用户行，自然把一次运行切成两轮；照这个定义走，不另做特例，测试里写明。
4. **上限**：按新的定义，只读（`file:…?mode=ro`）量 JC 本机 `~/Library/Application Support/app.galley/workbench.db`，口径同裁决 50（所有会话的「一轮」，用户的话加回复的字数）：中位、p90、p95、最长、样本数。规则：三个 p90 的轮次放得进 `CARRY_MAX_CHARS`（6,000）就不改；放不进就改成不小于 3×p90 的最小整千，最多 12,000，并把新的依据写进常量注释。只回报数字，不回报任何消息内容。
5. **对真实数据核对**：把数据库用 `sqlite3 … ".backup <你自己的临时目录>/wb.db"` 备份一份到 worktree 之外的临时目录，写一个不提交的临时测试或小程序，对主对话（`sessions.main_chat = 1` 那一行）段首 27 与 37 算出新窗口：回报带过去的每轮的用户行号、最后一行助理行号、字数，确认 20、26 两个答案在段首 27 的窗口里。跑完删掉临时测试与备份，不提交，不回报内容。
6. **注释与测试**：`carry.rs` 模块注释、`from_rows` 与 `main_chat_carry_from` 的注释改成新定义。补测试：多步运行（用户行与第一步同号、后面几步无用户行、最后一步是答案，形状照上面 13–20）完整带过去；截断时留住答案的结尾；`ask_user` 切开的一次运行；叫醒行开头的一轮；问候不算；排在最前面没有用户行的回复不带；`main_chat_carry_from` 在多步运行上取到正确的起点。原有测试按新定义调整，不要删掉覆盖的情形。
