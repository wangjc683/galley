## 为什么

勾掉一件之后这一行原位停 1.5 秒，然后「跟着新清单一次挪走」：这一行消失，下面各行瞬跳一个行高（收起的行约 32px 或约 51px，打开的更多）。删除、跳过这一次、撤销放回、取消勾回到原位、它替你改了日子换了位置，都是瞬跳。主对话删消息已经不跳了（裁决 138：「跳才是硬的主因」）；面板是每天扫的主清单，更该不跳。

## 要做的

### 一、清单换了一份时，行从旧位置到新位置

面板在屏上、「待办」页的清单（`TodoPanelGroups` 画的那一份）因为数据变了而重画时：

1. **离开的行**（勾完停够落走、它勾的停够落走、删除、跳过这一次、取消它自己的提醒后离开、在「已完成」里取消勾）：在原来的位置淡出，`--motion-base`、`--ease-exit`，不缩、不移。照 `playRemoval` 的做法放一份拷贝在零尺寸的层里淡出，真的那一行照 React 的结果已经不在。
2. **留下的行**：从旧位置滑到新位置，`--motion-slow`、`--ease-firm`，位移就是真实的距离。组名、「还有 N 件没有列出」、开机自启提示这些夹在行之间的东西一起滑。只用 `transform` 与 `opacity`，加在已经落在新位置的元素上；终点的版面与没有动效时逐像素相同。
3. **新出现与放回的行**（撤销放回、Core 拒绝后放回、取消勾回到最上面那一段、重复的待办生出的下一期、Galley 新记的一件）：别的行滑开让位，它在自己的位置淡入，`--motion-base`。「亮一下」（`message-locate-flash`）照旧，规则不改；两样落在同一行上时不能互相打断。
4. **换位的行**（日子改了重新排序，你在浮层里改的或它改的）：滑到新位置，同第 2 条。改日期的浮层开着时这一行换位：浮层按版面在终点，行滑过去；真做出来看着不对（浮层与行脱开得明显）就这种情形不滑，写进回报。
5. **落进「已完成」**：「已完成」收起着时，这一行在上面淡出，组名那一行的件数跳一下（第二节）；展开着时，上面淡出、下面的新位置淡入，不跨组滑过去（中间隔着别的组，会从别的行上面穿过）。
6. **只在视野里的动**：滚出面板视野的行不加动画。面板的滚动位置照现在的规矩走，不为动效改；量位置时把滚动位置的变化算进去（清单变短、浏览器收回滚动时不能读成整列跳）。
7. **只放在眼前发生的那一次**：下面这些不是「清单换了一份」，一律不放：面板挂载与第一次读回、切到「备忘」页再切回、打开或收起一件、展开或收起「已完成」、拖窗口或拖面板宽度、跨午夜的重读没有改变次序时。打开、收起一件照旧瞬时（裁决 208 第 7 条：没做）。
8. **途中又来一次**：上一次还没走完，清单又变了：从当前看到的位置接着走到最新的位置，不排队、不补放。
9. **减少动态**（实时读 `prefers-reduced-motion`）：只淡不移。留下与换位的行一步到位，离开的淡出、新出现的淡入照留。

### 二、「已完成」的件数跳一下

`gui/src/components/todo/GroupLabel.tsx`：件数在挂载之后变了（多了或少了）的那一下，数字用 `sidebar-step-tick`（`globals.css` 现成的：淡入加上移 1px，`--motion-slow`）。挂载时不放。减少动态下照那个类现有的处理；它现在在减少动态下还会移 1px 的话，给这一处补成只淡。

### 三、放哪

- 规则（哪些行算离开、留下、新出现、换位，位移，时长与曲线取哪个 token，减少动态的模式）是纯函数，放 `gui/src/lib/todo-row-motion.ts`，有测试。
- 量与动 DOM 放 `gui/src/lib/todo-row-motion-play.ts`；由一个 hook 接进 `TodoPanel.tsx`。行认 `data-todo-row`，组认 `data-todo-group`。
- 可以从 `bubble-motion.ts` 引用与对话无关的小工具（比如 `rowShift`、读 token 的函数）；不改 `bubble-motion*.ts`，不引用绑着对话滚动锚点的部分。
- 需要新的类或关键帧时写在 `globals.css` 的 `message-locate-flash` 那一段后面，自带一段减少动态的 `@media`，不往文件后面那张共用名单里加行：票 160 同时在这个文件里加自己的一段。

### 2026-11-11 主会话验收

- 读了分支的接线部分（`TodoPanel.tsx`、`GroupLabel.tsx`、`useTodoPanelFlash.ts`、`useTodoRowMotion.ts`）；rebase 时 `reply-cards.md` 与票 160 相邻冲突，「勾掉与取消勾」留票 160 的、后面接本票新增的「离开与合拢」。在票的工作树里跑门禁：`typecheck`、`lint` 通过，`TZ=UTC` 测试 272 个文件、3125 个全过，文档链接与 `git diff --check` 干净。
- 做法：每次提交把这一页画的行的次序与上一次比，变了才放；旧位置在改清单的那次 store 写里读，新位置在 layout effect 里量，同一帧摆回原位再放。新出现的行等别的行让开（`--motion-fast`）再淡入。
- **票面前提不对的一处**：改日期的浮层不按版面放在终点，Radix 跟着行画出来的位置走、晚一帧，滑得最快时每换一行落后约 13px。代理改成：浮层开着、它这一行在滑时，取消这一次的滑动、一步到位，淡入淡出照留；选一天或快捷项（浮层随后关）通常照样滑。
- 动了 `useTodoPanelFlash.ts` 两处，只为配时序：它勾的那件停够放走之前先记旧位置；「滚到第一件」按行的终点判。亮行规则没改。
- 代理报的风险，原样记下（都要在真窗口量）：
  1. 第一帧不跳，靠 WebKit 在 `element.animate()` 后第一帧就用上第 0 个关键帧（票 94 依赖同一点）。
  2. 清单变短、浏览器收回滚动时，上面的行是否从原位滑下来、拷贝是否原地不动，只在假版面里测过。
  3. 行在滑的时候变换可能临时撑大滚动范围约 240ms（主对话为此用了 clip；这里没加，clip 会把从组下沿往上滑的行切掉）。
  4. 浮层那条规则里「下一帧再看一眼」依赖关浮层那次重画先于下一帧；偶尔晚了，选一天也会一步到位。浮层不关时不滑是推出来的，没在真窗口看过。
  5. 淡出的拷贝叠在滑上来的行上，最初约 80ms 两层文字重叠；按票面「同时淡出、同时滑」做的，没比过。
  6. 拷贝里的 CSS 动画直接放到终点，是为票 160 预防的，写的时候看不到票 160 的实现。
  7. 拷贝保留了菜单开着时那行的悬停底色（只藏了按钮），会一起淡出。
- 「已完成」的件数：`sidebar-step-tick` 在减少动态下本来就整个不动（票面那句「还会移 1px 的话」不成立），没另加类。
