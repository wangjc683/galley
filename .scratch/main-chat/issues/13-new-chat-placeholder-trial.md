# 13 新对话占位试验：现状 / B / A

Status: ready-for-human（2026-10-14 切换器已进 tauri dev，等 JC 真机比）

来源：主聊天 PRD 裁决 55（2026-10-14，JC：「其他对话的新对话，占位太大，位置也不合理」）。依赖 08。只改 GUI，不碰 Rust。

## 问题

按 `+` 或 ⌘N 后，「其他对话」分区最顶上冒出一条选中的「新对话」占位行（`SidebarNewSideChatRow`）。

- **大**：连上边距 40px，全宽杏色加抬起阴影，是侧栏里最重的一块；平时不在，按 `+` 才出现，整个列表下移。
- **位置有四处不对**：
  1. 对话发出后落在「今天」，在「项目」下面；占位行却在「项目」上面。发出那一刻占位行消失，「今天」标题和新行插进来，亮着的行往下跳约 60px（按 JC 当时的数据：项目 1、本周 1、今天没有对话）。
  2. 从项目组 `+` 新建时它也在分区顶上（票 07 列为已知、08「照旧」，没比过）。
  3. 列表滚下去后按吸顶的 `+`，占位行在视口外，侧栏没有一处亮着（`newChatActive` 只用来渲染这一行，没有代码去滚列表）。
  4. 紧贴分区头的 `+`，两个加号叠着，读作一个大按钮，不像列表里的一行。
- 另：首句发出到切屏之间，占位行与「今天」里那条没选中的新行同时在。`createSessionPersisted` 先把会话放进列表、设为活跃，`submitFromEmpty` 还要等 `create_session` 与 `activateSession` 才切屏。
- **根因**：10-08「侧栏恰好一行说『你在这里』」是给外置的新对话行定的，那一行本来就在，亮起来不占地方；票 07 为守这条规则，在最省事的分区顶上补了一行。

## 三档（切换器真机比）

- **现状**（对照）：票 08 的占位行。
- **B 亮加号**：不要这一行。空的新对话开着时，按的那个 `+` 保持按下态（选中底色加抬起）：普通新对话是分区头的 `+`；项目新对话是组行的 `+`，平时悬停才出现，这期间常显，计数让位，`⋯` 仍然悬停才出现。
- **A 落点**：一条草稿行，放在对话将来出现的位置。
  - 普通新对话：「今天」第一行；今天还没有对话就连「今天」标题一起出现，计数算上它。
  - 项目新对话：那个项目组的第一行。展开时在抽屉里，替掉空项目的「新建项目对话」；组或项目分区收着时，照选中会话的规则挂在下面；项目在「更多项目」后面时把组借出来。侧栏不认识的项目落回「今天」（它的第一条会话本来就是普通行）。
  - 单行 32px，选中会话行的样式。出现时滚进视野，上方留出「今天」标题或组行（`scroll-mt-11`）。
  - 点它把焦点送回输入框；项目新对话走 `onStartProjectConversation`，不丢项目（`onNewChat` 会清掉项目上下文）。
- **B、A 两档的接替**：首句发出、还没切屏时，那条新会话的行立刻接替并显示选中（`newChatSessionId`），草稿行或按下的加号同时退场。所以 A 发出前后位置不变，只是行高从 32 长到 48。现状档保持今天的行为。

## Comments

2026-10-14 实现（主会话直接做）：GUI typecheck、lint 通过；layout 测试 92 条通过（新增 16 条）。harness 自查结论：

- 现状：滚到底再按 `+` 时侧栏没有一处亮着；首句发出切屏前，分区顶上的占位行和「今天」里没选中的「新对话」行同时在。两条都是今天就有的行为。
- B：分区头与组行的按下态都在原位，组行计数让位；滚到底时吸顶的 `+` 仍亮着；接替那一帧加号退场、新行选中。
- A：七种情形落点都对；首句发出切屏前与切屏后两帧一模一样。第一版滚到底再按 `+` 时「今天」标题被滚到吸顶头下面，草稿行看起来又像在分区顶上，加 `scroll-mt-11` 后标题留在视野里。
