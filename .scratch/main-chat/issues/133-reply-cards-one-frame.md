# 133 写定一框列表：回复下的卡片一条回复一个框、一件一行；拆掉切换器

Status: ready-for-agent

来源：[主对话 PRD](../PRD.md) 裁决 182（定 181 第 2 条的一框列表，加票 132b 的两处 WebKit 修法）。只改 GUI；只影响内置运行时（外置运行时没有主对话，工作台不画这些卡片）。

## 为什么

JC 嫌回复下的卡片太大（裁决 180），讨论后定了结构不换、画法照过程卡片（181），在切换器上比过有框、一框列表、无框行三档，定一框列表（182）。切换器（`gui/src/dev/reply-cards-trial.tsx`，票 131、132、132b）里的一框列表就是要写定的样子；它开头的注释写了写定步骤。

## 要做到

1. **拆切换器**：删 `gui/src/dev/reply-cards-trial.tsx` 与 `reply-cards-trial.test.ts`；撤掉三处接入：`MainView.tsx` 的 pill 与 `useCardFiles`（混排），`SubtaskCards.tsx` 的 `useShownState`（演示状态）。`Conversation.tsx:621` 外壳上的 `data-role="reply-cards"` 写定后用不上就撤。`gui/src/dev/` 空了就删目录。生产包里不再有切换器留下的工具类。
2. **写定一框列表**（样子以切换器里 132b 之后的一框列表为准，下面是要点；和切换器注释冲突时以本票为准，报告里说明）：
   - **一个框**：同一条回复下的所有卡片（文件、子任务、待办、提醒、备忘，次序照旧）在一个框里。框照过程卡片（`ProcessCard.tsx`：`rounded-md border border-line bg-app`，行区上下左右 4px），宽度随最宽那一行（`w-fit`），上限是气泡上限（`ASSISTANT_BUBBLE_MAX`），离气泡 12px。框放在哪由你定：推荐在 MainView 画的那一层加一个小组件（比如 `ReplyCards`）包住五种卡片，而不是给 `Conversation` 的通用外壳加样式；和过程卡片共用框的类名常量可以，但过程卡片必须逐像素不变。原来每张卡片自己的框、底、圆角、`min-h-10`，以及卡片之间、组之间的间距（`afterFiles`、`afterSubtasks`、`afterCards` 一类参数）都去掉，用不上的参数删掉。
   - **一件一行**：24px（`h-6`），`px-2`，`rounded-sm`；16px 图标列照旧（`data-card-icon` 必须留着：待办、提醒、备忘飞进顶栏按钮靠它找起飞点，`lib/todo-flight-run.ts`），图标与名字 6px；字号 `--conversation-step-size`；名字 `ink-soft`，已经是淡色的照旧淡色（已提醒、已删除、过期、已移走）；划线等各卡片现有的状态写法照旧。
   - **浅色对象**：文件的文件夹、待办的日子与提醒、提醒的时间与状态，跟在名字后面 8px，`ink-muted`，同过程卡片的对象；文件夹与待办日子的上限 16em，不用百分比（132b 第 2 处）。子任务的短词跟在名字后 8px，颜色照旧。提醒的「取消」在行尾，`h-5`、左右 6px。
   - **整行可点**：能打开的行点任何空处等于点标题；用标题按钮的内边距伸满整行、同样大小的负外边距收回、行 `overflow: hidden`（132b 第 1 处：**不要**用绝对定位的伪元素）。浅色对象和没有原因的短词让指针穿过；待办的方框、提醒的「取消」、带原因的短词（「出错」「没有开始」）各管各的。能打开的行悬停与键盘聚焦时整行 `bg-hover`、名字转 `ink`；不能打开的行没有悬停底。原来标题按钮的悬停下划线与聚焦环不要了（整行底色代替，同过程卡片）。
   - **文件行**：整行是按钮，照旧；「在文件夹中显示」浮在框右边外侧、对着那一行垂直居中，框不为它变宽，从行移到按钮的路上悬停不断。
   - **在卡片里答提问**（裁决 101）：提问与输入框在那一行下面原地展开，那一块淡琥珀底，这时框撑到气泡上限。待办、提醒失败时那一行下面的原因照旧，在框里。
   - **图片缩略图**：在框里自成一段，上下 4px、左右 8px，左缘对齐图标列。
   - 状态判定、文案、i18n 不动。
3. **测试**：五种卡片现有的测试照新结构改；新加的钉住：一条回复一个框；行是 24px；整行可点的结构（内边距伸展、没有 `::after` / `::before`）；浅色对象让指针穿过、方框与「取消」与带原因的短词不让；对象上限是 16em、没有百分比上限；`data-card-icon` 还在。
4. **在 WebKit 里量**：用票 132b 的量具（scratchpad 里 `132b/132-webkit.swift`），这次加载由**真组件**渲染的静态页（不再是切换器的样式），量 132b 那张截断检查表里一框列表的几行（派活两张、两个带数字的待办、带数字的提醒与备忘、76 人文件、混排两种），每个标题有没有被截、框宽，与 132b 改后的一框列表数字对比（差 1px 以内算一致，不一致说明原因）。再看一眼暗色下框线与悬停底。
5. **设计文档** `docs/design/conversation.md`：
   - 新加一节「回复下的卡片（一框列表）」：框、行、对象、整行可点、悬停、在卡片里答提问、缩略图；为什么（裁决 179–182 的链条：抢戏 → 太大 → 结构不换只换画法 → 一框列表）；两条 WebKit 教训（随内容宽的框里不用绝对定位的伪元素做整行可点，不用百分比上限）。
   - 「子任务卡片」「提醒卡片」「待办卡片」「备忘卡片」四节：形态、位置那几段改成指向新一节，只留各自特有的（图标、短词、状态、点了去哪）。文件卡片现在没有自己的一节：在新一节里写清它的特有部分（类型图标、名字中间截、文件夹、默认程序或阅读面板、已移走或删除、缩略图），或单开一小节。
   - 「助手的对话」里「子任务卡片放进派活那条回复的那一组……最宽同气泡的上限」、「过程卡片」一节里「形态借子任务卡片……与子任务卡片同宽……撑满也让它和上面的子任务卡片对齐」：改成现在的关系（回执框随内容宽、过程卡片撑满；同一种框，上面是这条回复做了什么，行动条下面是怎么做的）。
   - grep 全仓文档里「最宽同气泡」「借子任务卡片」「借待办卡片」「借提醒卡片」「min-h-10」「40px」与卡片有关的说法，过时的跟着改；`docs/devlog/deferred.md` 里「回复里的可视化卡片」那条的「形态借子任务卡片」改成借回复下的框。devlog 不改（是历史）。
