# 25 主对话的输入框定稿：一行式，离窗口底边 24px

Status: ready-for-agent

来源：主聊天 PRD 裁决 72（2026-10-15，JC 在 tauri dev 里比完票 24：「一行式明显更好」；底边距：「直接定 24」）。依赖 24。只改 GUI 与文档，不碰 Rust。

## 目标

主区开着助手时，输入框就是票 24 的「一行式」，不再有切换器与演示；离窗口底边 24px。票 24 直接做的几件（在忙时 Enter 直接排队、没有提示行、占位「发消息…」、停止中那句在队列条标题）照旧。

工作台的会话、从助手点开的子任务、外置运行时、新对话的空状态输入框，与本票开工时的 main 逐像素一致。

## 一、按赢家撤掉票 24 的试验

照 `gui/src/components/conversation/composer-trial/composer-trial.ts` 头部的删除步骤做，「Always」与「If 一行式 wins」两段：

- 删掉整个 `composer-trial/` 目录里只为试验存在的东西：切换器 pill、选择的 store、演示（`ComposerDemoInert`、演示队列）、`galley.tmp.composerTrial.*` 的读写（JC 机器上留下的旧键不用清）、App 的 `composerTrial` 接线、MainView 的 `composerTrial` 与 `useComposerTrialOverrides`、Composer 的 `trial` 参数（`queueItems` 回到只读 store）。
- `ComposerOneLine` 与 `ONE_LINE_*` 量值挪到 Composer 旁边（文件名你定），一行式成为 Composer 的一个普通参数，由 MainView 在主对话里设上，同时关掉提示行；队列条的 `heading`（停止中那句）留着。
- 一行式那支用到的旧组件参数（`ComposerImageStrip` 的 `className`、`ComposerDropOverlay` 的 `line`、`LLMPill` / `EffortPill` 的 `popoverAlign` 等）留着，主对话靠它们；名字里带 trial、tmp 的改掉，注释改成正式说明。
- 代码与注释里不留「ticket 24」「票 24」「TEMPORARY」。
- 试验测试（`composer-trial.test.tsx`）里赢家的用例并进各组件自己的测试，删掉切换器、现状档、演示的用例。

## 二、离窗口底边 24px

- 主对话的输入框外层底边距从 16（`pb-4`）改成 24。只改主对话；工作台照旧 16 加提示行。
- 输入框上方与对话之间的距离不动；贴底滚动（票 20 的 `stickBottom`）照旧，量一下最后一条消息与输入框之间的距离前后一致。
- 实测输入框底边到窗口底边 24px，写进 Comments。

## 三、文档

- `docs/design/conversation.md`：
  - 「4.4 Composer」里加一节「主对话的输入框」（名字可以换）：一行式（＋、输入、模型 · 强度、发送 / 停止排成一条；起一行、随内容长高、8 行后在框里滚动；高 48、圆角 24；附件条在框内输入上方；模型与强度的弹层向上开、右对齐；小窗口下模型短语最多占四成、截断模型名）；离窗口底边 24 与理由（裁决 72）；没有提示行与理由，以及与 07-29 裁决 A（拖放提示永不退休）的关系（裁决 71 第 3 条）；停止中那句在队列条标题；占位「发消息…」；在忙时直接排队（裁决 71 第 4 条）；模型留在输入框、不进顶栏菜单的理由（裁决 71 第 2 条）。

## 不做

- 排队的消息挪进对话、显示成气泡（裁决 71 第 6 条，晚点再谈）。
- 工作台、子任务、空状态的输入框；外置运行时；手机端。

## 验收

- 跑这几项：`pnpm --dir gui typecheck`、`pnpm --dir gui lint`、`TZ=UTC pnpm --dir gui test`，再用 `TZ=America/Los_Angeles` 全量跑一遍；`git diff --check`；全角标点自查（扫新增行）。gui 只格式化自己改的 hunk，新文件可以整篇格式化。
- **测试**至少覆盖：主对话是一行式、普通会话与子任务是卡片；主对话没有提示行；占位「发消息…」，在问你时「回复上方提问」；停止中且有排队时那句在队列条标题；主对话在忙时 Enter 直接排队；离底边 24 的结构（类名或样式）；再也读不到 `galley.tmp.composerTrial.*`。
- **反向检查**：改坏几处，确认测试会挂；恢复后逐字节一致。例如：普通会话也变一行式、主对话又出提示行、底边距回到 16、又出现切换器。
- **逐像素**：
  - 工作台的会话、子任务、外置运行时、空状态的输入框，与开工时的 main 比，静止、在跑、在问你，浅色与深色，全部一致。
  - 主对话与开工时 main 的「一行式」档比（关掉演示）：差别只能是切换器 pill 没了、输入框整体上移 8px；逐处列出并解释。
- **自查截图**（Chrome harness，可以复用会话草稿目录里 `s24/` 的脚本，复制到新目录再改，不进仓库）：空闲、三行、很长、两张图、幽灵文字、在问你、在跑（真跑或模拟 Core 的在跑态）、停止中且有排队、模型弹层；浅色与深色、中英文、默认窗口、小窗口与宽屏；出总览图。截完把 harness 从工作树删掉。
- **JC 在 tauri dev 里走一遍**：
  1. 打开助手，看 pill 没了，输入框是一行式、离底边多了一点；
  2. 打几行字、拖一张图，看长高与附件条；
