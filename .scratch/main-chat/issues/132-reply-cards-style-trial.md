## 为什么

票 131 比的是卡片的宽与高。JC 倾向乙 + 32 之后，讨论转到「卡片本身能不能更轻」。结论是挂在气泡下的结构不换，换画法：照主对话里点「过程」展开的那张过程卡片（`gui/src/components/conversation/ProcessCard.tsx`），一条回复一个框，一件一行。对照档是现在的有框（乙 + 32）和无框行。

## 要做到

1. **pill 加一组「样式」**，放在最左，三档，默认**一框列表**：
   - **有框**：票 131 现在的样子，宽度、高度两组照旧生效。
   - **一框列表**（见第 2 条）。
   - **无框行**（见第 3 条）。
   - 样式不是有框时，宽度、高度两组置灰、点不动（选择照旧存着，切回有框时恢复）。状态、数据两组三档都生效。pill 要紧凑：JC 的窗口 1480 × 920，待办面板开着或关着，pill 都不能盖住输入框的发送键；放不下就让 pill 能收成一个小按钮，点开再展开。
2. **一框列表**：
   - **一个框**：同一条回复下的所有卡片（文件、子任务、待办、提醒、备忘，次序照旧）合进一个框。框照过程卡片：`rounded-md border border-line bg-app`，行区上下各 4px、左右 4px（`ProcessCard.tsx` 的 `pt-1`、`px-1`、`pb-1`）。宽度随最宽那一行（`fit-content`），上限是气泡上限。原来每张卡片自己的框、底色、圆角、`min-h-10`、卡片之间与组之间的 8px 间距都去掉，行一行接一行。框离气泡照旧 12px。
   - **一件一行**：行高 24px（`h-6`），行内左右 8px（`px-2`），`rounded-sm`。左边照旧 16px 图标列（子任务的状态图标、文件类型图标、待办的方框、提醒的闹钟、备忘的 `Notepad`），图标与名字之间 6px。字号 `[font-size:var(--conversation-step-size)]`（标准档 12px，随对话字号三档变）。名字 `ink-soft`，一行省略、悬停给全文（各卡片现有的截断写法照旧）。
   - **浅色对象**：原来卡片右边的东西（文件的文件夹、待办的日子与提醒、提醒的状态与时间）改成跟在名字后面 8px（`ml-2`），`ink-muted`，同过程卡片的对象（`ProcessCard.tsx:154`，最宽 40%，自己截断）。子任务的短词「等你回复」「出错」「没有跑完」「没有开始」也跟在名字后面 8px，颜色照旧（`warning` medium、`error`、`ink-muted`）。提醒卡片的时间原来在那句话前面，改成名字（那句话）后面的浅色对象；「取消」按钮放在行尾，压到 24px 行里放得下（比如 `h-5`），在报告里写尺寸。
   - **悬停**：能点的行（打开文件、打开子任务、打开面板里那一件）悬停与键盘聚焦时整行 `bg-hover`、名字转 `ink`，同过程卡片有细节的行。原来标题按钮的悬停下划线在这一档里不要（整行底色已经说了能点）；点击目标照旧是原来那一个（文件整行；子任务、待办、备忘、提醒是标题或那句话，点哪里能打开就照旧，报告里写清楚）。不能点的行（没派出去、已删除、过期的备忘等）没有悬停底。
   - **文件的「在文件夹中显示」**：浮在框的右边外侧、对着那一行垂直居中，同票 131 甲、乙两档的做法；框不为它变宽。
   - **划线、淡化、「已删除」「已移走或删除」等各卡片现有的状态写法**照旧，只是落在一行里。
   - **在卡片里答提问**（裁决 101，`SubtaskCards.tsx` 的 `answering`）：提问气泡与输入框在那一行下面原地展开（同过程卡片点开一步），那一块淡琥珀底；这时框撑到气泡上限。
   - **待办、提醒失败时那一行下面的原因**（12px `error`）：照旧在那一行下面，在框里。
   - **图片缩略图**（96px 那一排）：放在框里，自成一段，左缘对齐行的图标列，上下留 4px；选的做法写进报告。
3. **无框行**：
   - 没有框：每张卡片去掉自己的框、底色、圆角，一件一行，行高 28px（`min-h-7`），左右 8px，`rounded-sm`，每行只有自己的字那么宽（`w-fit max-w-full`）；行与行之间不留缝。第一行离气泡 8px。
   - 字号 13px（同现在的卡片），名字 `ink-soft`；悬停与键盘聚焦时这一行 `bg-hover`、名字转 `ink`；浅色对象与短词同第 2 条（跟在名字后 8px）。图标列同第 2 条。
   - 「在文件夹中显示」浮在那一行的右边外侧；在卡片里答提问时，那一张展开成一块淡琥珀底的区域、撑到气泡上限。
4. **只在 dev 版**：照票 131 的做法（不分层的 `<style>` 按 `data-role` 覆盖，加在 `reply-cards-trial.tsx` 里）；需要组件里加 dev-only 钩子的，越少越好，接入点只用 `import.meta.env.DEV`。文件开头注释补上「样式」一组每档是什么，以及拆除与写定的步骤（选中一框列表或无框行时，要写进哪些组件哪些类、`conversation.md` 哪几节要改）。
5. **量**（照票 131 的静态页 + 无头 Chrome 做法，脚本放 scratchpad、文件名带 `132`）：紧凑栏 760 与宽松栏 1200 下，三种样式各量：
   - 派活回复（两张子任务「创建科学知识文档」「制作76人赛季战况网页」）整组的宽与高；
   - 一张文件卡片「GPS 为什么必须考虑相对论.docx」在 `~/Downloads` 的宽与高；
   - 混排（一张「费城76人_2026-27赛季战况_截至2026-11-03.html」在 `~/Desktop` + 上面两张子任务）整组的宽与高；
   - 一张带「取消」的提醒卡片的行高；一张待办卡片（带日子）的行高；
   - 演示「在问你」「出错」下派活回复整组宽度的变化；
   - 悬停文件那一行时框（或那一行）的宽度不变，「在文件夹中显示」在框（或行）右缘外、垂直居中；
   - 一框列表的行高与过程卡片一行是否同为 24px、字号是否同过程卡片。
   演示用的字一律虚构或照上面写的这几个名字，路径里不要出现真实的用户目录名。
