## 二、这张脸怎么动（裁决 117）

### 头像拆开

- 头像现在是应用图标（`gui/src/assets/galley-icon.svg`，测试保证与母图 `core/icons/master/galley-icon.svg` 逐字节相同），两条合成路径（深色描边、橙色填充）铺在浅底上。要动的部分：两只眼睛、嘴，以及整个头（歪、点、跳、缩）。
- 做一个可动的版本（例如内联 SVG 组件），把眼睛与嘴从合成路径里拆成单独的形状；母图与应用图标不动。静止时与现在的头像**逐像素相同**：28、40、64、72 四个尺寸 × 浅色 / 深色，用渲染截图相减对比（票 23 的做法：描摹不重建，验收靠逐像素），回报里写最大差值。
- 头像的 1px 内描边、未读徽标、等你回复与出错的徽标照旧。**在跑时角上那个转圈的徽标，乙、丙两档去掉**（裁决 117 第 1 条：它就是「程序在加载」），由脸来表达；现状（切换器关）照旧转圈。

### 状态从哪来

每个动作必须对应界面已经知道的一件事（裁决 117 第 2 条），不演它没在做的事。先读现有的来源，回报里列「状态 → 数据来源（`file:line`）」：

- 在跑、在写回复：`gui/src/lib/assistant-conversation.ts`（`assistantTyping`、`assistantWriting`，票 58）。
- 正在调哪个工具：运行事件里的工具名（`gui/src/lib/agent-turn.ts`、`gui/src/lib/ipc-handlers.ts` 一带）。工具分类：浏览器类（`web_scan`、`web_execute_js` 及浏览器桥的工具）→ 看网页；`file_read` → 读文件；`file_write`、`file_patch`，以及 `code_run` 里跑的 `galley todo add / update`、`galley schedule create` 一类写命令 → 记；其余 `code_run` → 动手。以代码里实际的工具名为准，分不清的归「在想」。
- 派出子任务、等子任务、子任务交回来：主对话的子任务卡片与叫醒（`subtask` 相关的 store）。
- 等你回复（`PendingAskUser`）、出错、你按停止：现有的会话状态。
- 叫醒的一轮是提醒到点还是子任务交回：叫醒消息的种类（票 58 的 `assistantTyping` 已经区分叫醒的一轮）。
- 你发出消息、你在主对话输入框打字、拖进文件或图片：输入框（composer）的事件；只在主对话的输入框。
- 鼠标移到头像或卡片上：悬停。

### 乙：状态表（裁决 117 第 3 条）

| 类别 | 时机 | 神态 |
|---|---|---|
| 在干活（事情在就一直演） | 在想（还没动手，或两步之间） | 眼睛往上或往旁边看，偶尔歪一下头 |
| | 看网页 | 眼睛一行一行从左往右扫 |
| | 读文件 | 眼睛往下，往下扫 |
| | 写文件、记待办、设提醒 | 眼睛往下，头轻轻点，像在记 |
| | 跑代码、动手 | 眯眼专注，身子微微一颠一颠 |
| | 派出子任务 | 转头往旁边看一眼，再转回来 |
| | 等子任务回来 | 隔一会儿往旁边瞄一下 |
| | 写回复（对话里有三点时） | 嘴一开一合 |
| 对你有反应（演一次） | 你发出消息 | 眨一下眼、点个头 |
| | 你在输入框打字 | 眼睛看向下方，在听 |
| | 鼠标移到它身上 | 看你一眼 |
| | 拖进文件或图片 | 眼睛睁大一下 |
| | 你按停止 | 眨一下眼，立刻停 |
| 事情的结果（演一次） | 做完 | 轻轻一跳，眯眼笑 |
| | 等你回复 | 进入时歪一下头，然后正看着你不动 |
| | 出错 | 愣一下（眨两下、缩一下），然后静止 |
| | 提醒到点叫醒它 | 从闭眼睁开，跳一下 |
| | 子任务交回来 | 转头看回来 |

没事时完全静止。

- **变化**：每个持续的动作备两三种变体，时机带随机（例如眨眼、扫视的间隔与幅度），不做匀速循环。
- **优先级**：几件撞在一起只演最要紧的：等你回复 > 出错 > 写回复 > 做事 > 想；一次性的反应插进来演完再回到当前的持续状态。
- **两处同步**：侧栏卡片的头像与主区顶栏身份行的 28px 头像是同一个驱动，同时演同一个状态。

### 丙：乙，再加没事时的生命感（裁决 117 第 4 条）

- 空闲时随机眨眼，8–15 秒一次，只在窗口在前台时；偶尔左右看看。
- 很久没互动（30 分钟，常量）或深夜（本地 23:00–07:00，常量）慢慢闭眼打盹；你一碰就醒：鼠标移上去、在主对话输入框开始打字、切到主对话。

### 规矩

- `prefers-reduced-motion`：乙、丙都只给一张静止的脸（实时读系统设置，同 `lib/animate-scroll.ts` 的做法）。
- 窗口不在前台、或头像不在屏上时暂停；只用 transform 与透明度（SVG 内部形状的 transform / opacity），不逐帧跑 JS。
- 数值（时长、间隔、幅度）集中在一个文件里，带注释说每个动作表达什么（定档后进 `docs/design/foundations.md` §2.7 的豁免）。
- 外置运行时没有助理：逐像素不变。

## 三、卡片版式（裁决 118）

两档，都是内置运行时有主对话时的卡片块（在 C 的框架里，区名与铺底不变）：

- **大头像行 64**：IM 列表的一行。头像 64px，左缘在 18px 线上；名字、时间、第二行（最后一句或状态，规则同现在）在右边，文字列从头像右边 10–12px 起（你定，写数）。卡片高约 78px，写实际数。
- **居中舞台 72**（默认档）：头像 72px 居中；下面是名字（14px），名字右边跟小字时间；再下面一行是最后一句或状态，规则同现在的第二行（出错 > 在问你 > 正在输入 > 草稿 > 最后一句）；单行、居中、截断。整个助理区约 140px，写实际数。
  - **选中**：不铺满整块（避开裁决 64「一启动就是 282×112 的选中色」）。先做「头像外一圈品牌色描边 + 名字满墨」，你觉得不够再给一个替代画法放进同一个切换器（最多两种），写理由。
  - **悬停、按下**：照现在卡片的语法，但作用在你选的区域上，写清楚。
  - **未读**：照旧挂在头像右上角，尺寸按 72 重新算。
  - **窄侧栏**：头像缩到 48px（阈值你定，参照现有的 152 / 184，写理由），名字与最后一句照旧；最窄 134px 不换行、不出错。
- 两档整块都是一个点击目标，按下（pointerdown）就打开，同现在。
- 顶栏身份行的 28px 头像不放大，同一套动画照跑。
