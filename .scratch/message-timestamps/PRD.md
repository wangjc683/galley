# 用户消息时间显示

Status: done

2026-09-28 与 JC 讨论定案，形态 A + B：断点常显，平时悬停。同日真机第一轮后
砍掉 A，只留 B（见「真机第一轮」）。

## 现状（讨论起点）

- `messages.created_at` 一直在存（`core/migrations/001_init.sql:74`），UTC ISO。
- `Conversation.tsx` 已把 `createdAt` 传进 `MessageUser`，唯一用途是 Supervisor
  来源图标 tooltip 的相对时间（「Supervisor · 3 分钟前」）。普通消息不显示。
- 助手侧只有时长（折叠头「用时」），没有时刻。
- 本地发送的乐观 user turn 不带 `createdAt`（`stores/messages.ts` `appendUserTurn`）；
  `AgentTurn` 没有时间字段。

- 数据来自开发者 dogfood，社区用户的跨天使用可能多得多。

## 定案

1. **形态 A + B**：断点处常显（B），其余消息悬停时显示（A）。**A 已于真机第一轮
   砍掉**，现只有 B。
2. **断点**：同一会话里，距上一条用户消息**超过 60 分钟**，或跨了本地日期。
   跨日一条是兜底（数据里 0 处），保证标签的「今天 / 昨天」不会缺席。
3. **会话第一条用户消息一直显示时间**。
4. **ask_user 回复**：和普通提问一样参与序列；下一个问题只跟上一条用户消息
   （含回复）比。已知代价：回复藏在折叠的 run 里时，折叠态下看不到那段等待；
   这种组合罕见，悬停可兜底。
5. **Supervisor 来源消息一直显示时间**：来源图标那一行本来就在，时间顺带常显；
   图标 tooltip 去掉相对时间，`formatRelativeTime` 退役。
6. **Goal 委派标记**参与断点计算，断点时同样显示标签；v1 不加悬停时间。
7. **只给用户消息显示时间，助手回答不加**。理由：同一规则套到回答上，
   409 轮里 0 处会触发；回答操作栏是常显的，放进去就等于「每条都显示」；
   空档都出在用户离开又回来。上一轮「提问时刻 + 用时推出完成时刻」的理由有误
   （用时不含 ask_user 等待，提问时刻平时也不显示），已撤回。
   长时间无人看管的运行（过夜 Goal、定时任务）的完成时刻进 deferred。
8. **问题轨悬停卡片 v1 不加时间**。

## 格式

精确到分钟。中文 24 小时制补零（`09:10`）；英文按英文习惯 12 小时制。

| 情况 | 标签 |
|---|---|
| 今天，上一条用户消息也是今天（或没有上一条） | `16:05` |
| 今天，上一条用户消息在之前某天 | `今天 09:10` |
| 昨天 | `昨天 21:14` |
| 今年更早 | `9月21日 14:32` |
| 往年 | `2025年9月21日 14:32` |

常显标签悬停给完整时间（含星期）。悬停时间（A）用同一格式，不再套 tooltip。
「今天 / 昨天」过零点刷新，复用 `useDayStamp`。

## 界面

- **B**：气泡上方独占一行，左对齐，占真实布局高度，复用 Supervisor 图标行
  （`mb-1`）。Supervisor 消息是同一行：图标 + 时间。字：11.5px sans、
  `tabular-nums`、`text-ink-muted`（同 `AnswerTelemetry`）。`select-none`，
  `<time dateTime>`。
- **A**（真机第一轮已砍，下面保留为记录）：跟在复制按钮后，同一淡入、同一 600ms 延迟收起。断点消息悬停不重复显示
  时间。已知风险：窄窗口 + 气泡撑满整列时右侧留白只有 32px，会压到问题轨。

## 真机第一轮（2026-09-28）

- 第一条消息显示时间：OK。
- **常显时间样式「稍微有点吵」**，要更安静、视觉层级更低。推断的来源：
  字号用了 11.5px（照搬 AnswerTelemetry），而规范给时间戳的是 `text-ui-micro`
  10.5px（`docs/design/foundations.md:328`）；位置在每段对话的入口；汉字笔画密；
  离气泡 4px 像标题；深色下 `ink-muted` 对比度 5.23:1，比浅色的 3.63:1 高。
- **悬停时间（A）砍掉**。JC：「有点吵，也没有必要」。
- **阈值定 60 分钟**，去掉 1 分钟调试档。
