# Galley 气质总纲

> 这份文档定义 Galley 的气质（temperament）——三份执行规范之上的「为什么」。
> 执行细则不在这里：
>
> - 怎么说：[copy-austerity-principles](./copy-austerity-principles.md)
> - 说什么词：[copy-language-guidelines](./copy-language-guidelines.md)
> - 怎么排：[typography-principles](./typography-principles.md)
>
> 本文档回答的是这三份规范共同服务于什么。改气质先改这里，再改规范，
> 最后改实现——顺序不可反。

## 定位：Galley 是文库，不是作者

Agent 应用有一个结构性事实：用户读到的绝大多数文字是模型写的，Galley
控制不了。如果气质定位在「作者」，这条路走不通。

出版社不控制作者的文风，但岩波文库、企鹅经典的气质成立——因为气质住在
版式、开本、编辑标准、选目的拒绝里。galley 在印刷史上是**校样盘**（galley
proof，排好字等待付印的那一版）。这个词就是定位：

**Galley 是一个把每场对话都当作值得好好排印的文本来对待的应用。**

壳是文库，内容是作者。气质住在壳里——这在出版史上被验证了一百年。

由此对齐参照系：Galley 的同类不是 IDE、不是 IM、不是 dashboard
（DESIGN.md §1 已拒绝），也不只是「另一个 chat 壳」；它向文库本的
编辑与排印标准看齐。

## 元规则：哲学以清晰的面目出现，绝不以深刻的面目出现

Galley 的气质受维特根斯坦影响，但哲学在这里的形态是**清晰、诚实、克制**，
不是引文、术语或深奥感：

- 气质被用户指认出来的那一刻就打了折扣。最高形态是用户从头到尾没有
  意识到任何哲学，只觉得这个软件安静、准确、诚实。
- 「凡是能说的，都能说清楚。」哲学承重（解释设计为什么如此），不贴金
  （摆语录装点门面）。引文只住在两类地方：题词位（empty-state
  epigraph，状态绑定、每次驻留冻结——章节题词式的反复是正当形式）与
  版权页（About colophon），永不进入功能文案。
- 清楚 > 简洁 > 气质（继承 copy-austerity 红线）。气质永远不能以用户
  多想一秒为代价——「深沉」与「新手易上手」冲突时，气质让步。

## 四个承重面

气质不是一个功能，是四个面上无例外的一致性。哪个面破了例，气质就从
那里漏掉：

| 承重面 | 内容 | 规范归属 |
|---|---|---|
| **语言** | 冷、准、省的声音；术语即契约 | copy-austerity / copy-language |
| **排印** | 对话按书籍标准排出来；排印只作用于渲染、绝不改写内容 | typography-principles |
| **节奏** | 静止的界面 + 有分量的触觉反馈；等待被诚实对待（不假装快、不催促用户） | DESIGN.md §2.5 / §2.7 |
| **拒绝** | 立场由不做的事定义 | 下方清单 |

## 拒绝清单（气质级）

气质由拒绝定义的程度大于由功能定义。以下是从全部决策史中收编的、
定义 Galley 人格的「绝不做」——按态度分组，不按实现层。完整台账（含
出处）见 [2026-07-03 devlog](./devlog/2026-07-03-temperament-charter-and-cjk-typography.md)。

### 对用户注意力的态度：不打扰、不催促、不索取

- 不 toast、不开新窗口、不弹层抢焦点——一个对话的所有进展在同一视图里刷新。
- 不用感叹号，不用最高级与 marketing 词，不寒暄、不说教、不道歉腔。
- 禁止无限闪烁 / shimmer / 大面积呼吸动效；警示靠颜色对比，不靠动。
- 不设保存按钮——设置即时生效自动持久化，用户不为软件的实现分心。
- 空状态不堆 quick prompt、快捷键提示、欢迎长文——把「今天交代什么」
  的聚焦还给用户。

### 对内容与事实的态度：不改写、不越界、不带走

- 排印只作用于渲染，模型原文一个字符不动；代码逐字呈现。
- 不修改用户的 GenericAgent——删除 Galley 后 GA 仍独立运行。
- localhost only，不开 TCP、不持有远程凭证；no telemetry；不存
  supervisor 与人的对话。数据是用户的，本机是边界。
- 错误陈述事实加下一步，不渲染情绪也不假装有把握。

### 对自己的态度：不表演、不故作深沉

- 不文艺、不精致、不端着——气质从删字来，不从加漂亮的词来。
- 绝不在按钮上贴哲学；功能不用行话命名（否决过 "Language Game"）；
  placeholder 不塞语录。
- 用户消息不用 IM 气泡——这是文档区，对话是被排印的文本。
- 产品名 sentence case，不做全大写 wordmark；dark theme 是同一产品的
  夜间版，不是另一个方向。
- 拒绝「哲学模式」沙龙引擎这类表演性功能——那是「语言在度假」。

**新增拒绝的准入标准**：一条拒绝要进入本清单，必须（1）定义人格而非
实现细节，（2）预期永久有效而非 deferred，（3）在 devlog 有决策出处。

## 这份文档怎么用

- 新功能 / 新文案 / 新视觉拿不准时，先问四个承重面里它落在哪个面，
  查对应规范；规范没写的，回到定位（文库不是作者）与元规则（清晰不
  深刻）推。
- 与拒绝清单冲突的提案，默认否决；确要翻案，先改本文档并在 devlog
  记录为什么，再动实现（约束先行）。
