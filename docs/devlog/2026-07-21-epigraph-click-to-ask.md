# 题词可点击：装饰成为第一条消息的入口

日期：2026-07-21
状态：已实现，随本条目 commit
相关：`gui/src/components/screens/Epigraph.tsx` · `gui/src/lib/epigraphs.ts` ·
`docs/design/conversation.md` §Empty State 题词段 ·
devlog 2026-06-03（philosophical-voice，题词的来历）

## Context

空状态题词（状态绑定的维特根斯坦句，译文 + 德文原文）对多数用户偏晦涩。
JC 提出：能否点击题词，让 AI 解释这句话？讨论起点是"新建一个对话来解释"，
收敛过程中发现两件事：

1. 用户点击时**已经站在一个空对话里**——不需要新建，点击让当前对话的
   第一条消息成为这个提问即可，更轻。
2. 空状态的本职就是引出第一条消息。可点击的题词是零打字的首条提问，
   不加任何新控件——装饰自身成为入口。且"用产品解释产品"是 AI 工作台
   唯一不自我否定的注释方式。

对 PI §43（meaning is use）有一层额外的对齐：点击这句话、把它投入使用、
让它产生意义——交互本身就是命题的演示。

## Decisions

- **交互深度 = 预填短问句而非点击即发送**（JC 于结构化三选一中拍板）：
  点击把解读请求预填进 Composer，用户按 Enter 才发出。零副作用、保留
  用户主权、顺带教会提问；未配模型走 requiresModelConfig 优雅降级。
- **预填模板 = 通用增强版**（二轮，JC 拍板）：完整出处署名 + 译文 +
  德文原文 + 通用三问「在说什么 / 针对什么问题或立场提出 / 与今天的
  AI · 大语言模型有什么关联或启发」。三味信息各司其职：署名解决弱模型
  识别（每句新增 `citeZh`/`citeEn` 完整引用，"PI §43" 弱模型展不开）、
  原文解决译本歧义、三问给答案结构。第三问 JC 指定用 AI/LLM 关联替换
  初稿的"为何适合作题词"——不依赖产品自指，弱模型也答得动，且这正是
  这几句话入选题词的真实理由。
- **铭文静默感不破**：静止态与纯铭文逐像素一致（无下划线、无边框、无
  提示文案），hover/focus 才有极轻墨色上浮 + pointer。可发现性靠自选择
  ——会被句子困住的用户恰是盯着它看的用户；掠过者不需要解释。
- **守卫**：composer 已有用户草稿时点击不覆盖（草稿 write-through，读
  到即实时值；仅聚焦）；重复点击自身预填幂等。`onAskAbout` 不传时组件
  与旧版渲染完全一致（About 页引用不受影响）。

## Rejected alternatives

1. **点击即发送**——误点烧掉一个会话 + 一次模型调用，不可反悔。
2. **隐藏上下文注入**（明面短句、暗里附加出处）——违背"用户所见即所发"
   的诚实原则（bridge 是 truth），腹语术不做。
3. **逐句定制阐述维度**（PI §43 问指称论、Tractatus 7 问可说边界）——
   策展负担 ×3 句 ×2 语言；预填越像 prompt 工程模板越不像用户自己的话，
   教学价值反降。通用三问对这三句话恰好都成立。
4. **一行短问句**「这句话是什么意思？」——一轮方案，实现后被 JC 以弱
   模型识别不稳为由升级为通用增强模板。
5. **hover 显示人工策展释义**——在 AI 工作台手写静态注释是自我否定。
6. **保持纯装饰**——晦涩对掠过者是氛围，对驻足者是痒处；而驻足者恰好
   会 hover 到。
