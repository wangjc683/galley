## 四个候选与推导

**一、打开旧会话时侧栏里找不到选中行。** 「更早」只折成一行入口
（`SidebarTimeline.tsx` 的 `SidebarEarlierEntry`），打开会话不刷新最后活动时间
（`activateSession` 不碰 `lastActivityAt`），所以从搜索 / ⌘K / 「更早」对话框打开 30 天前的
会话，侧栏没有任何一行亮起，⋯ 菜单也够不着它；61% 的会话在这里。轻一档的同类问题：「本月」
33 行，从外部选中一条屏幕外的会话，侧栏不滚过去（侧栏目录里原先没有任何 `scrollIntoView`）。
三个修法：A 把当前会话借一行挂在「更早」入口下面 + 外部选中时滚入视野（采纳）；B 只给入口
染选中色（看不出是哪条、也没法就地操作）；C 不做、靠主区标题。

**二、每行都写「已完成 · 」。** 默认宽度下副行约 235px，前缀约 43px（≈18%），而在静止的
大多数行上不带信息。查 05-12 旧裁决：当时比的是「第 N 步 · 摘要」「已完成徽章」「已完成 ·
摘要」三种，**没测过不加前缀**；选前缀的初衷是去掉「第 N 步」暗示的「还有下一步」，只留摘要
同样做到。去掉后「已中止 · 」「已暂停 · 」成为只出现在例外行上的标记（「· 1 是噪音」同一思路）；
运行结束仍有转圈图标、杏沙副行、字重三路变化，未读还会弹一下。因为是翻 JC 自己定过的事，
做临时切换器真机比。

**三、「已归档」行不在左缘网格上。** 会话行 `mx-1.5 + px-3` + 16px 图标列 + `gap-2`：图标
中心 26px、标题起点 42px；新对话行 25.5px / 43px；归档行（`px-3.5`）20px / 34px，唯一出格的
一行。

**四、会话标题的原生提示框。** 标题与副行无条件带原生 `title`，悬停约 1 秒就弹系统样式提示框，
内容与看得见的文字一模一样；57% 的标题从不截断。

看过但不动：中文桶标题 10px 加字距（纯气质，无硬理由）；新对话文字比标题偏 1px（不可见）；
项目视图（本机 0 项目，无素材）。顺带：库里 4 个标题是模型推理泄漏（「The user wants me to
generate a short session title…」），09-18 `c61b40c4` 已修、之后未再出现，是修之前的残留，
与侧栏无关。

## 落地

执行：一张 Opus 票（代码），文档与验收由主会话做。

- **借位行**：`SidebarTimelineBuckets` 在「更早」入口下方渲染当前会话（只看 `buckets.earlier`，
  backfill 提进「最近」的行本来就在列表里）；入口计数不变，切走即消失、无动效；按会话 id 作 key，
  在两个旧会话间跳转时整行重挂，行内状态不串。行接线抽成共享的 `SidebarTimelineRow`，与桶内
  行同一套 props。
- **滚入视野**：会话行根节点带 `data-session-id` 与 `scroll-my-2`（8px 余量）。`Sidebar` 的
  reveal effect 依赖 `[activeId, activeBucket]`（`findSessionBucket` 读已分好的桶，与 backfill
  一致）：选中从侧栏以外来（搜索 / ⌘K / 「更早」对话框 / 新对话首发 / 挂载），或当前会话换了桶
  （旧会话发一句话从借位行跳到「今天」）时，行不完全可见才 `scrollIntoView({ block: "nearest" })`，
  瞬时不平滑——注意力在主区，外围动效保持安静。**侧栏点击不滚**：行在 pointerdown 激活，滚动
  半露的行会让它在指针下滑走；点击经包装函数打标记，effect 见标记即跳过，且每次选中变化都清掉
  标记（点已选中行留下的陈旧标记不能误伤之后从外部选同一会话）。换桶不看来源。
- **折叠项目抽屉**：执行代理查出票面前提不成立——折叠的 `SidebarProjectDrawer` 行仍挂载、
  高度为零、外套 `overflow-hidden`，对它 `scrollIntoView` 会滚动抽屉自己的裁切盒，展开后错位。
  抽屉折叠时带 `data-collapsed-drawer`，reveal 遇到即返回。采纳。
- **归档行**：`pl-4.5`（18px）+ 12px 图标居中于 `w-4` 盒 + `gap-2` → 图标中心 26px、文字
  起点 42px，与会话行同线；按钮仍满宽（底边线与悬停底色），字号颜色不变。
- **提示框**：标题与副行去掉无条件 `title`，改 `onPointerEnter` 调 `lib/truncated-title.ts`
  的 `syncTruncatedTitle`：悬停时量 `scrollWidth > clientWidth`，截断才挂。悬停时量是有意的——
  悬停时行右侧给 ⋯ 让出 28px（`group-hover:pr-7`），静止时放得下的标题悬停时可能被截。
- 已知边角：视图切换退场约 200ms 内两套视图同在 DOM，恰在这一窗口换选中会话时
  `querySelector` 取到靠前那份（项目视图）；不处理。会触发 reveal 但可能出乎意料的两种：新对话
  首发（`activeId` 从空变成新 id）、右键置顶当前会话（换桶）——都符合规则。

纯前端，Core / runner 零改动；外置与内置两种运行时模式表现一致。

## 真机裁决：对勾圈 + 只留摘要

JC 真机看过前缀切换器后的反馈：全面显示「已完成」确实吵、不优雅，但仍想给用户一个已完成标识。
于是问题从「要不要前缀」变成「已完成该放在哪条通道」。

**推导。** 本地跑完的会话结算为 `idle`，左图标是灰色空心环——在待办类通用语法里（提醒事项、
Things、Linear）空心圆恰是「没完成」，「已完成 · 」三个字某种程度上是在替它纠正说法。这个状态
本来就该有对勾：最初的规范写着转圈跑完翻成对勾，07-05 审计发现本地从没翻过（只有 CLI 写的
`completed` 是对勾），当时只把现状记进规范，**没有否决过对勾**。三个方向：

- **A 图标承担「已完成」、副行只留摘要**（采纳）：看过的完成行 muted 细线对勾圈，未读同一个
  对勾圈填实成杏色（「填实 = 未读」语法不变）；状态回到左图标这一路，副行只说做了什么；CLI 跑完
  的行原先常驻杏色对勾、比本地完成行还吵，统一成看过即灰。
- B 「已完成」只在它是新闻时出现（前缀只给未读行）：「已完成」是事件不是状态，但看过的行仍无
  标识，不满足 JC 的诉求；未读行已有三路信号，再加文字是第四路。
- C 副行用小对勾代替三个字：仍每行重复，且在文字里塞图形字符，与左图标说同一件事。

子决定：没跑完的静止行（步数上限暂停、Goal 暂停或受阻、没有摘要）保留空心环，否则会出现
「对勾 + 已暂停」的矛盾；空心环从此只表示「停着，但不算完成」。

**切换器**：两个开关（图标：对勾圈 / 空心环；副行：只留摘要 / 已完成 · 摘要），默认推荐组合。

**裁决**：JC 真机「对勾圈 + 只留摘要」最舒服，问我的看法。我同意，附两个没看真机的翻车点：
① 深色模式下杏色 `#d6a083` 与琥珀 `#d6a250` 亮度几乎相同，未读实心对勾圈与 ask_user 实心暂停圈
都是 14px 实心圆，只剩内部字形与色相之别（浅色 `#d9a78a` / `#bf7a1f` 差别明显；以前未读点缩到
约 10px，靠大小就分开）；廉价修法是未读对勾缩一号。② Windows 1 倍屏上 thin 对勾圈（14px 下线宽
约 0.44px）可能发虚，低 DPR 加粗规则（foundations §2.3）应能兜住，发版前 Windows 冒烟顺带看。
JC 看过深色模式，没问题，定案。借位行、滚动、归档行、提示框四项 JC 真机未提意见。

**定案落地**：`StatusIcon` 新增 `incomplete`；`idle` 且非 `incomplete` 画成 `completed`，
`completed` 改 muted（未读仍 `fill` + `text-brand`）；光学配重只剩没跑完的空心环。会话行传
`incomplete={pausedAtStepLimit || goalParked || !cleanSummary}`。⌘K 命令面板与「更早」对话框
用同一组件、不传 `incomplete`，静止会话一律对勾。`settledSessionSubline` 完成态只返回摘要，
中英两个 locale 删掉 `completedSummary`；单测跟改，`status-icon.test.tsx` 锁住「静止跑完 =
completed 对勾、没跑完 = 空心环、看过 muted / 未读杏色」。切换器与全部 TEMPORARY 段已拆。
