# 主对话的桌面侧栏：从 A1 / A2 到 B′

日期：2026-10-12
关联：[主聊天 PRD](../../.scratch/main-chat/PRD.md)（裁决 24、28–36）、票 [02](../../.scratch/main-chat/issues/02-main-chat-form.md)、

## 起因

票 02 把主聊天做成内置运行时里一条一直在的会话，桌面启动就打开它；侧栏怎么摆先做 A1 / A2 两档切换器真机比。
同一天 JC 在 tauri dev 里比了三轮，最后定 B′。

## 三轮切换器

**第一轮：A1 / A2。** A1 把主聊天行放在新对话行上面，其余不动；A2 让主聊天行接任「逃生出口」（`docs/design/layout-and-chrome.md:172` 的三条标准），
新对话降为书眉第四个图标。我按「顶上放动作、列表放对象」推荐 A2。JC：A1 主次没拉开，文案也要重想；A2 干净，但用户想手动开一个对话时找不到入口。
两条都成立——A2 只剩图标，正是 10-03 定「新对话独占一行」时要避免的「找不到就像被困住」。

**第二轮：加 A3 与文案三组。** A3 = A1 的顺序、层级反转：主聊天行满墨色当首页，新对话行降为安静的一行（28px、12.5px 常规淡色、去品牌色加号），
仍是带字的整行，找得到。文案查到规范「用户可见的 session / chat 概念统一叫『对话』」（`docs/copy-language-guidelines.md:324`），
所以界面上的「主聊天」「旁聊」本身撞规范，列了甲「主对话 / 新对话」、乙「主聊天 / 新旁聊」、丙「助理 / 新对话」。
JC 样式倾向 A3，名字都不满意，并提出更大的问题：Galley 改成主对话为主、旁聊为辅，侧栏要整体调整，不是一个按钮一个文案。

**侧栏职责重排。** 侧栏要做的事按频率是：回到主对话 > 看哪里需要我 > 新开旁聊 > 找回旧旁聊；今天的侧栏服务的是后两件。
查旧规则的前提：「Sidebar 不可折叠」的理由是「多 session 是 Galley 的核心产品形态」（`layout-and-chrome.md:22`），主对话为主后不再成立；
「去掉 ACTIVE / WAITING 区块」当初靠「Approval Dock 兜底」（05-07 devlog），10-05 审批已移除——但状态区块仍不做，理由换成：在跑的对话本来就在时间线顶部，子任务状态汇到主对话行。
骨架定为主对话行 → 分区头（加号在头上）→ 置顶 / 项目 / 时间桶。分区头顺带解决叫法的认知门槛：词就是下面那串对话的名字。
说明文字用确定规则「只在空的时候出现」（先例：侧栏空列表「你的对话会出现在这里。」）。
JC 同时定：agent 开的对话（10 月本机 36 个会话里 30 个）移出这一区——在项目里的留在项目组，其余收成「其他来源 N」，按 10-08 项目组规则挂出等你回复 / 出错的行，与事项账本「只读人说的话」同一原则。

**第三轮：A3 / B / B′ + 叫法 + 演示状态。** B 是上面的骨架，B′ 再加侧栏可收起（⌘\，收起时展开按钮上显示在等你的对话数，不用状态点）。
JC 本机数据大多空闲，加了渲染层的演示状态（在跑、在问你、出错、新回复、其他来源里挂出一条）。JC 定 **B′ + 「其他对话」**，并删掉主对话行空态副行「什么都可以跟它说」（不太合适）。

## 定下的规则

- 有主对话（内置）：主对话行固定在顶、启动即选中；「其他对话」分区头带加号，进入空白新对话时分区顶上有一条选中的占位行；其他来源组；侧栏可收起，状态存 Core prefs。
- 没有主对话（外置）：侧栏保持原样，不可收起。
- 叫法：主对话 / 其他对话 / 新对话；「主聊天」「旁聊」只作 PRD 与代码里的内部术语。

## 被否

- A1（主次不分）、A2（新建入口只剩图标，找不到）、A3（层级对了但仍是旧结构）、不可收起的 B。
- 文案乙「主聊天 / 新旁聊」（撞「对话」规范，「旁聊」有认知门槛）、丙「助理 / 新对话」（助理不是对话这类名词）、按钮下常驻小字说明（改为空时才出现）。
- 叫法候选「旁聊」「话题」。
- 主对话空态副行「什么都可以跟它说」。
