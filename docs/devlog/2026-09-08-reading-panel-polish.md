# 阅读面板打磨：Markdown 预览与 Git 改动视图的 UX 复审

日期：2026-09-08

## 背景

JC 让我在发版前复审他用另一个 agent 做的两个功能（[本地文件预览]
(./2026-09-08-local-file-preview.md)、[Git 工作区审阅]
(./2026-09-08-git-worktree-review.md)），重点看 UX / UI。工程边界画得干净
（只读、按需、不落库、Core 拥有子进程），问题集中在**面板内 chrome 的层数**
和**几处控件语法没跟 Galley 既有规范对齐**。JC 裁决：列出的全部按建议做。

## 改了什么

Git 改动视图：

- **文件选择器**从浏览器原生 `<select>` 换成 `GitFileList`：eyebrow 组头带
  计数，一行一个文件，状态 chip + 等宽路径，当前行 `bg-selected`，方向键
  切换，`role="listbox"`。设计规范在模型设置里写的"不用原生 select"是全局
  原则。定时任务对话框里还有两处原生 select，本轮没动，记在这里。
- **三层 header 合并成一层**：仓库名做标题、基线做副标题、切换仓库 / 刷新 /
  关闭在右侧，用新建的共享外壳 `ReadingPanelHeader`。原来的「工作区改动」
  标题行信息量最低，去掉。
- **单/双列**改 `SegmentedControl`。原来一个按钮文字显示"要切到的状态"、
  `aria-pressed` 又反映当前状态，两者矛盾。
- **状态统一**走新建的 `PanelNotice`：加载灰字、信息行、错误行（沿用设置页
  ErrorLine 的形态）、居中带图标的空态。"没有未提交改动"是正常终态，用空态
  而不是左上角一行灰字。
- **diff 本体**：hunk 头改成「第 N 行起」（原始 `@@` 头留在 title），顶部
  粘住「第 i / n 处改动」计数 + 上下箭头；未跟踪文件用 `PlainFileLines`
  带行号显示，和 diff 表格同一寄存器。
- **顶部「改动」按钮**开态从 `bg-hover` 改 `bg-selected`：开着是选中态，
  和指针反馈要是两种物质（侧栏选中行 08-21 的同一课）。

Markdown 预览：

- 每个文档顶部那行「显示打开或刷新时的文件内容」常驻文案，挪进刷新按钮的
  tooltip。
- 图片下方「在文件夹中显示」改 hover / 聚焦时出现。
- 分栏阈值 1080 → **880**，两侧最小 480/420 → **440/400**。侧栏默认 20%，
  1280 宽窗口主区 1024，原阈值下永远是 dialog，边看边写不成立。
- 消息行内的文件夹按钮 24 → 20px，图标 13px 压到基线，不撑正文行距。
- 分栏模式 Escape 放宽到"焦点不在文本框"即可关闭，原先只在焦点落在面板内
  时生效。

横向：`ReadingPanelHeader` 和 `PanelNotice` 是两个面板共用的外壳和状态词汇，
以后新的阅读面板视图从这两个开始。

## 顶部「改动」图标（同日续裁）

JC 真机觉得自绘的"文件轮廓＋增删符号"不理想。诊断：16px thin 下内部的减号
和加号读成"写了两行字的纸"，落进「新建文件 / 笔记」的形状家族；自绘笔画和
Phosphor 邻居不是一只手；结构最密所以视觉最重。开了六变体切换器（自绘 /
`PlusMinus` / `FileMagnifyingGlass` / `Columns` / `SquareSplitHorizontal` /
`GitDiff`）真机实测，JC 选 **`GitDiff`**。我原按语义推 ±（改动 = 加减），实
测后改判同意：面板范围就是 Git，Git 味的图标更诚实；两点一线的重量和 `Sun` /
`Gear` 同级，± 只有两笔像掉进去的字符；双栏形状撞宽度按钮。之前 devlog 记的
"箭头不够直接"是它在带文字按钮里的表现，纯图标加 tooltip 后不成立。自绘例外
收回。切换器已拆，无残留。

## 没动的

- 定时任务对话框的两处原生 select（同一笔债，另开）。
- Git 审阅"窗口级"与 Markdown"会话级"两种生命周期并存（已裁决，只是提醒
  未来可能被报成 bug）。
- diff 不做语法高亮（首版范围）。
