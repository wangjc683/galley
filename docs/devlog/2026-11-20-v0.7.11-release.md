# v0.7.11 发布

**日期**：2026-11-20
**上下文**：v0.7.10 后一天，起头时 26 个提交。main 上动到应用的只有一件事：浏览器控制要用浏览器、却找不到可用网页时，Galley 自己把浏览器打开（GitHub issue #33 第二轮，[devlog](./2026-11-20-browser-auto-open.md)，票 01、02）。JC 问发版前要不要先升 GA 基线，主会话给了三个选项（不升照常发 / 先升再发 / 发完单独升），JC：「A」（不升，照常发）。

## 裁决

- **patch（v0.7.11）。** 主会话按 [project status](../project-status.md)「Release Version Rules」定的，JC 没有单独裁版本号，草稿握手点一并报。依据：`cli/` 与 `docs/agent-api/` 的 diff 为空，`schemaVersion` 仍是 3；没有新迁移；GA 基线没升；新功能是浏览器控制里一个自动的步骤，默认开、没有开关，够不上「功能量级够一条独立产品线」。
- **GA baseline 仍是 `d66509b`，上游的不跟。JC 裁（「A」）。** 上游 `main` 是 `7395dfd`（`git ls-remote` 查于 2026-11-20），比基线多 22 个提交。前 19 个是 v0.7.10 判过的那一批（[v0.7.10 devlog](./2026-11-19-v0.7.10-release.md)）；新增 3 个，提交时间都是 11-20：`e0ca8ae` 删掉第三方图标的许可说明文件；`8f6de5c` 让 `ui_detect` 不再按模板给图标起名（删 `memory/ui_icon_label.py` 与 `memory/icon_templates.npz`）；`7395dfd` 收紧记忆整理规则（`memory/memory_management_sop.md` 加「归纳与总结」一条、L2 小于 30 KB、L3 的长度上限，`ga.py` 的提纯提示词加一行「只允许记忆未来会复用的信息」，`memory/goal_hive_sop.md` 加一行指向 `hub.py`，删 shadow 模型的测试）。主会话在 scratchpad 里新克隆了一份上游，读了这 3 个提交的全部 diff（8 个文件），以及整段 `d66509b..7395dfd` 在 `ga.py`、`llmcore.py`、`agentmain.py` 上的 diff。不跟的理由：
  - **整段里动到内核的只有三个文件。** `ga.py` 两处（没调工具时的重试条件放宽、提纯提示词加一行）；`llmcore.py` 的 `show_thinking` 是可选键，Galley 不设；`agentmain.py` 只动 reflect 模式，Galley 不用。其余是 Galley 不加载的前端（conductor、hub、hub_p2p、p2p_ws_client）、可选的 shadow 插件，以及 `memory/` 下的种子文件。
  - **没调工具时的重试仍是升基线的前置项。** 上游 `5d17ade` 把条件放宽成「有 `DSML`，或以 `>` 结尾」（对应载荷 `managed-ga/code/ga.py:530`）。助理手册让主对话在唤醒时只回 `<no-reply/>`（`docs/managed-ga-runtime/galley-assistant-manual/wake.md:21`），正好命中；内核会注入「改用自然语言说明，不要以标签结尾」，最多重试 3 次（`ga.py:513-516`），本该静默的唤醒多半变成一条看得见的解释。仍是读代码得出的，没有实跑。下次升基线先做一个豁免补丁，再跑唤醒与派活的评测。
  - **种子文件的改动到不了老用户。** 升级只补缺失的种子、不覆盖已有的（[code-state-and-patches](../managed-ga-runtime/code-state-and-patches.md) 第 106 行），老用户能拿到的只有提纯提示词那一行。
  - **这一版本身就是内置内核的改动**（补丁 `0035`），Windows 那几步还欠着；再叠一次升基线（补丁栈重放、新补丁、评测），冒烟出了问题分不清是哪一份。
  - [GA baseline](../ga-baseline.md)「Upgrade Triggers」里真正的触发条件（用户报问题、上游的关键修复、上游改写历史）都没碰上。
- **打包门禁跑。** `managed-ga/`（补丁 `0035`、`TMWebDriver.py`、`ga.py`、清单）与 `runner/` 有改动。
- **Dry run 不跑。** 工作流、打包、签名配置都没动，tag 构建出的草稿本身不公开，起到同样的作用。
- **没有迁移。** 退回 v0.7.10 不用恢复备份，notes 不写退回说明。新偏好 `browser_control_last_browser_app` 旧版不读。
- **更新渠道**：stable，publish + 冒烟后推 stable。

## 范围（git log v0.7.10..HEAD：起头的 26 提交，加本文与 bump）

写进 What's New 的只有一条：**浏览器找不到可用网页时自动打开**。票 01（`0565566f`、`414b7bcf`、`6a7d819a`）：扩展没连上时打开它上次连接的那个浏览器，带测试页地址，一次断开只打开一次；票 02（`efcfc4ac`）：扩展连上了、但没有可用网页时也打开。notes 里的三个数对着代码核过：工具最多等 20 秒（`0035` 里的 `deadline = time.time() + 20`）；30 秒内没等到就不再打开，扩展新连上、出现网页或浏览器桥重启后恢复（`runner/managed_browser_bridge.py` 的 `BROWSER_WANTED_REPEAT_SEC`）；没认出过浏览器就什么也不打开（`core/src/browser_bridge.rs` 的测试 `browser_wanted_without_a_known_browser_opens_nothing`），所以 notes 写明「更新后扩展连上过一次才生效」。

不写：

- `core/src/app_update.rs` 的模块注释改正（`1918d99d`：加速地址能把一个更早的已签名包当新版推，注释原先说满了），行为没变；对应的口子 JC 已裁暂缓（[deferred](./deferred.md)）。
- v0.7.10 的发版文档、issue #33 第二轮的裁决与 deferred 条目、两张票的票面、本批的 devlog 与 Windows 清单。
- Under the Hood 不设：剩下的只有「12 秒的等待只留给刚成为主进程的会话」，它是同一个机制的一部分，单列一条读者看不出区别。
