# 新对话的「你在这里」：从占位行到按下的加号

日期：2026-10-14
关联：[主聊天 PRD](../../.scratch/main-chat/PRD.md)（裁决 55、56）、票 [13](../../.scratch/main-chat/issues/13-new-chat-placeholder-trial.md)、
[layout-and-chrome.md](../design/layout-and-chrome.md)「有主对话时由按下的加号承接『你在这里』」、
上一轮侧栏 [主对话的桌面侧栏：从 A1 / A2 到 B′](./2026-10-12-main-chat-sidebar-trial.md)

## 起因

JC：「其他对话的新对话，占位太大，位置也不合理。」指的是有主对话时，按 `+` 或 ⌘N 后「其他对话」分区最顶上冒出来的那条选中的「新对话」占位行（票 08）。

## 查到的问题

- **大**：连上边距 40px，全宽杏色加抬起阴影，是侧栏里最重的一块，比主对话行还重；平时不在，按 `+` 才出现，整个列表下移。
- **位置有四处不对**：
  1. 对话发出后落在「今天」（在「项目」下面），占位行却在「项目」上面。按 JC 当时的数据（项目 1、本周 1、今天没有对话）算，发出那一刻亮着的行往下跳约 60px。
  2. 从项目组 `+` 新建时它也在分区顶上。票 07 把这条列为已知，票 08 写「照旧」，从没比过。
  3. 列表滚下去后按吸顶的 `+`，它出现在视口外，侧栏一处不亮：`newChatActive` 只用来渲染这一行，没有代码去滚列表。
  4. 紧贴分区头的 `+`，两个加号叠着，读作一个大按钮。
- 另有一个今天就有的瞬间：`createSessionPersisted` 先把新会话放进列表、设为活跃，`submitFromEmpty` 还要等 `create_session` 与 `activateSession` 才切屏，这期间占位行和「今天」里没选中的「新对话」行同时在。
- **根因**：「侧栏恰好一行说『你在这里』」是 10-08 给外置的新对话行定的，那一行本来就在，亮起来不占地方。有主对话后新对话行没了，票 07 为守这条规则，在最省事的分区顶上补了一行。规则没错，位置是凑的。

## 三档真机比

- **现状**：票 08 的占位行，作对照。
- **B 亮加号**：不要这一行，打开空输入框的那个加号保持按下（分区头的，或项目组行的）。
- **A 落点**：在对话将来出现的位置（「今天」第一行或项目组第一行）放一条 32px 的单行草稿行，发出后真会话行原地接替。

B 与 A 都加了接替：新会话一进列表，它的行就显示选中，加号或草稿行同时退场，上面那个「同时在」的瞬间随之消失。

我推荐 A：只有 A 让「你在这里」与「它会出现在哪」重合，也守住 10-08「列表里的一行」；代价写明了，今天还没有对话时按 `+` 多出「今天」标题，发出前约 67px，比现状的约 48px 还多。

自查用临时 harness 页在 Chrome 里截了三档 × 七种情形，截完删掉。它抓到 A 的一个问题：滚到底再按 `+` 时，「今天」标题被滚到吸顶分区头下面，草稿行看起来又像在分区顶上；加 `scroll-mt-11` 后修好，再交给 JC。

## JC 选 B

JC 真机试后觉得 B 最合理。我认，A 输在三处：

- A 的核心论证是「侧栏要标出对话会落在哪」，可主区已经说了：标题是「新对话」，项目新对话的输入框提示是「在 {项目} 里交代什么？」（`EmptyState.tsx`）。侧栏只需要说「没有别的会话被选中」和「你按的是哪个加号」，B 不占地方就做到了。
- A 的代价每按一次 `+` 都要付：列表要动（当天第一个新对话约 67px，有对话时 32px，滚下去时整个滚回「今天」），不发又动回去。它的好处只在发出第一句那一刻出现，而那时人在看输入框。B 在发出前侧栏什么都不动，列表只在对话真的建出来时变一次。
- A 先画一行还不存在的对话，不发就消失；B 不显示任何还不存在的东西。B 的代码也最少。

记下来的 B 的代价：「恰好一行」改成「恰好一处」。10-08 比五档时否掉「读作工具条上按下的按钮」，针对的是夹在两条线之间的全宽色带；这里是一个 28px 的按钮停在原位，JC 真机看不别扭。发出第一句时选中从加号跳到「今天」那一行，JC 看过，可以接受。

不处理的两点：按了项目组的加号之后再手动收起「项目」分区，侧栏没有一处亮着（项目新对话的入口都从组行出发，建完项目会先展开分区，只有手动收起才会这样）；空项目展开时，加号按下的同时抽屉里的「新建项目对话」也还在（今天就这样，点它只是把焦点送回输入框）。

## 收尾

- 删掉切换器、「现状」的占位行与 A 的草稿位；保留按下态（分区头、项目组行，项目藏在「更多项目」后面时把组借出来）与接替。
- `Sidebar.main-chat.test.tsx` 的占位行用例换成按下的加号、项目加号、借组、接替四条，外置补一条项目新对话不按加号。
- 设计文档改写「你在这里」一条、分区简图、分区头间距、组行规则与「已知」；文案表去掉「空输入框时的占位行」。
- 外置运行时不变（裁决 42：外置侧栏冻结）。
