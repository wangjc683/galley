# v0.4.8 发布：一次以引擎为主角的小版本

**日期**：2026-08-14
**范围**：v0.4.8 发布叙事，聚合 `v0.4.7..HEAD`（6 个提交，代码面
managed-ga 补丁栈 9 个 patch + payload / core 1 / gui 3 个文件）

## 背景

`v0.4.7` 是「Discord 渠道 + 13 提交打磨马拉松」的大批次。`v0.4.8`
反过来，是本项目至今**最小的一次发版**，而且主角不在 GUI：

1. **GA baseline `308153b` -> `f06d550`**——本版唯一有分量的内容，
   完整审计见 [升级 devlog](./2026-08-14-ga-upstream-upgrade-308153b-to-f06d550.md)。
2. 两处 GUI 收窄：[Channels 自动展开谓词](./2026-08-13-channels-auto-expand-predicate.md)
   收到只认注意力态、sidebar footer 去掉已归档计数。
3. 一处死配置清理：macOS About 面板的 `website` / `website_label`。

## 版本决策：patch，无分歧

按 `2026-07-30` 规则，minor 要求单个功能大到能自成产品线。本版最大
单项是一次上游 baseline 审计——它连「功能」都不是，是维护。两处 GUI
改动都是**做减法**（少显示一个数字、少展开几张卡）。这一票没有可讨论
的余地，记在这里只是为了让「最小版本也照走定级流程」有据可查。

## 为什么现在发，而不是攒一批

值得留痕的是这个决定，不是定级。

两处 GUI 改动单独撑不起一次发版。真正的理由是 **baseline 积压有成本**：
已审计的 SHA 和已发运的 SHA 每多差一版，下一次发版要吞的未实测 delta
就更大。`v0.4.7` 发的还是 `308153b`，再压一版就变成两版的账一起结。

而「等一批更大的」在这里买不到东西：`.scratch/ga-log-retention/` 是
needs-triage 且范围未定，Session Workspace 是暂缓件，手上没有「再等
两天就能一起发」的候选。加上定级规则明写批次总量不影响定级——攒着
既换不来 minor，又让下一版的引擎 delta 变厚。

## 用户能感觉到什么

baseline 那两条上游改动都落在日常路径上，值得写进 release notes：

- **终答不再被无故重生成。** 上游给 `</summary>` 的不完整判定加了
  `len < 100` 门槛。此前任何**以 summary 块结尾的合规终答**都会被判成
  截断流并强制重生成——而上游自己的 sys_prompt 恰恰要求模型发
  `<summary>`，等于自伤。
- **OpenAI 协议模型遇到过载会重试，而不是把 `!!!Error:` 打进正文。**
  上游把原本只在 Claude SSE 上的过载启发式抽成
  `_raise_if_retryable_overload()` 并接到三条 OpenAI 路径上，HTTP 200
  裹着的过载体现在会抛进 `_stream_with_retry` 的网络退避。

**bundled runtime gate 本版强制**：`managed-ga/` 变了。注意
`pyproject.toml` 在本区间**零 diff**，所以 `GA_DEPS` 没有变化——但门禁
的触发条件是「碰了 managed GA **或** baseline **或** 打包依赖」三选一，
不是只看依赖，所以照跑不误。中途一度只对既有 bundle 跑了烟测，后来补了
从零重建，理由见下。

## 一个方法教训：别用「依赖没变」去省掉打包门禁

审计早期我判断「`pyproject.toml` 零 diff → `GA_DEPS` 未变 → 不必重建
bundle，直接对既有 bundle 跑烟测即可」。这个论证本身是对的，但**它回答
的不是门禁在问的问题**。

门禁问的是「新 payload 能不能在打包 Python 下跑起来」，而不是「依赖列表
变没变」。既有 bundle 的 site-packages 是上一次构建的产物，拿它去验新
payload，验的是一个和发布件不同的组合。而且这道门禁是本项目**唯一有
历史实证会翻车**的一条（Telegram 接入时 `python-telegram-bot` 漏进
`GA_DEPS`，导致正式包里 Telegram 起不来，dogfood 跑开发模式验不到）。

这是 `v0.4.7` 那次「0018 未过全栈重放」教训的同型复发：**当一个论证被
用来替代一次廉价的验证时，先核实它回答的是不是验证要问的那个问题。**
重建耗时几分钟，代价远低于把这个推理留在发布路径上。

## Intel 机器的物理限制（沿用 v0.4.7 的记录）

本机是 x86_64，`bundle-python.sh` 靠**运行** bundle 里的 python 装依赖，
所以 `mac-arm64` / `win-x64` 本地物理不可验，由 `release.yml` 各自的
runner 覆盖、tag 时硬失败。本地能验的只有 `mac-x64`。

## 不随本版发运

- `.scratch/ga-log-retention/`（needs-triage）——引擎日志保留策略，
  与本版解耦且范围未定。
- Session Workspace（`.scratch/session-workspace/PRD.md`，本区间新增的
  暂缓 PRD）。
- 原生 About 面板收口到 Settings → About（本次新进 `deferred.md`，与
  sidebar wordmark 可交互是同一件事的两面，绑定启动）。

## 待办

- **步骤 8 双模式 dogfood 未跑**（外部 GA + managed GA）。本版动的是
  managed runtime 的 `llmcore.py` / `ga.py` 和浏览器扩展，其中
  **Browser Control 必须真跑一次**：`background.js` 的四处冲突是手工
  解的，其中一处的错误解法会调用一个已被 `0006` 删除的函数——运行时
  `ReferenceError`，Python 编译扫描抓不到。本次补了 `node --check` 作为
  语法门禁，但它保不了行为。这是本版风险最高的产物。
- e2e 套件（opt-in，需真 GA + LLM 额度）未跑。
