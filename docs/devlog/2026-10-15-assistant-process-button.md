## 起因

IM 画法定稿后，JC 又问了两件事：

- 「N 步和用时，是否还有必要保留？作为 IM 体验是不是可以不要或者改成非常低层级显示，比如 hover 后在复制和保存按钮后面某个地方？」
- 「hover 后显示的 Token 消耗是否还有必要保留？作为持久会话设计，是不是不应该再让用户去关注 Token 和上下文？因为这里不同于工作台的普通 session 都是从 0 开始新开。」

当时的样子：两步以上的回复下面常显「9 步 · 用时 1 分 21 秒 ›」（裁决 67 第 2 条）；悬停出现复制、保存 | ↑ 输入 ↓ 输出、上下文百分比。token 与上下文在整个界面里只出现在这一处。

## 讨论

**过程入口。** 落定后的用时是事后统计，时间已经交给居中时间条，在跑时的计时那一行管。入口本身不能删：出错、中止的运行本来整段平铺，入口留给核实（它说查过正式预报，你想看它查了什么）。所以要定的是入口的形态：它是动作，不是状态。

三案：A 现状；B JC 的提法，挪进悬停行、字照旧；C 悬停行里一个图标按钮，和复制、保存同一族。主会话推荐 C：行动条只剩动作，数字一个不在表面（B 悬停时数字还在）；手机没有悬停，长按菜单「复制 / 保存 / 查看过程」原样搬过去；行动条隐藏时本来就保留占位，分组间距不变。风险是图标不如复制、软盘一眼认得（输入框 ＋ 菜单就因「不带字的图标要悬停才认得」改过文字），退路是换成文字按钮。

**数字放哪。** 主会话上一轮说「步骤区第一行」，JC 问那是什么：今天展开区没有第一行，入口那串字就是它的头。两种放法：a 展开区自己的第一行；b 跟在按下的过程按钮后面。推荐 a：展开区头一行概括、下面明细，与工作台折叠头同一写法；b 让行动条有展开、收起两种样子。

**上下文与 token 分开看。** 上下文百分比在主对话里没有对应的动作：不能 `/new`（裁决 14），按规则切段，GA 到上限自己从最早的消息裁（裁决 39）。它还会露出界面刻意藏起的段界（裁决 18）。`workbench.db` 里的真实数据：10-14 05:36 天气那条回复是 36,227 / 270,000 字符，13%；隔夜的下一条 1,832 字符，1%。同一段对话，仪表却在说「它忘干净了」。

token 不删：用户自带 key 付钱，这一行是界面里唯一看得到花费的地方。它和步数、用时同属「机器怎么干的活」，跟着进展开区第一行。重活派进子任务，子任务是工作台会话，token 与上下文照旧；一步就答完的回复没有过程、也就看不到 token，库里这类回复的输入在 4k 上下。

**卡片的「第 N 步」。** 主区那一行不报步数，侧栏卡片在跑时却写「第 N 步 · 摘要」，同一刻两处说两句话：天气那次第 2 步，主区是「我按 10 月 17 日和 18 日这两天查。」，卡片是「第 2 步 · 已明确查询日期；接下来打开天气搜索页核对预报。」。`summary` 是 agent 的工作记忆，不写给读者（conversation.md「不用 `AgentTurn.summary`」）。两案：i 只去掉「第 N 步 ·」；ii 卡片改说主区那一行的同一句。推荐 ii：一个来源、规则没有例外。

主会话上一轮说「卡片是剩下的唯一例外」，不准确：主对话里的子任务卡片也写「第 N 步」，顶栏名字下面那一行和卡片同一个来源，也写。改正后的规则：助手本人在哪里都不报步数；它派出去的子任务是任务对话，子任务卡片照旧，工作台会话行照旧。顶栏是主会话补进来的，代价是主区开着时顶栏与主区那一行同屏说同一句，真机看；嫌重的退路是顶栏在跑时只写「思考中」。

## 裁决（68）

JC：入口选 C，卡片「一起改」，数字放哪与卡片说什么「按你推荐和建议推进」。

1. 行动条只有图标：复制、保存，两步以上的回复再加过程。提示只写「展开过程 / 收起过程」，不带数字；展开期间整条行动条常显，过程按钮按下。推翻裁决 67 第 2 条的「常显」。
2. 展开区第一行：「4 步 · 用时 45 秒 · ↑33k ↓1.1k」，不可点。
3. 助手的对话里不画上下文百分比；token 只在展开区第一行。
4. 卡片与顶栏在跑时说主区那一行的同一句，没有就写「思考中」。

工作台的会话、子任务、外置运行时零变化；只改 GUI。

## 实现（票 21）

子代理在独立 worktree 里做（JC 的 tauri dev 开在主树），三个提交 `dfd43968`、`52ad0791`、`294c27cc`，主会话审过后快进合入。

- 过程按钮就是一个 `ActionChip`，只加了 `expanded`（`aria-expanded` 与按下态：常显 `bg-hover`、墨提到 `ink`）。`MessageActions` 的 `leading` 换成 `assistant`；不带它时工作台行动条的输出与开工时逐字节一致。图标先用 `Footprints`，`ListChecks` 的对照图留给 JC 挑。
- 键盘：原入口能 Tab 到，过程按钮跟 chip 走（06-29 指针优先规则）到不了；⌥↑ / ⌥↓ 跳转不受影响。
- 展开区第一行在竖线上面，左缘与气泡对齐，竖线从它下面挂下来；行动条底到它 4px，它到第一步 12px。↑ ↓ 抽成 `TokenMetrics`，工作台与这里共用，悬停说明（含缓存拆分）照旧。
- 卡片与顶栏：`assistantCachedSentence` 从主对话的消息缓存取 turns 与正在流出的文字，走主区同一个 `assistantLineSentence`。主对话不在屏上时 runner 事件照样写进它的缓存（按事件的会话追加）。选择器只返回字符串，流出 33 个 chunk 时卡片与顶栏各只重渲染 3 次。
- 验证：typecheck、lint、两个时区的全量测试（126 个文件、1224 条）、`git diff --check`；反向检查 12 处全挂、恢复后逐字节一致；工作台、子任务、外置运行时 30 个画面逐像素一致；主对话的差别只在两类该差的地方，另有 13 处 1–8/255 的栅格化抖动，用「只把旧入口画成透明」的对照复现出来，确认不是版面变化。

子代理顺带报的：泄漏工具调用标记的回复没有可复制的内容，悬停行里只放过程按钮；展开后下一条消息（或时间条）几乎贴着步骤区的底，这是开工前就有的，没在本票改。
