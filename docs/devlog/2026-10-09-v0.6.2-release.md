# v0.6.2 发布

**日期**：2026-10-09
**上下文**：v0.6.1 后两天。main 上有三块：深色主题转冷相，Settings 逐页第二段的五批，侧栏项目重构（「项目」区、Project Review 退役、组内最近 5 条、「显示更多」与单行、新对话一律开普通对话）。
JC：「发版 v0.6.2，讨论下」→「按建议推进」。四点都按推荐：不补整轮 dev 回归，03 号票不进本版，notes 写一句「旧流程最后一次」，冒烟用短清单。

## 裁决

- **发，patch（v0.6.2）。** Project Review 退役是把同一能力挪进侧栏「项目」区，既不是拿掉一整套用户可见系统，也没碰安全模型，所以 10-05 的「拿掉也定级」不触发。
  安装挪到点重启时才进行，属于修复。没有数据库迁移，`cli/`、agent-api、IPC 协议都没改，仍是 `schemaVersion: 2`。
- **不补整轮 dev 回归**（方案 A）。v0.6.1 要整轮回归，是因为提示词没有遥测；这次没有提示词或引擎改动，十篇 devlog 的 Status 行也都有 JC 的真机验收。
  没单独回报的几项进冒烟清单。落选：B，在 dev 里用 CLI 补一轮侧栏与渠道回归。
- **`.scratch/sidebar-project-groups/issues/03` 不进本版。** 其中 A 项（文件夹说明行按路径判断）只在 CLI 建项目且不带 `--enable-workspace` 时出现，文案和开启方式要先讨论；
  B 项（尾部全借位时「收起」后这一行消失）很少见，修不修待 JC 定。
- **notes 写一句「从 v0.6.1 及更早版本升级的这一次仍走旧流程」。** 安装挪到重启时，是 v0.6.2 自己的更新器带来的，而已装的 v0.6.1 跑的还是旧更新器：
  macOS 上更新在后台装好后，渠道和浏览器桥会停掉，而且不会自己恢复（[通用批 devlog](./2026-10-08-settings-general-shortcuts-feedback-about-pass.md) D1）。
  靠 IM 远程使用的人这一次会断线，服务端无法规避。所以 SOP 第 10 步这次走的是旧流程；新流程（后台只下载、点重启才安装、Windows 下载完不再自己退出）要等 v0.6.2 → v0.6.3 那次更新才能验。
- **GA baseline 无需审计。** 上游 `main` 仍是 `f308ee7`（`git ls-remote` 查于 2026-10-09），就是 10-06 审计过的基线。
- **打包门禁要跑。** `runner/managed_im_supervisor.py` 有改动（微信 `/help`、`/status`），v0.5.4 跳过门禁时依据的「没动 runner」这次不成立。
- **更新渠道**：stable，publish + 冒烟后推 stable。
- **README 的 `projects.png` 留到下一轮截图。** 图注还写着「项目视图」。10-07「截图先不动」的裁决早于项目视图退役，前提已经变了；但 README 在 main 上本来就是这个状态，和发版无关。
- **顺手清理**：「v0.6.1 发版回归」项目和它的 19 个会话，由 JC 在界面里用新的「删除项目 + 同时归档」一次清掉，顺便把这个功能用一遍。
