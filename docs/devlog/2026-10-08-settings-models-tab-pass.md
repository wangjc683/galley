## 起因

10-07 横切收的是跨页一致性（页头、徽标、折叠），第二段逐 tab 深挖，按 10-07 定的五批走：模型 → 运行环境、
智能体接入 → 浏览器控制 → 聊天软件 → 通用、快捷键、报告问题、关于。JC 问「是不是一个一个 tab 过」，回答是 10-07
已定，并把深色复查折进第一批：深色 10-07 刚换冷相，若问题是 token 级横切，逐 tab 发现会重演「第三页才暴露」。

## 做法

- 真机截图：tauri dev 里用 dev-only harness 驱动设置弹窗（长轮询 scratchpad 小服务），浅色拍模型页 15 个状态、深色拍
  九页加模型页 3 个展开态。坑：dev 窗口被别的窗口完全挡住时 WKWebView 先停动画（入场停在第 0 帧、菜单关了不卸载），
  几分钟后整页挂起（定时器、HMR 重载都不处理）；用 System Events 把窗口切前台，harness 的等待改走服务端 `/sleep`。
  已记进记忆。
- 代码审计派一个 Opus 子代理：页面结构图、状态全集（标出 JC 实库截不到的）、保存语义、10-07 遗留三条的来历、
  47 条历史裁决清单、首装共用件、31 条问题候选、deferred 交叉。主会话复读关键行后出本地对表页（7 个裁决点 + 14 条
  直接收口 + 2 个事实问题）。
- 实现：文案契约（zh / en 各约 37 处）与两张票的交接接口（默认配置卡受控展开、「编辑默认配置」的 context、空库
  文案）主会话先改好；两张 Opus 票按文件分域并行（票 1 模型列表与高级配置 + managed-models 视觉，票 2 服务商、
  页面级状态与编辑器保护），都不碰 locale。0 返工。

## 裁决（JC 全部按推荐）

- **D1 行尾 ↑↓ 收进 ⋯ 菜单（C）**。来历：05-25 拖拽被 dogfood 判不可信换成 ↑↓；09-08 为 #26 恢复拖拽（20 个模型
  从底挪到第 2 位要点 18 下），↑↓ 以「键盘路径」名义保留——但拖拽把手本身接了 KeyboardSensor，07-05 又定过鼠标
  优先，理由两头不成立。做了 A / C 真机切换器，JC 定 C：「自己用时要移动位置和排序，更多会选择拖拽」。⋯ 菜单为
  测试模型、上移、下移、分隔线、移除模型。代价（每移一步要重开一次菜单）JC 比过后接受。**两个默认信号（radio +
  「默认」标签）保留**：radio 是动作入口、标签是唯一的文字注脚，09-08 #26 作者就没认出 radio 是设默认。
- **D2 页内未保存保护（A）**。服务商表单此前没有任何脏检查（「添加」、另一张卡「⋯ → 编辑」直接覆盖已填内容）；
  模型草稿被拦时只滚回去不说明，「手动添加」的新草稿被拦时什么都不发生；编辑服务商时点卡头收不起来。现在三个入口
  在表单脏时拒绝，被拦的编辑器亮一圈 brand 外环（过渡）+ 一行「先保存或关闭当前编辑」；干净时点编辑中的卡头 =
  关闭编辑器并收起。服务商表单脏判断抽成纯函数 `isProviderFormDirty`（编辑与打开时的记录比，新增与预设预填比，
  只选卡不算改动）。被否：B 再加关设置 / 切 tab 的离开确认（丢的是一次粘贴、弹框打断所有人），进 deferred。
- **D3 报错位置（A）**。写操作错误此前全落在「服务商」节顶部一条永不消失的 ErrorLine（`clearError` 全仓无调用），
  加载失败还会和空行、自动展开的新增表单同屏，像「什么都没配」。现在 store 不再存写错误（`error` / `clearError`
  删除，写操作照旧 rethrow），页面把六个写操作包一层弹错误 toast（标题「操作失败」、正文原始错误、同类一个 id 不
  叠卡）；加载错误单独存 `loadError`，无旧数据时服务商区只显示「读取模型配置失败」+ 详情 + 重试、不自动展开表单。
  店里写死的中文兜底「操作失败」改为空串由 UI 本地化。被否：B 按来源分区显示。
- **D4 用词三条**。a 编辑器保存按钮去名词只写「保存」，检查按钮「检查服务商」，正文「服务商」（10-07 统一后按钮
  还是「保存服务」「检查服务」）；b 统一「添加 / 已添加 / 移除」，不用「启用」；c 字段名「API Key」、正文「密钥」，
  「凭证」只留给 Codex（徽标「需要登录」）。b、c 改到首装共用的 `noAuthConfirmBody` 等键，首装文案同步。
- **D5 服务商卡与编辑器**。a「已添加：」chips 只在拿不到列表或有列表外模型时出现（同一组模型此前一屏三遍）；
  b 编辑态加「测试模型」（换密钥能先测再存；controller 本就支持）；c 编辑态预设只读（换预设会重置地址协议、已有
  模型的预设层却不跟，10-01 记过）；d「本地端点（如 Ollama）无需鉴权」只在自定义卡显示（改写 08-31 旁注的展示
  范围，留空逻辑不变）。
- **D6 默认高级配置**。a 页尾卡标题「高级配置」改为内容摘要「推理强度、重试与超时」（与节标题叠成双层）；b 09-22
  裁的「折叠头链接」实现时掉了——devlog「落地」节与 GUI 票都只写纯文字「跟随默认 / N 项覆盖」，无「有意不做」
  记录。JC 不记得，听完来历后按推荐补上，落成编辑器高级配置底部动作「编辑默认配置」（折叠头本身是按钮，嵌链接是
  嵌套交互），点了滚到页尾并展开默认卡。deferred「页签变体」继续挂着。
- **D7 0 个服务商的空页**。同一个「空」说四遍，标题行 primary「添加」点了会清空已填内容。现在新增表单自动展开时
  隐藏空行与「添加」，`我的模型` 空框写「添加服务商后，这里会列出可用的模型。」。

## 直接收口（不需裁决）

模型层数字框逐键夹值是真 bug（读取超时 min 5，退格到「1」立刻变「5」，再输「60」得「560」；删空被 React 还原），
两层统一为本地草稿，失焦 / 回车 / 在字段外按下鼠标时才提交——最后一条是票 1 发现的：项目 `Button` 按下时
`preventMouseFocus`，输入框不失焦，只靠 blur 的话打完数字直接点「保存」会存旧值，默认层原本就有这个隐患。
「读取模型列表」失败 / 空列表回退不再冲掉别处的脏草稿（按请求返回时的草稿判断）。Codex：退出登录成功不再显示
绿色「需要凭证」、缺凭证提示改「需要重新登录 ChatGPT」。外置模式保存 toast 改「已保存，切回内置内核后生效」、
不带渠道 CTA（内置零变化）。Thinking / Adaptive / Disabled 译为思考模式 / 自适应 / 关闭，「CC 透传渠道必须置
True」改「Claude Code 透传类中转必须开启」；推理强度 tooltip 档位名改小写（09-22 裁决漏网）。编辑态保存按钮去
`+`，两个编辑器标题统一 13px。服务商下拉协议徽标 10.5px 汉字 → 11.5px；Codex 设备码标签中文不大写。「我的模型」
副标题与页尾说明同款、计数降到与节标题同级。开关行补继承淡墨（设计规则漏了开关）。拖拽把手、radio 改快
tooltip。服务商预设下拉以设置弹窗为碰撞边界（此前越出底边约 105px）。`managed-models/` 下字面量 px 换等值 token。
7 个死文案键删除。加载失败时 `我的模型` 空框也写读取失败（票 2 报告的遗留，主会话补）。

## 不做与暂缓

- 不做：「默认」一词两义（编辑器底部按钮与 radio 提示在不同位置，现措辞更准）；与默认相同的模型覆盖不自动归并
  （模型上选 high 是明确意图，归并后默认改 medium 会把它带走）；模型行编辑入口键盘不可达（07-05 鼠标优先）。
- 进 deferred：模型显示名入口太深（JC 7 个模型显示名全等于 id）；Settings 关闭 / 切 tab 的未保存确认；Codex
  「读取模型列表」是 Core 写死的旧列表、不含预设默认 `gpt-5.6-sol`。
