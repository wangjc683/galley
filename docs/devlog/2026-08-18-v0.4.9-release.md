# v0.4.9 发布：单修复热修（Windows 黑窗）

**日期**：2026-08-18
**范围**：v0.4.9 发布叙事，聚合 `v0.4.8..HEAD`（4 个提交，实质代码改动 1 个：
runner 3 文件 + managed-ga 补丁 `0020`）

## 背景

社区 issue #23（Windows，managed runtime）：每次创建/恢复会话或启动后台
任务，桌面上闪过一个空白 CMD 窗口。排查结论：Rust 侧
`process_command.rs` 的 `CREATE_NO_WINDOW` 覆盖是全的，bridge 自身无窗；
黑窗来自 **bridge（无控制台进程）再往下 spawn 控制台子进程**时 Windows
给子进程新分配的控制台。五个漏网点：

1. `workspace_cmd.py` 的 `cmd /c mklink /J`——project workspace 会话准备
   时执行，就是用户看到的那个字面 CMD 窗口（时机与 issue 描述完全吻合）。
2. `im_reporter.py` 跑 `galley` CLI（IM supervisor 汇报，「后台任务」时机）。
3. `workbench_bridge.py` 的 git 探测 ×2（仅 external 模式触发，顺手修）。
4. `workbench_bridge.py` 的 desktop pet Popen。
5. `ga_ultraplan.py` 的 daemon spawn。

修法统一：新增 `runner/process_command.py`（`core/src/process_command.rs`
的 Python 镜像，`no_window_kwargs()` 在 Windows 返回
`CREATE_NO_WINDOW` + `SW_HIDE` STARTUPINFO，其余平台返回空 dict，调用点
无条件 splat）；managed-ga 两处走补丁 `0020-managed-windows-no-console-spawns`
（upstream `ga.py` / `agentmain.py` / `code_run_header.py` 本就带 flag，
这两处是上游漏网，是 upstream PR 候选）。

## 版本决策：patch，无分歧

单个 bug 修复，比 v0.4.8 还小，定级没有讨论空间。

## 为什么单修复也立刻发

- **发布本身就是验证通道**：维护侧无 Windows 真机，修复效果只能由 #23
  报告者装真实构建确认；不发版，修复停在「理论正确」。
- v0.4.8 的先例逻辑同样适用：未发运的 managed-ga 补丁会加厚下一版的
  未实测 delta，而后面没有值得等的候选（#16 大概率是版本/设置问题，
  应用内播放提示音是设计项不该赶）。
