## 顶栏菜单（裁决 77，票 28）

JC：「主对话 IM 顶部的这个菜单，现在下拉下来只有两个，其实作用不是很大的按钮……是不是可以用来承担更多实用功能」。主对话不能改名，菜单只剩「重新注入工具、桌面宠物」两项，偏调试和好玩。

主会话照裁决 64「点身份行像 IM 里点名字进资料页」的思路，对照微信、Telegram 的资料页（查找聊天记录、免打扰、置顶、清空聊天记录）与 Galley 现有能力列候选：查找聊天记录、在手机与 IM 渠道里找它、重置主对话、关于助手；不放模型（裁决 71）、记忆（裁决 49）、子任务列表（库里还没有子任务）、免打扰与置顶（裁决 65）、导出（没有这项功能）。JC：「目前手机版还没有开始做啊，我觉得可以先做 1+3」，四个细节展开后「按建议推进」：

- **查找做成 ⌘K 面板带范围**，不做浏览器式查找条：主对话是分页的，更早的历史不在页面上，查找条要覆盖全部就得接 Core 搜索再配逐页加载，等于做两遍；在渲染后的 markdown、代码块、折叠的长消息里原地高亮细节多；又是一个新容器。面板带「在主对话里」（普通会话「在这个对话里」）的标签，只搜当前对话；结果第一行由会话标题换成日期（范围内标题都一样，没有尽头的对话里「什么时候说的」才是线索）；回车按现成的逐页加载定位跳过去；空输入框按退格去掉范围变回 ⌘K。先例：Slack 的 ⌘F、微信的查找聊天记录。
- **⌘F 在任何打开的对话里都是在当前对话里查找**，没有打开对话时等于 ⌘K。普通会话的菜单也加「查找聊天记录 ⌘F」：用途两边相同，和裁决 73 有意保留的复制差异不是一回事。
- **重置主对话在菜单里直接弹出设置里那个确认框**（按住 5 秒、有对话在跑时置灰并写原因）：防误靠按住 5 秒，不靠入口藏得深。

Core 的公开接口早已支持按会话搜索，只是界面用的那条 Tauri 命令没接；票 28 给它加了可选的会话参数与每条命中的日期，不带会话时 SQL 与排序一字不差。CLI 与 Agent API 不动（CLI 走的是 `GalleyApi::search_messages`）。`deferred.md` 里 09-08 暂存的「会话内查找（Ctrl+F）」（issue #27 提出）随之关掉。

实现：子代理在独立 worktree 里做（xhigh），主会话在合并结果上重跑 Rust 与界面的全套检查后用合并提交合入。子代理在自查截图时修掉一个焦点问题：从菜单打开面板或确认框，焦点会被菜单的焦点陷阱吞掉、打字进不去，改为菜单关好之后再打开。主对话菜单里「重新注入工具、桌面宠物」保留了与普通会话一致的先后（票面画反了）。

## 推理强度改为由高到低（裁决 78）

JC 试了新的选择器：「是不是越高的选项应该越在上面，从上到下从高到低的自然逻辑？」原来是 `默认` / low / medium / high / xhigh / max。弹层总是向上开（`side="top"`），所以紧挨按钮的是最贵最慢的 max，`默认` 最远。改为 max / xhigh / high / medium / low / `默认`：紧挨按钮的是 `默认`（9 月以来 75 个内置会话无一手动改过强度），往上移就是往上加，「上即多」同任何纵向刻度。模型弹层不跟着倒，那是「我的模型」里用户自排的偏好顺序。

顺带了结票 25 子代理报的出入：设计文档写「只给四档、`max` 留在设置里」，代码从 09-22 起就是五档（两种协议都认，引擎把 Claude 的 xhigh 与 max 映射到同一最高档），改文档不改代码。主会话直接改（`1c62fc4f`）。
