# 待办从底层捋一遍：分法不动，补角色变了留下的缝

日期：2026-10-22
关联：[主聊天 PRD](../../.scratch/main-chat/PRD.md) 裁决 128（改写助手 PRD 裁决 10 的巡看判据）、票 [80](../../.scratch/main-chat/issues/80-todo-panel-empty-notes-cancel.md)、[81](../../.scratch/main-chat/issues/81-review-wakes-only-for-what-has-no-alarm.md)；
[主动的第一阶段](./2026-10-21-proactive-first-stage-todo-rooted.md)、[deferred](./deferred.md)「待办上的进展」

## 起因

JC：「我们来继续优化和打磨主对话的待办功能和面板，可以从产品设计和底层逻辑聊起，比如这个待办的核心是什么，记录哪些事项，哪些分类？从用户角度，哪些是查看，哪些是上手要操作的？给用户看的 UI 上怎么设计层级和逻辑关系等等？」

## 主会话的读法

1. **核心**：待办是 Galley 手上还没办完的事，它答应过你的每一件，在这里都有一行。它不是让你自己管任务的 todo 应用，是助理的账本，你来核对它记没记住、有没有在跟。
2. **每件事是一个承诺，有三格**：下一步在谁手里、什么时候、怎样算办完。拿 PRD 里出现过的例子对现在的分组：

   | 例子 | 下一步在谁手里 | 现在在哪组 |
   |---|---|---|
   | 周三前交季度报告 | 你 | 以后 → 今天 |
   | 排查到一半，先吃饭 | 你（Galley 能帮着推） | 随时 |
   | 702 装修 11-20 完工 | 到时你要确认 | 以后（挂铃铛） |
   | HR 周五给 offer 答复 | Galley 到时问一句 | Galley 在办 |
   | 十分钟后提醒喝水 | Galley | Galley 在办 |
   | 查 NBA 预测（子任务） | Galley | Galley 在办 |
   | 每天巡看 | Galley | 例行 |

   裁决 92 的判法（你不理这次提醒，这件事还要留在清单上吗）问的就是「到那时下一步在不在你手里」，所以现有分组正好按这根轴分：方框是你要动手的，状态图标是只看的。查看与操作的分界就是组的分界，这一点最该保住。
3. **角色变了，面板没跟上**：10-17 定面板时它是「记事本」（裁决 91）；10-21 起它是「主动的根」（助手 PRD 裁决 10）。面板还只列出事，不说它替你把事推进到了哪。
4. **底数**（库里全部）：待办 1 条、它自己的提醒 2 条（喝水）、挂在待办上的提醒 1 条、例行 1 条（巡看）、子任务 1 个；主对话这一轮 JC 说了 8 句。常态是 0–3 件，六个组大多时候只显示一两个。

## 查实的三处缝

1. **空状态再也出不来**：票 73 起有主对话就建好巡看那条例行（`core/src/scheduler.rs:386`），面板判空把例行也算进去（`gui/src/lib/todo-panel.ts:319`）。新用户第一次打开待办，只看到一行巡看，票 46 定的「要办的事，说一声就记在这里」没了。
2. **巡看的「有事才叫醒」几乎每天都成立**：判据是「你有没勾掉的事，或 Galley 有在办的事」（`core/src/assistant_todo.rs:150`）。10-22 早上那一轮只因为 702（11-20 到期、挂着提醒）：读了三遍清单与记录，最后 `<no-reply/>`。Galley 自己的一次性提醒到点会自己叫醒它，也被算了进去。
3. **一件事挂不上进展**：派子任务的记录里没有待办 id；它记待办时写的备注只在提醒响时送到它眼前，面板和卡片都不显示。

## 查看与操作

| 你想知道 | 现在在哪能看到 | 缺口 |
|---|---|---|
| 今天有什么要我做 | 「今天」组，加顶栏上的数字 | 无 |
| 它记住了吗 | 主要靠回复下的待办卡片，其次是面板 | 备注看不到 |
| 它在替我忙什么 | Galley 在办 | 无 |
| 它什么时候会来找我 | 你的事上的铃铛，Galley 在办里的时钟 | 分在两组，可以接受 |
| 这件事推进到哪了 | 只在对话里 | 缝 3 |
| 它最近替我办成了什么 | 已完成（默认收起） | 无：交代在对话里 |

操作照旧按裁决 91 的丙：只改状态的直接点，要判断的都跟它说。一处不一致：它自己的提醒在回复下的卡片上能取消（`gui/src/components/conversation/ReminderCards.tsx:65`），面板里只能「说说这件」。

## 裁决

主会话给四条推荐，JC：「按你的推荐推进」（裁决 128）：

1. 判空不算巡看，空状态与「例行」那一行共存（票 80）。
2. 巡看只为没有自己闹钟的事醒：随时组里你的事、截止日不晚于今天加 3 天的事（含逾期）、没结束的子任务；不算远期的事、Galley 自己的提醒、例行（票 81）。没选：每件事记「上次巡看过」，进 deferred。
3. 面板显示备注（票 80）；「进展写进备注」与「子任务挂到待办上」等信号，进 deferred「待办上的进展」。
4. 它自己的提醒在面板里也能取消，与待办上的「取消提醒」同一颗（票 80）。

不动：六组同级（裁决 98）、「Galley 在办」不拆两组、名字（裁决 94）。

## 落盘时补的两处

- **备注是写给它自己的**：库里 702 那条备注是「JC 告知：702 办公室装修预计于 2026 年 11 月 20 日完工；……」，第三人称、复述标题与日子。原样显示出来像一份内部记录，所以第 3 条的前半要带一句手册：备注会显示给用户，写给用户看，不复述标题与日子（并进票 81）。讨论时没看到这一层，推荐里只说了「显示备注」。
- **命令名说错了**：讨论里写的「`todo edit --notes`」不存在，改备注的命令是 `todo update --notes`（`docs/managed-ga-runtime/galley-assistant-manual/todos-change.md:10`）；裁决与 deferred 里已按 `todo update` 写。

## 已完成（同日第二轮，裁决 129）

JC：「已完成的，是不是颜色更淡一些？然后如果随着使用时间增加，已完成越来越多后，怎么设计已完成条目的显示？比如默认只显示前 30 条或者 50 条？」

1. **要淡的是方框，不是字**：品牌色实心方框是面板里最饱和的东西，一展开已完成就多出 N 个杏色方块；按顶栏的颜色规则，`brand` 是「Galley 在为你做事，或邀请你开始」，办完了的事不该用它。字已经在最浅那档（`ink-muted`），再淡只能降不透明度，即 10-17 否掉的 C2。另外已完成里子任务、提醒的标题比勾掉的待办还深一档。切换器四档：现状 / A 档位拉齐 / B 方框退成中性灰 / C 再整行 70%，主会话推荐 B（票 83）。
2. **例行响过不进已完成**：从裁决 128 的定义推出来：已完成是办完了的承诺，例行响一次没有办完什么。这也是唯一会让已完成永久变长的一类（票 82）。
3. **不按条数截**：条数截出来的范围随忙闲变，时间窗口的意思固定；「显示更多」是按钮后面再套一层折叠。维持 7 天加 50 件；按天分小标题与更早的记录进 deferred「已完成变长以后」。
4. **认错**：讨论里说例行排除后「CLI 的 `todo list` 也会跟着少这几条」，核对后不对：CLI 读的是待办本身（`core/src/assistant_todo.rs` 的 `todo_list`），分组只给面板，Agent API 不变。

## 密度（同日第三轮，裁决 130）

JC 拿苹果「提醒事项」对比，觉得面板空间利用更低，问是不是行间距。主会话用 `screencapture -l` 截了两边的窗口（只存草稿目录，不进仓库），折成 CSS px 对表：一行字 32 对 34、两行字 50.8 对约 51，每一行的高度一样，Galley 还略紧。差在三处：组名与组间距（JC 现在两件事、三个组名，组名加间隙占约 48% 的高度；JC 截的苹果是不分组的普通列表）、Galley 每行都带一行小字（苹果多数行只有标题）、宽度只有一半。上切换器比现状 / B 你的事不分组 / B+C 再收紧组名，带演示档（票 85）。

认错：讨论组间距（裁决 128 第 9 条）时估一行约 47px，实量 50.8px，PRD 已改，12px 的结论不变。

## 开与关（同日第四轮，裁决 131）

JC：「目前用户打开主对话，待办是会默认打开吗？我们讨论下这个待办面板在出现与关闭应该怎么样是最佳用户体验。」

1. **现状**：默认关，只有你能打开（顶栏按钮、⌘K、面板里点出去的跳转），Galley 一处、其他一处分开记，重启也记得；×、再点按钮、Esc、文件预览或「改动」审阅换掉它时关；主区窄于 760px 时盖住对话右边；没有任何事件会自己打开它。主会话推荐骨架不动，补两处缺口：窄窗口时记住的「开」每次进来都盖住对话（覆盖层点对话不关）；从第一件待办到面板没有路（卡片标题不能点，顶栏的数字只数今天，第一件若是下周的，顶栏没有任何变化）。
2. **JC 追问「它动了待办之后自动打开」**：按开关记住以后自动打开落在谁身上拆开：开着看的人没作用，关掉的人每次被推翻，没发现的人只有第一次有用；巡看悄悄派子任务时自己弹开，违背裁决 125。站得住的只有「只开一次」，与卡片标题叠加；上一轮把它列为三选一的 C 时没算进助理 PRD 裁决 10「巡看那一条看得见、撤得掉」。背后的需求「看见它动了什么」分两半：面板开着时亮行（现在做），回复下挂回执卡（要 Core 记录，进 deferred「待办的回执卡」）。
3. **用量**：JC 本机一共 2 件待办，一件记下 5 秒后更新（像是挂提醒），一件在面板里勾的，没有一件在对话里改过。回执卡因此暂缓。

落盘时补的一处：讨论里说「被它勾掉或取消的行亮一次」，写票时发现取消的待办会离开面板，面板里没有取消的样子，亮一下就没了；裁决定为勾掉的原地停 1.5 秒亮一下再落进「已完成」，取消的照旧直接离开。
