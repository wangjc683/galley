## 起因

＋ 菜单验收后，JC 问推理强度选择器能不能优雅地并进模型选择器。

## 讨论轨迹

**一、合并成一个组件。** 翻 09-22：第一版就是「弹层里一行档位」，真机被否（模型一多像
挂在最后一个模型下面；新对话里看不到），之后拆成独立 pill、十轮打磨成「一个短语、一个
箭头」，两半各自的悬停框是有意留的「两个目标」信号。现状的张力是「长得像一个、用起来是
两个」。本机数据：7 个模型，09-22 后 15 个新会话用了 5 个不同模型，改推理强度 0 次。
方案：A 保持；B 一个触发器 + 左右两栏弹层（「弹层就是展开的短语」，我推荐）；C 动作栏
一行 + 子菜单。**JC 想过之后认为两个弹层没有体验上的大问题**，不满在 UI 本身，B 不做。

**二、短语本身。** 放大截图读出三个毛病：

1. 强度词读作型号后缀：「gpt-6.1-sol high」同字号同字体、只差一级墨色，而 low / high /
   mini / max 本来就常出现在模型名里（ChatGPT 有过「o3-mini-high」）。Codex 的
   「GPT-6 Astra Medium」不混，是因为前面是排过版的产品名。
2. 模型名是 API 标识符：本机 7 个模型 `display_name` 全部等于 `model`。根子在设置（显示名
   留空即用 id），不在 Composer；不做自动美化（gpt → GPT 之类是猜品牌写法）。
3. ⚡ 读作「快」：7 个模型里两个叫 `*-flash`。

位置不动：挪到发送钮左边（Claude.ai）会让左边只剩 ＋、右边三件挤在一起，也与同日「左边
是放进什么、谁来回答」相反；挪到顶栏（ChatGPT）在新对话时离居中的 Composer 太远，且违背
07-04「Composer 居中，含模型切换器」；挪到输入框下方的提示行破「hint 槽只放文字」。

强度显示三个方向：C 中间加「·」（最便宜）；A 改四格刻度（我推荐：短语里只剩一个词，档位
一眼可比、不用翻译）；B 人话档位（轻 / 标准 / 深入 / 极深，仍是裸词，且要推翻 09-22「全
应用统一小写原词」）。**JC 选 C。**

**三、「LLM」改称「模型」。** JC 先提 tooltip「切换 LLM」应改「切换模型」，与文案规范
「`LLM` 紧凑控件可保留」冲突；我建议动作和控件一律说「模型」，JC 裁一起扫。

**四、⚡。** 07-20 第四次修订把审批图标并进模型 pill 时已写明「⚡ 在模型名前可能被误读为
turbo 变体……dogfood 观察」。观察结论：本机 135 个会话 0 个偏离默认（默认自动执行），⚡
挂在每一个会话上、从不变化——与 TopBar YOLO 徽章退役同一条原则，常亮的警示等于没有警示。
方案：1 只在偏离默认时显示图标（我推荐）；2 常驻但换图标（`FastForward` / `Play` 等「自动」
类图标都带「快 / 开始」的歧义，零信息不变）；3 维持。**JC 选方案 1。**

**五、悬停框。** JC 指出两个选择器悬停后「向左和向右多了一块」。原因：09-22 为了在无分隔
时把两个词压到一个词距，模型 pill `pl-2.5 pr-0.5`、强度 pill `pl-0.5 pr-2.5`，悬停框一个
往左、一个往右各多出 10px。有了「·」之后内侧不必再压。临时对照页（同款类名，悬停态画成
常亮，无头截图）比了 4 / 6 / 8px 三档对称内边距：Inter 12.5px 下空格 3.52px、「·」前进
宽度 3.6px（墨迹两侧各约 1px），正常排版的「 · 」墨迹间距约 5.5px；4px 档点两侧约 8px、
点离两个框各约 3px，6px 以上点两侧拉到 10px 以上，短语又散成两个控件（09-22 第二轮否过）。
定 4px。

**六、箭头。** 真机验收时 JC 指出：模型选择器没有向上箭头，推理强度有，不统一。09-22
第四轮 JC 问过同一个问题，我以「末尾一个箭头属于整个短语 / 零箭头读作状态行 / 上限 pill
带箭头」反对，未开真机变体。今天「·」把短语明确分成两项、悬停框又各自对称，末尾的箭头
落在强度的框里，第一条前提不成立。两个都加是 09-22 被否的形态且挤；**按推荐两个都去**，
模型单独显示时的箭头一并去掉。Goal 上限 pill 保留箭头（夹在 eyebrow 标签字中间要区分开）。
风险知情：成熟产品的模型选择器几乎都带箭头。

## 落地

- `Composer.tsx`：两 pill 之间加不可点的「·」（`text-ink-muted/60`、`px-0.5`、`aria-hidden`）。
- `LLMPill.tsx` / `EffortPill.tsx`：短语模式下两 pill 都是对称 `px-1`；`CaretUp` 全部去掉；
  模式图标改由 `ComposerApprovalModeState.deviatesFromDefault` 控制。
- `App.tsx`：会话态与空状态（pending）两处算出 `deviatesFromDefault`（生效模式 ≠ 全局
  默认）；用比较而不是「有无覆盖」，覆盖值事后与默认相等时也不显示。
- 文案（zh / en）：Composer tooltip「切换模型」、运行中「运行中无法切换模型」；命令面板
  「切换模型 / 搜索模型… / 没有可用的模型配置。」；错误卡「模型配置可能有问题」「请求未能
  到达模型提供商…」「可切换其他模型继续。」与按钮「切换模型」；Health Check / 引导页「模型
  连接测试」。**保留**外置 GA 路径校验里「mykey.py 存在」的副标签「LLM 配置文件」（技术
  语境）。文案规范 `LLM` 词条改为「界面一律说模型」。
- 设计文档：conversation.md 审批模式 Trigger、推理强度 pill（「·」与对称内边距）；
  onboarding-and-cards、overlays-and-settings 里引用的旧文案同步。
- 运行时影响：外置 / 内置同一套 per-session 审批机制，只改显示规则；Core / runner / CLI
  不动。

## 插曲

改语言文件后 tauri dev 侧栏会话与模型列表全空：Core 进程与数据库都完好，是热更新把 store
模块重新执行成空实例、而拉数据的 hydrate 没重跑。touch `gui/index.html` 整页重载即恢复，
正式包不受影响。

## 被否

- 推理强度并进模型弹层（B 双栏、C 子菜单）：JC 判两个弹层无体验问题。
- 强度四格刻度、人话档位：JC 选「·」。
- 模型短语换位置（发送钮旁 / 顶栏 / 提示行）：见轨迹二。
- 模型名自动美化：猜品牌写法，猜错比不改更糟；显示名在设置里可改。
- 两个 pill 都加箭头：见轨迹六。
- ⚡ 换成其他常驻图标、维持 ⚡：见轨迹四。
