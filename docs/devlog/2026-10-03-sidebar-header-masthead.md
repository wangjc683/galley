## 起因

JC 的提议：把 Supervisor SOP 变成图标挪进主区顶栏，再把新对话、搜索、定时、项目四个图标
放到字标右边，进一步提高侧栏的空间利用率。JC 自己也没想好，要求先对齐设计理念再定方案。
这是一场纯讨论（六轮）后定案的改动，过程里两次推翻了我自己的说法，所以把推导链留全。

## 事实底座

- 入口行是 32px 按钮 + 上下 4px + 1px 底边 ≈ 41px，不到一条会话行（最少 48px）。09-28 已从
  约 152px 压到 41px，这次能省的只剩这一截。
- mac 顶行左边要给红绿灯让 88px（09-18 实机调过）。Windows 没有这笔税。
- JC 本机是 5K iMac + 1920 的 Dell，侧栏比例存的是默认 20%（webview localStorage 只读查得），
  默认宽度下什么都放得下；挤的是笔记本用户。默认窗口 1480 宽（`tauri.conf.json`）→ 侧栏 296px。
- 本机 135 个会话里 Supervisor 创建的 19 个；项目 0 个、定时任务 0 个（workbench.db 只读）。
  复制 SOP 是做一次就完的设置动作；命令面板里没有 SOP 命令。
- 侧栏那个新对话按钮是**窗口里唯一一直看得见的新对话入口**：主区顶栏的「新对话」只是空状态
  标题（`MainHeader.tsx:246`），其余入口是 ⌘N、⌘K 和 mac 菜单栏，都要用户先知道；Windows
  没有菜单栏。

## 推导

**一、四个入口全上顶行的代价。** 按 JC 原提议，mac 顶行要约 283px（88 + 字标 47 + 间隙 12 +
四个 28px 图标 124 + 右边距 12）；外置模式再加「外部 GA」徽标更宽。顶行右侧还驻着「配置模型」
「连接外部 GA」两个设置态指示，要先给它们找家。

**二、字标的三个方向。** JC 问能否让字标和按钮成为协调的整体，或者把字标拿掉 / 挪到更巧的位置。
摆了三个方向：

1. **书眉**（采纳）：顶部两栏看成摊开的书，左页书眉印书名（Galley），右页印章名（会话标题）。
   现在的结构本来就是这样；整体感靠给字标这个角色、再让按钮与它共用一套网格（两端分组、
   图标组右缘对齐下方会话行 ⋯ 那一列、按钮与右栏同规格），而不是把两者焊在一起。
2. **平台分治**：mac 去字标（菜单栏一直印着粗体 Galley，窗口标题隐藏），Windows 保留（自绘
   标题栏、无菜单栏，窗口里只有这一处写着 Galley）。否：两平台长相不同；官网 / README 截图
   多是 mac，截图里不再有字标；JC 每天用 mac 看不到它。
3. **落款**：字标移到侧栏底部「已归档」那行左边；离开顶行就不再是拖窗把手，08-14 那条硬约束
   随之解除，可以做成通往「设置 → 关于」的门（deferred 里 About 那条写着「别单独启动」，这是
   一起启动的时机）。否：底行要从「有归档才出现」改成常驻，左下角在很多应用里是账号位，范围
   扩到 About。仍是 About 那条将来启动时的现成候选。

一并否掉的：把加号焊进字标 / 字标当新对话按钮（08-14 已判死：字标是拖窗把手，题词先例——
误点不能烧掉一个会话）；四个按钮装进胶囊与字标拼成工具条（多一层 chrome，新对话主次被框抹平）；
字标挪到空状态 Composer 上方（撞「不放欢迎文案」，重演 quick prompt 两块安静衬线夹住 Composer
的问题）；两平台都去掉（Windows 窗口里就没有任何地方写着 Galley）。

**三、更正一：字标不用缩。** 我先估字标约 53px、主张降到 13–14px「和右栏标题同一档」。用
`@fontsource` 的字体文件实测（系统 python3 的 fontTools）推翻了：17px Newsreader 斜体 500 宽
46.8px；Newsreader 的 x 高只有 0.43em（Inter 0.55em），**17px 的 x 高 7.24 与右栏 13px Inter 的
7.10 已经同档**，降到 14px 只是大写 G 与 Inter 大写等高、小写反而小一号；宽度上 17px 只比 14px
多 8px。定案：字标完全不动。

**四、逃生出口。** JC 的新思考：新开对话是非常高频的操作，这个按钮要像逃生出口一样好找，否则
用户会像被困在旧会话里。把它拆成三条标准——显眼（对比）、能读（有字）、位置固定（不随宽度或
状态挪）——再对照：

| | 显眼 | 能读 | 位置固定 | 高度 |
|---|---|---|---|---|
| 09-28 现状（新对话与三图标同一行） | ✓ | 侧栏 < 198px 掉字 | ✓ | — |
| 四个都进顶行，新对话只剩加号 | ✓ | ✗ | ✓ | 省 41px |
| 同上，宽屏（≥ 约 350px）带字 | ✓ | 笔记本上 ✗ | ✓ | 省 41px |
| **新对话独占全宽一行，三个低频图标进顶行** | ✓✓ | ✓ 任何宽度 | ✓ | 与现状同 |

笔记本宽度下，「字标常驻 / 新对话带字 / 省一行」只能三选二。JC 前面选了留字标，现在把带字排到
省一行之前，于是新方案是顺理成章的结果。还有一种「宽屏全并进顶行、窄屏新对话下沉」看似三全，
但新对话的位置随宽度变，违反「位置固定」，不做。

**代价如实写：这一版不省高度**（44 + 41px，与 09-28 相同），JC 最初「提高空间利用率」的目标
被有意放弃。换来的是层次理顺：顶行 = 书名 + 低频工具，第二行 = 唯一主动作，下面 = 会话；
新对话在任何宽度都带字、热区全宽；SOP 移出顶行。

**五、项目按钮放顶行是否合心智。** JC 的疑虑：项目按钮会把整个侧栏切到另一个视图、还带动画，
挪到顶行后离它切换的列表远了一行。逐条核：作用域对（侧栏顶行是侧栏自己的 header，06-24
「每栏各管自己的 header」）；与搜索同一层级（05-22 否掉「拿项目分组标题当开关」的理由正是项目
入口要和新对话、搜索平级）；进场动画从上方落下（`-translate-y-2` → 0），触发在上、方向一致；
顶行不滚动，按下态常驻可见。

**更正二：中间那行不是不动的。** 我先说新对话行「在两种视图下都不动」，JC 追问「让新对话也
同样切换、变成某个项目的新对话，是不是更自洽」——查代码发现这正是现状：进入项目视图自动展开
第一个项目并软设项目上下文，新对话立刻变成「新对话 · 项目名」，退出时清空
（`useProjectNavigation.ts:65-86`，注释写明是为避免「项目视图里 New Chat 是个死按钮」）。所以
按下顶行的项目按钮，最先变的是正下方那一行，再是列表，因果链从上到下连续；「远了一行」的
弱点基本不存在，「项目按钮留在新对话行右端」的替代方案也就失去唯一的好处，不再做变体比较。
新布局还让这条链更好读：09-28 的已知边角「项目名可能只剩一个省略号」随新对话独占一行消失。

**六、顺带查出的矛盾。** 项目上下文里新对话按钮的悬停提示写「新对话 · 项目名 ⌘N」，但 ⌘N
总是开普通新对话（`useGlobalShortcuts.ts:73` 清项目上下文）。JC 选 A：⌘N 保持「总是普通
新对话」，作为键盘上永远不变的逃生口；项目上下文里悬停提示去掉 ⌘N。另一选项（⌘N 跟随
上下文）会少掉一个总能回到普通新对话的出口。

## 定案

- **顶行（书眉）**：字标不动（17px、88px 红绿灯留白不动）；右侧搜索 / 定时 / 项目三个图标，
  用右栏的 `TopBarIconButton`（28px、16px thin、`gap-1`），顺序不变；右边距让「项目」图标与
  会话行 ⋯ 同一竖列。项目按下态、定时角标原样带过来。
- **新对话行**：独占全宽，任何宽度都带字；行末淡色 ⌘N，只在无项目上下文且三图标不在本行时
  显示；项目上下文里悬停提示不写 ⌘N。
- **窄宽回落**：单一门槛（mac 251px、Windows 189px、Linux 179px）以下，三个图标回到新对话行，即 09-28
  的一行布局（含 198 / 220px 掉字规则），顶行只剩字标。新对话行两态都在，列表不跳。
- **Supervisor SOP** → 主区工具簇、齿轮左边，`PlugsConnected` 图标，常驻、两种模式都有
  （它没有状态，进状态簇会破坏「状态簇只放有状态的东西」；本质是「设置 → 集成」的深链）。
- **内核状态指示** → 主区状态簇，Goal 之后、浏览器控制之前（内核是后面那些能力的前提）。照
  浏览器控制的语法：「配置模型」「连接外部 GA」为文字徽标，外置就绪收成安静的 `Cpu` 图标
  （Settings 运行时 tab 的图标）、可点进设置；内置就绪不显示。色调保持中性——侧栏原来就是灰点，
  搬家不能顺手升级严重度。改掉 layout-and-chrome「runtime 详情不进 MainHeader」一条：状态簇里
  早已有渠道、更新这些 app 级状态，这条的前提已松。09-18「外置模式 SOP 退成图标」随之作废。

两种运行时模式：侧栏顶部从此完全一样。内置模式顶行右侧的 SOP 文字按钮变成三个图标；外置模式
「外部 GA」徽标从字标旁移到主区状态簇。

## 被否

- 四个入口全进顶行、新对话只剩加号（JC 原提议）：笔记本宽度下新对话无字，违背逃生出口。
- 宽屏三全（并进顶行且带字，窄屏下沉）：新对话位置随宽度变。
- 平台分治、落款：见推导二。
- 字标缩到 13–14px：见更正一。
- 项目按钮留在新对话行右端：见更正二。
- 窄宽时「字标先让」：在新方案里三图标退回新对话行就是现成的回落形态，单门槛、无纵向跳变、
  字标始终在，比「先藏字标再回落」干净。
- ⌘N 跟随项目上下文：见推导六。

## 已知边角
