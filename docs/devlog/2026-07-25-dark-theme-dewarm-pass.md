## Context

JC 提出想打磨 dark theme 配色，问 Ghostty 是否可参考。先做现状测量（OKLCH
+ WCAG 对比度），再由 JC 定方向：**"稍微多了一点点，偏暖"**。

### Ghostty 参考的实际结论（与直觉相反）

把 Ghostty 默认 dark（`Ghostty Default Style Dark`：One Dark 底 + Tomorrow
Night 调色板）与几个参照放到同一坐标系：

| | 背景 L | 背景 C | 背景 H | 正文对比 |
|---|---|---|---|---|
| Ghostty `#282c34` | **29.3** | .0157 | 264°（冷蓝） | **14.0:1** |
| Galley dark（旧）`#171411` | 19.4 | .0077 | 67°（暖） | 15.0:1 |
| GitHub dark `#0d1117` | 17.6 | .0140 | 258° | 16.0:1 |
| Notion dark `#191919` | 21.3 | .0000 | — | 11.9:1 |
| Linear dark `#08090a` | 13.9 | .0029 | 246° | 18.7:1 |

- Ghostty 的舒适**不来自低对比**——它 14:1，和我们几乎相同。来自**画布被抬起**
  （L 29.3，比我们高约 10 点）：同样的对比比例，绝对亮度落差小得多，且上下都
  留了层级空间。
- Ghostty 的染色是我们的 **2 倍**且旗帜鲜明地冷蓝。它的克制在于调色板**色相
  均匀撒开 + 明度对齐**（平均 C .088，L 集中 62–85），不在低饱和。
- 因此可借的是**结构**，不是色相——foundations.md 明确写死 dark 是"暖炭黑，
  不走冷灰蓝 IDE"，Ghostty 默认恰恰就是冷灰蓝。

### 诊断：问题在表面，不在墨色

关键指标是**按各自明度归一后的饱和度（C/L）**，它暴露了 light / dark 用的其实
是两套策略：

| token | dark C/L | light C/L | 倍数 |
|---|---|---|---|
| app | .0395 | .0017 | **22.8×** |
| surface | .0458 | .0017 | **26.6×** |
| chrome | .0447 | .0030 | 15.0× |
| line | .0536 | .0031 | 17.2× |
| line-strong | .0645 | .0054 | 12.0× |
| ink | .0184 | .0266 | 0.7× |
| ink-soft | .0317 | .0279 | 1.1× |
| ink-muted | .0443 | .0219 | 2.0× |

light 的表面实质是中性的（C ≈ .002），暖度全交给暖墨 + 杏沙品牌；dark 却悄悄
换成了"染色纸"。而**墨色两个主题基本对齐**——最初的猜测（"奶油白字才是元凶"）
被数据推翻。

## Decisions

- **降暖幅度取 ×0.6（"收一档"）**，表面与墨色同幅。仍读作可辨认的暖炭黑，
  噪音减半。JC 在带 hex 阶梯预览的三选中选定。
- **只动 chroma，L 与色相原样保留**——纯旋钮改动，对比度 / 层级 / 可读性
  数值上不变：正文 ink/app **14.97:1 → 14.95:1**，明度漂移全部 ≤0.17 点，
  阶梯保持单调（chrome 17.5 → app 19.3 → surface 21.6 → code 23.3 →
  elevated 24.6 → hover 25.8 → line 30.0 → line-strong 38.0）。
- **墨色必须与表面同向同幅**，不能只降底。近中性的底会变成参照物，把奶油字
  衬得更黄——暖感不降反升。同批次跟随 ink 的还有 `--color-line-subtle` 与 17 处
  `--shadow-*` 的高光内嵌（`rgba(239,231,220,…)` → `rgba(236,231,225,…)`）。
- **品牌家族与语义色本轮不动**（`brand` / `brand-strong` / `brand-tint` /
  `selected` / `success` / `warning` / `error` / `info`）。先看安静下来的底色
  之下品牌色的**相对响度**对不对，再决定要不要动——避免同时拧两个旋钮。
- 顺带修掉一个旧色相跑偏：`elevated` 原为 73.4°、比其余表面偏 6°，重算后
  归到 67.5°。

落地值（旧 → 新）：`chrome #13100d→#12100e` · `app #171411→#161412` ·
`surface #1d1915→#1c1917` · `code-surface #221d18→#201d1a` ·
`elevated #24201b→#23201d` · `hover #28231e→#262320` ·
`line #332c25→#312d28` · `line-strong #4c4035→#48413b` ·
`ink #efe7dc→#ece7e1` · `ink-soft #c9bcad→#c5bdb4` · `ink-muted #958878→#91897f`

## Rejected alternatives

1. **B · 对齐 light 的绝对 chroma（表面 ×0.30，墨色直接取 light 值）**——
   两个主题第一次在数值上真正同一策略，但表面近中性、有"变冷"风险。JC 的
   反馈量级是"稍微多了一点点"，×0.30 超调。留作升级路径：若 ×0.6 用久了仍
   觉得暖，直接再拧这个旋钮即可，不需要重新设计。
2. **C · 全中性炭（表面 C=0，纯灰）+ 微暖墨**——最干净，≈ Notion dark 的策略，
   但与 foundations.md "暖炭黑"的定位直接冲突，要同步改设计文档。为一次配色
   微调改产品调性定位不划算。
3. **只降表面、墨色保持奶油白**——最小改动，但见上方"墨色必须同向"：中性底会
   放大奶油字的黄，暖感可能不降反升。
4. **抬画布（L 19.4 → ~25，Ghostty 式）**——本轮 JC 只提了暖度，没碰。移入
   [deferred.md](./deferred.md) 台账。
5. **借 Ghostty 的冷蓝色相**——见 Context，与 foundations.md 写死的方向冲突。

## Open questions / Next

底色安静下来之后按可能性排序，下一轮从上往下看：

1. **`brand-tint` 用户消息块**（`#4a3829`，C .0355）——它比 app 高 **16 个 L 点**
   （light 侧只高 7 点），globals.css 里本就标着 `provisional`。底色降噪后大概率
   变成屏幕上最响的东西，最可能第一眼看到。
2. **代码块的 shiki `github-dark`**（`CodeBlock.tsx:42`）——8 个 token 里 4 个落在
   250–255° 冷蓝，与暖画布 67° 正面对冲；green `#85e89d`（L 85 / C .14）是霓虹。
   底色转中性后这个冲突是缓和还是更刺眼，需要实看。
3. **语义色明度不齐**——`error` L 68.3 比 `success` 75.8 / `warning` 74.5 暗
   7.5 点；`info` 的 C .040 只有其余的约 1/3，并排时"音量"不一致。
4. **发光 keyframe 硬编码 light 品牌色**——`globals.css` 585 / 603 / 622 / 632 /
   657 / 740 行写死 `rgba(191,122,31,…)`（= light `warning #bf7a1f`）与
   `rgba(198,135,98,…)`（= light `brand-strong #c68762`），不随主题翻转；dark 的
   实际值 L 高约 10 点，导致暗色下这些光晕发闷。**这条是纯 bug，与审美无关，
   可独立修。**
