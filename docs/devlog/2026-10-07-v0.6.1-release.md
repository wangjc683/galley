## 裁决

- **发，patch（v0.6.1）。** 改动最大的是提示词与设置页，都是已有功能的增强，也没有拿掉任何系统；按 07-30 的功能量级规则与 10-05 的
  「拿掉也定级」规则都判 patch。回归中修掉的两处丢数据（见下）是修复，不改定级。
- **先在 dev 里回归，再打 tag**（方案 A）。提示词没有遥测，回归清单是唯一的检验手段，三轮改写又是一天内做完的；在 dev 里发现问题改完
  提交即可，在草稿里才发现要重打 tag。落选：B 一次做完（问题一出就重打 tag）、C 等设置页 Models 第二轮与暗色一起发（引擎与提示词继续
  堆在 main 上没人跑）。
- **回归中发现的丢数据现在就修**（JC：「丢数据 bug 现在就修，开一个 subagent 开始做」），不挪到下一版：页面重载会丢掉正在跑的一整轮，
  stable 渠道会自动推送，`session wait` 还会把中间步骤当结果交给 supervisor。修法与复现见
  [devlog](./2026-10-07-core-owned-turn-persistence.md)。
- **测试产物发版后再删**（JC）：`~/Downloads` 下的 `生活随笔.{md,txt,csv,json}` 与 `galley-env-inventory.md`、项目「v0.6.1 发版回归」
  及其会话、一个 Chrome 标签页。
- **GA baseline 无需审计。** 上游 `main` 仍是 `f308ee7`（`git ls-remote` 查于 2026-10-07），就是 10-06 审计过的基线，这次不用写跳过理由。
- **Agent API 不变**：仍是 `schemaVersion: 2`。`session wait` 的形状没变，只是 Core 自己落库后它等到的是真正的最终回答。
- **更新渠道**：stable，publish + 冒烟后推 stable。
