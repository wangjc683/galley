# Question Rail：门槛降到 1，间距保持等比映射

日期：2026-07-21
状态：已实现，随本条目 commit
相关：`gui/src/components/conversation/UserQuestionRail.tsx` ·
`docs/design/conversation.md` §Right Question Rail

## Context

JC 提出：超长回答想翻回提问开头，靠滑动太久；rail 能跳转，但只有一两条
对话时 rail 不显示（`MIN_USER_MSGS_TO_SHOW = 3`），体验缺失。排查发现
⌥↑/⌥↓ 键盘跳转与对话长度无关、一直可用（Settings → Shortcuts 已列），
缺的只是可发现的鼠标路径。

## Decisions

- **门槛 3 → 1**：rail 有两个职能——多问题间的**索引**（≥3 条才有意义）
  和回到提问开头的**跳转锚**（1 条即成立）。旧门槛按索引职能设定，饿死
  了锚职能；而深度研究型对话恰是一问 + 数千字回答，最需要锚时 rail
  缺席。降门槛复用既有控件与已学会的交互，不新增任何东西。单点 rail
  的代价（初见读不出"这是导航"）由 hover tooltip 自解释兜底。
- **dot 间距保持等比映射，不紧凑化**（同日第二轮讨论，JC 认可"先不
  动"）：dot 位置 = 提问在文档中的滚动位置百分比，rail 是缩略地图。
  稀疏本身携带信息（"两问之间隔着长回答"）；且"hover 逐个辨认"的需求
  与稀疏错开——问题少时靠顺序即可辨认（一次移动一次点击），问题多时
  等比映射自然变密、dense cluster（<14px 合并 + hover 展开列表）已是
  现成的紧凑浏览 UI，顺序浏览另有 ⌥↑/↓ 零移动路径。结构自洽：密端有
  cluster 压缩，疏端保地图语义。

## Rejected alternatives

1. **条件性「回到提问」浮动按钮**（滚深时在滚到底按钮旁浮现向上对应
   物）——新控件，且 ≥3 条时与 rail 职能重叠冗余。
2. **常驻滚动到顶按钮**——"顶部"在长对话里不是用户想去的地方。
3. **dot 紧凑化（TOC 式堆叠）**——把地图变目录，位置编码信息整个消失，
   dot 位置变任意排列反而更需要解释。
4. **相邻 dot 间距上限（分段压缩）**——保序、有界移动，但位置编码从此
   不诚实。留作升级路径：若真实使用中反复出现稀疏 dot 间来回 hover 的
   动作，再回来谈。
