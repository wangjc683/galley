# 工作台对话跟上助手的语法：语法统一，密度按关系与工作分

日期：2026-10-16
关联：[工作台对话 PRD](../../.scratch/workbench-conversation/PRD.md)（裁决 1–7）、票 [01](../../.scratch/workbench-conversation/issues/01-speaking-grammar.md)、[02](../../.scratch/workbench-conversation/issues/02-process-one-line-per-step.md)、
[助手 PRD](../../.scratch/assistant/PRD.md)、[主对话 PRD](../../.scratch/main-chat/PRD.md)（裁决 60–79）、[conversation.md](../design/conversation.md)

## 起因

助手的对话 10-14、10-15 两天改成了 IM（双侧气泡、居中时间、过程藏进悬停按钮与过程卡片），工作台照旧是文档式的任务记录。JC：「组对话和普通对话现在的显示体验……差别比较大，甚至有点割裂……一个作为个人助理，一个是作为工作台，统一风格后，肯定是还是可以保留差异」，提了三处想统一（用户消息放右侧、时间居中、过程步骤照助手），三处没想好（上下文百分比、过程更详细、工作台的回复要不要也变气泡），要求从助手 PRD 的地基出发：助理是幕僚，普通对话人用、助理用、agent 也用。

## 诊断

主会话把两边的差别分成两类：**语法**（谁在哪一边、时间挂在哪、一步怎么写）与**密度**（默认露多少过程、给不给数字、回复装不装进气泡）。割裂感几乎都来自语法：从助手点子任务卡片进工作台，你的话从右跳到左，时间从中间跳到气泡左上，同一个「一步」换了一套写法。密度的差别本来就该有。

地基给了分界：助手管关系，只放判断和交代；工作台是办公室，底线是「不用管，但随时看得见、接得过来」，办公室是信任的来源，所以工作台不能也把过程藏起来。「agent 也用」对界面的要求只有一条，发话的一方标明是谁：agent 读 CLI JSON，不看界面，界面上的工作台会话都是给人看的。

数据（本机库，9 月以来）：工作台回复中位 678 字、p90 2310，47% 带表格、41% 带标题、14% 带代码块、23% 超过 1500 字；过程中位 2 步、p90 11，40% 一步就答完；你的消息中位 19 字。会话来源人开 44、CLI 24、supervisor 6、子任务 0。

## 裁决

JC：「1，认可；2，按你推荐；3，按你推荐；4，这条我也还没想好；5，按你推荐，不要；6，按你推荐，P1，不用切换器；7，按你推荐。」随后「按建议推进」。

1. 分界改说法：「语法统一，密度按关系与工作分」，取代主对话 PRD 裁决 73 第 4 条的「助手像 IM、工作台是文档」；工作台保留悬停复制的结论不变。
2. 工作台你的话在右，上限同助手 `min(80%, 560px)`；推翻设计文档「不要 right-align」。它的两条理由：一个阅读左缘（你的话中位 19 字，跳的代价小；ChatGPT 就是右侧气泡加散文回复）、右缘挤问题轨（只在栏宽撑满主区时，内缩能解）。悬停复制挪到气泡下方右对齐：助手里否掉「下方」是因为连发只隔 4px，工作台没有这个问题；镜像到左下是助手里否掉的位置。
3. 时间居中，断点不变。
4. 派活说明（助手、外部 agent 写的、出现在右侧的消息）的颜色暂缓，进 [deferred](./deferred.md)「派活说明的颜色」。
5. 工作台的回复不进气泡：表格、长文与代码会框里套框。
6. 过程取 P1：在跑照旧，落定后折叠头照旧常显，折叠头后面换成助手过程卡片的一行一步（不设上限、不内滚、没有数字行）；中途提问与你的回答留在外面。没选 P0 现状、P2 全照助手（工作台就不再「看得见」）。
7. 一步就答完的回复不画折叠头，数字照旧在悬停行。

工作台保留：流式显示、live 窗口、token 与上下文百分比（裁决 68 不给助手画百分比的理由是「没有对应的动作」，工作台有：开新会话）、问题轨、悬停复制、提示行、提问贴顶滚动。外置运行时全部跟着变，更新说明要写。

## 主会话漏查的两条 deferred

讨论时主会话没扫 deferred，写票时才发现第 6、7 条各碰一条旧的暂存项：

- **「过程区密度」B 刀「全面单行合并」**，2026-09-16 真机否过（JC：「太密集后，单个步骤的阅读体验其实变得更差了」），重开条件是「只能以阅读形态本身更好为由，且要同时解决同行两个披露 caret 的问题」。P1 不是 B：B 把工具标签挤进 summary 那一行；P1 一行只有一句话与对象，工具标签收进点开，整行是唯一的点击目标，没有 caret，单步点开后是原来的阅读形态；这一形态 JC 已在助手里真机验收（主对话票 22）。重开的理由是语法统一，不是密度。deferred 那一节的 B 条加了这次重开的记录，C 与横向案不动。
- **「单步 run 的『第 1 步』前缀收敛」**（08-23 暂存，09-16 维持）：第 7 条就是那一节「待定」里的「删整行」。它留下的两条约束：DetailPanel 入口（那一步的推理与开场白）——库里 46 个一步回复 0 个带，接受；StrongHr 的「行动 → 结论」需要上方有行动列——没有行动列就不画。那一节从 deferred 撤下，来龙去脉以本篇为准。

教训：推荐涉及过程区、气泡这类反复改过的部件时，先 grep deferred 与设计文档的「否决 / 暂缓」，再给推荐。
