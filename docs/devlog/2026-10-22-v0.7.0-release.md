# v0.7.0 发布

**日期**：2026-10-22（打标签）
**上下文**：v0.6.2 后两周，`v0.6.2..HEAD` 共 687 个提交（665 个非合并）。大头是产品形态从工作台变成私人助理：主对话、子任务与叫醒验收、待办与提醒、主动做事与每天的巡看。另有 Sign in with ChatGPT、Goal 移除（Agent API `schemaVersion: 3`）、IM 四个渠道的打磨、远程访问的地基，以及 GA 基线升到 `b70079d`。
JC：「准备发版了，有比较大的新功能和产品定位和形态变化，我们讨论下版本号用什么合适」→「按建议推进」。

## 裁决

- **发 minor（v0.7.0），不发 1.0.0。** 版本规则按量级定级，拿掉也定级：Goal 整族移除、CLI 升到 schema 3，在 0.x 里就是 minor。形态变化写进 release notes 的开头两段，不靠版本号。
  1.0 要等三个条件，写进了 [project status](../project-status.md) 的 Release Version Rules（`04380be1`）：手机端随发版构建一起发；助理与主对话走完一整条 0.7.x 不再有破坏性改动；欠着的 Windows 冒烟清掉。
- **Release notes 四点按推荐**：
  - 降级那句先实测再留。v0.6.2 的 DMG 读升级后的库，启动时直接 panic 退出（`migration 43 was previously applied but is missing`），不弹窗；句子按实测改写，指向 `app.galley.backup.*`。
  - 用「订阅」，不用「套餐」。
  - 开头两段放在 What's New 之上。
  - 25 条不压。
- **GA 基线升到 `b70079d`**（`44eca66d`，[devlog](./2026-10-22-ga-upstream-upgrade-5205f40-to-b70079d.md)）。打标签前 `git ls-remote` 查过，上游 `main` 仍是它。
- **回归怎么跑**：
  - 主对话清单 18–40 在临时 HOME 起的第二个 dev 实例上跑，不进 JC 的主对话和试用统计。
  - 发版前必过 22 项，其余 45 项发版后、首次使用时再看。
  - B2a 由代理跑，B2b 免。
  - Mac 的升级路径在草稿出来后用临时 HOME 测；Windows 另开一个账户装 v0.6.2 走 H1。
- **提示词清单不通过的几条**：
  - 第 5 条改期望、不改提示词（`6417bd55`）：引擎的电脑操作 SOP 让「去聊天软件里看」成了真路径，Galley 自己仍不存 IM 聊天。
  - 第 10 条不挡发版，草稿出来后在打包版上复测（站点表 F8）。
  - 第 40 条改提示词（`d062c900`）：工作台里说「加一个待办」，模型把人指到顶栏的「待办」面板去发送，可面板没有输入框。工作台、子任务、IM 共用的那句改为写明顶栏的待办只是列出来；同一模型评测 0/3 → 3/3，主对话提示词逐字节不变。代理加的主对话哈希钉死测试合入前拿掉了：以后每次改功能地图都要跟着改，失败信息看不出改了什么，Windows 上的归一化也没验过。
  - 第 21、32 条算通过；第 28 条算瑕疵（多出一段建议、`--notes` 写了它自己的建议），和第 39 条一起进 F8 复测；第 24 条（问进度时读引擎日志）只记一笔。
- **E1 不等明早真跑。** 在 JC 库的快照副本上用真代码 `fire_review` 模拟 10-23 08:51：结果 `Skipped`，日志多一条 `skipped`；同一副本加一条明天到期的待办后判为要看，反向对照成立。到点调度走到 `fire_review` 这一段，10-22 09:00 已在真机上走过一次（`woke`、`delivered`）。JC：「那我觉得可以继续推进发版了，不用等明天了」。
- **发版早于 10-28 主动试用结束**：「取消或嫌吵过半就收紧门槛」那条结论只能进下一版（站点表约束 6）。
- **更新渠道**：stable，发布并冒烟后 promote。
