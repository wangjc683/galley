## 缘起

主对话打磨了两天（裁决 60–79：助手卡片、IM 画法、过程卡片、一行式输入框），JC 仍觉得定位和产品设计的核心「差那么一点东西」，
并想到它是 Supervisor SOP 的延伸：一个幕僚长、管家、副手、「教父边上的律师和军师」，替用户统管会话、项目、上下文和多任务进展，
开会话、写提示、验收、汇总，也记着日常提醒和事务；用户只需要像和真人在 IM 上聊天。JC 要一个扎实的核心理念，作为桌面、手机与之后 UI / UX 的地基。

## 诊断：前台与负责人

读码与查库后的判断：主对话的样子已经是一个「人」，角色还是前台，接话、做小事、把大活转出去就不管了。

- 派完就放手：入口层「its card shows the progress, and you can look it up when they ask」（`core/src/managed_prompt.rs:300-301`）；裁决 9 不注入汇报轮。
- 不碰配置：「What Only The User Changes In Galley」（`core/src/managed_prompt.rs:89`）。
- 记不住在办的事：账本撤了（裁决 49）。

JC 列的职责里它只做了开会话、写提示；缺的是派出去之后那一半：回来验收、给交代、记住答应过的事。

## 三条线索：不是新方向

1. **名字与宪法里就有**：README「为什么叫 Galley」是人在 GUI、Supervisor Agent 经 CLI 管团队、同一张桌子（`README.zh-CN.md:225`）；
   Product Shape「一个助手不够时扩成一支团队」（`AGENTS.md:15-16`）。
2. **Supervisor 没用起来是因为在门外**：到 10-06，`galley-im/*` 开的会话是 0，IM 里都是小事（`docs/devlog/2026-10-06-im-entry-layer-phone-first.md:10-12`）；
   要用户自己找 agent、复制 SOP，那时的活也小到用不着管理。
3. **JC 每天都在用这个形态**：他给 Claude Code 定的规矩（2–4 个选项加推荐、按建议推进就执行到底、结论带依据、别只声称已改、写动作先问、执行票派子代理、裁决进 devlog）
   读起来就是一份幕僚长授权书。

结论：不是给主对话加功能，而是请 Supervisor 进门、坐到主对话的位置上，两条线合成一条；SOP 变成助手自己的手册。

## 裁决（JC：「按你的建议次序推进」，六条都取推荐档）

1. **地基**：你只跟一个人说话；它替你带一支团队，事事给你交代。Galley 只造手（派活标签与 CLI）、账（库里的记录）、办公室（工作台）；底线是「不用管，但随时看得见、接得过来」。
2. **闭环**：子任务完成或提问时 Core 叫醒助手一轮，它对照派活说明验收、不够就打回、够了一两句告诉你；提问先到它，它答得了的替你答，钱、对外、不可逆的转给你。先例是 IM 汇报（`runner/im_reporter.py:3-6`）。
3. **三级授权**：自己做（做完说怎么撤）/ 先问 / 只能你来（凭证、运行环境、更新、重置）。依据：会话与项目的 CLI 写操作 10-06 就不在禁止之列（`docs/devlog/2026-10-06-runtime-prompt-self-description.md:50-51`），
   「配置只归用户」挡的是没有手时的假装完成（同文件 `:28-29`）。
4. **开口**：只在欠你一个交代时；不发主动建议；「提醒不必是闹钟」改由当场承诺来做。
5. **记事**：记录是做事的副产品；每段开头由 Core 从库里确定式地拼「在办的事」，不调模型，不另起记忆。
6. **一个人**：原则现在定，IM 并入排在桌面闭环之后，再和 iOS 排先后。

次序：闭环 → 承诺（提醒、「在办的事」）→ 授权补全（定时任务 CLI 等）→ 一个人。

## 反方（记下，不阻挡）

- 需求未证：`subtask_dispatches` 0 行，主对话重置后 5 句，工作台多是一到四句的生活查询。没活可派时它退化成今天的助手，不亏；第 1 步后量派活、打回与盯卡片的次数。
- 验收可能走过场：生活事务没测试可跑，派活说明要求交回证据，核不了就明说。
- 两个操作者撞车：助手只往自己派的会话里写。
- IM 在第 4 步前不是同一个它。

## 重量

粗估三千行上下（含测试），账本是一万行；宪法不用改；没有一次调用不是用户交代的事引起的；GA 没有管理用户看得见的会话这一层，是 Galley 自己 CLI 平台的延伸。
