# 主动的第一阶段：以待办为根，主动的是动作，不是建议

日期：2026-10-21
关联：[助手 PRD](../../.scratch/assistant/PRD.md) 裁决 10、[主聊天 PRD](../../.scratch/main-chat/PRD.md) 裁决 124、票 [73](../../.scratch/main-chat/issues/73-act-unasked-and-daily-review.md)、[74](../../.scratch/main-chat/issues/74-files-in-the-bubble-and-review-label.md)；
[助手带团队](./2026-10-15-assistant-runs-the-team.md)、[撤掉事项账本](./2026-10-13-drop-affairs-ledger.md)、[deferred](./deferred.md)「主动的第二阶段」「主对话先应一声、办完另起一条」

## 起因

JC 读了公众号「AI产品阿颖」的《很多人压根没看懂 Personal Agent。》，作者重度用了一个月 Today AI（接飞书、钉钉的个人助理）：「我一直想象中 Galley 主对话助理要像真人一样，要优化用户 IM 渠道，助理要主动办事，而不是像闹钟一样等用户设置和定时，这篇文章可以说很好说明我的意思。」

文章的 Aha：作者和同事在群里排查一个没上线产品的资源消耗，排查到一半说「先吃饭吧」，吃完饭打开手机，Today AI 已经推来一条：「我翻了你那份 9 月 20 日的《谷雨网站流量优化诊断》」，比对了最新数据，拆好主要消耗项和口径。作者从没给它布置过这件事。

## 主会话的读法

1. **四个案例只有一个是没人吩咐的**。另外三个（Banner、早鸟冲刺计划、讲师还没上官网先别放）都是作者开口布置的，好在不用交代背景；作者收尾落在「能把 Context 和记忆组织好，让用户不用反复交代背景」。唯一那次主动，前提是它读到了群聊和旧文档。
2. **「主动」拆成三件**：看得见（没对它说过的东西）、敢动手（自己判断做什么）、够得着你（推到手机）。Galley 这一个月补的是中间那件（助手 PRD 裁决 9 自己建提醒，主聊天 PRD 裁决 112 判断式跟进）；文章那次 Aha 靠的是另外两件，Galley 的助理两样都没有。
3. **地基一致**：文章的论点「用户都快成 AI 的项目经理了」就是助手 PRD「为什么是现在」那句，10-15 自己推到的；文章引的 Anthropic「交互式会话里约 80% 的时间在等人输入」是同一根据。
4. **ground truth**：10-16 到 10-21，JC 在主对话里说了 7 句，派出的子任务 0 件、叫醒 0 次；库里待办 1 条（702 装修）、定时任务 3 条（两条喝水的测试、一条 702），全是它建的。判断写得再好，没有输入也就没有可主动的事。
5. **和旧裁决的冲突要明说**：文章那种主动要在用户没开口时花 token。助手 PRD 裁决 4 定了「只在欠你一个交代时开口」、没选后台定期生成建议；主聊天 PRD 裁决 49 撤账本的理由之一是「后台每天替用户花 token」。主会话的看法：49 否掉的是每天无差别地整理用户说过的话，没有触发、产出也没人看；文章示范的是看到变化、判断值不值得说、多数时候不出声，两种花法可以分开裁。
6. **上游已有同形的原语**：GA 的反射模式轮询一个脚本的 `check()`，返回任务才 `put_task`（`managed-ga/code/agentmain.py:332-361`），`reflect/autonomous.py` 就是「用户离开 30 分钟，读自动化 SOP 执行任务」。Galley 不走反射模式，但叫醒（裁决 9）加不出声（裁决 8 的 `<no-reply/>`）已经是同一副骨架，缺的是眼睛和预算。

主会话给了四个选项：A 只改手册；B 给眼睛、先按需读；C 心跳；D 先把主动的消息送到手机（走 IM 渠道）。推荐 B → C，D 最后。

## 一处误读

JC 说的「优化用户 IM 渠道」，本意是「优化主对话的 IM 渠道体验」，即主对话像在 IM 里和一个真人聊（主聊天 PRD 裁决 60–110 那条线）。主会话读成了微信、飞书等渠道，第一轮里「IM 是眼还是嘴」的裁决点和选项 D 作废。按主对话的 IM 体验重新对截图，有两处不一样：

- **先应一声、办完另起一条**：Today AI 动手前先发「好，我把这份计划做成一份能在飞书里打开的精简标注版……」，办完另发「阿颖，文档建进飞书了……」。Galley 动手前那句进顶栏、被下一句替掉（裁决 107、110），两条消息的节奏只有派子任务时才有，而 10-16 以来一件没派过。
- **交出的东西本身就是一条消息**：HTML 文件、飞书文档、Banner 图各占一条。Galley 主对话回复里的 `[FILE:路径]` 被清掉，只有侧栏卡片写「[文件] 名字」（`gui/src/types/conversation.ts:270-276`）；库里主对话的回复一次也没带过这个标记，入口层没教过它。

## 裁决（JC：「1，主动的边界，可以接受；2，……第一阶段还是以待办功能为根基，让助理自己写下可以跟踪或扩展的事项，猜测用户可能会需要的协助」，随后对四件加 IM 两处：「按建议推进」）

1. **边界**：开口的条件加「它替你做成了一件事」；仍不发建议。后台只做不花 token 的确定式检查，有事才叫醒，每天有上限；不另起一套记忆照守。
2. **以待办为根**：第一阶段不接眼睛，料只来自主对话；清单的「Galley 在办」一栏由它自己长出来；以后接了眼睛，看到的也先落成待办，待办是所有眼睛的汇合处。代价：做得到「你提过一嘴的事它记着、往前推」，做不到「你没说过的事它也知道」。
3. **记什么**：裁决 112 的门槛第①条要「有日子」，加一类没日子的：用户在推进、有下一步、在意、这一轮办不完的事（「排查到一半，先吃饭吧」）。
4. **主动的是动作，不是建议**：能撤回、不花钱、不替你对外说话的准备直接做完再说；对外、花钱、不可逆的照三级授权先问，带着做好的准备问；什么都没做成就不开口，不说「要不要我帮你……」。理由：文章里打动人的几次都是做完才说；只给建议就是裁决 4 当初没选的主动建议卡片换了个地方；与三级授权直接对齐。
5. **何时想：记下时，加每天 9:00 巡看（B）**。叫醒前 Core 先看有没有没结束的事，没有就不叫醒；当天补跑、过了午夜不补；一次巡看最多派两件子任务；巡看是清单「例行」里一条 Galley 的事，说「别每天过了」它就停用，Galley 不建回来；它因巡看开口时话里带出「早上过了一遍在办的事」。没选：A 只在记下时想（记下之后没人回头看）；C 再加按事项状态触发（进 deferred）。
6. **不等 10-26**：裁决 112 的试用两天里它只自己建了 1 条，读出来说明不了什么，并进本次试用（到 10-28）。
7. **IM 体验**：交出的文件在对话里看得见，并进第一阶段（入口层教 `[FILE:路径]`，气泡下挂卡片）；先应一声进 deferred。
8. **打开白名单补文档格式**（票 74 回报后，JC：「按建议推进，并进 73」）：卡片上 PDF、Word、Excel 点了只能在文件夹中显示、HTML 只能看源码，根子在 Core 的「用默认应用打开」白名单（`core/src/local_file.rs:36-44`）。它为防脚本被执行而设，白名单写法把无害的文档也挡了。补 `pdf`、`docx`、`xlsx`、`pptx`、`pages`、`numbers`、`html`、`htm`；能带宏的老格式与 `*m` 格式不放，`key` 撞私钥文件扩展名也不放。卡片上的 HTML 用浏览器打开（交出的成品要看渲染）；回复正文里的 HTML 链接照旧进阅读面板看源码（工作台多是写代码），不能预览但在白名单里的改为直接打开。

9. **巡看要无感**（合入后 JC 问要不要让用户学习、配置，还是无感地主动工作；JC：「按建议推进，B」）：不学、不配、不宣布，面板那一条留着；开口去掉固定开头「早上过了一遍在办的事」，来源随话带出；门槛提到「做成了，而且你会想知道」。理由：配置会把它变回闹钟（裁决 9 的起因）；文章那次 Aha 没有先介绍自己，直接把结果推过来；毁掉惊喜的是隔三岔五一句没用的话。没选：维持固定开头；面板也隐藏（违背「看得见、接得过来」）。票 75。

## 被否与搁置

- **D 先接嘴**：嘴没东西可说（叫醒 0 次），而且是基于误读提的。主动消息到手机仍归 iOS App。
- **心跳看外部来源**（原 C）与眼睛（原 B）：JC 还没想好先接哪个来源，进 deferred「主动的第二阶段」，带启动信号。
- **巡看建成助理自己设的例行**（模型在第一次记事时 `schedule create --daily`）：靠模型记得去建、容易建重，且撞上「每天花钱的定时任务先问」；改为 Core 种一条，幂等，停用后不建回来。
- **第一次巡看开口时说明一次**：哪次算「第一次」要么靠模型猜、要么要 Core 多数一样东西；改成每次因巡看开口都在话里带出来源，一句话的成本。

## 真机第一轮（10-21 晚，10-22 派票）

JC 走查票 75 第 2 步（「把早上那个巡看现在跑一次」），看到两处错。模型这一轮做得对：只派了一件子任务，以 `<no-reply/>` 收尾。

1. **跑完后三步被平铺进主对话**（JC：「巡看触发后开始显示进度调用轮次，而不是在顶栏」）。票 73 让模型在只派子任务时写 `<subtask>` 加 `<no-reply/>`，界面判静默时却排除带 `<subtask>` 的回复（10-16 票 29/31 定的：「派了活的，卡片必须显示」）。剥完标签没有正文，这一轮既没答完也不静默，跑完退回工作台样式平铺。漏在票 73：改了手册和 Core 叫醒措辞这一边，没查界面怎么判这种写法；评测只判模型的文字，8/8 全过也抓不到。裁决 A：叫醒轮里只派了子任务就什么都不画，子任务只在面板「Galley 在办」里出现。没选 B 只画那张卡：等于半个通知。票 76。
2. **答过的 NBA 被当成没答**（JC：「主对话前面关于 NBA 的问题我明明都已经有收到回复」）。新段带过去的三轮按 `turn_index` 配对，一次运行每一步占一个号，多步回答的答案没有同号的用户行，被当成不完整丢掉；带过去的只剩「我先查一下西部阵容」「东部我先核对」两句，模型逐字照此判断「此前两次只说会查，没有交付」。这是票 11（10-13）起就有的错，一步答完的闲聊带得过去，所以一直没被发现；票 73 让它会主动动手，记错才变成派子任务重做。每天早上的巡看几乎总是新段的第一轮（10-22 09:00 那次又误判一回「尚未汇总」），天天会碰上。改成一轮是一句用户行加到下一句之前的全部回复，上限按新配对重量。票 77。

两处都在主聊天 PRD 裁决 125。
