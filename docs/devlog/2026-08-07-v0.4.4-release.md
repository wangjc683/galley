# v0.4.4 发布：ask_user 可达性、滚动双态信号与两处视觉回归修复

**日期**：2026-08-07
**范围**：v0.4.4 发布叙事，聚合 `v0.4.3..HEAD`（13 个提交，其中 8 个代码）

## 背景

`v0.4.3`（2026-08-06）之后一天内累积的全部是既有会话面上的增量增强与
修复，没有新产品线。本条只记**为什么现在打包成 `v0.4.4`**、聚合了哪些
线，以及发布点的 gate 状态。各线的设计推演有独立 provenance，不在此
复述。

发版的直接触发不是「攒够了」，而是 `v0.4.3` 自己引入了一个视觉回归：
08-05 的 chrome 加深让 sidebar 的 `--color-hover` 反比底色更亮，hover
反馈在 0.4.3 上是失明的。装了 0.4.3 的用户当前就在受影响。

## 版本决策：patch

沿用 `v0.4.1` 确立、`v0.4.2` / `v0.4.3` 复认的定级规则（按单个功能
量级判，minor 要求够一条独立产品线；按最大单功能判，不按批次总量判）。
本批全部是既有面上的增量增强与回归修复，无一够 minor 量级。

产品形态、Agent API schema（`schemaVersion: 1`）、GA baseline
（`d8d90ee` 不变）、更新渠道策略均不变。本批**零 Rust 改动**，
managed GA 未触碰。

## 聚合的线

| 线 | 性质 | provenance |
|---|---|---|
| ask_user 三连：pending 期回显去重、「等你回答」通知、重启后 pending 恢复 | 可达性修复 | [ask_user UX polish](./2026-08-06-ask-user-ux-polish.md) |
| 折叠头 scent：按次数降序、提问计数移出截断区、溢出 tooltip | 增强 | 同上 |

| Sidebar hover 失明修复（`.chrome-hover-scope` 作用域覆写） | **v0.4.3 回归** | [hover 重调](./2026-08-07-sidebar-chrome-hover-retune.md) |
| Overlay 尺寸阶梯 920 档定型 + GA 兜底摘要脏数据双端清洗 | 增强 + 数据修复 | [920 档 + 摘要清洗](./2026-08-07-overlay-920-tier-and-session-recaps.md) |
| 推理强度：默认语义可读、第一方预设显式 high、Models 行档位徽章 | 增强 | [推理强度](./2026-08-07-reasoning-effort-default-and-badge.md) |

其中 ask_user 那条是本批里最贴 Galley 定位的修复：agent 卡在提问上而
操作者不知道，编排台就退化成了要人守着的终端。通知 + 重启后 pending
复活合起来才闭环——只有通知，重启一次线索就丢了。

摘要清洗是唯一跨 runner / GUI 双端的改动（`_clean_turn_summary` /
`cleanSessionSummary` 互为镜像），因此本批 `runner/` 有测试增量。

## Next

标准 release SOP：tag/push → `release.yml` 出 draft → JC 装机 smoke
（macOS + Win11；本次重点：sidebar hover 在真机上的可见性、ask_user
通知与重启后 pending 复活、置底按钮双态在长会话里的信号准确度、
Models 页推理强度徽章）→ publish → promote stable channel → 验证 live
manifest → 回填 project-status。

应用内更新通路 dogfood（SOP step 10）的欠账已收窄：JC 在 `v0.4.3`
发布后实测过 `v0.4.2 → v0.4.3` 升级，**通过**（2026-08-06 前后，事后
补报，project-status 当时未回填）。仍无记录的只剩 `v0.4.1 → v0.4.2`
那次。本次从装机的 `v0.4.3` 更到 `v0.4.4` 会再实测一遍。

这里的实际教训不在更新通路本身，而在**回填时机**：smoke 结果由 JC
在 GUI 外完成，不经过 agent 的工具调用，所以除非当场说，就不会进
project-status——两次 carry over 里至少一次是这个原因，不是真没做。
release SOP step 9 回填时应显式问一句 step 10 的结果，而不是默认
「没听说 = 没做」。
