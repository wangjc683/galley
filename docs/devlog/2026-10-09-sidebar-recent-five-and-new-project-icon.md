## 起因

JC 问：项目多了，是不是只显示最近活跃的一部分、其余折起来；一个项目展开后也一样，只显示最近几条。

两层其实都已经有上限，只是按时间：分区只列 30 天内活跃 / 置顶 / 新建的项目，组内平铺 30 天内的会话、更早的进尾行。
本机数据：项目 1 个（CLI 回归建的，19 条）；Supervisor 建了 20 个会话，一个都没进项目——SOP 的「拆成项目」那条路 JC
实际还没用过。05-13 做过一模一样的项目数量上限（≤ 8 全显示，≥ 9 显示前 8 个 +「查看全部」→ 项目对话框），05-22 嫌它
「有上限、扩不上去」换成 Project Review；当时项目也少，算不上测过之后被否。

## 组内只显示最近 5 条（X）

我先判组内这一层没必要：展开是用户自己点的、不跨重启，长列表是用户要看的。JC 给了场景：**同时开着三个项目，每个都有
会话在推进，要一轮轮查看和继续；历史会话多时找不到那三条，小屏更难。**这推翻了我的判断——我假设「展开 = 想看全部」，
场景里展开是「把这个项目正在推进的那条放在眼前」；而 10-08 删项目视图时，「同时盯几个项目」的替代方案本来就是「同时
展开几个组」，组一长这个承诺就破了。

卡在哪：组内按最近活动排序，活跃的那条就在每组第一行，难的是组与组之间——三组各 15 条时第二、三条活跃会话在第 17、33
行左右，小屏一屏约 14 行。收起也不行：一轮跑完是「未读」、看过是「空闲」，都不挂出。

- **X（JC 定）**：展开后只显示最近 K 条，其余进尾行，就是把尾行的分界从「30 天」改成「第 K 条之后」，组里仍只有一处折叠。
  我上一轮说数量上限会打破时间分组的意思，是夸大：组内不分时间组，没有时间标签可破。K = 3 时三组约 690px，K = 5 时约
  980px（第三条活跃会话在约 680px，贴着小屏底边）。**JC 取 5。**
- 被否：Y，收起时也挂出每组「今天最近活跃的一条」（三组收起约 320px）——改变了「收起只露需要你处理的」的意思，Supervisor
  拆出 4 个并行会话时挂几条要另定，与 X 二选一；跨项目的「进行中」区块（设计文档「去掉 ACTIVE / WAITING FOR YOU 区块」）。
- 项目数量上限仍进 deferred 不做：活跃项目按活动排序本来就在最前。

连带一条：尾行分界改成第 5 条之后，最近几天的会话也会进尾行，所以展开且尾行收着时，尾行里出错 / 等你回复的会话与选中的
一起借位挂在尾行上方（此前只借位选中的）——「需要你处理的永远不藏」。

## 书眉第三个图标改为新建项目（A）

JC 问：书眉「项目」打开的项目列表和分区展开后的列表重复，是不是直接改成「新建项目」。

菜单做三件事：新建项目（看得见的入口只有这里：分区头不放 `+`，零项目时分区不出现）；列出全部项目（与分区重复，独有的是
30 天窗口外的项目——⌘K 只有「新建项目」不列项目，「移到项目」子菜单是移会话）；点项目 = 在里面新建对话并展开组（分区里
组行 `+` 是同一件事）。重复是真的，菜单不可替代的价值全在「沉下去的项目」上。

我的意见：同意，但只改按钮不够——那些项目会失去唯一入口。方案 A：按钮直接新建项目，分区末尾加「其他项目 N」就地展开。
理由：顶上放动作、列表放对象，与「新对话在顶上、会话在列表里」同构；零项目用户点开菜单只有「新建项目」+「还没有项目」，
多一次无意义的点击。代价：最低频的动作占常驻位置（「降级不藏」本就是给低频入口的）；窄宽时与「+ 新对话」挨着。被否：
只改按钮（沉下去的项目置顶 / 编辑 / 删除都没入口）、保留菜单、去掉书眉按钮把 `+` 放分区头（分区头右侧是计数；零项目时
项目功能没有入口）。「其他项目」这一行顺带是将来项目数量上限的溢出行。

真机切换器两档：「新建 + 其他项目」/「菜单（现状）」。JC 定 A。

## 实现

- `gui/src/lib/sidebar-timeline.ts`：`PROJECT_GROUP_RECENT_COUNT = 5`，组会话 = 窗口内 + 更早的拼起来取前 5，其余进
  `olderSessions`；分区外的项目进 `otherProjects`（同序、同样取前 5），它们的会话进 `groupedSessionIds`，「更早」入口不再
  借位挂它们；`findSectionsSlot` 一并查。
- `SidebarProjectGroup.tsx`：尾行收着时借位挂需要你的 + 选中的；尾行按钮抽成 `SidebarTailToggle`（标签由调用方给），
  「其他项目」复用。
- `SidebarTimeline.tsx`：分区末尾「其他项目」、收着时的挂出、分区折叠时一并挂出；分区头数字为 0 时不显示。
  `Sidebar.tsx`：「其他项目」展开状态（本次运行），揭示请求指向其中的项目时先展开它。
- 书眉 / 新对话行第三个图标：`FolderPlus` 按钮。删除 `SidebarProjectsMenu.tsx`、`useProjectNavigation` 的 `openProject`
  及一路透传的 `projects` / `onOpenProject` props；切换器（临时 zustand store + 右下角 pill）裁决后删除。
- 纯 GUI，Core / CLI / Agent API 零变化，外置 / 内置两种运行时一致。

**测试的坑**：组件测试用 `renderToStaticMarkup`，zustand 在服务端渲染下读的是初始状态，`setState` 塞进 runtime store 的
出错状态读不到；改用 `vi.mock` 包一层 `useSessionsAttention`，在真结果上追加需要你处理的 id。

**测试数据**：用 CLI 临时建「测试 · 近期 A / B」（各 8 条 7～30 天前的会话）与「测试 · 沉底」（5 条 30 天前的会话；移会话
只改 `project_id` 与 `updated_at`，不改最后活动时间，`core/src/db/session.rs:925`），裁决后 `galley project delete` 删除，
会话原样回到时间分组。「近期 B」界面显示 7 条、库里 8 条：其中 1 条是外置模式会话，侧栏只显示当前运行时的会话
（`applyExternalSessionUpdated`），不是 bug——拿库算侧栏数字要按 `ga_runtime_kind` 过滤（10-08 devlog 的「本月 36」因此
更正为 34）。
