## 裁决（JC 全部按推荐）

- **D1 按持久化的验证标记分页（A）**。页面分支此前只看 `status`：验证过的用户一遇到常驻桥报错（端口被占、服务没起来）或桥
  重启（约 1 秒的 `unknown`），整页换成「打开扩展页 → 拖入文件夹 → 测试连接」三步，错误原文挤在第 3 步按钮下。设计文档写的
  其实是「结构按验证状态二分」，只是括号里把 `unknown` / `error` 列成了「未验证」——10-04 常驻桥之前 error 只来自探测。现在
  验证过就始终是状态卡 + 维护行 + 修复折叠卡：桥错误是红卡（顶栏的 `errorKind` 分组标题 + 原文 +「正在自动重试。」，与顶栏
  菜单共用 `browserControlErrorRetries`），`unknown` 是 spinner +「正在连接浏览器控制服务…」。被否：B 指引卡上方加一张红卡。
- **D2 等待网页两态分开（A）**。offline 与 connected_no_tabs 此前一字不差（「等待网页 / 打开测试页后，点击重新检测。」），
  该做的事完全不同；10-04 之后状态是实时的，「点击重新检测」当天就记过过时；「重新检测」在 offline 下转满 35 秒、页面不变。
  现在两态与顶栏同口径各说各的，删掉「重新检测」和两个裸「Chrome」「Edge」测试页按钮（06-10 保留它们的理由正是那句旧副文案），
  等待网页态没有 primary（改写 07-05「未连接时唯一 primary 是测试连接 / 重新检测」的后半）。被否：B 留两个按钮、C 只改文案。
- **D3 其他 Chromium 浏览器（B）**。只能选 Chrome / Edge，macOS 按 bundle id 打开：JC 的 Mac 上 Chrome 装了但没装插件，点了会
  拉起错的浏览器；没装 Edge，点了报错。05-27 要求「文案要提到其他 Chromium 可手动加载」，一直没做。现在选择器加「其他」：
  第 1 步写在地址栏输入 `chrome://extensions`（mono 地址 + 复制），第 3 步不给「打开测试页」（Core 只开 Chrome / Edge）。被否：
  A 只加一行提示（旁边仍是两个开错浏览器的按钮）、C Core 探测本机装了哪些浏览器。06-02 否决的「默认浏览器」没碰。
- **D4 修复入口换成折叠卡（A）**。已连接时叫「重新加载插件」（读作 Chrome 扩展卡上的 ↻，点了却只展开安装步骤），未连接时叫
  「重新安装或修复插件」，展开后叫「收起」，与「遇到问题？」展开后的「收起」同屏两个；两个开关都不在 10-07 定的两种折叠里。
  现在是维护行下方的 `SettingsDisclosureCard`，头部固定「重新安装或修复插件」；「遇到问题？」展开不换标签。审计顺带查出：
  插件文件夹每次启动都重建，但浏览器里跑的插件代码要用户重新加载才更新，桥也不报插件版本——修复卡第 2 步补一句「已经装过的：
  Galley 更新后，在扩展页找到 Galley Browser Bridge，点 ↻ 重新加载。」（「重新加载插件」这个旧名也许本来就想说这件事）。被否：
  B 不补那句、进 deferred。
- **D5 结果文案由 GUI 按 `kind` 写（A）**。探测结果、常驻桥错误、store 兜底约 19 句写死的中文会进英文 UI；中文 UI 反过来，探测
  异常时第 3 步只有一行英文异常。Core 探测结果加 `kind`（`connected` / `no_tabs` / `not_connected` / `script_failed` / `no_result` /
  `exception`）与 `detail`（只给失败类带技术原文），只加字段、`message` 保留给日志；GUI 按 `kind` 出本地化标题、`detail` 另起一行；
  store 不再写中文兜底，`error` 只存原文。桥错误原文（中文句子）不动，仍是明细行（守 10-04「保留桥原文」），正文字体显示，技术原文
  才用 mono。被否：B 只在 GUI 侧对英文 UI 隐藏中文、C 进 deferred。
- **D6 插件没连上时不空等 35 秒（A）**。手动「测试连接」在常驻桥正在运行、且桥没看见插件时不起探测进程，直接显示「还没检测到
  插件，装好后会自动连上。」。browser-control.md 要求「不要把探测窗口缩回几秒，除非插件有同等的立即唤醒路径」——常驻桥就是
  那条路径，手动探测和桥等的是同一次重连。桥不在 running 时照旧探测。被否：B 照旧探测、忙碌文案写「最多约 35 秒」。
- **D7 「新建测试对话」不动（A）**。它是 accent-secondary 不是 primary；设置页没有 toast 那样的上下文，保留说清「会新建对话」的
  名字，toast 里的「试一试」也保留。英文 demo 从百度换成 Bing（05-27 只要求中文 UI 用百度）。被否：B 降为 ghost、C 用过浏览器
  工具后隐藏。

## 直接收口

  错误原文，顶栏 error 明细会暂时变空——票 1 改为入口不清、await 后按当时状态判断（入口记旧值的写法在并发同步一败一成时会把

  「再点测试连接」（主会话集成时补的 `stepTestHintRepair`：票 2 报告修复模式的提示还指着一个不存在的按钮）。

## 两种运行模式与首装

整页只在内置模式出现；Core 的探测命令只被 GUI 内置分支调用。两种模式共用的只有 `switchRuntimeKind` 多收一条 toast：外置模式少
一个误触面（切到外置后点「试一试」会对外部 GA 发 demo），内置零变化。首装没有浏览器步骤，零影响。
