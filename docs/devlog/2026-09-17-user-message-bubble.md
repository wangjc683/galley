# 用户消息改为杏沙气泡：把「经典气泡」拆成零件后只有投影是硬冲突

日期：2026-09-17
状态：已落定。`MessageUser` 从逐行高亮笔触改为左对齐平涂气泡（`rounded-md`
12px，`bg-brand-tint`，无边框无投影），委派标记不动。
相关：翻转 [高亮笔重设计](./2026-08-06-user-message-highlighter.md) 的形态裁决，
继承 [质感实验](./2026-08-21-user-message-texture-experiment.md) 的「不给抬升」
论证；foundations §1 与 §1.2 的「不借用 message 气泡」改为「不借用双侧 /
右对齐气泡」。

## 起因

JC：「我现在又有点倾向于探索最经典、最符合用户心智和预期的气泡设计。但这个
设计要怎么跟我们的整体风格和 Design 哲学相契合、相融合、相统一？」

先读现状再发言。DESIGN 里对气泡的否定有三处：foundations §1「不是 chat
气泡 IM」、§1.2 Claude.ai 行「不借用 message 气泡」、conversation §4.3
「不要 right-align 不要气泡——这是文档区，不是聊天 IM」。08-21 还专门写过
「圆角上限 `--radius-sm`，再大就进 chip 语汇，等于把 chat bubble 从后门放
回来」。这是一条明文规则，翻它要有据。

## 为什么有据重开

1. **「死板 / 硬 / 平」出现了三次**（08-05、08-06、08-21），两轮实验后仍没
   落地。高亮笔的隐喻漂亮，但三次没治好，说明治的不是病根。
2. **气泡本身从未被真机测过**。08-06 测的是 slab vs 纯排印 vs 高亮笔，08-21
   测的是高亮笔加 4/6px 圆角——那仍是 5px 纵向 padding 的笔触，不是容器。
3. **高亮笔有两个实打实的功能缺口**，08-06 自己承认「略读时的边界感知是
   slab 移除后唯一真缺口」；粘贴内容带空行时空行不上色，一条消息碎成几截。
4. **我们的设计源头之一 Claude.ai 今天就是「圆角平涂容器 + 助手散文」**。
   foundations 那格「不借用 message 气泡」写的时候针对的是 IM 式双侧气泡；
   而「用户在容器里、助手是散文」恰恰是 JC 说的那个用户心智，Claude.ai /
   ChatGPT / Codex app 全是这个形态。高亮笔在同类产品里才是异类。

## 拆零件：只有一个零件真的冲突

| 零件 | IM 经典值 | 与哲学冲突吗 | 结论 |
|---|---|---|---|
| 圆角容器 + 内边距 | 有 | 否。Notion callout、ToolCallout 都是内容层里的圆角盒子 | 采纳 |
| 平涂填色 | 灰 | 否 | 采纳，但用杏沙不用灰——灰会和 code-surface 混，杏沙延续「人的声音是暖色」 |
| 无边框无投影 | 通常无 | **投影是唯一硬冲突**，08-21「chrome 是材质、content 是纸」仍成立 | 坚决不加，这一条守住它就是 callout 不是卡片 |
| 右对齐 | 有 | 真正的分歧点：IM 最强的身份信号，也是唯一打破「一份文档一个阅读左缘」的零件 | 进切换器裁决 |
| 小尾巴 | 有 | 纯 IM 装饰 | 不要 |

融合方案一句话：**Notion callout 的盒子语法，穿杏沙，不浮起，左缘跟散文栏。**
08-06 的 A/B 结论「色彩面积是滚动回找真正依赖的信号」反而更成立，容器的
色域比逐行笔触只多不少。

## 切换器与裁决

MessageUser 内临时两维切换器（⌥V 形态 A 高亮笔 / B 左气泡 / C 右气泡，⌥R
圆角 12 / 16，右上角常驻 pill，localStorage 记忆），代码与 pill 测完全拆。

JC 要我先给自己的推荐再给裁决。我推 **B 左气泡、12px**，排序 B > A > C：

- **B**：唯一同时满足「用户心智里的经典形态」和「一份文档一个阅读左缘」的。
- **12 不选 16**：单行短消息高约 45px，16 已近半高，「好」「继续」会变成
  一颗药丸进 chip 语汇；12 与 ToolCallout 同档，机器与人同样圆润，08-06
  「机器圆润、人方正」的倒挂反向解除。
- **A 排第二而不是 C**：右对齐是最强的 IM 信号，也是唯一破坏阅读左缘的零件；
  760px 栏里用户的话靠右、Composer 满宽左起、agent 散文左起，眼睛要两边跳，
  且气泡右缘紧挨 Question Rail 的点。它经典，但经典的是 IM。A 三次没治好
  「硬」，至少没有结构性代价。
- 我事先声明这是推理不是观感，最可能翻车的是 B 的文字左缘比 agent 散文
  缩进 14px；若刺眼改推「容器向左出头、文字仍贴栏」的 B 变体而不是退回 A。

**JC 裁决：B 左气泡、圆角 12。** 与推荐一致。

## 定案

- `MessageUser`：`w-fit max-w-full rounded-md bg-brand-tint px-3.5 py-2.5`，
  `{content}` 直接渲染（`whitespace-pre-wrap break-words` 不变），
  `HighlightedLines` 与偏移 box-shadow 出头一起删除。
- copy chip `ml-3 → ml-1.5`：气泡的绘制边就是布局边，6px 是真 6px；08-10
  修过的 `ml-1.5` 被出头吃成 2px 的问题随出头消失。
- 折叠、附件、`data-role` / submit 置顶 / Rail 全部不动。
- `GoalCommissionMarker` **不跟**：竖条 + 硬角色板的加冠正装保留，「平民 =
  圆角平涂、加冠 = 带竖条的硬角」的对比继续承担 Goal 委派辨识；昨天
  armed 态 Composer 也穿这套正装，链条一致。真机若混淆，调节旋钮是加冠行的
  eyebrow 与竖条，不动普通消息。

## 承认的代价

- **翻转一条明文规则**。foundations §1 改为「不是双侧气泡的 chat IM」并加括注，
  §1.2 Claude.ai 行「借用」列加「用户消息的单侧平涂容器」、「不借用」列改
  「双侧 / 右对齐气泡」；conversation §4.3 三重区分表与「高亮笔」节整节重写。
- **辨识度**。高亮笔是 Galley 少数一眼可认的笔触，气泡是所有人的默认。
  我的判断：用户一天回看几十次的东西不是该「别致」的地方；这是 JC 的价值
  判断，他选了经典。
- **文字左缘不再与 agent 散文对齐**（缩进 14px）。这是高亮笔时代靠出头方案
  换来的性质，随笔触退出。

## 连带清理

- deferred「落笔」入场动效**作废**——隐喻「被划过的句子」不再成立；若日后
  补入场动效，从「块级软淡入与 agent 侧对称」重起。其后续「排印微调」拆成
  独立条目（明确不与形态捆绑，且必须作为 2026-06-20 排印统一的重审来做）。
- deferred「brand-tint dark 响度」：先补记「气泡色域更大会放大问题」，同日随后记了结、条目删除。
- deferred「copy chip 锚点」补记：「块右边缘已不是视觉对象」的论点随容器
  形态回归而失效，只剩 `top-1.5` 锚第一行那条。
- overlays-and-settings 的 locate 高亮措辞「笔触上」→「气泡底上」。
- `GoalRunMarkers` 头注释与 objective 框注释更新；globals.css 里
  「user-message band」的注释仍准确，未动。

## 方法

- **把「经典 X」拆成零件再对哲学**，比整体接受或整体拒绝都有效：五个零件
  只有一个硬冲突，而那个零件（投影）恰好不是 JC 想要的。
- **翻旧裁决前先查旧实验测过什么**：08-06 与 08-21 都没测过真正的容器，所以
  「气泡被否过」是错觉——被否的是 slab 和大圆角笔触。
- **先给推荐再收裁决**是 JC 这次的要求，推荐要连同「我没看真机」和「最可能
  翻车在哪」一起给，否则一致只是巧合。

## 后记：dark 的 `brand-tint` 收响度（同日）

JC 真机看过 light 后说舒服，唯一想再动的是 dark：「棕色背景色和黑色背景稍微
有一点不太协调」。这正是 08-21 挂进 deferred 的那笔账——dark 的 `brand-tint`
自 08-06 定值起从未单独校过响度，07-25 给 dark 地面去暖 0.6× 时还明确写着
「brand 系列先对着更安静的地面评估响度」，而这一步没做过。

先算再提案（OKLCH）：

| | light | dark（旧 `#4d3b2b`） |
|---|---|---|
| 气泡相对画布 ΔL | −7.1 | **+16.5** |
| 气泡彩度 C | 0.030 | **0.036** |
| 画布彩度 C | 0.002 | 0.006 |
| 相对 elevated | 更暗 | **亮 10.8** |

三件事叠加：明度步长是 light 的 2.3 倍；彩度反而比 light 高，而暖色在低明度
上发泥是 07-25 自己写下的理由；它跳出了 elevation 阶梯（hover 27、elevated
26、气泡 36.7），一块内容层平涂亮过 chrome 最高层，读作发光面板贴在黑底上。
对照 ChatGPT / Claude.ai 的 dark 用户气泡（凭印象取值）步长 +4 到 +6、彩度
近零。

两个旋钮都往下收：ΔL 收到 +10（暗底上填色感知衰减，取 light 的 1.4 倍），
C 收到 0.020（light 的三分之二，与去暖地面同一逻辑），色相 63 不动。给了四个
候选（+8/0.020、**+10/0.020**、+10/0.028、+12/0.036 作「只降亮不降彩」的
对照组），推荐 `#362d24`，JC 裁「直接落推荐值，真机看」。ink 对比度 11:1。

连带：Goal 委派标记与 armed Composer 同穿此 token，一起变安静（同一件衣服，
是好事）；侧栏 dark 的 `--color-selected` override 曾与 brand-tint 同值，注释
早已写明「巧合不是绑定」，本次 brand-tint 动了它没动，恰是那条注释的实证；
全文搜索的 locate 高亮盖在更暗的气泡上只会更清楚。deferred 该条目删除，
foundations dark 色板表与 globals.css 注释同步。若真机仍觉得棕，下一个动的是
彩度（试 +8/0.020），不是亮度。
