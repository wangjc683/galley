# 新应用图标与助手头像：一张母图，两种裁切

日期：2026-10-15
关联：[主聊天 PRD](../../.scratch/main-chat/PRD.md)（裁决 70）、票 [23](../../.scratch/main-chat/issues/23-galley-icon-and-avatar.md)、
[layout-and-chrome.md](../design/layout-and-chrome.md)「助手卡片」、`core/icons/master/README.md`

## 起因

JC：「现在主对话卡片的头像，圆形头像和我们整个软件的图标，其实是完全不一样的。你觉得如果这两个是一样的，是不是更合理呢？我也没想好，听听你的独立意见。」

侧栏助手卡片的头像是杏色圆盘上一个 Newsreader 斜体「G」，代码注释写着「until it has a real likeness」，裁决 65 也把「助手的形象」留作另议，本来就是占位。

## 讨论：一样，而且就用应用图标

主会话的论证：助手叫 Galley，和应用同名；它不在眼前时靠系统通知找你，macOS 通知左边只能是应用图标（平台决定），Dock 也是，同名就该同脸。ChatGPT、Claude 的助手头像就是产品标志；IM 里以产品身份说话的账号（微信团队、Telegram 官方通知）头像也是应用图标。杏色圆盘斜体 G 像应用图标却又不是，两头不靠。

把现图标按头像尺寸放到侧栏四种底上预览后，发现三个问题：28px 下右边的夹块糊掉；浅木色底在浅色侧栏上几乎没有边界；`icon.icns` 画满 1024 画布，在 Dock 里比按苹果网格留边的应用大一圈。

JC 随后点出原图标的构思：「一个木质机器人吐出一个很长的舌头，形成一个字母 G 的感觉」。顶板是头、两颗铆钉是眼睛、深色方块是嘴、右边竖条是下巴，舌头绕一圈成 G。这样图标本身就是一个有脸的角色，天然适合当头像；问题只是脸太小（512 原图里眼睛约 12px，28px 头像里不到 1px）。

## 过程

- **方向草稿**：主会话先用 SVG 画了四个结构方向（铅字块、排版盘、木 G 扁平、品牌斜体 G）在头像尺寸下比，JC 选择保留原构思，不换方向。
- **Codex 第 1 版**：主会话用本机的 Codex CLI 生图，给它原图和一张比例草稿，要求头放大约 1.3 倍、铆钉换成圆眼睛、嘴更大、铺满方形、内容收进中心圆、底色深一档。脸在 28px 下认得出了，但 JC 发现颜色和原图差得多：主会话写的「深一档」没给数值，Codex 把底色从 L* 90 降到 65、饱和度翻倍，读作橙色樱桃木。
- **第 2 版**：颜色改回原图，浅色侧栏上的边界交给界面加 1px 内描边，不改图标本身。去掉第 1 版嘴里一根多余的斜线。
- **扁平化**：JC：「整体感觉不错，不过我想试试能不能更现代简约偏平一点，现在放小了看元素稍微有一点点繁琐」。繁琐来自木纹、凹槽与倒角阴影（粗描边里又一圈暗边）、头部几块拼接的分缝。Codex 并行出 F1（扁平加统一描边、头合成一块）与 F2（纯色块无描边）；F2 在 20px 最醒目，但头和舌头同色、机器人的角色感淡了。主会话推荐 F1，JC：「我也喜欢F1」。
- **矢量化走了一次弯路**：主会话先按量得的尺寸用 shapely 做几何重建（正圆环、等宽笔画、规整圆角）。JC 先指出上颚下面「明显笔画不干净」（内圈弧线比嘴底多凹约 6px，留下一截被齐刀切断的月牙），修完又指出「v12 和 F1 Codex 位图还是明显不一样，F1 更舒服」。根因是重建把 F1 手绘字形的粗细变化、蛋形、更平的底部全抹平了：重建版与 F1 有 23,223 像素不一致。改为把 F1 放大 4 倍、平滑、按底 / 木 / 墨三色分层后用 potrace 描摹，与 F1 只差边缘抗锯齿（滤掉 3px 后成片差异 0），JC：「没问题了，推进」。

## 裁决（70）

头像就是应用图标；图标改成扁平版（F1 的描摹矢量）；一张母图，应用图标切成圆角方形（macOS 按苹果网格），头像切成圆加 1px 内描边；随下一个版本发，托盘图标不动。

## 实现（票 23）

子代理在独立 worktree 里做（xhigh），五个提交 `dba700ef`、`e332b667`、`75436b33`、`01eb93ee`、`450b08c9`，主会话审过后用合并提交合入（分支开出后 main 只多了票 24 的规划，没有重叠文件；合并而不变基，票里引用的提交号仍有效）。

- **母图**在 `core/icons/master/`：`galley-icon.svg` 是母图，`app-icon-rounded.svg`、`app-icon-macos.svg` 两个裁切文件用 `<image href>` 引用它；`scripts/trace-galley-icon.py` 从位图重描（对源位图重跑逐字节一致），`scripts/render-app-icons.py` 经 Tauri CLI 的 resvg 出全部尺寸，重跑逐字节一致。以后改几何：让图片模型改位图，再重描。
- **macOS**：1024 画布里 824 居中、连续曲率圆角（近似 Figma corner smoothing 60%）、半径 185.4，投影黑 50%、向下 12、模糊 28；icns 的 1024 成员不透明区正好 100–924。参数来自 Apple 开发者论坛对官方模板的转述，苹果没有公开数值。
- **Windows / Linux** 照今天画满方框，圆角取 23%（旧图量得 235.8 / 1024）；iOS、Android 两套用新图重生成（原来是 05-18 的旧排版盘铅字图，05-22 换桌面图标时没跟着重生成）。删掉了 `core/app-icon.png`：它是旧木纹图的源图，正好在 `tauri icon` 不带参数时的默认输入路径上，留着一跑就生成回旧图标。
- **头像**：`AssistantAvatar` 用母图 SVG（有测试保证与母图逐字节相同），`<img>` 裁成圆，上面叠一层 1px 内阴影作描边，新 token `--color-avatar-ring`（浅黑 12%、深白 10%）。描边没画进 SVG：`<img>` 里的 SVG 读不到界面主题。重算的亮度：图标浅底 L* 89.0，侧栏静止 94.1、悬停 90.3、选中 87.0。
- **README**：`docs/assets/galley-icon.png` 换新，横幅与社交预览重新生成。
- 验证：两个时区的全量测试（128 个文件、1257 条）、`cargo check --workspace`；反向检查 10 处全挂；外置运行时逐像素 0 差，工作台、子任务与助手对话只差在头像框内。

子代理报的另外几件：Linux 托盘用的就是 `icons/32x32.png`（`core/src/tray.rs:193`），会跟着变，macOS 与 Windows 托盘是单独的图；tauri dev 的 Dock 取的就是 `icon.icns`，重启 dev 后应能看到新图；Android 前景照 Tauri 默认是整张母图，四边约 2% 会被系统遮罩切到。
