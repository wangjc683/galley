# 待办重做：Galley 的记事本，哪条对话旁边都能看

日期：2026-10-16 晚 — 2026-10-17
关联：[主聊天 PRD](../../.scratch/main-chat/PRD.md) 裁决 90–98，票 [39](../../.scratch/main-chat/issues/39-todo-core.md)–[46](../../.scratch/main-chat/issues/46-todo-panel-everywhere.md)；接 10-16 的裁决 84、86（定时任务加「一次性」与「叫醒助理」，票 33–37，迁移 049）

## 起因

裁决 86 把侧栏顶上原来 ◷ 的位置改成「待办」，打开的是定时任务列表。JC 真机：「我现在觉得这个按钮入口可能还是太弱了……这是一个对于主对话助理来说非常非常重要的一个功能，集待办事项，定时任务，主动提醒……打开后的 dialog 也比较弱，我想象中可能类似于是一个 todo 列表？」接着追问「是不是人应该只需要通过主对话解决一切……打钩也是由助理打」。

## 裁决 91：记事本，你只能勾掉自己的事

主会话给甲（全靠对话、清单只看）、乙（一起维护）、丙（主要靠对话，清单上只留两个直接动作）三案，JC：「丙，说说这件也要，按你推荐」。

- **边界**：只收能办完的事，只从对话里来；不后台整理、不放信息（地址、航班号归 GA 记忆）。裁决 49 撤账本的两条理由（后台花 token、另起一套记忆）都不碰。
- **清单上只有勾掉、取消勾、取消提醒**。勾一个状态不需要判断，绕一轮模型要几秒和 token；「More model」是判断交给模型，不是开关也绕模型。新建、改时间、改说法都跟 Galley 说，所以面板上没有输入框、时间选择器、编辑表单。没选甲：空方框天生让人点，画了点不动会卡住；没选乙：又回到「设闹钟」。
- **底层**：新增待办记录，提醒是挂在待办上的一次性定时任务（`scheduled_tasks.todo_id`）；Galley 自己回头查的仍是定时任务。
- **发版前做**：旧的「待办」还没发版，先发一版很快要换掉的不值。

## 之后七条

- **92 只要提醒、没有要办完的事，用 Galley 自己的提醒**（JC：「A」）。票 41 回报「十分钟后提醒我喝水」记成待办后，响过就标红逾期、占着「今天 N」等你去勾。判法写进手册：你不理这次提醒，这件事还要留在清单上吗？不用就是它自己的提醒。没选「Galley 响完自己勾」：勾就不再只由你或你开口才发生。
- **93 入口挪到 Galley 对话顶栏右边**。JC 看了票 42 卡片下面一行的三档：「这几个我都不满意，感觉是不是不应该放在这个位置」。理由是在哪点就在哪开、视线不横穿窗口；按钮切换器比完定只要图标加数字（D1）。没选默认开着：会推翻 5 月撤右侧检查栏时「右侧常驻面板让 Galley 读起来像 IDE」。
- **94 名字照旧叫「待办」**。JC 问改「待办事项」「待办备忘录」是否更好懂。按钮不写字，第一次弄懂靠回复下的卡片和数字；「备忘录」在中文用户心里是记笔记的地方（华为备忘录分「笔记」「待办」两个列表），会邀请「帮我记一下房东地址」，撞裁决 91 的边界；「待办事项」意思一样，改起来文案、提示词、手册、测试一起动，不值。
- **95 面板与主对话解耦**。JC 一度说「工作台暂时不用加到待办相关功能」，随即改口「但是工作台时也可能查看，作为查看面板，我觉得待办面板可以和主对话解耦」。解耦的是看，不是待办这件事：每条对话的顶栏都能开，勾与取消提醒原地做，点标题、「说说这件」、空状态按钮都带你回 Galley；开关分 Galley 与其他对话两处记，默认都关。工作台的提示词改道句补上待办（工作台的模型手里有 `galley` CLI，人最容易在面板旁边的输入框里说「加一个待办」）。空状态精简成一句、一个例子、一个按钮「跟 Galley 说」：「在左边说一声」在工作台旁边正好指错，「Galley 助理」助手 PRD 裁决 7 否过。
- **96 开机自启提示降一级、可关**。JC：「如果用户不准备开机启动的话，这个提示会永远在有点吵」。挪到列表最后、12px 小字；关掉后本机永远不再出现，不按条件再冒（合盖睡眠也让提醒晚到，判不准）。文案改准：错过的一次性提醒下次运行时照补（票 33），只有例行过了午夜那次会丢。
- **97 第二行照 Apple「提醒事项」**。JC：「一行字截止，提醒，今天记下，多个内容没有主次」。Apple 一件事只有一个「什么时候」；我们有截止与提醒两个时间，所以主时间写截止且不写「截止」两字，提醒退成铃铛加时刻，「记下」的日子不写（点标题能跳回原话）。切换器比 A（铃铛加时刻）、B（只铃铛，看不出几点响）、C（只删字，同一天的日子写两遍），JC：「按你建议定」。
- **98 去掉「你的事」组名**。JC：「作为一个助理，不太会这样分类待办事项」。秘书给老板列待办按时间排，自己在跟进的事另外汇报，不会给老板那份贴「你的」；口语里「这是你的事」还常带「跟我无关」。今天、以后、随时直接是一级组名，和「Galley 在办」同一档。没选改名「你要办的」（仍给主角贴标签）、按时间混排 Galley 的事（子任务多半没时间，方框与状态图标混一列）。

## 实现要点

- 迁移 **050** 加 `todos` 表：截止是 `due_date`（只有日子，浮动本地日期）或 `due_at`（带时刻，UTC 时刻）二选一；状态由 `done_at`、`cancelled_at` 两个时间戳读出，照 049 的写法记谁勾的。勾掉或取消待办，没送到的提醒跟着取消；待办不再开着的提醒到点不响。
- `galley todo list / show / add / update / done / reopen / cancel`（Agent API `3` 内加法，`--schema=1`、`2` 也认）；`ScheduledTask` 加 `todoId`。事件 `todos:changed`。
- 面板与「在办的事」共用一个查询，改成四组（你的待办分今天、以后、随时，Galley 在办，例行，已完成），守「你看到的就是它看到的」；「在办的事」是段首快照，回答前先 `todo list` 读最新的，因为之后你可能在面板上勾过。重置主对话时待办跟着清。
- 真模型评测加 `todo` 套件（`.scratch/main-chat/entry-layer-eval/todo/`）：12 个用例各跑两遍，24/24。
- 共用提示词净增 0 字节，仍在静态预算内。

## 事故：dev 的 CLI 是旧的

票 46 合入后 JC 实跑，Galley 把「明天 10 点提醒我理发」写进了 macOS「提醒事项」。原因：`tauri dev` 只在启动时编一次 galley CLI，引擎调的 `core/target/debug/galley` 还没有 `todo` / `schedule`，模型找不到命令就自己想办法。重编 sidecar、替换那个文件后，JC 重置主对话重跑，记待办成功。
