## 裁决

- **今天发，草稿只做 Mac 冒烟（乙）。** 主会话推荐的是甲（做 W1）：这一版改了 runner（插话、`tell_user`）、加了补丁 0031、GA 基线换版（上游拆 `llmcore.py` 正好落在补丁 0007、0030 那里），迁移 053–056 还没在 Windows 的旧库上跑过，CI 的 Windows job 只编译、跑单元测试，不跑真模型。JC 选乙，W1 继续欠着。
- **patch（v0.7.6）。** 版本号是 11-03 裁决 186 时定的：JC 选两件一起发 v0.7.6（`003ce468`）。最大的单项是主对话的判断与插话，都是 v0.7.0 主对话的延伸；照 08-06 的规则不按批量（75 个提交）定级。
- **不触发「拿掉也定级」。** 本区间里加了又拿掉的（票 135 的浏览器硬闸、裁决 183–185 的派活条款、票 134 的四轮）没有发出去过；v0.7.5 的派活判据（裁决 160）换成几条判断，是提示词改动，不是拿掉一个系统。

- **迁移 056 一个**（`056_subtask_background.sql`）。升级前 Core 照旧自动备份数据目录；v0.7.5 打不开升级后的库（sqlx `ignore_missing=false`，同前几版），notes 写退回要恢复那份备份。
- **GA baseline 发 `d66509b`，之后的不跟。** 上游 `main` 现在是 `38085e0`，比 `d66509b` 多 4 个提交（GitHub compare API 查于 2026-11-04）：`agentmain.py` 反射模式里挪一行（选模型从每次触发挪到加载时），其余是 `frontends/p2p_ws_client.py`。Galley 不走反射模式也不加载 p2p 前端（`runner/`、`core/src`、`managed-ga/patches` 里 grep `--reflect`、`reflect_script`、`p2p_ws_client` 为空），这次不跟，下次发版照例再看。
- **打包门禁要跑**：`managed-ga/code/`（基线、补丁 0031）与 `runner/`（插话、`tell_user`、步骤里的字）都动了。
- **不另跑 dev 回归一轮。** 提示词改动都跑过评测（票 139 v5，票 143 v6，票 145 v7–v9 三个模型）；dev 真机走过票 136 两次、票 139 四句加一次插话、票 143 与 144 一句、票 145 两句。
