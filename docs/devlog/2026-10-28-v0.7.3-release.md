## 裁决

- **发，patch（v0.7.3）。** 最大的一项是待办按钮挪位与胶囊，属于 v0.7.0 主对话这条线上的打磨；删掉的两个临时切换器只在 dev 里有过，用户从没见过，不触发「拿掉也定级」。
- **不影响 1.0 的计数。** 没有 Rust 源码、runner、CLI、迁移、内置 GA 的改动，Agent API 不变。手册 `reminders.md` 由 `include_str!` 编进 Core，Core 二进制会变，逻辑不变。
- **现在发，10-28 试用的复盘不绑这一版**（拍板点 1，选 A）：这批是用户反馈「不知道有面板」推出来的，自成一体；复盘可能什么都不改，也可能要改提示词、重跑评测，绑在一起这一版的日子定不下来。复盘结论进下一版，同 v0.7.0、v0.7.2 的处理。
- **GA baseline 不升**（拍板点 2）。上游 `main` 已到 `e4d956f`（`git ls-remote` 查于 2026-10-28），比基线 `a9a36b4` 多 6 个提交、6 个文件，没有一处落在 Galley 跑的引擎代码上：
  - `frontends/conductor.py`（委派提示词的措辞）：Galley 不走 conductor，原因见 `runner/managed_im_supervisor.py:29`。
  - `memory/` 下 5 个（`macljqCtrl.py` 修 macOS 按键修饰符、`ocr_utils.py` 用 macOS 原生 OCR、截图走进程内 Quartz、`ljqCtrl_sop.md` / `vision_sop.md` / `memory_management_sop.md` 改写）：在 Galley 里是 state-seed，升级只补缺的文件、从不覆盖（`core/src/managed_runtime.rs:199`），升了也只有新装的才拿到。
  - `ga.py`、`llmcore.py`、`agentmain.py` 没动。
  - 外置 GA 不受影响：用户自己的 GA 自己更新。换来的只是新装用户的 macOS 键盘修饰符修复，不值得为它在 patch 里多跑一轮审计、打包门禁与引擎冒烟；下次有引擎代码差量时一起审。
- **打包门禁不跑**：没碰内置 GA、基线与打包依赖。
- **更新渠道**：stable，publish + 冒烟后推 stable。
