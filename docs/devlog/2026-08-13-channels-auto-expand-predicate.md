# Channels 自动展开谓词收窄：注意力不给永久静息态

日期：2026-08-13
关联：`im/status.ts`、`WeChatCard.tsx`、`FeishuCard.tsx`、`TelegramCard.tsx`、
`DiscordCard.tsx`、[Settings tab 逐个打磨](./2026-06-11-settings-tab-by-tab-polish.md)、
[Settings 入场运动三连修](./2026-08-10-community-issues-triage-and-settings-polish.md)

## 背景与结论

JC 问「进 Channels 时有些渠道折叠头自动展开，这个逻辑该是什么样」。读完四张
卡的推导发现它们各说各话，且谓词把两件不同的事混成了一件。结论：**四张卡统一
成一个谓词，只有 `waiting_scan` / `expired` / `error` 自动展开**，「未接入」
和「已暂停」不再展开。

改动前的实际推导：

| 卡片 | 自动展开的状态 |
|---|---|
| WeChat | `waiting_scan` / `expired` / `error` |
| Feishu | 上述 + `not_connected` + `stopped` + 凭证不全 |
| Telegram / Discord | 上述 attention + `not_connected` + `stopped` |

## 为什么收窄：永久静息态不能当注意力信号

`2026-06-11` 那次把自动展开明确定位成注意力手段（「brand 不为『展开』消费，
注意力交给 StatusBadge + 自动展开 + primary 按钮」）。这个定位不变，**被推翻的
是谓词范围**：它把「还没配」也算成注意力事件，而「还没配」是绝大多数渠道的
**永久静息态**，不是事件。

两个后果，第二个才是致命的：

1. **全新用户**一进来三张卡（Feishu / Telegram / Discord）同时展开，飞书那张
   尤其长（开放平台建应用 + 权限清单 + 两个输入框 + 命令参考），一屏放不下。
   他只想配一个，而系统猜不中是哪一个——猜不中时全展开不是保险，是把选择成本
   转嫁给用户。
2. **稳定态更糟**：只用飞书的用户，飞书跑起来后折叠了，**Telegram 和 Discord
   因为永远「未接入」而永远展开**。噪音量与「你不用这个渠道」成正比，正好反了。
   而且这份代价是永久的，收益只在头一分钟。

判定原则记在 `status.ts` 的谓词注释里：**自动展开 = 现在有件事等你动手，而且
折叠头（图标 + 名称 + 徽章）表达不了它**。「未接入」表达得了——徽章就写着；
「等待扫码」表达不了——二维码本身就是交互；「异常」表达不了——错误详情在体内。

WeChat 本来就是这套，它是四张卡里唯一对的那张，收窄等于把它推广出去。

## 顺带删掉的 `ready` 门槛

`2026-08-10` 修 Channels 闪跳时加的 `ready = config !== null && status !== null`
（双 fetch 完成前不做自动展开推导）**随谓词一起删了**，不是回退那次修复，而是
它的前提消失了：新谓词只读 supervisor state，`status` 为 null 时 `derivedState`
只会落到 `not_connected` / `stopped`，两者都不在展开集合里，所以推不出假阳性，
最坏情况是「折叠 → 展开」的增量出现——正是那次裁决明文允许的方向（「先折叠后
展开是增量出现，先展开后收回是闪跳」）。Feishu 那串
`!canSaveCredentials || (非 running && !canStartService)` 的凭证推导同时删除。

净 -44 / +24 行，四张卡的展开推导都塌成
`expandedOverride ?? shouldAutoExpand(derivedState)`。

## 逐项裁决

- **「未接入」不展开**：采纳。本次改动主体。
- **「已暂停」不展开**：采纳。代价是重启一个已配置渠道多一次点击（「启动」
  按钮只在卡体内）。发生频率低，且改模型后的批量重启已有全局横幅那条路。
  补救方案（折叠头 actions 区给 `stopped` 加 ghost「启动」）**先不做**，进
  [deferred](./deferred.md) 等实感。
- **空态引导**：不做。全折叠后首访是四行「未接入」，带 caret 的四行比三坨
  表单更像「选一个」。真觉得缺引导应该补 copy（`imCopy.subtitle` 现在是
  「在聊天软件里和 Galley 对话」，不含「点开配置」的暗示），**不该用展开去
  当引导**——展开是注意力通道，借给引导用就又回到了这次要修的病。
- **展开态跨进出 Settings 记忆**：不做，进 deferred。自动展开变稀疏后，配到
  一半切走再回来要重点一次；有 `cachedFeishuConfig` 那个模块级缓存的现成路子。
- **多开 vs 手风琴单开**：维持多开。自动展开变稀疏后多开不再制造噪音，改单开
  反而碍「对照两个渠道的配置」。

## 未走真机变体

未开。硬理由已足（谓词自相矛盾 + 稳定态噪音与使用率成反比 + WeChat 已是反例
基准），气质票不是决策点，符合「仅当气质票是决策点才开变体」的边界。JC 真机
验收兜底，重点两处：全新状态四行是否一屏放得下、故意写错飞书凭证时那张卡是否
是全页唯一展开的。
