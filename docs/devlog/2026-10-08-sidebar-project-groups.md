## 起因

JC 问：普通侧栏要不要只显示非项目会话，项目会话交给项目视图。

本机 workbench.db（只读）：160 个会话、1 个项目「v0.6.1 发版回归」19 个会话，全是 10-07 CLI 代跑回归时建的；近 7 天
未归档 25 条里 19 条是它（76%），JC 手建项目 0 个。同样的形态以后会常见：Supervisor SOP 把复杂任务拆成「项目 + 2～4 个子
会话」（`docs/integrations/galley-supervisor-sop.md`「Split Into A Project」），每拆一次时间线多几行。

当时的结构：时间线列出全部未归档会话、行上不标所属项目；项目要按书眉「项目」进 Project Review 模式看，进去后时间线整个
隐藏（05-22 起）。

## 讨论与裁决

**直接隐藏（B）被否。** 项目会话的正在工作 / 等你回复 / 出错会在默认视图里失明——「项目」图标没有徽标，项目行也不汇总状态，
要展开才看得到，而 Supervisor 拆出来的子会话正是最想盯的；从 ⌘K / 搜索 / 通知打开一个项目会话，时间线里没有它，破坏
「选中行必在侧栏里」（10-03）；两个视图都残缺，切换成了必须。把这些补齐（项目图标徽标 + 选中会话借位）的成本接近折叠方案，
信息却更少。

**JC 选折叠（C），并提出：既然折叠，是不是不必分两个界面。** 讨论结论是合一、删掉项目视图：C 之后项目视图只剩「全部项目
清单」和「只看项目」两样独有价值，前者是翻档案（05-13「侧栏是当前工作面，不是档案浏览器」），后者没有使用证据；05-22 做
项目视图的理由「同时盯几个项目」，时间线里同时展开几个组即可。C 与项目视图并存会让同一个项目抽屉出现在两处，撞 05-13
删 ProjectsDialog 就地展开时的「避免两种交互并存」。

逐条定下的规则（全文在设计文档「Project 组行」）：

- 一个项目只出现一次，组按最新子会话的活动时间落桶、与会话行交错；置顶项目进置顶区；活动时间在「更早」的项目不出现。
  被否：每个桶各一个组（项目名重复）。
- 置顶会话留在置顶区、不进组（置顶优先于日期）。
- 组内平铺、不再套时间分组（Project Review 的抽屉里是按今天 / 本周分组的，搬进时间线就成了时间分组套时间分组）；
  窗口外的会话放在尾行「更早 N」，就地展开。
- 状态汇总沿用会话行的优先级与三通道（状态条、名字字重、pop）；组行永远不用 `bg-selected`，侧栏里恰好一行在说「你在这里」。
- 折叠时，等你回复 / 出错的子会话和选中的子会话挂在组行下面，每个只挂这一份；正在工作与未读不露。规则一句话：需要你处理
  的会话永远不会被折叠藏起来。这一条同时补上了 B 的失明问题。
- 展开 / 收起组不设项目上下文（Project Review 时代展开即软设）：时间线里展开多半只是看一眼，不该顺手把新对话行改成
  「新对话 · 项目名」。只有组行 `+`、空项目 CTA、书眉菜单里的项目项设项目上下文。
- 展开状态只在本次运行内记住。
- JC 提到的「隐藏」不新增隐藏状态，改为组行菜单「归档全部对话」：折叠已经把一组压成一行，真想让它消失的多半是一批跑完的
  子会话，归档才是对的语义。
- 书眉「项目」从模式开关改成菜单：新建项目 + 全部项目，点项目 = 在该项目里新建对话并展开它的组。已知代价：沉到「更早」的
  项目，它的旧会话只能靠搜索 / EarlierDialog 找。
- 桶标题计数改为顶层行数（一个组算一行）；「更早」入口计数不变。

## 真机切换器（JC 定）

| 维度 | 档位 | JC |
|---|---|---|
| 组行 | 单行（图标 + 名称 + 右侧计数）/ 双行（第二行写汇总） | **双行** |
| 折叠门槛 | 一律折 / ≥2 才折 | **一律折** |
| 默认 | 折叠 / 展开 | **折叠** |
| 演示状态 | 无 / 正在工作 / 等你回复 / 出错（dev 伪造第一个组最近一条子会话的状态） | 只用于查看，不裁决 |

单行把组当容器标题（比 48px 会话行矮），双行把组当会话的同级行，是「相对角色」分歧，按惯例真机定；JC 选了与会话行同级的
双行。

## 执行中与 PRD 的出入（主会话认可）

- 「时间线全空时从更早补 10 条」按会话补完再折叠，补出来的行可能少于 10；换来「更早」入口计数与 EarlierDialog 列表仍由
  同一份计算得出。
- 「归档全部对话」不含置顶会话（它们不在组里）。
- 组的汇总也算尾行里的旧会话。
