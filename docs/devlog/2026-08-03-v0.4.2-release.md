# v0.4.2 发布:定时任务信任面 + 引擎升级到 d8d90ee

**日期**:2026-08-03
**范围**:v0.4.2 发布叙事,聚合 `v0.4.1..HEAD`(11 个提交)

## 背景

`v0.4.1` 之后累积了三条线:定时任务的信任面打磨(issues 11–14)、
Question Rail tooltip 的回答预览,以及 GA baseline 从 `4086d5c` 升到
`d8d90ee` 并附带一个新补丁 `0016`。三条线各有独立 provenance,本条只记
**为什么打包成 `v0.4.2`** 以及发布点的聚合状态。

## 版本决策:patch

沿用 `v0.4.1` 确立的定级规则(按功能量级判,minor 要求够一条独立产品线):

- 定时任务信任面是 `v0.4.0` 那条产品线上的增量打磨,不是新面;
- rail tooltip 是辨识度打磨;
- 引擎 baseline 升级不改产品形态。`v0.2.16` 发运审计后 baseline 时同样
  走 patch,先例一致。

产品形态、Agent API schema(`schemaVersion: 1`)、更新渠道策略均不变。

### 引擎升级是本次的重量项

上游 20 commits 里对 Galley 有实质影响的是**中断响应性与流式健壮性**:
停止现在会真正撕掉在途 HTTP 流(`active_response` + `should_stop`),
而不是让它跑完;`retry-after` 有了 `max_retry_after` 封顶(默认 60s),
超大值不再吊死会话;Responses API 的 `response.incomplete` / `response.failed`
被当作合法终止事件,不再触发空响应重试风暴。

同轮引入的 `0016-managed-native-thinking-tags.patch` 是**发运前提**而非附带:
上游开始把 Anthropic 原生 thinking 无标签地 yield 进输出流,而 Galley
剥的 `<thinking>` 是提示词约定的另一条通道。因为 `managed_model.rs` 对托管
Anthropic 模型默认下发 `thinking_type: adaptive`,这是**默认命中**路径——
不打补丁直接发版,用户会在回答正文最前面看到推理内容,思考面板反而空,
且脏数据会永久落进 `final_answer` 与 FTS 索引。补丁把新通道归一到既有标签
约定,顺带让原生推理第一次正确进入思考面板。

### 不随本次发运的东西

- `.scratch/scheduled-tasks/issues/06`(CLI schedule 命令面)仍是
  `needs-triage`,延续 `v0.4.0` 的有意 v1 非目标:GUI 已闭环,等真实
  supervisor 用例出现再动。它属于 Agent API 面,风险等级与 GUI 打磨不同,
  不该被一个 patch 版顺带捎上。
- 遗留开口:`extractThinking` 只取**第一个** `<thinking>` 匹配,当模型同时
  产出原生推理与提示词叙述时,后者被剥掉而不显示。两者都正确排除在回答之外,
  属展示取舍,留给 JC 定。
