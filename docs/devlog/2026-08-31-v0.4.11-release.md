# v0.4.11 发布

**日期**：2026-08-31
**上下文**：v0.4.10（2026-08-24）后主干只有一件实质工作，当天讨论后 JC
裁决直接发小版本。

## 范围（git log v0.4.10..，两件）

1. **无鉴权 Provider（galley#24）**——headline。社区问「GA 手改 mykey
   可留空 apikey，Galley 咋弄」；落地为新建 key 可留空 + 一次确认弹窗、
   编辑加「清除密钥」（清除 = 转无鉴权）、底层 `ManagedModelAuthKind`
   加 `"none"`。设计裁决与四层闸门勘查见
   [当日 devlog](./2026-08-31-no-auth-provider-empty-apikey.md)。
   Agent API additive，schemaVersion 不动。
2. **GA baseline `30b24ad` -> `efb3bc6`**——兑现 v0.4.10 留下的
   「下次发版再审」。引擎 delta 全是 Galley 正收益（可中断重试退避、
   abort 强制唤醒阻塞 recv、裁剪线性化）；一处真冲突（0017 × 上游
   token ledger）已合成。见
   [升级 devlog](./2026-08-31-ga-upstream-upgrade-30b24ad-to-efb3bc6.md)。

发版触发器与 v0.4.8/9/10 同型：用户上报的修复压着不发会加厚下一次的
未验证 delta。反方（#24 用户手里有占位 key workaround，紧迫度低）摆过，
被上面这条压过。无 riding-along：deferred 台账无启动信号被触发的项。

## 定级

patch，无争议——最大单项（无鉴权 provider）是既有 Settings 面上的
增量能力，`v0.4.1` 规则只看最大单项。

## 门禁

- **打包门禁 mandatory**（`runner/` 与 `managed-ga/` 都有提交）：
  `bundle-python.sh mac-x64` 从零重建 161M + bundled smoke OK；
  `mac-arm64` / `win-x64` 照例由 `release.yml` 平台 runner 在 tag 时
  守门。烟测脚本本轮改过一处自家断言（desktop_bridge 降级 find_spec，
  见升级 devlog）——CI 跑的是同一脚本，修复随主干生效。
- **补丁栈 full replay**：升级流程自带（老栈 byte-verify → rebase →
  19/19 clean + py_compile + payload 校验）。
- 版本一致性：`check-version-consistency.mjs --tag=v0.4.11`。
- 常规矩阵：cargo check/test、gui typecheck/lint、vitest 347、
  runner 235 + mypy + ruff，全绿（no-auth 落地当天 + 升级后各跑过）。

## Smoke 计划（draft 门）

JC 装 draft 包做真机验收，一次覆盖三件事：no-auth provider 流程
