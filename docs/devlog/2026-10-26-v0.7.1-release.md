# v0.7.1 发布

**日期**：2026-10-26
**上下文**：v0.7.0 后三天。main 上是主对话的三轮打磨（在跑时的进展行、表格短列、气泡动效）和删掉桌面宠物与重新注入工具。
JC：「准备发版，0.7.1 是否合适？」→ 主会话推荐 patch → 「按建议推进」。

## 裁决

- **发，patch（v0.7.1）。** 加法按量级定级（project-status Release Version Rules）：只看最大的那一个功能，零碎改进攒得再多也还是 patch。
  这次最大的是进展行，属于 v0.7.0 主对话的打磨，撑不起一条产品线。
- **删掉宠物与重新注入工具不触发「拿掉也定级」。** 那条要的是拿掉一整套用户依赖的系统、改了产品行为或安全模型（例子是 10-05 的工具审批，
  社区 #16 明说依赖它）；条款的理由是 patch 号会让自动更新的用户以为没拿走他们依赖的东西。这两项都早已坏了：宠物在内置运行时里从 05-24 起就打不开，
  重新注入从 06-23 起点了只报错（[删除 devlog](./2026-10-23-remove-desktop-pet-and-reinject-tools.md) 裁决 1、2），GitHub issue 里没有相关反馈；
  体量是标题菜单两项加侧栏一个徽标。
- **不影响 1.0 的计数。** 1.0 的第二个条件是「助理与主对话走完一整条 0.7.x 不再有破坏性改动」（[v0.7.0 发布](./2026-10-22-v0.7.0-release.md) 第 10 行），
  宠物不在这个范围里。`cli/` 没改，Agent API 仍是 `schemaVersion: 3`；删掉的 3 条命令、3 条事件只在 runner ↔ Core 的内部线路上。没有数据库迁移。
- **GA baseline 审计并升级到 `a9a36b4`。** 上游 `main` 比 `b70079d` 多 2 个提交（`git ls-remote` 查于 2026-10-26），只改 `ga.py` 6 行，
  两处都是稳定性修复，其中一处在浏览器控制的路径上。SOP 默认发版前升，代价小，就升了。详见
  [GA 上游升级 b70079d -> a9a36b4](./2026-10-26-ga-upstream-upgrade-b70079d-to-a9a36b4.md)。
- **打包门禁要跑**：内置 GA 的代码变了，`bundle-python.sh mac-x64` + `check-bundled-python-managed-ga.sh` 已在基线升级时跑过。
- **更新渠道**：stable，publish + 冒烟后推 stable。
- **notes 写明宠物与重新注入已移除**，虽然是 patch。外置用户仍可以自己运行上游的宠物脚本。
