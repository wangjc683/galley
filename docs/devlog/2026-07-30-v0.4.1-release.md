# v0.4.1 发布:composer 文件拖放 + 窗口布局复位

**日期**:2026-07-30
**范围**:v0.4.1 发布叙事,聚合 `v0.4.0..HEAD`(含发版讨论中追加的分隔条双击升级 + tooltip)

## 背景

`v0.4.0` 之后累积了一条用户可见新功能线(composer 文件拖放 / 文件引用)、
一条窗口布局线(几何持久化 + 恢复默认布局),外加 2026-07-27 架构评审轮的
结构性收口和两处主题微调。各线已有独立 provenance,本条只记
**为什么打包成 `v0.4.1`** 以及发布点的聚合状态。

## 版本决策:patch 而非 minor(JC 裁决)

agent 按 `v0.4.0` 先例(新用户可见能力 → minor)推荐 `0.5.0`,理由:
文件拖放是新交互面而非修复,且带一次有意的行为 trade-off(HTML5 文本
拖拽随 `dragDropEnabled: true` 移除)。JC 裁决 `0.4.1`:定级按
**功能量级**判——文件拖放是 composer 的输入增强,量级不及定时任务
那种带独立 sidebar 面的整块功能,归入 0.4 线的增量打磨。

- **本次先例的规则修正**:minor 的门槛不只是"是否新用户可见能力",
  还要看功能量级是否够一条独立产品线。后续 agent 定级按此判,
  拿不准时列裁决点问 JC。
- **Rejected**:`0.5.0`(minor,agent 推荐)。

## 发版讨论中追加的打磨:分隔条双击升级 + tooltip

发起发布后 JC 提出两项打磨,均随本次发运(细节与 agent 反对意见留档在
[窗口几何](./2026-07-30-window-geometry-amnesia.md)):

1. **分隔条双击从"仅恢复分栏"升级为完整恢复**(JC 裁决,可发现性理由:
   三入口中唯一可见面应承载完整命令);
2. **分隔条 hover tooltip**「双击恢复默认布局」(JC 提议、agent 支持:
   时机精准 + 兼作大爆炸半径手势的预告)。

### 文件拖放的 trade-off 与收口

`01 spike` 的 JC 裁决(方案 A):迁到 Tauri 原生 drag-drop 事件
(`dragDropEnabled: true`)后,HTML5 DnD 连带文本 / URL 拖拽一并失效,
接受该损失并用 toast 缓解。图片仍走原有 attachment 管线,只是改由原生
事件喂入。`05 Windows smoke` 是 tracker 收口的最后门槛:裁决为 agent
跑清单 + JC 在发布装机 dogfood 时终验,因此随本次 release 的 Windows
装机 smoke 一起完成,不阻塞 tag。

### 不随本次发运的变化

GA baseline 保持 `4086d5c` 不变;`managed-ga/` 自 `v0.4.0` 起仅
`manifest.json` 增加 `commitDate` / `treeHash` 两个元数据字段(架构评审
candidate 4),无 GA 代码 / patch 变化。bundled runtime gate 照跑,通过。
