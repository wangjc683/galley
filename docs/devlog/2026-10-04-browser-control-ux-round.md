## 起因

顶栏打磨讨论到健康态的状态图标时，JC 指出浏览器插件和 Channels 既是配置入口又是状态显示器，
倾向常显；继而定位：GA 的真实浏览器控制是 Galley 最大的卖点之一，这一块的 UI/UX 要好好过一遍。

## 事实底座

- **用量**（`workbench.db` 只读）：135 个会话中 61 个用过浏览器（45%）；`web_execute_js` 622 次 +
  `web_scan` 262 次，是 `code_run`（274）的三倍多，所有工具第一。README 首图也是多步浏览器操作。
- **发现**：新手唯一入口是黄色「浏览器控制 · 待连接」徽章 + 黄色横幅，warning 语义是「坏了快修」；
  引导与空状态都不提它；空状态下方是写明的勿回退区（`conversation.md` §7）。
- **状态**：只在启动时检测一次（`useBrowserControlStartupEffect`），之后不刷新；Chrome 没开时每次启动挂
  35 秒「检测中」；检测在网页里执行 `document.title` 并临时占用 18765 / 18766。顶栏图标脸上没有状态：
  已连接 / 浏览器没开同一个拼图，渠道「从没设置」与「在跑」同一个气泡。
- **使用中**：对话里浏览器步骤只写「读取网页 / 执行网页脚本」；预览代码读 `query` / `url` 参数，GA 的
  `web_scan` 没有这两个参数（死代码）。结果里其实带 `metadata.active_tab` + `tabs[]` 与 `tab_id`。
- **GA 侧**：TMWebDriver 首个实例当 master（WS 18765 + HTTP 18766 `/link`），后来者见端口在听就当远程
  客户端；GA 在第一次网页工具调用时才建 driver（`ga.py` `first_init_driver`，最多等 12 秒）；上游 SOP
  自己就建议后台常驻一个 master。远程客户端的默认标签页永远是 None（见裁决 2）。

## 裁决（JC，2026-10-04）

1. **对话工具条显示网站**（`db2dde5e`）。`web_scan`：「读取网页 · 页面标题 · 主机名」，取扫描当场的
   当前标签页；`web_execute_js`：只显示主机名，按会话里最近一次标签页列表（加上它新开的标签页）回查
   `tab_id`——标题过期太快（下一次扫描时 38% 已变）；只列标签页的步骤显示「N 个标签页」；认不出不显示。
   本机 884 个浏览器步骤 825 个有显示（93%）。行宽不够时标题让位、主机名保留。IM 渠道**先不跟**
   （显式代价与方案进 deferred.md）。
2. **S‑b 常驻浏览器桥**（`450dbeb1`）。内置模式下 Core 托管 `python -m runner.managed_browser_bridge`，
   它持有 TMWebDriver master，Chrome 一开插件就连上，会话全部走上游已支持的远程客户端模式。启动 /
   切到内置时起，切外置 / 退出 / 装更新前停，崩溃退避重启；外置模式绝不启动（Rule 1）；Core 不开监听
   （Rule 2），端口是引擎自己的、内置会话今天就会开。状态行变化即推，Core 发 `browser-bridge-updated`、
   答 `get_browser_bridge_status`。删掉每次启动的检测（35 秒徽章、页内脚本、端口竞争一起消失）。
   **连上即自动验证**：未验证时插件第一次连上，自动跑一次完整检测，设置第 3 步不必再点「测试连接」。
   - **补丁 0028**（`7044db88`，偏离「不改 GA」的票面，主会话核实后接受）：远程客户端的默认标签页恒为
     None，每次 `execute_js` 发出 `"None"`、撞上 master 3 秒的死会话等待，且 `active_tab` / `tab_id`
     为 null（本机已有 17/261 次扫描如此）。常驻后所有会话都是远程客户端，会多等 3–12 秒、网站预览
     全空。改为远程分支的 `get_all_sessions` 维持一个活的默认标签页，7 行。
3. **顶栏点灯 + popover**（`fe001911`）。浏览器控制、Channels 两个图标常显；在线＝细线轮廓下铺同形
   淡填充（Phosphor `fill` 叠在 `thin` 下，`--opacity-medium`：浅色 20% / 深色 28%），不在线＝只剩轮廓；
   不加点、不加色、无动效。点击弹 popover：浏览器写实时状态、标签页数、范围说明、「浏览器控制设置…」；
   Channels 每个已设置的平台一行、「重启 Channels」走设置页同款确认框、「Channels 设置…」；从没设置
   过直达设置。启动第一秒按已存的「已验证」标记渲染，消掉「检测中」闪烁。
4. **「待解锁」代替「待修」**：未验证时徽章「浏览器控制 · 待解锁」用 `brand` 色调，横幅改为
   「让 Galley 用你已登录的浏览器办事：查资料、填表单、操作网页后台。」+「解锁浏览器控制」；仍常驻、
   不可关；只在从未验证时出现（桥出错走红色徽章，不邀请解锁已解锁的东西）。状态徽章色调规则改写为
   「每种色调说的是一类状态」：`brand`＝Galley 在为你干活或邀请你开始。
5. **范围说明**（06-16 设计审计建议、此前未做）：popover 与设置页已连接卡加一句「Galley 只在你交代的
   任务里读取和操作这个浏览器，沿用你的登录态。读网页时，它能看到你打开的所有标签页的标题和网址。」
   后半句如实：`web_scan` 每次把整张标签页列表交给模型。
6. **成功那一刻的「试一试」**：自动验证通过时弹一条常驻到手动关闭的提示「浏览器控制已连接」+「试一试」，
   点了跑现有天气 demo。原提议的「空状态首次试用入口」撞 §7 勿回退条，收回。
7. **顺手修**：顶栏所有 popover 触发器的按下态从没显示过——外层 tooltip 的 `data-state` 盖掉了 popover 的；
   改按 `aria-expanded`（「显示」/ Goal / 更新一并生效）。
8. **不做 / 暂缓**：不做暂停开关；插件上架商店暂缓（deferred.md）；审批的读／写区分调研后全部取消，
   JC 进一步裁定**去掉整个审批系统**（下个 session，见票）。

## 当日真机修订

- **灯改为反转极性**（JC 真机：两颗实心图标与顶栏其他细线图标格格不入）：在线＝普通 thin 图标、与相邻工具完全一样；离线 / 未设置＝同一图标 50% 不透明度（蓝牙关掉时的 macOS 先例）。静态对比 V0 现状 / V1 反转 / V2 斜线换形 / V3 底线 / V4 描边加粗，JC 选 V1、透明度 50%（40% 太像不可点）。上面裁决 3 的「淡填充」由此作废。
- **浏览器 popover 只讲状态**（JC 嫌冗长）：「已连接 · N 个标签页」一行 +「设置…」；范围说明撤出 popover，只留设置页已连接卡；渠道 popover 按钮同改「设置…」（`a572632f`）。
- **浏览器 / 渠道浮层改成菜单式**（JC 真机：字体和样式与「显示」不统一）：对表发现顶栏有两套浮层——「显示」、会话菜单、＋ 菜单是紧凑菜单式（`p-1`、6px 偏移、13px 行、整行菜单项），状态簇四个是卡片式（`p-4`、8px 偏移、凸起的「XX 设置…」按钮、写死 px）。定为**入口类用菜单式、决策类用卡片式**：Browser Control / Channels 换成 DropdownMenu，状态行 + 分隔线 + 菜单项（macOS 菜单栏图标先例）；Goal / 更新是带停止、延长、重启决定的通知，维持卡片。渠道菜单的「已接入」改用 success 绿（JC：一眼扫过去看颜色就知道健康；也与设置页渠道卡片徽标同色），推翻 T03「健康状态不着色」；浏览器菜单的「已连接」同改绿色，两菜单同一健康色。被否：五个全改菜单（Goal 的多目标列表与停止确认、更新说明塞不进菜单行）、只对齐字号间距保留按钮（凸起按钮照样突兀）。
- **渠道菜单加平台图标、收掉空档**（JC：有奇怪的空间浪费，想加 Settings 里的 IM 图标，一眼扫过去就能认出平台）。量下来空档有三处：最小宽度 200px 比内容（约 140px）宽，两端对齐把多出的约 60px 全塞进名称与状态词之间；`lastError` 把 `w-max` 撑到 300px，健康行中间空出约 200px；状态行文字从 8px 起、菜单项文字从 30px 起，两条左缘。改为每行「14px 单色平台图标 + 名称 + 右列状态词」：图标与「重启 Channels / 设置…」的图标同列、文字同列；渠道菜单最小宽度降到 168px；报错原文缩进到名称列，仍可撑到 300px。图形沿用 Settings 卡片的单色版（抽出 `ChannelPlatformMark`），不用品牌色：微信绿会被读成「已接入」的健康绿。真机切 A（右列）/ A′（再把已暂停行的图标降到 50%、名称降一档墨色，即灯的语法逐行用）/ B（状态词紧跟名称）三档，JC 选 A′（未述理由；我原推荐 A，A′ 是并列候选）。B 我不推荐：状态词不成一列，扫颜色变难。静态对比时否掉的还有图标 16px `ink-soft`（Telegram 的实心圆是菜单里最黑的一块；14px `ink-muted` 才与细线动作图标同重），以及让报错原文服从窄宽度（两行就截断）。识别上的收益如实记：平台名只有两个字或一个短词，1～2 个平台时差别不大，单色 14px 的飞书图标也不太好认；这一轮真正的收益是左缘对齐和收掉空档。
- **浏览器菜单改用渠道菜单的行写法**（JC：浏览器控制 popover 也有问题）。对表发现三处：和刚改好的渠道菜单成了两种写法（状态行文字从 8px 起、「设置…」从 30px 起；同一个健康绿，「已连接」13px medium、「已接入」12px 常规；宽 200px 而内容约 136px）；报错时同一件事说三遍（徽章「浏览器控制 · 端口被占用」→ 红色标题「浏览器控制的端口被其他程序占用」→ 桥原文「浏览器控制端口 18765 被其他程序占用……」），菜单被撑到 300 × 144px；连接中断时桥原文已是「……暂时无法访问，正在重试。」，菜单又补一行「正在自动重试。」。改为「拼图 14px + 浏览器 + 右列状态词」，未连接 / 检测中图标与名称减淡；报错去掉红色标题，右列红字写原因（徽章后半截），次行桥原文（两行截断），「正在自动重试。」单独一行且连接中断不再加；两个灯菜单的最小宽度 168px 收进 `status-menu.ts` 共用。重试去重放在界面侧按原因判断，不改桥的原文：Settings 直接显示原文，在那里靠这半句说明正在重试。真机切 A2（标签页数跟在名称后）/ A1（标签页数放次行）/ B（保留「已连接 · N 个标签页」一句，只补图标列与报错去重）三档，JC 选 A1（未述理由；我原推荐 A2，理由是常态少一行）。B 我不推荐：两个灯菜单仍是两种写法。报错态真机造不出来，靠临时渲染页 7 种状态 × 3 档截图核对。

## 被否方案

- 状态健康时隐藏（S1）、收进一个「接入」汇总入口（S2）：JC 要两者各自常显，问题在图标脸上没状态，不在常显。
- 只做 popover 不点灯（P1）：相邻两个图标一个会亮一个永远不亮，语法不成立。
- 被动查询 18766（S‑a）：只在某会话建过连接后才有答案，之前只能显示「待命」暗灯，新手会以为坏了。
- 定时跑现有检测：起 Python、占端口最长 35 秒、往网页注入脚本，会和会话抢端口。
- 用子类把 `"None"` 映射到 master 的默认标签页代替补丁 0028：消得掉 3 秒等待，修不了 null 的 `active_tab`。
- 状态点：气泡上的点读作未读（05-31），浏览器控制就绪后「无点、无动效」（05-27）。
- `duotone` 权重：描边是 regular，比旁边的 thin 重。单一固定透明度：22% 浅色清楚、深色发虚，28% 起浅色成灰团。
- 「待解锁」用 `neutral`（与「有更新」同权重，配不上头号能力）或 `warning`（就是要摆脱的「待修」）；
  半透明品牌色横幅（在米色徽章旁发粉）。
- 定时消失的提示（用户还在扩展页时就过期了）；手动测试成功也弹提示。
- 脚本步骤也显示标题（38% 过期）；正则嗅探跳转语句让标签页记忆失效（12 次抓 7 次，却让 46 个正确标签消失）；
  每条用户消息清空记忆（覆盖率 81%→69%，准确度不变）；用参数里的 `switch_tab_id` 代替结果里的 `tab_id`；
  主机名用等宽字体。
- 审批按 `no_monitor` 区分读写：标记由模型自报、因模型而异（deepseek-flash 0%、claude-opus-4-8 79%），
  要拦 366 次、多是跳转，只拦到 31 次写操作。

## 风险与后续

- Windows 真机冒烟常驻桥：stdin EOF 退出、`GALLEY_CORE_PID` 看门狗、端口被占时的提示。
- 在 Galley 之外手动跑的上游 GA 会成为 Galley master 的远程客户端，它没有 0028，会有 3 秒等待（以前某内置
  会话当 master 时也一样）。
- 约 5% 的脚本步骤可能挂着旧站名（同一标签页两次扫描之间有跳转）。
- 设置页离线 / 无网页状态的副文案「打开测试页后，点击重新检测。」在实时状态下已过时；
  `overlays-and-settings.md` 写的 demo 按钮名「试用浏览器控制」与代码「新建测试对话」不一致。
- 英文横幅在窄窗口会被截断。
