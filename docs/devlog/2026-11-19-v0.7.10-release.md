# v0.7.10 发布

**日期**：2026-11-19
**上下文**：v0.7.9 后两天，起头时 16 个提交。main 上动到应用的只有一件事：更新连得上（GitHub issue #33，[devlog](./2026-11-19-update-proxy.md)）——更新器与 Core 的请求跟系统代理，设置里多一项「更新加速地址」。JC 看过真窗口截图后：「推送，然后发版，发版后再回帖」。

## 裁决

- **patch（v0.7.10）。** 主会话按 [project status](../project-status.md)「Release Version Rules」定的，JC 没有单独裁版本号，草稿握手点一并报。依据：`cli/` 与 `docs/agent-api/` 的 diff 为空，`schemaVersion` 仍是 3；没有新迁移；GA 基线没升；唯一的新功能是设置里的一个输入框，够不上「功能量级够一条独立产品线」。
- **GA baseline 仍是 `d66509b`，上游的不跟。主会话定，JC 未裁。** 上游 `main` 是 `6d44d31`（`git ls-remote` 与 GitHub compare 接口查于 2026-11-19），比基线多 19 个提交、20 个文件。前 8 个是 v0.7.7 … v0.7.9 判过的那一批（[v0.7.7 devlog](./2026-11-06-v0.7.7-release.md)）；新增的 11 个（提交时间 11-08 至 11-17：Conductor 渲染分页、`ui_detect` 的本地图标标签、可选的 shadow 模型日志插件、无工具回复以 DSML / XML 样标签结尾时重试、记忆整理与子代理的文档）起初只读了提交标题；旁路代理提醒「现在定最省事」后，主会话在打 tag 前读了这 11 个提交动到的文件清单（13 个）与其中三个文件的 diff（`ga.py`、`memory/memory_management_sop.md`、`memory/subagent.md`），其余没读。不跟的理由：
  - **`ga.py` 的那条修复不能直接跟。** 上游把「没调工具的回复要不要重试」的条件从「结尾 50 字里有 `DSML` 和 `｜` 且以 `>` 结尾」放宽成「有 `DSML`，或以 `>` 结尾」。Galley 的助理手册让主对话在几种唤醒场合只回 `<no-reply/>`（或子任务标签加 `<no-reply/>`），这类回复正是「没调工具、以 `>` 结尾」；照搬上游，它们会被内核判成格式错误而重试。这是读 diff 得出的，没有实跑。下次升基线要先处理这一条（多半是一个新补丁，再跑唤醒与派活的评测）。
  - 记忆整理与子代理两份文档的改动是措辞（提炼与遗忘、`--func` 只用于一次性任务），动到的文件有 Galley 的补丁（`0001`、`0003`、`0006` 涉及这批文件里的若干个），要重放才知道冲不冲突。
  - 其余是 Conductor 前端、`ui_detect` 的图标标签、可选的 shadow 模型日志插件，Galley 没有入口用到。
  - 这一版只动更新连接；升基线要审计、重放补丁栈、跑打包门禁与评测，是另一件事。
- **打包门禁不跑。** `git diff --name-only v0.7.9..HEAD -- managed-ga runner cli scripts .github core/installer docs/agent-api` 为空；`core/tauri.conf.json` 只有 bump 改的版本号。内置内核的载荷与 v0.7.9 相同。
- **Dry run 不跑。** 工作流、打包、签名配置都没动；动的是更新器的运行时逻辑（`core/src/app_update.rs`），tag 构建出的草稿本身不公开，起到同样的作用。
- **没有迁移。** 退回 v0.7.9 不用恢复备份，notes 不写退回说明。新 pref `update_proxy_prefix` 旧版不读。
- **更新渠道**：stable，publish + 冒烟后推 stable。
