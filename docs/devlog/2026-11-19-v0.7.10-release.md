# v0.7.10 发布

**日期**：2026-11-19
**上下文**：v0.7.9 后两天，起头时 16 个提交。main 上动到应用的只有一件事：更新连得上（GitHub issue #33，[devlog](./2026-11-19-update-proxy.md)）——更新器与 Core 的请求跟系统代理，设置里多一项「更新加速地址」。JC 看过真窗口截图后：「推送，然后发版，发版后再回帖」。

## 裁决

- **patch（v0.7.10）。** 主会话按 [project status](../project-status.md)「Release Version Rules」定的，JC 没有单独裁版本号，草稿握手点一并报。依据：`cli/` 与 `docs/agent-api/` 的 diff 为空，`schemaVersion` 仍是 3；没有新迁移；GA 基线没升；唯一的新功能是设置里的一个输入框，够不上「功能量级够一条独立产品线」。
- **GA baseline 仍是 `d66509b`，上游的不跟。主会话定，JC 未裁。** 上游 `main` 是 `6d44d31`（`git ls-remote` 与 GitHub compare 接口查于 2026-11-19），比基线多 19 个提交、20 个文件。前 8 个是 v0.7.7 … v0.7.9 判过的那一批（[v0.7.7 devlog](./2026-11-06-v0.7.7-release.md)）；新增的 11 个（提交时间 11-08 至 11-17：Conductor 渲染分页、`ui_detect` 的本地图标标签、可选的 shadow 模型日志插件、无工具回复以 DSML / XML 样标签结尾时重试、记忆整理与子代理的文档）**只读了提交标题，没有读 diff**。不跟的理由：这一版只动更新连接，升基线要审计、重放补丁栈、跑打包门禁，会把一个两天的小版本拖成另一件事；标题里没有看到要立刻跟的稳定性或安全修复。
- **打包门禁不跑。** `git diff --name-only v0.7.9..HEAD -- managed-ga runner cli scripts .github core/installer docs/agent-api` 为空；`core/tauri.conf.json` 只有 bump 改的版本号。内置内核的载荷与 v0.7.9 相同。
- **Dry run 不跑。** 工作流、打包、签名配置都没动；动的是更新器的运行时逻辑（`core/src/app_update.rs`），tag 构建出的草稿本身不公开，起到同样的作用。
- **没有迁移。** 退回 v0.7.9 不用恢复备份，notes 不写退回说明。新 pref `update_proxy_prefix` 旧版不读。
- **更新渠道**：stable，publish + 冒烟后推 stable。

dev 里已验过的见 [更新连得上的 devlog](./2026-11-19-update-proxy.md)。装草稿前要停掉 dev（两边共用数据目录）。

- **S1（Mac 草稿，必过）**：启动正常；设置里各 IM 渠道是连上的；主对话发一句，答得出来。看的是加了系统代理特性之后，打包版的各条请求照常。
- **S2（Mac 草稿，必过）**：设置 → 通用里有「更新加速地址」一行；留空时「检查更新」报已是最新（与以前同一条路）；填一个真实可用的加速前缀后再检查，仍报已是最新（清单经前缀取回）；填一个不通的前缀后再检查，仍报已是最新（回退直连）。草稿装上后通道里还是 v0.7.9，没有更新可下，**下载经前缀这一步在这一版验不了**，要等 v0.7.10 升到它的下一版。

- **S3b（Mac 草稿）**：一个官方模型点一次「测试模型」，照常通过（`probe_client` 改过）。
- **W1（Windows 草稿）**：从 v0.7.1 欠到现在。这一版新增了只有 Windows 能验的东西：更新器读注册表里的系统代理（S3 的 Windows 版）。
