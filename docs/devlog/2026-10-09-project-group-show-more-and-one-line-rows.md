## 起因

项目体验打磨（同日上午）之后，JC 提了两个问题，后来又加了一个：

1. 项目里的「更早」把项目里的会话分隔开了，能不能变成「显示更多」，点了以后按钮到最下方变成「显示更少」；项目多的时候「显示更多项目」是不是也应该统一。
2. 展开项目后，里面的会话和普通会话、项目行在视觉层级上没什么差异，层次感不足。
3. 项目行是双行，但大多数时候没有需要处理的会话，第二行只有会话数量，是不是不如一行、数字放到别处。

## 讨论

### 尾行

同意，读成分隔线有三层原因：

- 形态：尾行用的是分区头那一档样式（10px 小标签 + 计数 + caret），与「本周」「项目」同档，在组里读成小节头。
- 位置：展开后停在第 5、6 条之间，把一个项目切成两段。
- 名字：10-09 分界改成按条数后，尾部可能是本周的会话；而「更早」在时间桶里的意思是 30 天前、点了开对话框——同一个词两个意思两种行为。

判据：折起来的是另一类东西，还是同一列表的后半截。另一类时开关留在原地当分隔是对的——Gmail 左栏的 More / Less，展开后
Less 停在主列表与隐藏标签之间（[Cedarville 的 Gmail 说明](https://cedarville.teamdynamix.com/TDClient/KB/ArticleDet?ID=58741)：
把标签拖到 Less 上方就回到主列表），因为隐藏的是用户挑出去的另一类标签。项目里的尾部是同一个项目、同一个排序截在第 5 条，
是后半截，开关该在末尾。「显示更少」放末尾这一做法没找到桌面侧栏的权威先例，Apple HIG 也不讲 show more 控件，靠判据不靠先例。

「其他项目」同理：同一个按活跃度排的项目列表的后半截，30 天窗口规则用户看不见。统一后挂出规则顺带变好：此前「其他项目」收着时
需要你的会话直接挂在它下面、不缩进，看不出属于哪个项目（10-08 devlog 记过）；改为借位露出那个项目的整个组行，会话按组的规则
缩进挂在它下面——项目列表借项目行、会话列表借会话行。

### 层级

按代码量的现状：三种行同为 48px 双行、13px 标题 + 11px 副行；项目名与会话标题同为 13px `ink-soft` medium，父行并不比子行重；
唯一的区分是缩进加 1px `brand/35` 引导线，而且两者都没对上网格——线在 24px、文件夹图标中心在 26px，子会话状态图标在 47px、
父行项目名从 42px 起。我的判断：子会话与普通会话是同一种东西，长得一样是对的，缺的是「包含」（看不出组从哪开始到哪结束），
所以先改容器，不改行本身。抽屉的缩进与引导线是 Project Review 原样搬来的，从没单独比过；项目行双行是 10-08 两轮真机定的，
这一题不动它。我推荐 V1（对齐），JC 真机选了 V3（子会话单行）——结构级的那一档，按惯例放上去当对照，结果它赢了。

V3 之前我提了一个顾虑：JC 看 V3 时组里全是空闲会话，单行的代价恰好落在有状态的行上。于是加了「演示」开关（只改显示，伪造
正在工作 / 等你回复 / 出错）和 V3′（空闲单行、有状态保留副行）。V3′ 我不推荐：行高随状态伸缩，一条会话跑完就从 48px 缩到
32px，下面整片跟着跳，常开的状态板上比少一行字更难受。JC 看完定 V3。

### 项目行

第二行除了空闲时的总数，还在干三件事：是正在工作 / 未读的汇总位（10-08 挂出规则：这两种不挂、交给组行汇总）；V3 之后它让
父行（48px）比子行（32px）高一截；10-08 第二轮真机否掉的正是「单行 + 右侧计数」。但第三条的实验条件变了：那时子会话是 48px
双行，单行项目行比自己的子会话还矮、层级倒挂，输掉不奇怪；子会话改单行后值得重比。我推荐 B：空闲时信息不减；等你回复 / 出错
本来就挂在组行下，第二行的「1 个等你回复」与它重复；正在工作有呼吸竖条；每个项目省 12px；右侧数字永远是总数、含义不变
（Mail 在邮箱名右侧放数字是同一类 mac 写法）。C（空闲单行、有状态双行）与 V3′ 同理反对。

## 真机切换器（右下角 pill，localStorage；JC 定）

| 维度 | 档位 | JC |
|---|---|---|
| 尾行 | 现状「更早」/ A 收起在末尾 / A′ 无收起（收起整组后下次从 5 条开始） | **A** |
| 层级 | V0 现状 / V1 对齐（引导线在文件夹图标中心并从图标接下来、子会话图标对齐 42px）/ V2 对齐 + 整组淡底托 / V3 对齐 + 子会话单行 / V3′ 有状态的留副行 | **V3** |
| 项目行 | 现状双行 / B 单行 + 右侧总数 / B′ 右侧随状态换成图标 + 计数 / D 双行、空闲时第二行「最近：某会话」 | **B** |
| 演示 | 全部空闲（真实）/ 最新三条伪造正在工作 / 等你回复 / 出错，另在一个沉底项目里伪造一条等你回复 | 只用于查看 |

JC 看过 A 之后要「显示更多」更小、更安静：字号 12px → 11px、行高 32px → 28px、箭头改 regular 10px 60% 不透明度；颜色不再降
（10.5px + 75% 淡墨曾被社区反馈看不清，汉字最小 11px）。分区末尾那行按我的建议叫「更多项目」：截图里组内「显示更多 14」与
分区「显示更多 2」上下紧挨，只靠缩进区分，「2」是 2 个什么也看不出来。

推翻的旧裁决：10-08 两轮的「组行双行」（理由见上，条件变了）；10-08 的「组内尾行『更早 N』、`SidebarTailToggle`」；10-09 上午的
「其他项目 N ›」。代价：收起的组里「几个正在工作 / 几个未读」的数字没了（JC 开演示状态看过，竖条与字重够用）；子会话的状态行
（「第 N 步 · …」「等你回复」「出错」）看不到了，要点进去。

## 实现

纯 GUI，Core / CLI / Agent API 零变化，外置 / 内置两种运行时一致。切换器（临时变体 store + 右下角 pill + 演示伪造状态）由主会话
直接做；定稿一张 Opus 票，0 返工。

- `SidebarProjectGroup.tsx`：组末 `SidebarShowMoreRow`（「显示更多 N」/「收起」两种模式放在同一个 JSX 位置，收起时是同一个实例，
  `useLayoutEffect` 才能把它留在鼠标下）；借位行在它上方；`GROUP_CHILDREN_CLASS` 换成定稿几何（`pl-6` + `before:` 伪元素引导线在
  25.5px），项目行的连接线从文件夹图标下方接到行底；项目行单行 36px + 右侧总数（空项目不显示 0，主会话集成时补，与「项目」分区头
  不显示 0 一致）；删掉 `SidebarTailToggle`、第二行汇总。为了能测「展开后」，组件加了 `defaultOlderOpen`（同 Radix `defaultOpen`）。
- `SidebarTimeline.tsx`：「更多项目 N」在项目列表之后，收着时沉底项目借位露出组行，展开后末尾「收起」；分区头折叠时的挂出不变。
- `SidebarSessionRow.tsx` / `SidebarTimelineRow.tsx`：`singleLine` prop，不渲染副行、`min-h-8`、按无副行逻辑居中。组内、借位、挂出
  的行传它；分区头折叠时挂出的行与时间桶的行不传。
- 文案新增 `showMore` / `showLess` / `moreProjects` / `showMoreSessionsAria` / `showMoreProjectsAria`（英文 aria 分单复数）；删掉不再用的
  `groupErrored` / `groupWaiting` / `groupWorking` / `groupUnread` / `groupTotal` / `groupOlder` / `otherProjects` / `otherProjectsCount`。
- 测试改为描述定稿行为：`SidebarProjectGroup.test.tsx` 7 例、`SidebarTimeline.test.tsx` 8 例（会话都带摘要，证明组内行没有副行、
  时间桶与分区头折叠时的挂出行有）。
