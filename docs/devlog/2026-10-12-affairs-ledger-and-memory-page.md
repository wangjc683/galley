## 起因

概念重审把主聊天定为「入口 → 事项账本 → 出口」，界面一条、上下文分段。票 01 的账本（后台每天读用户说过的话、按上游历史重点挖掘 SOP 整理）当天上午合入，
默认关、只靠环境变量 `GALLEY_LEDGER_SINCE` 打开。下午到晚上接着做两件：让主聊天真的分段并带上账本（03a / 03b），让用户看得到、删得掉账本记了什么（04）。

## 切段与查历史（03a / 03b）

- **切段**：主聊天上一轮结束后空闲超过 N 小时（隐藏 pref，默认 4），下一条消息开新段：runner 换成新上下文，回放只回放当前段，界面照常显示整条。段界存迁移 046。
- **段首注入**：挖掘最后一步写一份事项短清单（最多 12 行、每行 40 字，Core 截 1536 字节），主聊天和 IM 的状态块带上它。三周的 `activities.md` 已有 17KB，不能整份注入。
- **查历史不做新工具**（裁决 41）：内置提示词已经教模型用 Galley CLI 的只读命令查以前的对话，缺的只是「读到一条前后的内容」和「知道哪条是主聊天、这段从哪开始」。
  CLI 只做加法（`session show --around` / `--since` / `--until`，搜索结果带时间与轮次），状态块加「## Main Chat」一节。
- **主聊天不单独调小 `context_win`**（裁决 39，JC 选 A）：它按整个模型生效、从最早的消息裁、连着工具结果上限，调小会在重任务中途丢掉用户的要求，等于撤回 06-23 的 `751bbc8c`。
  跨话题累积靠切段，单个重任务靠子任务（06）；按体量切段留作预留规则。
- 主会话真机验过：切段、新段不记得旧段、模型自己用 `sessions search` + `--around` 找回、清单联想、重启只回放当前段。

## 宪法 Rule 4 补句

票 01 落地核对时发现：IM 归档是 Core 为账本写的、比引擎日志活得久的副本，08-13 的解释盖不住。补句措辞先给 JC 过目再写（照 Rule 2 的先例），
「用户能在 Galley 里查看和删除」要等票 04 做完才成立，所以随 04 一起写进 `AGENTS.md`。当晚随裁决 47 改了括号里那段（见下）。

合入 04a 时据补句里的「never enters Galley's database」查出一处冲突：挖掘会话跑完只是归档，任务提示词、账本内容、批次里的 IM 原话都留在库里。
改成每次整理结算后把挖掘会话从库里彻底删掉（成功、失败、被停止都删，「清空」和启动时清残留）；顺带修了共用删会话路径不删 `messages_fts` 索引行的旧 bug。
同时加了失败回滚：整理失败或被停止时三个产物文件恢复到开跑前，「失败 = 什么都没发生」。

## 「它记得我什么」页面（04，裁决 43–45）

- 放在设置里新开的「记忆」一页（只在内置），主对话标题菜单「它记得我什么」直达。
- 挖掘提示词把产物格式钉死（上游 SOP 只说「格式自定」），页面按条目显示：标题、一行现状、最近提到、来源对话，展开看原文，每条能删；认不出的段落原样显示，不藏。
- 删一条是确定的；同一件事以后不再被记下，靠提示词遵守「别再记」清单（推断式）；确定式的出口是「不用于了解我」（对话或项目，票 01 的排除表）。不做逐条编辑：改过的内容下次挖掘会被模型重写，要保住还得再造一层覆盖机制。
- 情绪时刻单独一区、默认折叠，写明用法（只为把事办好时引用，不单独评论情绪，裁决 20）；GA 全局记忆两份文件显示原文、可编辑，不受账本开关控制。
- 真模型评测（林晓语料，三次挖掘）：钉死的格式三次都认全；第一次后删掉「日语 N3 备考」，后两周语料仍提到日语，没有重建、编号不复用。
  观察：模型执行「别再记」偏严，把另一条原文里提到日语的半句也截掉了。没改提示词。

## 默认开启：裁决 46 → 47

JC 先问「开关是指什么、为何要有」。答：环境变量普通用户设不了；账本每天把用户的话再交给模型服务商读一遍、推断生活与情绪、花用户的钱，用户没在对话里要求过；
补句当时写的是「用户打开才开」。真正要定的是默认状态，我推荐默认关、主聊天第一次有来有回后问一次（裁决 46），做了 A（输入框上方一条）/ B（时间线末尾卡片）两种形态的真机切换器。

JC 接着重新捋初始阶段：主聊天下个版本才发布，升级和新装的用户就是第一批；理想是一打开就在主对话里，AI 主动说一句，告诉用户记忆默认开着、建议保持开启，不让用户三选一。
我同意方向：要用户主动选择加入，账本多半一直空着，第一天就削掉主对话的价值；AI 先开口正好是「主动找你」。裁决 47：

- **问候用固定文案**（中英两版）：新装的用户这时可能还没配好模型，披露内容要一字不差，也不花钱。只显示、不回放进模型上下文（以 AI 消息开头的历史，有的模型接口可能不接受）；
  账本开着时主对话状态块固定带一行说明，否则升级当天还没有清单，AI 不知道记忆开着（我先说「状态块本来就有」，查代码不对，改正）。主对话因此是空状态规则的例外。
- **以前的对话默认读**，没有单独的开关，「记忆」页只有一个「允许」开关；关掉时仍问「保留 / 清空」（问的是已记下的东西）。每次最多读 6 万字用户原话，读不完 10 分钟后接着读。
- **第一次整理等到下一个 04:00**，不立刻跑：默认开 + 读全部历史 + 立刻跑，等于用户还没读到问候，历史已经交给模型服务商；等到当晚，读到问候的人有几个小时可以关。
- 问候写明读什么（含以前的对话、不含 AI 的回复）、也记情绪时刻且只用来把事办好、第一次整理在今晚、要多调用模型、只存在这台电脑上、在哪关。
- Rule 4 补句括号改为 "on by default, which the main chat's first message tells the user, and the user can turn it off"（JC 认可）。
- 落地（04c）：问候、开关与主对话行同一事务写入；问候用现有来源字段标记（system + `galley-greeting`、`turn_index` −1），不加迁移；
  第一次整理靠开关里的 `notBefore` 挡住，启动时的 IM 归档也等到它之后，在第一次整理前关掉就不留任何副本。开发机上已有主对话的不补问候、不改开关。

## 每次整理的用量（发版前量）

引擎日志不记 token，按「每次调用 = 系统提示 + 截至当时的全部历史」从评测的三次挖掘估算：每次 11 次模型调用，输入累计约 33–38 万字（大部分是每次重发的历史，可走缓存），
输出约 1 万字，最后的历史约 3–4 万字。这是一周合成语料的批次；真实用量随产物变大（三周 17KB）和回溯批次（最多 6 万字）上升。某天没说过话就不调用模型。

## 被否

- 默认关、在主聊天里问一次（裁决 46，被 47 取代），以及它的 A / B 两种形态。
- 开关藏在设置里、只能自己去开（多数人永远不开）。
- 页面显示 markdown 原文、整份编辑（17KB 读不下去，改坏结构会让下次挖掘出错）；逐条编辑（靠提示词尊重改动，推断式）。
- 问候由模型现场写（要模型、不确定、花钱）。
- 「也读以前的对话」单独开关；第一次整理立刻跑。
- 在对话里说「别记了」就关掉：这一版不做，要给 CLI 加写命令，Agent API 的加法另议。
