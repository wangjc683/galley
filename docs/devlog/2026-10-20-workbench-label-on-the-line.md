# 区名「工作台」放回线上：19px 软过渡加居中

日期：2026-10-20
关联：[主聊天 PRD](../../.scratch/main-chat/PRD.md) 裁决 120，票 [68](../../.scratch/main-chat/issues/68-workbench-label-placement-trial.md)、[69](../../.scratch/main-chat/issues/69-workbench-label-on-the-line-final.md)；设计文档 [layout-and-chrome](../design/layout-and-chrome.md) §4.2「区名『工作台』」「下面那块的底与分隔线」；前情 [侧栏分两区](./2026-10-20-sidebar-zones-and-a-living-face.md)

## 起因

JC 看截图：「工作台那个分隔线以及『工作台』的三个字，现在总感觉它有点不够理想，尤其是工作台三个字背后的色块区分」。

## 诊断（裁决 120 第 1 条）

- **色块从哪来**：区名那一行 13px，底色在行内 6px 处由 chrome 硬切成 app。JC 的截图（2x）量得字墨在 402–422 行、台阶在 412 行，正好从字的中线切过：上半个字在灰上，下半个字在白上。票 62 的实现记录在「看到没改」里记过这一条。
- **同一条边界画成了三种**：0–18px 只有底色台阶，18–51px 台阶穿过字，59px 往右是 `line-strong`。
- **主会话当时的判断**：字坐在线的断口里，是表单分组框图例（fieldset legend）的语法，前提是线两边同一种底；这条线同时是底色交界，断口必然露出台阶。所以只有三条路：字整个归上，字整个归下，或者线不再是底色交界。

## 票 68：A、B 与线的两档

- **A 字落进工作台**：线通栏不断，就是底色交界；字整个落在 app 上，是工作台区的第一行，比现在多 5px。
- **B 字站在线上**：字整个在 chrome 上，站在一条通栏的线上，字墨底到线约 3px，也多 5px。
- **线**：两档的线都通栏，296px 的 `line-strong` 比原来约 237px 的一截更重。票 09 定「加重」时线上还没有区名，条件变了，所以加了一档「默认」（`line`），三档位置都能配。
- **测出来的**：浅色下 `line` 对 chrome 只有 ΔL* 2.45，比底色台阶本身的 3.85 还淡，线以上那一侧几乎看不出线；B 档卡片悬停时，字离悬停底 7px、离线 3px，读着像挂在卡片块下面。

## 主会话推荐 A，被真机实感推翻（裁决 120 第 3、6 条）

- **推荐 A 的理由**：共同区域压过邻近，区名落在它命名的那块底上没有歧义；B 的字在助理的 chrome 上，按色块扫会读作「灰块 = 卡片 + 工作台」。
- **JC 真机比完**：先说「有点倾向于 A + 加重，但是拿不准」，主会话的独立意见也是 A + 加重。多看几遍后：「还是感觉有点不理想，从表意上甚至不如是写在线上的位置，只不过之前写在线上的时候有点设计细节没有做好」。
- **认错**：A 把区名变成了列表里的一个标题，表意不如坐在两区交界上。第 1 条说「只能三选一」也说过了头：下一节重新看台阶后发现，毛病不在字坐在断口里，在台阶露出来的那两段。

## 放回线上：几种做法

主会话重新看了一遍台阶：它在区名那一行的 6px 处，线也在 6px。画了线的地方，台阶被 1px 的线盖住；只有左边 0–18px（线还没开始）和字背后（线断开的那一段）露出来，色块就是这两段。修法是去掉这两段的硬边，不必挪字。示意里给了五种：

- **① 软过渡 13px**：只在区名那一行里由 chrome 渐变到 app。
- **①′ 软过渡 19px**：从卡片块下沿那 6px 起，到区名那一行底。
- **② 小签**：字垫一枚描边胶囊。没选：像标签或按钮，抬了层级，违背裁决 114「视觉层级应该低一点」，也多一个容器。
- **③ 同底**：列表回到 chrome，线两边同底。没选：推翻票 09、62 两次真机裁决，悬停与选中在 chrome 上变弱。
- **④ 软过渡加居中**：字落在舞台卡片的轴上，线分两段到两缘。

JC：「①′ + 居中，我感觉比较接近我想要的感觉：安静地介绍用户工作台区域」。比起 13px 那档，他选了更柔的 19px。

## 定下的做法（票 69）

- **软过渡**：从卡片块下沿（从侧栏顶算 180.8）到区名那一行底（199.8），一共 19px，由 `chrome` 线性渐变到 `app`，以下照旧整块 `app` 铺到窗口底。卡片块下面那 6px 从卡片块的 `pb-1.5` 挪进区名元素，一个元素拥有整段渐变，两端就是上面的 chrome 与下面的 app，没有边。高度不变：卡片 52–180.8，线 192.8，新对话按钮 205.8。
- **居中**：字落在侧栏的中轴上，与舞台卡片同一条轴；线分左右两段，各隔字 8px，画到两缘。票 62 定左对齐时卡片是头像贴在 18px 线上的行式卡片，票 67 改成居中舞台，条件变了。
- **不变**：线固定 `line-strong`，「默认」档拆掉；字的配方（11px、常规字重、`ink-muted`、不转大写、不加字距）；工作台铺到底，「已归档」钉在脚上。外置运行时零变化，生产构建逐像素比过。
- **实现里多出来的一处**：区名元素画在卡片块后面，卡片的键盘焦点环（卡片外 2px）的下沿会被渐变盖住。卡片块只在环亮着时定位（`has-[:focus-visible]:relative`），把卡片画在上面。没有常驻定位：常驻时，无头 Chrome 在带 Windows 滚动条的页面上把卡片光栅化得差一两级色值；只在焦点时定位，静止的卡片与此前逐像素相同。悬停底止于卡片下沿，按下时卡片的 `translate` 本来就把它画在上面。

## 真机要看的两点

- 深色下 chrome（较亮）往 app（较暗）渐变，会不会读作卡片块投下的影子。
- 居中的带字分隔线，会不会读作 IM 对话里的时间分隔。
