# 用户消息「更有质感」的实验：零采纳，以及为什么不给抬升

日期：2026-08-21
状态：**零代码改动**。变体真机实测后 JC 裁决「效果都一般，先不改」，
脚手架已全拆，工作区回到实验前状态。
相关：承 [高亮笔重设计](./2026-08-06-user-message-highlighter.md)（本条不
推翻它，只是没能在它之上再加东西）· 同日 [选中行三通道](./2026-08-21-sidebar-selected-row-three-channels.md)
是本条的起因

## 起因

JC 对 sidebar 选中行的新样式满意后回看主对话区：「用户消息的设计样式，
有点死板和太硬了，是否也可以学习 sidebar 选中 session 的样式，变成圆角的、
带抬升质感的呢？」

## 先排除一个嫌疑：不是刚才那两轮改出来的

我刚动过主区的地面（抬画布 + chrome 翻转），所以先自查：

| 阶段 | app L\* | brand-tint L\* | Δ |
|---|---|---|---|
| 08-06 定案时 | 6.45 | 25.09 | +18.63 |
| 08-21 抬画布后 | 10.00 | 28.79 | +18.79 |
| 08-21 翻转后 | 7.51 | 26.39 | **+18.88** |

漂移 0.25，不可察觉；light 从未改动。**「硬」不是新引入的**，是这个形态
一直如此、而 JC 刚看完 sidebar 的抬升后产生了对比。

## 「抬升」被否：这是寄存器问题，不是审美问题

**理由不是 08-06 说过不行**（那次根本没讨论过投影），而是它与我们同期刚
确立的规则直接冲突：

**chrome 是材质，content 是纸。** sidebar 选中行的抬升之所以成立，正因为
它是 chrome——导航状态、控件语汇，卡片浮在材质上是对的。用户消息在 content
层，它是**纸上的墨**。高亮笔的痕迹**渗进纸里**，不浮在纸面上；给它加投影
等于宣称「这块颜色悬在纸的上方」，物理隐喻自相矛盾。

而这正是 08-06 花两轮 A/B 治的那个病——**寄存器倒挂**（原话：「大面积平涂
矩形读作 UI 机件……机器圆润、人方正」）。投影在 Galley 里是纯粹的控件语汇
（button / card / dialog / 浮层，无一例外）。给人的声音加投影，是同一个病
换个方向再犯：机器不再方正，但人的声音穿上了机器的外衣。

**不是理论担心，08-10 已经犯过一次并修回来了**：用户消息的 copy chip 当时
穿 `floating`（实边框 + 实底 + 投影），修正结论是「一个带边框的控件盒紧贴
笔触，正是本次改造要治的寄存器倒挂又犯了一次（机器该克制，人的声音是手划
的）」，改回裸 `inline`。

**这条论证是本篇最该留下的东西**：以后再有「让用户消息更立体 / 更有卡片感」
的提案，先回到这一条。

## 实验：沉积 × 圆角（真机，两维度切换器）

问题重述后可用的手段就清楚了：**在纸墨语汇里，质感来自墨的物理特性
（沉积、边缘、笔头），不来自物体的悬浮**。当前这支笔画得太完美——纯色平涂、
边界绝对整齐，那不是笔痕是印刷色块，「死板」这个词其实非常准。

- **维度 1 · 墨水沉积**：每道笔触下缘用 6px 软渐变压深（light 压暗 / dark
  提亮——方向随主题翻转，同 chrome 规则）。档位 3 / 4 / 6 L\*，对应
  ΔE 0.026 / 0.035 / 0.051（**先算 ΔE 再提案**，避免重演同日「色相归一」
  那种改了也看不见的方案）。
  它同时是 08-06「b-gap 留缝 vs b-fused 融合」之外的**第三条路**：
  `box-decoration-clone` 会逐行重绘背景，所以沉积边能让融合块**重新浮现行
  的节奏，而不必把缝放回来**。这才是它被寄予厚望的地方。
- **维度 2 · 笔触圆角**：2px（现状）/ 4px / 6px，上限取 `--radius-sm`——
  再大就进 chip 语汇，等于把 08-06 明确否掉的 chat bubble 从后门放回来。

**JC 实测裁决：「沉淀和圆角的效果都一般，先不改。」** 零采纳。

## 讨论中已验证否掉的候选（留痕防重提）

- **半透明墨水**（真马克笔是透明的）——听着最忠于隐喻，但**在纯色底上，
  半透明与不透明的渲染结果完全一致**。除非先给主区画布加纸纹，否则零效果；
  而纸纹是全局改动，另一个量级的事。
- **斜切笔头**（chisel tip，马克笔最标志性的特征）——隐喻满分，但与现行
  实现冲突：左右各 4px 出头是偏移 `box-shadow` 画的（08-06 为绕开 WKWebView
  折行 bug 的方案），`clip-path` 会连 shadow 一起裁掉。要做得重写出头方案，
  风险回到那个已经踩过的坑。
- **边缘不规则**（SVG `feTurbulence` 扰动）——真实感最强，但花哨，与
  paper-quiet 调性冲突。
- **内阴影**（inset）——方向上其实与「渗进纸里」兼容（凹陷不是悬浮），但
  `shadow-inner` 在 Galley 已被控件占用（SidebarQuickActions），会造成寄存器
  混淆，且极难做得不像凹槽控件。

## 已知的实现约束（下次动这里必读）

沉积方案若日后重启，第一个要解决的是：**两端那 4px 出头是 `box-shadow`
画的，而 box-shadow 只能画纯色、画不了渐变**，所以主体渐变、两端平涂，
可能出现色差。实验里这一条列为重点观察项。

## 留在账上的欠账（与本次实验无关，但因它被发现）

`--color-brand-tint` 的 dark 值旁边一直写着
`/* Dark-mode user-message band — provisional; revisit in the dark pass. */`，
而 08-21 的抬画布 + 翻转**就是那个 dark pass，我只让它跟着阶梯移动、没有
复核它的响度**。数据上它确实可疑：dark 的带相对地面 Δ **18.88**，而 light
只有 **8.39**——响 2.25 倍。

本次没处理是因为 JC 明确说他看的是 light，而 light 的响度正常，所以这不是
「死板」的病因。**但欠账仍在**，已记入 [deferred](./deferred.md)。

## 探讨出的后续方向（未实施，已记台账）

零采纳之后反推「质感还能从哪来」，结论是**静态形态之外还有三个维度，而其中
两个完全空白**：**时间**（用户消息没有任何入场动效，而 agent 那侧有块级软
淡入——时间维度上的寄存器倒挂）、**声音**（与 agent 正文字号/字重/行高/墨色
完全相同，字这条通道是零）、**空间**（`my-5` 竖向节奏，全局问题、不推荐为
单组件动）。首选是「落笔」入场动效，理由是它维度全空、与「被划过的句子」这
个隐喻高度自洽、且不碰任何已裁决项。JC 当日裁决先不改，方案已存
[deferred](./deferred.md)。

## 方法教训

**「学习另一个组件的样式」这个诉求，要先问那两个组件在不在同一个寄存器。**
sidebar 选中行和用户消息看着都是「一块带颜色的区域」，但一个是 chrome
（机器的部件）、一个是 content（人的声音），它们的质感语汇本就该不同——
这个区分是 08-06 花两轮 A/B 换来的资产。跨寄存器照搬样式，等于把当初测出来
的东西免费还回去。

**实验失败也是结论。** 这次搭了切换器、真机测了、结果零采纳；但「抬升为什么
不给」「哪些候选已验证无效」比一次成功的调参更值得留下——它们决定的是下一次
有人提同样想法时，讨论从哪一行开始。
