# v0.5.5 发布

**日期**：2026-09-30
**上下文**：v0.5.4 后两天，main 上积了当天一整轮 IM 渠道打磨（Discord / Telegram 对话体验对齐桌面、四个渠道重启续接）
与两项同批发现的修复（macOS 停止、`galley llm list`）。JC：「考虑发版了，我们讨论下版本号」→「按建议推进」。

## 裁决

- **发，patch（v0.5.5）。** 按最大单个功能的量级分（`v0.4.1` 起的规则，不看批量）：最大的两项是 Discord / Telegram
  对话体验对齐桌面、四个渠道重启续接，都是既有 IM 渠道线上的呈现与连续性改进，不是新产品线。先例同 `v0.4.7`（Discord
  并行监督，渠道局部语义，在 Telegram 撑起 `v0.3.0` minor 的先例下仍裁 patch）。无迁移；`schemaVersion` 不变——
  `llm list --runtime` 是新增参数，默认输出在内置模式下的变化按 Agent API §7.1 记为行为修复。唯一支持 minor 的是体量
  （新增约 1.46 万行、四个新托管补丁 `0023`–`0026`，`v0.5.0` 以来最大），而体量按规则不计。
- **打包门禁必须跑**：`managed-ga/`、`runner/` 都动了。本机 `mac-x64` 通过（`bundle-python.sh mac-x64` +
  `check-bundled-python-managed-ga.sh`，managed GA import OK，bundle 162M）。
- **GA baseline 本次不审计，理由如下。** 上游 `main` 已到 `f308ee7`，比锁定的 `1b6442f` 多 8 个提交，比 v0.5.4 核对时的
  `e86ca72` 多 6 个。这是连续第四次不审计，也是第一次**引擎代码确有变化**时不审计，所以把判断写全：
  - 引擎三处：`ga.py` 的记忆提炼提示词重写（`start_long_term_update`，含「整理完仍须报告原任务结果」一句）、`llmcore.py`
    的 claude-cli UA 从 `2.1.251` 升到 `2.1.280`、`agentmain.py` 一行只作用于 reflect 模式。其余是 Galley 不用的前端
    （`hub.py`、`stapp.py`、`tuiapp_v2.py`）、上游 `memory/` 两个 SOP 文件和社群二维码。
  - 都不是关键稳定性 / 安全修复，也没有用户报告，不满足 [Upgrade Triggers](../ga-baseline.md#upgrade-triggers) 的立即审计条件。
  - 8 个提交里 3 个是今天推的，上游仍在动；记忆提炼提示词改的是每个内置用户的记忆写入行为，值得单独审计、单独观察，
    不宜夹在一个以 IM 为主的发版里。
  - 下一版照常核对上游；若届时仍未审计，记忆提示词这一项要单列结论。
- **更新渠道**：stable patch，publish + 冒烟后推 stable。

- **装机版的 Channels**（dev 里测过，装机版没测过）：Discord 激活频道在「重启 Channels」后不需重新 @；Telegram 发一条两步以上的
  任务，看状态消息与回答顶部的可展开步骤列表；任一渠道重启后问一句「刚才我们聊了什么」。

- **Windows 停止**：`0025` 只在非 Windows 去掉 close，Windows 分支保持上游行为；装机后在一个长任务里点一次停止。
- **CLI**：装机版内置模式下 `galley llm list` 列出的是模型库里的模型。
