# 全仓审计：读一遍、修确信的、其余逐条裁

**日期**：2026-11-10
**上下文**：`v0.7.7` 发布后四天，`main` 上没有在途功能。JC：「阅读整个项目，找出所有损坏、不一致、低效或不再需要的东西。修复你确信的部分，并将其余部分列出供我审查。」裁决表与各票在 `.scratch/audit-1110/`，合入内容的清单在 [project status](../project-status.md) 的「Unreleased On Main」。本篇记怎么做的、为什么这样裁、哪些被否。

## 做法

- **先跑门禁，再读代码。** 六个脚本门禁、typecheck、lint、vitest、pytest、mypy、ruff、`cargo check` / `test` / clippy 当时全绿（clippy 118 条警告，无错误）。所以要找的是门禁看不见的东西，给审计代理的说明里明写：编译错误与测试失败不归你管。
- **十个只读审计代理，按切片读。** Core 的数据与运行链路、Core 的命令面与 CLI、GUI 三片（对话、外壳、`lib`）、Python 桥与补丁栈、脚本与 CI、远程模块、契约文档、产品文档与 `.scratch`。只读、不许跑门禁（主会话在跑，机器上还开着 `tauri dev`）。
- **证据门槛写进说明。** 每条发现要有能复跑的证据；说「没人用」之前全仓 grep，含字符串用法、模板拼出的 key、`#[cfg(windows)]` 代码；说「与裁决不一致」之前查 ADR、设计文档与暂缓台账；标 CONFIRMED 或 PLAUSIBLE，后者写明哪一环没验；修法分三类：机械安全、改行为、要 JC 裁。已知有意为之的事（死表不迁移、外置模式不追平、远程模块在发布版里关着）列成清单，不许报。
- **169 条发现，分三步落地。** 机械安全且经主会话复核的，当天派三张修复票（`gui/`、Rust 与 runner、文档）合入；其余归成 28 条给 JC，每条附建议；JC 回「按建议推进」后分两波派票。
- **验收靠叠起来跑。** 每一波把各票的分支在一个集成 worktree 里合到一起，跑完整门禁（vitest 三个时区、`cargo test` 本地与 UTC），再逐个变基快进合入，并核对合入后的树与跑过门禁的那棵逐字节相同。能代验的在 dev 里对着真实库验：一次性的测试会话，验完永久删除。

## 当天修的（确信的部分）

值得记的不是清单，是几条被门禁放过了很久的东西：

- 新对话页选的推理强度从功能上线起就没生效：读预选的函数只有一个调用方（浏览器控制的演示），用户走的那条路径从不读它。测试测的是没人走的那个函数。
- webview 仍持有「以任意参数启动十二种 Python」的权限，GUI 自 2026-05 起就不用 shell 插件了，`csp` 又是 `null`。三个审计代理各自独立报了这条。
- 每次写消息都在写事务里全表扫一遍搜索索引，去删一条不可能存在的行（`message_id` 是不建索引的 FTS5 列）。
- 夏令时回拨那天之后，按天滚动的标签会停住直到重启：定时器按「加 24 小时」算，25 小时的那天触发时还在当天，状态没变，定时器就不再重挂。

## 28 条里值得记原因的裁决

- **A1 搜索索引一条规则。** 回填数「该有多少行」用的规则与实时写入不同，于是几乎每次启动都清空重建，还把工具步骤的原始内容灌了进去。统一成「助理行只索引非空的最终回答」会让没有该字段的老会话回答搜不到；量了 JC 的库：181 个有助理消息的会话里只有 1 个完全没有，代价可以忽略。已有的库靠一个 prefs 标记重建一次，不加迁移。
- **A2、A3、B10 只改 CLI。** 项目空闲判断查的是 Core 从不写的状态值；watch 把 runner 安静 120 秒当成 Core 死；pin 旧 schema 时输出里永远写 3。三处都选了不动线上协议的修法。A3 的代价记在票 01：Core 的 runner 管理器锁若在 `ping` 之后卡死，watch 会无声挂住。
- **A5 删、A6 接。** 错误卡片上的重试等按钮五个半月没接线、没人报缺，删掉并把设计文档改成现状。⌘K 的「Enter 直接发问？」同样没接线，主会话起初也建议删；写票时才查到设计文档把它定为要做的功能，退回 JC，改裁按设计接线。结论：「没接线」不等于「不需要」，先查它是不是一条没做完的裁决。
- **B9 改文档不加校验。** 文档要求校验 IPC `protocolVersion`，没有代码校验。Core 与 runner 总是来自同一个安装包，错位在发布版里不会发生，所以删的是要求。
- **C14、B11 删。** 三个没人发的 `tool_call_*` 事件、三个 Goal 遗留的 socket 命令、写入侧的 `visibility`。读取侧的可见性过滤留着：老库里有 Goal 写下的内部消息。
- **D22 载荷的定义变了。** 内置内核从「上游原样加补丁」变成「上游去掉列明的演示媒体加补丁」，每个安装包与更新包小约 22 MB。排除清单逐项列出、不用通配，基线里找不到某一项时构建失败，免得清单过期。`AGENTS.md` 的 Product Shape 那句没改：排除的只是没有代码读的媒体。
- **D20 不改写历史，devlog 也不往前修。** 抹掉的是工作树里的本机路径、测试夹具里的家目录、一个私有仓库的名字、两处真实待办例子（连同评测场景里的地址与开业月份，JC：不管真假直接换）。git 历史与 devlog 条目保持原样：敏感度低，而改写公开仓库的历史会让所有克隆与 release tag 对不上。
- **手册加一句。** 审计收尾时查评测用例 `w-long` 为什么一直不过，结论是两样都有：评测搭错的部分（把并发的工具调用各算一次、叫醒说明没整份交、固定数据自相矛盾）改了；剩下的是主对话读不出截图上的字，每次花三到五步找识字办法，有时还为此把子任务打回。JC 选最轻的修法：手册 `subtasks.md` 验收那条末尾加一句，读不出的截图算没能核对的东西，不找办法、不为它打回。重跑后整套 wake 里带截图的用例都不再找识字办法，该打回的照样打回。

## 被否与暂缓

- **改写 git 历史**：否，理由见上。
- **`release.yml` 的 dry-run**：JC 这次不做。票 04（CI 改用 `.mjs`、删掉没人用的 Setup Python）与票 07（`runner/*.py` 的打包映射）的第一次真验证因此是下次发版的 CI。
- **让主对话真能看图**（打包的 Python 带识字组件，或叫醒时把截图当图片交给模型）：没选，会加 harness；等「主对话需要看图」有别的场景再说。
- **浏览器桥报错时显示诊断原文**：暂缓，进了 [deferred](./deferred.md)。
- **章程的另外两条拒绝**（不 toast、不设保存按钮）：查下来没有被推翻，原意比审计转述的窄；JC：暂不用改。
- **`docs/PRD.md` 全面重写、README 截图重拍**：暂缓，信号分别是下次 minor 或对外介绍产品、下次发版前。
- 没列进 28 条的约 60 条小发现（未实测的性能疑点、IM 渠道两条时序疑点、GUI 与 Core 各一套 runner 淘汰、中继没有准入控制等）记在 `.scratch/audit-1110/PRD.md`，没有逐条裁。

## 过程里记下的

- **主会话四次把话说满了，都当面纠正了。** A6 没查设计文档就建议删；B10 说「核过 Core 写死版本号」，看的其实是测试里请求的字段，数字是 CLI 拼的；A8 说「原始报错留作详情」，Core 给的是一整句、拆不出来；转述「`w-long` 三遍全不过、撞 8 次上限」，实际只有一遍撞上限、上限是 10。共同点是把代理的回报或一眼扫到的代码当成了核实过的事实。
- **本机的 pytest 测的不是内置内核。** `runner/tests/conftest.py` 在不设 `GA_PATH` 时导入维护者主目录下的 GA 检出，CI 用的是仓库里钉住的那份。第二波起集成门禁显式设了它。
- **票面写窄了一次。** D20 的原话包括测试，票 06 只列了手册与一个目录，补了票 09。
- **代理共用 worktree 可行，前提是目录不重叠、提交写明路径。** 第一轮三张修复票共用一个 worktree；`git rm --cached` 之后再用带路径的 `git commit` 会把磁盘上的文件重新加回索引，票 05 撞上过。
- **JC 说试过了而库里没有对应的行**：先找别的痕迹（引擎日志里那次运行的时间与第一句话），再直接问。这次是他试完把测试对话归档并删除了。

## 没验到的、留给下次发版的

- `runner/` 与 `managed-ga/` 都变了，打包门禁必须跑；发版 CI 红了先看三处：`runner/*.py` 的打包映射、`.mjs` sidecar 脚本、删掉的 Setup Python。
- 启动一次确认没有权限报错（shell 插件移除）。
- Windows 真机：安装前钩子现在同时结束主程序与 CLI，应用内更新后的重启会不会被打断只有真机能看。
- 安装包应比 `v0.7.7` 小约 22 MB。
- GUI 的几处没走到：Core 拒绝写入时的回滚与提示、新的错误文案、⌘K 那一行用鼠标点与对话内查找的情形（有 vitest）。
- `w-long` 仍是只记录：加了手册那句之后的三遍里有一遍把全文贴了回来，样本太小，分不清是波动还是改动带来的。套件里也没有「派活说明要了截图、文件却不在」的用例。
