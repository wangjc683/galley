# 回复下的卡片与待办面板

> [Conversation 主区与 Composer](./README.md) 的一篇：2026-11-10 从 `docs/design/conversation.md` 拆出，正文原样搬过来。

#### 回复下的卡片（一框列表）（2026-11-03，主聊天票 133）

一条回复下挂的东西（它交出的文件、派出的子任务、记下的待办、建的提醒、记下的备忘）合进一个框，一件一行（[主聊天 PRD](../../../.scratch/main-chat/PRD.md) 裁决 181、182；框是 `ReplyCards`，各行由 `FileCards`、`SubtaskCards`、`TodoCards`、`ReminderCards`、`MemoCards` 画，共用的类与标题按钮也在 `ReplyCards.tsx`）。只在主对话里画（内置运行时）；工作台、子任务、外置运行时没有。各种卡片自己的内容（图标、短词、状态、点了去哪）见下面各节。

- **框**：照过程卡片的框（`ProcessCard.tsx`）：hairline `border-line`、`rounded-md`、页面底 `bg-app`，里面上下左右 4px（`p-1`），不加投影、不抬升，没有状态竖条。宽度随最宽那一行（`w-fit`），最宽到气泡的上限（栏宽减 134px，`ASSISTANT_BUBBLE_MAX`，裁决 199）；紧贴气泡下 4px（2026-11-06，[主聊天 PRD](../../../.scratch/main-chat/PRD.md) 裁决 199 第 8 条：同一边的气泡之间已是 4px，框还离自己的回复 12px、下面紧跟的气泡只隔 4px，框就读成属于下一条，主对话里「回复 → 待办框 → 叫醒那一轮的回复」就是这样；此前 12px，行动条在框下面）。框不裁内容（没有 `overflow-hidden`）：文件那一行的「在文件夹中显示」浮在框外。
- **次序**：文件、子任务、待办、提醒、备忘。这条回复自己做出的东西在前，然后是交出去的活，再照面板的页序：「待办」页的待办、提醒在前，「备忘」页的在后；同一种照各自的先后。行一行接一行，卡片之间、组之间不留缝。
- **一件一行**：24px（`h-6`），左右 8px（`px-2`），`rounded-sm`；左边 16px 图标列（`h-5 w-4`），图标与名字之间 6px；字号 `--conversation-step-size`（标准档 12px，随对话字号三档变：11.5 / 12 / 12.5px），同过程卡片的行。名字 `ink-soft`，一行省略，被截断时悬停给全文；已经是淡色的照旧淡色（已提醒、已删除、已过期、已移走）；划线、淡化照各卡片自己的状态写法。待办、提醒、备忘的图标上留着 `data-card-icon`：新出现时飞进顶栏待办按钮的那一份从这里起飞（`lib/todo-flight-run.ts`）。
- **浅色对象**：原来卡片右边的东西跟在名字后面 8px（`ml-2`），`ink-muted`，同过程卡片的对象：文件的文件夹、待办的日子与提醒、提醒的时间与状态、备忘的「已删除」「已过期」。文件夹与待办的日子最宽 16em（标准档 192px），自己截断：用长度，不用百分比（见下「两条 WebKit 教训」）。子任务的短词（「等你回复」「出错」「没有跑完」「没有开始」）也跟在名字后面 8px，颜色照旧。提醒的「取消」在行尾（`ml-auto`），20px 高（`h-5`）、左右 6px，字号同这一行。
- **整行可点**：能打开的行（打开文件、打开子任务、打开面板里那一件），点这一行任何空处等于点它的标题。
  - 文件那一行本来整行就是按钮。
  - 子任务、待办、提醒、备忘的标题或那句话是按钮（`ReplyCardTitle`）：往左伸 30px 盖住图标列（行的 8px、16px 图标列、6px），往右一直伸过行尾，靠同样大小的内边距与负外边距（`-ml-[30px] pl-[30px] -mr-[100vw] pr-[100vw]`），排版和量宽都只按自己的字；伸出去的部分由这一行的 `overflow-hidden` 裁掉。按钮是外层的 flex 项，跟着行剩下的空间收窄；字在按钮里自己一层，由它截断，悬停给全文时量的也是它（按钮自己的滚动宽度在 WebKit 与 Chrome 里算内边距的方法不同）。
  - 跟在名字后面、点了该算打开的东西让指针穿过（`pointer-events-none`）：浅色对象、没有原因的短词（「等你回复」「没有跑完」）。各管各的：待办的方框（在标题前面，抬到上层）、提醒的「取消」、悬停给原因的短词（「出错」「没有开始」）、待办日子里那颗铃（悬停给提醒的时间）。
  - 不能打开的行（没派出去、已删除、不在面板里、过期的备忘等）标题是字，没有这一层，点了什么也不发生。
- **悬停与聚焦**：能打开的行悬停时、它的标题键盘聚焦时整行 `bg-hover`、名字转 `ink`，同过程卡片有细节的行；没有下划线、没有聚焦圈，整行的底已经说了。不能打开的行没有悬停底。Tab 落在标题按钮上，回车打开。
- **文件那一行的「在文件夹中显示」**：浮在框右边外侧（离行的右缘 9px：框的 4px 内边距和 1px 边线，再 4px），对着那一行垂直居中；框不为它变宽。它从行的右缘起就在这张文件卡片里面，所以从行移到按钮的路上悬停不断；只在这一行悬停或聚焦时接住指针，框旁边的空白不会把它点亮。
- **在卡片里答提问**（裁决 101 的兜底，见下「子任务卡片」）：提问与输入框在那一行下面原地展开（同过程卡片点开一步），从名字的左缘起（30px），那一块淡琥珀底；这时框撑到气泡的上限，提问与输入框不被挤窄。待办、提醒失败时那一行下面的原因（12px `error`）照旧，也从 30px 起，在框里。
- **图片缩略图**（文件卡片 96px 的那一排）：在框里自成一段，上下 4px、左右 8px，左缘对齐图标列。
- **为什么**（裁决 179–182 的链条）：179 嫌子任务卡片抢戏，降成一行回执；180 嫌回复下的卡片太大（每张都撑到气泡的上限，字只占两三成），先上切换器比宽度与高度；181 认定结构不换、只换画法：挂在气泡下仍是对的，毛病只是大，照主对话里已有的过程卡片，一条回复一个框、一件一行；182 在切换器上比过有框（乙 + 32）、一框列表、无框行，定一框列表。日常一条回复只挂一件（主对话 286 条回复里 32 条挂卡片，29 条只挂一张），一框列表与无框行省的空间几乎一样（派活两张 58 对 56px），差的是框：它让交出的文件像一件东西（票 74 的起因），当时也把回执和气泡下面悬停时出现的行动条隔开（裁决 199 起行动条在气泡右边，不再挨着框）。主对话回复下的框只剩一种样子：上面这个框是这条回复做了什么，过程按钮点开的过程卡片是它怎么做的。
- **两条 WebKit 教训**（票 132b；真窗口是 WKWebView，只在 Chrome 里量看不出来）：
  1. 宽度随内容的框里，不要用绝对定位的伪元素（拉伸的 `::after`）做整行可点。盒子里有绝对定位的子元素时，WebKit 算 max-content 会漏掉中西文之间的自动间距（`text-autospace`）：「制作76人赛季战况网页」少算 3px，「预约11月8日上午9点的体检」少算 9px，框按少算的宽度定，标题就被截成省略号。改用上面那种内边距伸展。
  2. 宽度随内容的框里，浅色对象的上限不要用百分比。框按内容定宽时百分比还算不出来，框会按文件夹全长撑宽，渲染时文件夹又被截到那个比例，框里空出一大截（`~/Library/Application Support/…` 那种文件夹，框 576px，字只写到约 427px）。用 em 或 px 的长度。
- **代价与翻车点**（裁决 181 第 4 条、182 第 3 条）：成果变轻（文件名从 13px `ink` 降到 12px `ink-soft`，退路是文件那一行回到 13px `ink`）；展开「过程」时回复下有两个相像的框（回执的行有图标，过程卡片顶上有数字行）；回执框随内容宽、过程卡片撑满，同时出现时右缘不齐；用几天后若嫌「一件也套个框还是像卡片」，说明嫌的是框，换无框行。

#### 文件卡片（2026-10-21，主聊天票 74）

回复里交出的文件（[助手 PRD](../../../.scratch/assistant/PRD.md) 裁决 10）：回复写的每个 `[FILE:<路径>]` 标记一行，照标记的先后，在这条回复的框里排第一（`FileCards`，`lib/file-cards.ts`；标记从回复正文里拿掉，`filesByMessage` 读的是回复自己的 `files`）。只在主对话里画。

- **一行**：类型图标（Phosphor 的 `File*` 一家，14px thin，`ink-muted`，按扩展名与 Core 说的种类挑；Core 说是文件夹的画文件夹，Pages、Numbers 这类包也算文件）、名字、后面 8px 的文件夹。名字从中间截，扩展名留着（`FileNameText`：前半截省略，后半截不截），被截断时悬停给全名。文件夹把家目录写成 `~`，先截上级、留住最后一级（`FolderPathText`，悬停给完整的文件夹路径），最宽 16em。从不写整条路径。
- **点**：整行是按钮。文档（pdf、docx、xlsx、pptx、pages、numbers，以及 HTML：交出的网页看的是画出来的样子，不是源码；`fileCardClick`）用系统默认程序打开；其余的去正文里文件引用去的地方（`LocalFileWorkspace` 的 `activate`）：Markdown、图片、文本进阅读面板，别的在文件夹中显示。悬停时行外有「在文件夹中显示」；右键菜单是「在文件夹中显示」与「复制路径」。
- **图片**（png、jpg、jpeg、gif、webp）：画成同你自己的图片附件一样的 96px 缩略图（经 asset 协议，裁满），点了在对话的看图里打开（`ImagePreviewDialog`，它的「打开原始文件」）；加载不出来的画回文件那一行。
- **还在不在**：卡片出现时问 Core 一次（`useFilePresences`）。不在了的留着这一行，名字退到 `ink-muted`，后面写「已移走或删除」，没有悬停底，也没有「在文件夹中显示」；点它只再问一次，文件回来了就打开，从不报错。问过之后才挪走的也一样：每次点都先问。

#### 子任务卡片（2026-10-13，主聊天票 06a）

主对话把要跑很久的活派给子任务（[主聊天 PRD](../../../.scratch/main-chat/PRD.md) 裁决 25、52、53）：回复里每个 `<subtask>` 标签开一个子任务，派活的那条回复下面一个子任务一张卡，按标签顺序叠放（`SubtaskCards`，在这条回复的框里一件一行，见上「回复下的卡片（一框列表）」）。卡片只给人看，不进模型上下文；模型要知道子任务怎样了，按编号用 CLI 去查。框紧贴回复气泡下 4px（行动条在气泡右边），见「[助手的对话](./assistant.md#助手的对话2026-10-15)」。

- **一行回执，同待办卡片一个家族**（2026-11-03，[主聊天 PRD](../../../.scratch/main-chat/PRD.md) 裁决 179，票 130；推翻 06a 借工具块的外框）：2026-11-03 起是回复那个框里的一行（裁决 182，见上「回复下的卡片（一框列表）」；此前照待办卡片，一张自己的框，至少 40px，13px `ink` 标题），没有自己的框与底，任何状态都不铺浅底（在卡片里答提问时除外，见下），没有左侧状态竖条。一行里：左边一个**静止**的状态图标，标题（子任务的标题，没有标题时写「子任务」；`ink-soft`、常规字重，一行省略，被截断时悬停给全文），后面 8px 只在要你处理或没办成时写一个短词。不写步数、不写结果、不写「第 N 轮」，没有「打开」按钮：点标题打开（见下「点标题」）。
  - **为什么**（裁决 179 第 1–3 条）：子任务在主对话、侧栏、待办面板三处都看得见，卡片抢戏，视觉层级应低于主对话的消息（JC 2026-11-03 真机）。原来的卡片借工具块：细线框、3px 状态竖条、在跑时铺浅底，两行（标题 13px 中等字重，下面 12px 的步数或结果），右边「打开」；一张约 60px，两张在派活回复与交代回复之间约 130px；同一条回复下的待办、备忘、提醒卡片都是一行、约 40px、页面底、没有竖条。第二行是重复：在跑时同侧栏那一行，做完时紧接着被 Galley 的交代再说一遍。三处各管一件事：侧栏管「现在谁在跑、谁在等你」（[layout-and-chrome](../layout-and-chrome.md)「有主对话时」的「子任务」），卡片管「这条回复派出过什么，点进去看」，待办面板管「Galley 手上的完整清单」。2026-11-04 起只剩两处（[主聊天 PRD](../../../.scratch/main-chat/PRD.md) 裁决 197 第 3、5 条，推翻裁决 179 第 2 条的「待办面板不动」）：待办面板是你和 Galley 将要做的事，不再列子任务；侧栏是「现在」（会转、会走），回执是「记录」（静止、留在派出它的那条回复下、点进去看）。
  - **代价与翻车点**（裁决 179 第 4 条）：往回翻对话时，那件办成什么样只能靠上下文与 Galley 的交代；在跑时卡片上没有进展，要看进展去侧栏或点进去。用哪颗静止图标表示在跑，真机看。没选：乙「一条回复派出的几件合成一行字、不加框」（离开卡片家族，派出四五件时折行，每件的状态分不开）；丙「留框，只去掉第二行与竖条」（仍是单独一种样子）。
- **图标与右边的词**（`subtaskCardWord`，`lib/subtasks.ts`；状态判定照旧是 `deriveSubtaskCard`）：

  | 状态 | 图标（静止，14px） | 名字后面的词 |
  |---|---|---|
  | 在跑 | `CircleDashed`（regular，`ink-muted`）：读作「还没完」；侧栏那一行已经在转，卡片不再转，也不用不转的 `CircleNotch`（看着像卡住） | 不写 |
  | 在问你 | 实心 `PauseCircle`（`warning`） | 「等你回复」（侧栏的字，`warning`、`font-medium`）：提问由助理转到主对话，你在那里答；叫醒没送到、卡片里画出提问来答时不写，提问气泡自己写（下条） |
  | 完成 | `CheckCircle`（thin，`ink-muted`） | 不写 |
  | 失败 | `XCircle`（thin，`error`） | 「出错」（`error`）；悬停给原因全文：「出错：……」「没能启动：……」 |
  | 没有跑完 | `XCircle`（同失败） | 「没有跑完」（`ink-muted`）：没有更多的原因，不挂悬停 |
  | 没派出去 | `XCircle`（同失败） | 「没有开始」（`error`）；悬停给原因全文：「没有开始：Galley 没写要做什么 / 没写完要做什么」「没能启动：……」 |
  | 已删除 | `Prohibit`（thin，`ink-muted`） | 不写；标题悬停给「这个子任务已经删除」 |

  悬停是原生提示（`title`）。无障碍：卡片是一个 `group`，名字是「子任务 · 标题」，有词时接词，有原因时接原因全文（「子任务 · 标题 · 出错：……」），已删除的接「这个子任务已经删除」；标题按钮的名字就是标题。没读到历史的旧子任务先画空心圈、不写词，读完最近一页再定状态。不做浏览器的「已看 3 / 7」与网站图标（裁决 53）。
- **在问你时只写状态，提问在主对话里答**（2026-10-19，[主聊天 PRD](../../../.scratch/main-chat/PRD.md) 裁决 101，票 48；推翻 06a 的「卡片里直接答」）：子任务的提问先到助理（[助手 PRD](../../../.scratch/assistant/PRD.md) 裁决 2），它能替你答的就答，要问你的就在主对话里用它自己的提问问你；卡片只写「等你回复」，不画问题、候选与输入框。起因：06a 的卡片里能答与「提问先到助理」叠在一起，同一个问题在卡片和主对话里各出现一份（JC 2026-10-19 真机）。按 Core 的送达状态判断，不靠提示词。代价：子任务刚问、助理还没转述的几秒，卡片上没有可答的东西（标题照旧能点）；它能替你答的，你看不到这个问题。
  - **兜底：叫醒没送到时在卡片里答**。Core 发 `subtask-report-undelivered`（主对话在等你回答别的事、runner 起不来或没收下叫醒）时，这个子任务此刻的提问画回卡片：复用 `AskUserBubble`——问题、候选 chip、右键 / ⌘ 点击填入——它以无边框的形态坐在那一行下面，左缘对齐名字的 30px（`pl-[30px]`，同待办卡片下面写失败原因那一行；2026-11-03 前是 42px）；这时这一块（那一行连同下面的提问）铺 warning 淡底，框撑到气泡的上限（裁决 182），提问与输入框不被挤窄；淡底（`bg-warning/[var(--opacity-subtle)]`，同提问气泡平时的底），不加竖条（2026-11-03 起，票 130：这一处要你动手，要看得见，又是一张卡片、一层淡底，不压过对话里的气泡；此前穿 warning 竖条与淡底）；名字后面不写「等你回复」，提问气泡的抬头写着；下面一行输入框（「回复…」，Enter 发送，旁边纸飞机按钮），给验证码这类自由回答。点 chip 或回车走的是输入框回答提问的同一条 Core 发送（`send_user_message`），发到子任务，作为它的回答；回答不算「在子任务里说话」，子任务不会因此升级进侧栏。
  - **「这次提问」到哪为止**：从 Core 说没送到起，到子任务再开跑（`turn_start`：你答了，或别处让它跑了）、或之后有一次叫醒带着它送到了助理（叫醒行 `dispatched`，行的备注列着子任务）为止；它换了问题也不算（换问题必然先开跑）。送到了就回到只写状态：助理拿到了，会在主对话里问你，两份不能再出现。判定在 `answeredInCard`（`lib/subtasks.ts`），状态在 subtasks store 的 `askInCard`，不挂组件，切走再回来还在。
  - **页面重载后**：这个状态只在内存里，Core 每份汇报只说一次没送到，重载后不会再说，卡片回到只写状态；提问并没有丢：点标题进子任务，它自己的对话里照旧能答；Core 那份汇报还在等，主对话下一次跑完、不在等你回答时送到助理，由它在主对话里转述。不为此做持久化。

#### 提醒卡片（2026-10-16，主聊天票 37）
