> Galley 设计系统 · 原 DESIGN.md §3–§4.2（2026-07-04 拆分）：两栏布局、SidebarHeader（书眉）/ MainHeader、Browser Control / 内核 / Channels indicator、Sidebar 结构（含有主对话时的助手卡片与收起）、Session Row、Project 组行。

## 3. 整体布局

```
┌─────────────────────────────────────────────────────────────┐
│ Top Bar（44px）— traffic light reserve · Title menu · actions │
├──────────────┬──────────────────────────────────────────────┤
│              │                                              │
│  Sidebar     │   Conversation + Tool Timeline               │
│  14–30%      │                                              │
│  resizable   │   ┌──────────────────────────────────────┐   │
│              │   │ Composer                             │   │
│              │   └──────────────────────────────────────┘   │
└──────────────┴──────────────────────────────────────────────┘
```

- 两栏布局：Sidebar / Main，整体 minimum window width 960px，minimum height 600px。
- Sidebar 用 `react-resizable-panels`，默认 20%，约束 14–30%；宽度持久化到 localStorage。
- Sidebar **有主对话时可收起，外置运行时不可折叠**（2026-10-12 起，主聊天票 08；此前一律不可折叠）。内置运行时有主对话：MainHeader 最左的开关或 `⌘\`（Windows / Linux 为 `Ctrl+\`）收起 / 展开，收起后主区占满窗口，展开回到原宽度；收起状态存 Core prefs `sidebar_collapsed`，跨重启记住。外置运行时没有主对话，侧栏照旧不可折叠，没有开关也没有 `⌘\`。两种运行时都可以拖拽缩到 14%。细则见 §4.2「有主对话时」。
  - **前提为什么变了**（[主聊天 PRD](../../.scratch/main-chat/PRD.md) 裁决 30、34）：05-13 定「不可折叠」的理由是「多 session 是 Galley 的核心产品形态，隐藏 Sidebar 等于隐藏差异化」。有了主对话，侧栏的职责重排为「回到主对话 > 看哪里需要我 > 新开对话 > 找回旧对话」，首页是主对话而不是会话列表，收起后留下的正是首页；JC 真机比过不可收起的同一骨架（B）与可收起的（B′），定 B′。外置运行时没有首页，侧栏仍是产品形态本身，旧理由照旧成立。
- 右侧 Inspector 已退役。详情分散到各自最相关的上下文：Tool callout inline 展示工具细节，Runtime metadata 进入 Settings。
- 主区默认只有 Conversation column；阅读宽度（compact / wide）在 MainHeader 的「显示」popover 里切换（另有 Settings → General 与 macOS View 菜单）。
  点击 Markdown 文件或顶部「改动」时可临时打开右侧阅读面板：主区至少 1080px 时支持拖拽调整，
  预览默认占 46%，全局记住比例，双击分隔线复位；
  否则进入内容工作台档的覆盖预览。关闭后恢复原对话布局。完整行为见
  [本地文件引用与预览](./conversation.md#本地文件引用与-markdown-预览)。
  有主对话时，同一个位置还放 Galley 的待办面板（2026-10-17，主聊天票 42）：每条对话旁边都能开
  （票 46，裁决 95；票 45 时只在主对话开着时出现），由顶栏工具簇的「待办」开关（票 45，见 §4.1「待办按钮」），
  有自己的默认宽度（320px）与自己记住的比例，和阅读面板同时只开一个，后开的换掉先开的；
  主区窄于 760px 时盖住对话的右边，不是对话框。见 [conversation.md](./conversation.md)「待办面板」。

## 4. 组件 Spec

### 4.1 列头（SidebarHeader + MainHeader）

**不存在全宽 top bar。** 两栏各自在 panel 内部长出自己的 header，均 **44px 高**、底边对齐成顶部一条连续 chrome，被全高 `ResizeSeparator` 分隔；两栏两色（Sidebar `bg-chrome` 暗 / Main `bg-app` 亮）。根因：全宽 bar 与下方两栏结构错配——session title 语义属于「当前对话」（Main），全宽 bar 里左对齐会落到 Sidebar 上方、长标题还横跨分割线；在 bar 内按 sidebar 宽度切两段又得追可拖拽 + 持久化的宽度（脆弱）。让每栏各管自己的 header，宽度天然继承、分割线天然全高，两平台的 OS 窗口控制也各自落回本属的那一栏。

两个 header 都带 `data-tauri-drag-region`，共同作为窗口拖动 handle（Tauri v2 需 `core:window:allow-start-dragging` 权限，buttons 自动豁免）；非 mac 双击 header 空白处切最大化（`isWindowActionTarget` 判定），mac 由 overlay 接管。

**SidebarHeader（Sidebar 栏顶，y=0）—— 书眉**（2026-10-03）
- `Galley` 字标（左）+ 搜索 / 定时 / 新建项目三个图标（右），单行。角色是**书眉**：顶部两栏像摊开的书，左页印书名（Galley），右页印章名（会话标题）。整体感靠这个角色和共用的网格，不靠把字标和按钮焊在一起。字标不可点（08-14：它是拖窗把手；按题词先例，误点不能烧掉一个会话）。
- 字标 17px Newsreader 斜体 500，**不缩**：Newsreader 的 x 高只有 0.43em（Inter 0.55em），17px 的 x 高 7.24px 与右栏 13px Inter 标题的 7.10px 同档（字体文件实测）；缩到 14px 小写反而比右栏小一号。宽 46.8px。
- macOS：traffic light 浮于窗口左上 = 本 header 左上，故左 padding 让出 **88px**（红绿灯簇右缘约 68px + ~20px 间隙；代码现状，2026-09-18 回写——早先记的 ~78px 已被实机否掉：10px 间隙让斜体衬线字标看起来挤着彩色圆点）。**不要**退回 78px 或更贴。非 mac 用 16px 常规 gutter。
- 三个图标用 MainHeader 同款 `TopBarIconButton`（28px、16px thin、`gap-1`），左右两栏顶上的按钮是同一种东西；顺序 搜索 → 定时 → 新建项目。右边距让新建项目图标与会话行 hover `⋯` 落在同一竖列（行 `mx-1.5` + 触发器 `right-1.5`，同为 28px）：mac / Linux 12px；Windows 22px，多出的 10px 是会话列表 `scrollbar-gutter: stable` 留的滚动条槽位。新建项目、定时徽标见 §4.2。
- **窄宽回落，单一门槛**：放不下「字标 + 三图标」时，三个图标回到新对话那一行，即 09-28 的一行布局，顶行只剩字标。新对话行两态都在，所以切换时列表不上下跳；字标始终在。门槛按侧栏内容宽度（`@container/sidebar`，面板宽减 aside 的 1px 右边框）：mac 251px、Windows 189px、Linux 179px，算式在 `sidebar/sidebar-width.ts`。
- **有主对话时没有字标**（2026-10-14，主聊天票 18，[主聊天 PRD](../../.scratch/main-chat/PRD.md) 裁决 62、64）：「Galley」是助手的名字，写在书眉下的助手卡片上，品牌只出现一次（§4.2「有主对话时」）。书眉就是红绿灯区加右边的搜索 / 新建项目两个图标（2026-10-17 起，见下条）：macOS 左边让出 80px（与收起侧栏后顶栏开关让出的 80px 同），Windows / Linux 用常规 16px；按钮之外整条是拖窗区，非 macOS 双击最大化照旧；图标与提示照上面这一套，新建项目仍压在会话行 `⋯` 那一列上。窄宽门槛按没有字标、两个图标重算：mac 80 + 60 + 12 = 152px，窄于它两个图标挪进新对话行（外置运行时的一行排法，新对话行一直在，所以跨门槛时列表不上下动；挪下来时「新对话」三个字要 163px 以上，所以只剩加号）；Windows 16 + 60 + 22 = 98px、Linux 16 + 60 + 12 = 88px，都低于最窄的 133.4px（960 窗口的 14% 减 1px 边框），没有窄态。算式在 `sidebar-width.ts` 的 `ASSISTANT_*`（三个图标时是 184px，票 42 前）。此前（票 08 起）有主对话时窄了三个图标落到书眉下单独一行（`SidebarNarrowNavRow`），跨门槛时列表上下移一行高，随主对话行一起撤掉。
- **有主对话时书眉没有第二个图标**（2026-10-17，主聊天票 42，[主聊天 PRD](../../.scratch/main-chat/PRD.md) 裁决 91 第 5 条，推翻裁决 86 第 1 条的「书眉第二个图标」）：内置运行时没有给用户的「定时任务」功能，定时任务是助理的手（裁决 84）；待办的入口在顶栏的工具簇里（下文 MainHeader「待办按钮」，2026-10-17 票 45 起；票 46 起每条对话的顶栏都有；票 42 时是助手卡片下面那一行），书眉回到搜索与新建项目两个。原来 ◷ 的「上次触发失败」计数在内置运行时不显示（角标只放需要你处理的数，07-30；子任务问你、出错已算在助手卡片的徽标里）。外置运行时照旧是 ◷「定时」、它的徽标与原来的定时任务对话框，一个像素不变。⌘K 的「待办」在当前对话旁边打开同一个面板（票 46 起；票 45 时先进 Galley，那时顶栏按钮只在 Galley 里）。
  - 历史：2026-10-16 票 37 把 ◷ 的位置换成 `ListChecks`「待办」，打开一个待办对话框（裁决 86：它是常看的待办，不进第二层；当时没选的有挪进助理顶栏菜单、助理对话顶上的「接下来」条、助理顶栏的图标）。JC 10-16 觉得这个入口还是太弱、对话框也弱（裁决 91），入口挪到卡片下面、打开改在对话旁边。
- 运行时状态与 Supervisor SOP 已移出（2026-10-03）：前者进 MainHeader 状态簇（见下「内核 Indicator」），后者进工具簇。2026-09-18「外置模式 SOP 退成 icon-only」一条随之作废。

**MainHeader（Main 栏顶）** —— `[ 标题 ▾  ··· drag ···  状态簇 │ 工具簇 │ (Win 窗口控制) ]`
- session title 左对齐贴 main 栏左 gutter（**不对齐居中的对话列**——对话列宽随 compact/wide 变，对齐它会让标题左右跳）。title 属于「当前对话」，放在对话区上方、视线最先到达处。本栏左侧无 OS chrome 保留区（例外：有主对话且侧栏收起时，标题前的侧栏开关替红绿灯让位，见下「侧栏开关只在有主对话时出现」）。
- **Session title menu**：有 active session 时 title + `CaretDown` 是一个按钮，打开 session-scoped 菜单：「查找聊天记录… ⌘F」「重命名」，分隔线，「重新注入工具」「桌面宠物」（查找是 2026-10-15 票 28 加的，见下「标题菜单里的查找与重置」）。空状态渲染 italic muted "新对话"，不可点。Rename 进入 inline edit（Enter 提交 / Esc 取消）。
- **开着助手时是身份行**（2026-10-14，主聊天票 18，裁决 64）：主对话开着时，标题的位置换成助手的身份行：28px 头像（与侧栏助手卡片同一个：应用图标裁成圆、加 1px 内描边，2026-10-15 裁决 70，见 §4.2「有主对话时」助手卡片的「头像」）、「Galley」（标题同款 13px medium），名字后面紧跟标题按钮那个 11px 小箭头，名字下一行写状态。整行就是标题菜单的触发器：悬停、按下与打开态同标题按钮（`hover:bg-hover`、`data-[state=open]:bg-hover`），内边距收成 `py-0.5 pl-1.5 pr-2`，填色离开 44px 顶栏的上下边（静止时 32px 高，有状态时 35.4px）；点开是主对话的标题菜单：查找聊天记录、重新注入工具、桌面宠物、重置主对话（查找与重置是 2026-10-15 票 28 加的，见下条），没有重命名（主对话不改名），像 IM 里点对方名字进资料页。第二行照 IM 会话顶栏只写状态：在跑（它正在写字时「正在输入…」，其余时候「思考中」，见本条末；它正在说的那句在下面对话末尾那一行，2026-10-16 裁决 87 起这里不再重复；10-15 裁决 68 到 87 之间写同一句，68 前写「第 N 步 · 摘要」）、等你回复（不接问题原文，原文就在下面的对话里）、出错、子任务在问你、子任务出错；静止时只有名字，不写最后一句，也不写草稿。它与侧栏助手卡片的第二行有意不同：卡片在你不在助手里时替它说话，这里最后一句和草稿都已经在下面的对话与输入框里。在跑时只写一个短状态、不写内容（2026-10-16 裁决 87，JC 真机：顶栏、侧栏卡片、对话区三处同一句「完全是重复多余的」；此前是裁决 68 的同屏说同一句，当时留的退路就是这条）：往上翻历史、末尾那一行看不见时，它仍告诉你它在忙。**在跑时两个词**（2026-10-19 [主聊天 PRD](../../.scratch/main-chat/PRD.md) 裁决 104，票 52）：它正在写字时写「正在输入…」（IM 的「对方正在输入…」，Telegram 的状态本来就分动作），其余时候写「思考中」。「在写字」是确定的判断，不猜：这一步的原始流（`inFlightContent`）里没有没闭合的 `<thinking>`、还没出现工具派发标记（`modelReplyEnd`），清洗后（`cleanPartialContent`，对话末尾那一行用的同一份）有字；`<no-reply/>` 被清洗扣住时没有字，照「思考中」。规则在 `assistantWriting`，只有顶栏读它，选择器只返回布尔值，所以只在两个词翻转时重渲染。两个词同色（品牌色）同高，切换不改身份行高度。主力模型多半不写旁白，「正在输入…」基本只在回复流出的那几秒出现，紧接着气泡长出来（裁决 103）；模型不流式时一直是「思考中」。没选：一律「正在输入…」（等待大半在查和读，不实）、按工具细分（「正在看网页…」：与对话末尾那一行重叠，要维护词表）。身份行在按钮里，不带拖窗属性（`data-tauri-drag-region` 不冒泡，按钮里的元素带上它，按下就成了拖窗）。
- **标题菜单里的查找与重置**（2026-10-15，[主聊天 PRD](../../.scratch/main-chat/PRD.md) 裁决 77，票 28）：照 IM 资料页给菜单派实用的活——微信资料页的「查找聊天记录」「清空聊天记录」。此前主对话的菜单只有两个低频按钮。

  ```
  主对话                     普通会话
  查找聊天记录…      ⌘F      查找聊天记录…      ⌘F
  ──────────                 重命名
  重新注入工具                ──────────
  桌面宠物                    重新注入工具
  ──────────                 桌面宠物
  重置主对话…
  ```

  - 「查找聊天记录…」打开 ⌘K 面板、只搜这个对话（范围标签、日期行、退格去范围，见 [overlays-and-settings](./overlays-and-settings.md)「范围：在一个对话里查找（⌘F）」）。`⌘F` 在任何打开的对话里做同一件事，菜单这一行是发现它的地方，所以普通会话也有：查找的用途两边相同，与裁决 73 有意保留的复制差异不同。行尾的 `⌘F` 照侧栏「新对话」行尾 `⌘N` 的写法（`SHORTCUT_TEXT_CLASS`：等宽 10.5px 灰字，靠右）。普通会话里它和「重命名」同组（对这个对话的日常动作），「重新注入工具」「桌面宠物」照旧在下一组；两个菜单里这两项的先后不变。
  - 「重置主对话…」直接弹出设置里同一个按住 5 秒的确认框（`ResetMainChatDialog`），设置里那一行照留：防误靠按住 5 秒，不靠入口藏得深；跳设置页要自动展开「更多」再滚到那一行，绕且活多。出现的条件同设置那一行：内置运行时、开着的是主对话。有对话在跑时这一项置灰，下面一行写原因「有对话正在运行，结束后才能重置主对话」（设置那一行的同一句）；照设置的导航行只调淡图标和名字，原因那行不调淡，它是唯一值得读的一行。图标 `Eraser`，文字与其他项同色：它只是打开确认框，确认框里才是红色。
  - 不放：手机与 IM 渠道的入口（手机端还没开始做）、关于助手（未定）、模型（裁决 71）、记忆（裁决 49）、子任务列表、免打扰与置顶（裁决 65）、导出（没有这项功能）。
- **子任务的面包屑**（2026-10-13，主聊天票 06a；2026-10-14 起写「Galley ›」，票 18）：主区开着一个还没升级的子任务时，标题前多一段「Galley ›」（无障碍名「回到 Galley」）：「Galley」是一个按钮，与标题按钮同样的命中区与悬停底（`px-2 py-1`、`rounded-md`、悬停 `bg-hover`），墨色低一档（`ink-muted`，悬停 `ink-soft`）——标题是你所在的那一页；中间的 `CaretRight` 11px bold `ink-muted` 是 chrome，不可点。点它回助手（`openMainChat`）。子任务没有自己的侧栏行，这是回去的路；侧栏选中停在助手卡片（§4.2「有主对话时」）。从 ⌘K 打开子任务也是这个形态。挤压时面包屑先让宽（`shrink-[2]`），标题后让。升级后的子任务是普通对话，没有面包屑。外置运行时没有主对话，也就没有子任务。
- 右：两个清晰 group，最后才是 Windows window controls（不属于工具簇）：
  - **状态簇**（aria label：`运行状态`）：内核（2026-10-03 从 SidebarHeader 移入）→ Browser Control → Channels → 应用更新。只放有状态的东西。Browser Control 与 Channels 就绪后是「灯」（见下「两 header 共通视觉规约」），点开状态菜单（菜单式浮层）。

**两 header 共通视觉规约**
- 状态控件统一视觉语法：文字 badge 统一 28px 高度、6px 圆角、12px 字号、border / hover / press 节奏；icon-only 状态统一 28px 方形按钮、Radix tooltip，且不显示浏览器默认 focus outline。色调只表达**状态类别**，不给某个功能单独造身份视觉：`brand` = Galley 在为你做事或邀请你开始（浏览器控制待解锁）；`warning` = 要你动手（如等扫码）；`error` = 坏了；`success` = 做完待看；`neutral` = 过渡中或安静的设置缺口。（2026-10-04 把 `brand` 写进这条：此前条文只列四色，Goal 运行中早已用 `brand`；浏览器控制待解锁从 `warning` 改 `brand`，见下。）
- **灯（lamp）**（2026-10-04，Browser Control 与 Channels）：macOS 菜单栏语法（蓝牙关掉时的样子）——单色，状态画在字形本身。**亮** = 此刻有活连接：就是普通的 16px thin 图标，和相邻工具图标完全一样；**不亮** = 同一图标 50% 不透明度。极性是刻意的：在线是常态，所以融进整排，只有掉线才偏离。墨色与其他顶栏图标相同，亮灭切换无过渡，悬停照常给按钮底板。实现只有一处：`header/TopBarLampIcon.tsx`。当日真机修订：初版把「亮」画成 thin 轮廓下垫一层淡填充（`fill` 字重、`--opacity-medium`），两颗实心图标在细线行里重了一档、不统一，JC 改为现行反转极性；同时否掉的还有斜线 / 叉变体（带斜线的气泡读作「通知已静音」，拼图也没有斜线版）、图标下短线（16px 下看不见）、描边加粗一档（仍不同族）。50% 而非更低：要读作「关着」，不是「不可点」。

#### Browser Control Indicator

Browser Control 是 managed GA 的核心能力，位于状态簇的内核后、Channels 前（仅内置模式）。状态是常驻浏览器桥报来的实时状态（[browser-control.md](../managed-ga-runtime/browser-control.md)）。

| 状态 | 形态 | 点击 |
|---|---|---|
| `connected` / `connected_no_tabs` | `PuzzlePiece` 灯，**亮** | 菜单 |
| `offline`（验证过，插件没连上，多半浏览器没开） | `PuzzlePiece` 灯，**不亮** | 菜单 |
| `not_connected`（从没验证过） | `浏览器控制 · 待解锁` 文字 badge，`brand` | 直达 Settings → Browser Control |
| `error` | 按桥的 `errorKind` 命名的 `error` badge：缺少组件 / 端口被占用 / 连接中断 / 未能启动；无 kind（脚本测试失败、插件目录同步失败）为 `需检查` | 菜单 |
| `unknown`（桥首次报告前、或重启中） | 验证过 → 不亮的灯；没验证过 → 待解锁 badge；验证标记读出前的几毫秒不渲染 | 同对应形态 |

- **待解锁不是待修**（2026-10-04，改 05-27 的 `warning` 规约）：浏览器控制是 Galley 的头号能力，第一印象该是邀请，不是「坏了」。`brand` 而不是 `neutral`：`neutral` 会把它降到「新版本可用」那一档；`brand` 在本簇的含义是「Galley 在为你做事或邀请你开始」，是一类状态，不是这个功能的身份色。
- **`unknown` 不再闪「检测中」**：启动时它只持续约一秒，旧的 neutral「检测中」badge 每次启动闪一下再换成别的。改为按已持久化的验证标记先画结论：待解锁的含义就是「设置没完成过」，这个标记启动时已知。
- **菜单**（菜单式，见上「两套形态」）：只讲状态，行写法与 Channels 菜单相同——**拼图图标**（14px thin，与「设置…」的图标同列）+「浏览器」+ **右列状态词**（与 Channels 的状态词同字号、同色规则）；次行缩进到名称列。
  - 已连接：右列「已连接」克制的 success 绿（与 Channels 的「已接入」同一健康色），次行「N 个标签页」/「暂无网页」浅墨。
  - 未连接 / 检测中：图标 50%、「浏览器」降为 `ink-soft`（灯的语法逐行用，同 Channels 的暂停行）；右列「未连接」/「正在检测」浅墨；未连接次行「打开装了插件的浏览器后自动连接。」。
  - error：右列红字写原因（端口被占用 / 连接中断 / 缺少组件 / 未能启动 / 需检查，即徽章后半截）；次行是桥自己的中文原文（两行截断，全文在 Settings）；探测失败造成的 error 次行是技术原文（2026-10-08 起 store 只存明细，探测的中文整句不再进顶栏）；桥类错误再单独一行「正在自动重试。」（接在原文后会被两行截断吃掉）。连接中断不加这行：桥的原文已经以「正在重试」结尾。**不另起红色标题**：它只是把徽章再说一遍。
  - → 分隔线 →「设置…」菜单项。宽度同 Channels：最小 168px，报错原文可撑到 300px。
  - 2026-10-04 真机三档（A2 标签页数跟在名称后 / A1 标签页数放次行 / B 保留「已连接 · N 个标签页」一句只补图标列），JC 选 A1（见 [devlog](../devlog/2026-10-04-browser-control-ux-round.md)「当日真机修订」）。
**范围说明不进菜单**（2026-10-04 JC 嫌长）：瞄状态的浮层每次打开都要重读，「它能看到什么」读一次就够，只留在 Settings 已连接卡（见 [overlays-and-settings](./overlays-and-settings.md) Browser Control）。

#### 关键决策

- **书眉 Header**（2026-10-03）：`Galley` 字标 + 搜索 / 定时 / 项目三个图标同行，规格与窄宽回落见 §4.1 SidebarHeader；有主对话时没有字标（同节）。产品名使用 sentence case，不使用全大写 wordmark，避免读成 acronym。字标自带 `data-tauri-drag-region`（该属性不冒泡）。运行时状态与 Supervisor SOP 不在这里（移入 MainHeader，见 §4.1）。
- **新对话独占一行 = 逃生出口**（2026-10-03）：侧栏这个按钮是窗口里唯一一直看得见的新对话入口（主区顶栏的「新对话」只是空状态标题；⌘N / ⌘K / mac 菜单栏都要用户先知道，Windows 没有菜单栏）。用户找不到它，会像被困在旧会话里。所以它按逃生出口的三条标准设计：**显眼**（品牌色粗加号 + medium 文字，这一带唯一的颜色）、**能读**（任何宽度都带字）、**位置固定**（不随宽度或状态挪去别处）。代价是不省高度：笔记本宽度下「字标常驻 / 新对话带字 / 省一行」只能三选二，JC 定带字优先于省一行。搜索 / 定时 / 新建项目是低频入口，上顶行是**降级不藏**（JC 本机项目与定时 0 使用，社区用法未知）。定时徽标在时钟图标右上角（只在有待处理事项时出现、增加时 pop）；第三个图标直接新建项目（命令面板也有「新建项目」），见下方「书眉第三个图标是新建项目」。演进：四行（约 152px）→ 一行（2026-09-28，[devlog](../devlog/2026-09-28-sidebar-quick-actions-one-row.md)）→ 书眉 + 独占一行（[devlog](../devlog/2026-10-03-sidebar-header-masthead.md)）。
  - **有主对话时照旧独占一行**（2026-10-14，票 18，裁决 64）：新对话行是助手卡片下面滚动列表吸顶的第一行，三条标准照旧：品牌色加号 + medium 文字，任何宽度都带字（只有 mac 窄于 152px、书眉的两个图标挪进这一行时只剩加号，见下；票 42 前是 184px、三个图标），位置固定。回助手的路是它上面的卡片。此前（票 08 起）有主对话时没有新对话行：逃生出口交给固定在列表上方的主对话行，新建交给「其他对话」分区头的加号（不带字，悬停提示「新对话 ⌘N」）；JC 真机比完侧栏上半块后定「新对话还是单独一行一个按钮更合理」，主对话行与分区头随之撤掉（见下「有主对话时」）。
- **新对话是列表的开头，空状态时是选中行**（2026-10-08，JC 真机比五档后定）：主区是空的新对话输入框时（`screen === "empty"`，含从组行 `+` 进入的项目新对话），这一行用与打开的会话行相同的选中样式（`bg-selected` + 抬起阴影，`aria-current`），侧栏因此永远恰好有一行在说「你在这里」——此前点了新对话，侧栏里没有任何一行亮着。发出第一句后选中交给「今天」里那条新会话。它是动作按钮，选中时悬停也要有反馈（选中时再点一下会把焦点送回输入框）：选中底色朝正文墨色再走一个悬停步（`--color-selected-hover`，浅色混 5%、深色 12%，与侧栏普通悬停的 OKLab 明度步一致）；选中的会话行仍然不响应悬停。它与列表之间**静止时不画分隔线**：列表在顶部时没有东西被裁，那条线只是把新对话隔成一条孤立的工具带；列表一滚动，线出现，标出会话行滑进去的裁切边（macOS 工具栏随滚动出现分隔线的同一行为；1px 边框常在、静止时透明，出现时不跳）。被否：保留分隔线只加选中态（选中被两条线夹在一条带子里，读作工具条上按下的按钮，而不是列表里的一行）、去线不加选中、去线且滚动时也不出线（会话行被看不见的边硬切）。⌘N 常显。
  - **有主对话时也是这一行亮**（2026-10-14，票 18，裁决 64）：空的新对话输入框打开时（项目的也算），新对话行用上面同一套选中样式亮起，直到发出第一句：`createSessionPersisted` 先把新会话放进列表、设为活跃，切屏还要等 `create_session` 与 `activateSession`，这期间它的行已经显示选中，这一行同时退场。项目组行的加号不按下，照旧悬停才出现。侧栏恰好一处说「你在这里」，与选中的会话行同一种语法。它取代了票 13 的按下加号（裁决 56：没有新对话行时，打开空输入框的那个加号保持按下，分区头的或项目组行的，[devlog](../devlog/2026-10-14-new-chat-pressed-plus.md)）。与列表之间静止时照旧不画线；列表滚动后行滑进它下沿时渐隐（见下「有主对话时」），也不画线：卡片下那条 `line-strong` 已经把上下两块分开。
- **新对话文字不截断**：独占一行时任何宽度都带字（中文约需 96px、英文约 116px，都低于最窄的 134px）。只有窄宽回落态（三个图标回到这一行）沿用 09-28 规则：动作文字要么完整显示，要么只剩加号，门槛中文 198px、英文 220px（「New chat」Inter 500 13px 实测 58.8px）。这两个数只在 mac 上起作用（都低于 251）；Windows / Linux 的回落门槛本身就低于它们，回落态一律只剩加号。有主对话时（票 18）：mac 的回落门槛是 152px（票 42 前 184px），挪下来的是两个图标，字要中文 163px、英文 183px，都高于门槛，回落态一律只剩加号；Windows / Linux 没有回落态，字始终在（Windows 这一行还要让出列表的 10px 滚动条通道，英文也只要 124.8px）。
- **新对话永远是普通新对话，行末 ⌘N 常显**（2026-10-09，JC 定，[devlog](../devlog/2026-10-09-new-chat-row-always-plain.md)）：这一行与 ⌘N 是同一个动作——清掉项目上下文、开一个不属于项目的对话；标签永远是「新对话」，行末淡色 ⌘N 只在三个图标回到本行时让位。有主对话时，Windows / Linux 侧栏太窄也让位，字留着（Chrome 实测 Ctrl+N 39.4px，加 1.5px 给 WebKit）：Windows 中文 158px、英文 178px 以下不显示（含滚动条通道），Linux 中文 148、英文 168px 以下；mac 的 ⌘N 跟书眉同一个 152px 门槛（票 42 前 184px）。右缘离侧栏边 18px，mac 上与顶行新建项目图标的字形右缘对齐。在项目里新建走组行 `+` 或组行菜单「新建项目对话」。此前（06-18 起）打开一个项目会话，这一行就变成「新对话 · 项目名」、落进那个项目：那是为项目视图「连贯工作区」定的，10-08 删掉项目视图后前提没了，离开项目要先点这一行、再点输入框下的 ×；逃生出口的三条标准（显眼 / 能读 / 位置固定）里位置和样子都固定，去处却随上下文变，设计文档只好把「永远不变」交给 ⌘N——而 Galley 是鼠标优先（07-05），唯一恒定的出口在键盘上。ChatGPT 的做法同构：全局 New chat 开不属于项目的对话，项目名旁的小图标在项目里开。代价：在一个项目里连开新对话要用组行 `+`（悬停才出现）或菜单，不再是顶上这一行。
- **项目是侧栏里的一个分区，没有项目视图**（2026-10-08，[devlog](../devlog/2026-10-08-sidebar-project-groups.md)）：侧栏只有一个列表，自上而下 置顶 → 项目 → 今天 / 本周 / 本月 / 最近 / 更早。项目会话不进时间桶，折进「项目」分区里所属项目的组行；分区与组行规则见下方「Project 组行」。同一天先试过把组行按活动时间混排进时间桶，JC 真机后翻案：一个列表混两种东西，项目位置随活动跳动，「本周」下的组还装着更早的会话，对普通用户是认知负担。此前（05-22 起）项目要按书眉「项目」进 Project Review 模式看，时间线同时列出全部项目会话、行上不标所属项目——Supervisor 拆一次任务、或一批回归，就把「本周」刷满（JC 库 10-08：近 7 天 25 条里 19 条是一个回归项目）。直接把项目会话从时间线藏起来被否：等你回复 / 出错会在默认视图里失明，也破坏「选中行必在侧栏里」。
- **Project row 不用 emoji**：用 Phosphor `Folder` / `FolderOpen` 表达层级与 filter，避免跨平台 emoji 造成的视觉重量和渲染差异。
- **书眉第三个图标是新建项目**（2026-10-09，JC 真机切换器定，[devlog](../devlog/2026-10-09-sidebar-recent-five-and-new-project-icon.md)）：`FolderPlus`，悬停提示「新建项目」，点了直接打开新建项目对话框；窄宽回落态（三个图标回到新对话行）同一个按钮。演进：Project Review 模式开关（05-22）→ 项目菜单（10-08：新建项目 + 全部项目）→ 新建项目。菜单被替换的理由：它列的项目和项目分区重复，独有的价值只剩 30 天窗口外的项目，而这些项目现在在分区末尾的「更多项目」里（10-09 下午起的叫法，此前叫「其他项目」）；顶上放动作、列表放对象，与「新对话在顶上、会话在列表里」同构；零项目用户此前点开菜单只有「新建项目」和「还没有项目」，多一次无意义的点击。代价：新建项目是项目功能里最低频的动作，占一个常驻位置；窄宽时与「+ 新对话」挨着，图标形状（带加号的文件夹）与颜色（不用品牌色）把两者分开。被否：保留菜单（真机对照档）；去掉书眉按钮、把 `+` 放到分区头（分区头右侧是计数，零项目时分区不出现，项目功能就没有入口了）。
- **项目对话创建是独立动作**：组行右侧轻量 `+`、组行菜单「新建项目对话」（2026-10-09 加，给不靠悬停的入口）、空项目 CTA `+ 新建项目对话`、建完项目，才会把右侧切到 project-aware EmptyState（placeholder: `在 {Project} 里交代什么？`，第一句话 lazily create 到该 project）。展开 / 收起组不设项目上下文，也不改变右侧当前对话——侧栏里展开多半只是看一眼（2026-10-08；Project Review 时代展开即软设项目上下文）。
- **新建项目 / 「查看项目」**：建完项目、或「移到项目」提示里点「查看项目」，在项目分区里展开该组并滚进视野；分区折叠时先展开分区，这次展开会记住（是用户自己要看项目）；项目在「更多项目」后面时先展开那一行。新建的空项目出现在分区里，展开即见 `+ 新建项目对话`。

- **项目上下文是一次性的，打开会话清空它**（2026-10-09 下午，[devlog](../devlog/2026-10-09-new-chat-row-always-plain.md)）：项目上下文只由明确的「在项目里新建」设置（组行 `+`、组行菜单、空项目 CTA、建完项目），第一句话发出后就用完了；所有打开会话的入口（侧栏行、⌘K 会话与消息搜索、「更早」对话框、定时任务对话框）、侧栏新对话、⌘N、⌘K「新对话」都清空它；移动会话不碰它。这回到 05-22 的「一次性」语义。同日上午曾反过来把 ⌘K / 消息搜索 / 「更早」也改成「跟着打开的会话走」（理由是它们与侧栏行不一致），下午 JC 指出新对话因此常常不是普通新对话，查下来该改的是规则本身（06-18 项目视图的遗留），于是全部改成清空。
- **去掉 ACTIVE / WAITING FOR YOU 区块**：普通 timeline 不做状态队列，也不按 failed / waiting / running / unread 重排；状态只在 row 内用 rail / icon / subline / tint 表达。当初的理由之一「Approval Dock 兜底」已随 10-05 移除审批失效；2026-10-12 起（主聊天 PRD 裁决 30）的理由是：在跑的对话本来就在时间线顶部（今天桶按最近活动排），子任务的状态汇到助手卡片（10-14 前是主对话行），等你回复 / 出错的会话在折叠处也会挂出来，不需要另起一块。
- **去掉 "UNFILED" 命名**：通用 Agent 工作台 80%+ 对话本就 free-floating，时间分组就是主体
- **PINNED section** 仅在有 pin session 时显示，空时不占位
- **时间桶是滚动窗口，四桶**：`今天`（自然日）/ `本周`（滚动 7 天）/ `本月`（滚动 30 天）/ `更早`。不用日历周 / 月：日历月在每月 1 号会把上月全部掉进「更早」，那天体验最差；「本周」叫日历名走滚动窗口从未被抱怨过，「本月」照此办理。`本月` 桶 2026-09-09 新增——一周对轻度用户偏短（JC 库里 8–30 天区间的会话数是 1–7 天的近三倍，正是「上次那个任务」最常落的区间），而一个月以上的确可以接受多两步去「更早」里找。加桶而不是把「本周」改名「本月」：重度用户一个月可能四五十条，保留「本周」这一段近的仍然近，一整块「本月」扫起来才有结构。
- **时间桶 header 显示总数**：`PINNED 3` / `今天 5` / `本周 8` / `本月 14` / `更早 24 ›`。数字是桶内的会话数（时间桶里没有项目会话，2026-10-08 起），不拆 running / waiting / failed 分项。「项目」分区头的数字是列出的项目数。「更早」入口的数字是 30 天前的会话数（EarlierDialog 的列表），含项目会话。
- **EARLIER 折叠成单行入口**：sidebar 是当前工作面，不是无限历史列表；完整旧 session 浏览进入 `EarlierDialog`（文案「N 个 30 天前的对话」）。Earlier 入口沿用同一 header + count 视觉族，只多一个 caret 表达可打开。
- **选中行必在侧栏里**（2026-10-03）：当前会话属于「更早」时（从搜索 / ⌘K / EarlierDialog 打开，打开不刷新最后活动时间），它借位挂在 Earlier 入口正下方，是一条普通会话行（选中三通道、⋯ 菜单齐全），入口计数不变，切走即消失、无动效。选中从侧栏以外来、或当前会话换了桶（旧会话发一句话跳进今天）时，行不完全可见就瞬时 `scrollIntoView({ block: "nearest" })`（行带 `scroll-my-2`）；侧栏里点行不滚——行在 pointerdown 激活，滚动会让半露的行在指针下滑走。折叠的项目组里，选中的子会话挂在组行下面；项目分区折叠时，挂在分区头下面（见「Project 组行」），因此照样可见、照样滚进视野；折叠的地方不再挂它，`data-session-id` 不重复（`data-collapsed-drawer` 里的行仍然跳过）。
- **永不空侧栏**：置顶 / 今天 / 本周 / 本月全空但有更早会话时，自动把最近 10 条提出来标为「最近」（2026-09-09 从 5 条提到 10 条，条件从「本周为空」扩到「整窗为空」——本月有内容时正常显示本月桶，不叠加回填）。提出来的行离开「更早」，计数与 dialog 保持一致。

- **子任务**（2026-10-13，票 06a，裁决 25、30、53）：主对话在回复里派出去的活是子任务，是那条回复下面的一张卡片（[conversation.md](./conversation.md)「子任务卡片」），**不进侧栏的任何地方**：置顶、项目、时间桶、「其他来源」、「更早」与「更早」对话框都不列它，⌘K 不搜索时的最近列表也不列（搜索能搜到）。它的状态汇到助手卡片，照会话行的优先级（出错 > 等你回复 > 在跑 > 未读）：子任务在问你时卡片是在问你的样子（头像挂暂停、名字加粗），第二行写「子任务在问你」；出错时写「子任务出错」。主对话自己出错或在问你时，写它自己的。判定与项目组同源（`useSessionsAttention`：在问你看待回答的提问，出错看运行时出错）。子任务开在主区时，**侧栏选中停在助手卡片**（「选中行必在侧栏里」，上文「关键决策」），顶栏是「Galley ›」面包屑（§4.1）。用户在子任务里自己说过一句话（回答它的提问不算），它就升级为普通对话：从此照人开的对话进时间桶，不进「其他来源」，状态也不再汇到卡片（裁决 25「升为旁聊进侧栏」）。
- **重置**（2026-10-14，[主聊天 PRD](../../.scratch/main-chat/PRD.md) 裁决 59，票 15；2026-10-15 裁决 77、票 28 加顶栏入口）：卡片没有菜单，顶栏身份行的菜单也没有重开、归档或删除，裁决 14 不翻：日常不需要重开，上下文由切段承接。想把它整个清掉，入口有两个：设置 → 运行环境 → 更多的最后一行「重置主对话」，与顶栏身份行菜单的最后一项「重置主对话…」（同一个确认框，见上「标题菜单里的查找与重置」）；长按 5 秒确认，连同引擎的长期记忆回到刚装好时（[overlays-and-settings](./overlays-and-settings.md)「Runtime」与「确认弹窗」）。它是数据出口，不是整理上下文的手段；单条消息可以在对话里删掉（气泡的消息菜单：右键或回复行动条的「⋯」），见 [conversation](./conversation.md)「助手的对话」的「消息菜单」（票 32、38）。票 15 把它藏在设置深处，裁决 77 改为防误靠按住 5 秒、不靠入口藏得深（微信的清空聊天记录也在资料页直接弹确认）。重置后卡片换成新的那条（第二行是问候），主区落到它上面；升级过的子任务照旧在列表里。

#### Session Row（参考 PRD §7.5）

Sidebar 的设计目标是一块**可一眼扫描的多 session 状态板**：很多 session 同时跑时，扫一眼左列就能 triage 每个 session 的处境——还在跑 / 等你回复 / 出错 / 完成未读 / 闲置。外围 liveness 在这里是被**加强**的，不是被削弱的（对照 §2.7：A/B 原则在外围监控面是例外，环境 liveness 有价值）。

状态由三条独立信号承载，不互相覆盖：**左侧 status spine（rail + icon）→ 状态行文案 → 标题字重**。

##### 1. 左侧 status spine（rail）

左缘一条 3px 连续状态通道，是整列最先被扫到的信号：

- **running**：brand `bg-brand-strong` **呼吸**（`sidebar-liveness-rail` 底 + `sidebar-liveness-tick` 每步跳动）。**只有 running 会动**——动 = 仍在推进。
- **ask_user**：`bg-warning` 静态。
- **error**：`bg-error` 静态。
- **completed / idle**：无 rail。

motion 语义专属于 running：静态彩条表示「卡在这、需要你」，呼吸表示「正在前进」，无条表示「无事发生」。rail 不表达百分比，不得从左到右推进成 progress bar。ask_user 使用极轻 warning tint，error 使用极轻 error tint，强化可扫性但不改变时间线排序。**running row 不叠底 tint**（2026-07-20 修订）：行背景是「选中」的专属通道——`bg-brand-soft` 与 `bg-selected` 同色值，running 行叠 tint 会与选中行在扫视时无法区分；running 已有呼吸 rail + spinner + brand 状态行 + 加粗标题四条信号，可扫性不依赖底色。blocking 状态保留 tint：色相不同，且属最高 triage 优先级。

**选中态占三条通道**（2026-08-21 修订，真机裁决）：只靠底色不够——底色这条通道被 selected / hover / warning / error / actionsOpen / editing **六个状态共用**，在里面比响度只会让选中读成「更用力的 hover」。三条通道是 ① 底色（chrome 层专属覆写，见 foundations「Chrome 的方向随主题翻转」）② **抬升**（`--shadow-selected`，全行唯一一个投影）③ **减法聚焦**（选中行标题保持 `ink`，其余行降到 `ink-soft`）。有意不用的两条：左 rail 属 running/waiting/error（且选中行常常同时在 running），标题字重属 running/unread。

##### 2. 左侧 status icon（兼承未读）

行最左 14px Phosphor 图标，颜色随状态（见 `status-icon.tsx` `STATUS_MAP`）：

- 静止且跑完（`idle` 与 `completed` 同画）`CheckCircle` muted / 静止但没跑完（步数上限暂停、没有摘要；`StatusIcon` 的 `incomplete`）`Circle` muted / connecting `CircleNotch` 旋转 / running `CircleNotch` **bold** 杏沙旋转 / ask_user `PauseCircle` 深琥珀（「停下等你」）/ error `XCircle` 深红 / cancelled `Prohibit` muted（区别于 error：用户主动）/ archived `Archive` muted。
- **「已完成」由图标承担**（2026-10-03，JC 真机裁决，[devlog](../devlog/2026-10-03-sidebar-polish-selection-visibility.md)）：`completed` 枚举只由 CLI / Supervisor 面写入（`galley session` 收尾），GUI 本地跑完的会话结算为 `idle`（07-05 澄清）；两者都画成 muted 细线对勾圈，看过的完成行不分来源。此前本地完成行是空心环，靠副行 `已完成 · ` 前缀补说完成——空心环在待办类通用语法里恰是「没完成」，前缀又在几乎每一行重复成噪音。空心环从此只留给「停着但不算完成」的静止行。对勾是 muted 不是杏沙：它是几乎每一行的静止态，必须是最安静的那个；杏色只给它的未读形态。同一个 `StatusIcon` 也画 ⌘K 命令面板与「更早」对话框的会话列表，三处一致（那两处不传 `incomplete`，静止会话一律对勾）。
- **三信号优先级必须一致**（rail / icon / 状态行同序）：error > ask_user > running > unread > idle。任何一路擅自换序都会让同一行「自相矛盾」。
- **未读并入左图标，不再用右侧独立点**。旧方案的右侧静点在 hover 时会被 `⋯` 菜单顶替而消失，体验割裂；现在「完成未读」= 把左侧那个本就存在的图标渲染成 `weight="fill"` + `text-brand`（细线对勾圈→杏色实心对勾圈；没跑完的行仍是空心环→实心点），无需新增元素。实心对勾圈与 ask_user 的实心暂停圈同为 14px，靠字形与色相区分（深色模式下两色亮度接近，2026-10-03 真机看过可分辨）；整行还有琥珀竖条、琥珀副行与底色兜底。
- **光学权重而非几何直径对齐**：plain `Circle`（只剩「没跑完」的静止行）是整列唯一的实心盘 / 空心环，按视觉重量调尺寸——实心未读点 `size*0.7`（≈10px，填充墨量重），空心环 `size*0.78`（≈11px），让环略大于点但两者视觉重量相当。其它有内部结构的图标（spinner / check / pause / x）保持 14px。
- 未读优先级低于进行中状态：`showUnread` 仅在 settled（非 active、非 running、非 ask_user、非 error）时为真。

##### 3. 状态行文案（subline = 状态行）

第二行直接当状态行用，始终状态着色、**直立不斜体**，blocking 状态给显式文案，扫一眼即读懂、不靠解码图标：

- running：`第 N 步 · {summary}`（brand-strong，N=最近完成步 `lastStepIndex`，故意比实时滞后一步）或首步未完成时 `思考中…`。这是工作台的会话行（子任务卡片同源）；助手卡片在跑时不报步数，说主区那一行的同一句（见上「助手卡片」，裁决 68）。N 是 run 内按位置的连续序号（2026-09-18）：GA 每次 `put_task` 步号从 1 重数，ask_user 回复也是一次 `put_task`，侧栏把 GA 步号加上回复前已完成的步数（messages `runStepBase`），与主视图序号栏同源，不再在回答后跳回「第 1 步」。
- ask_user：`等你回复`（warning，copy key `waitingForYou`）。
- error：`出错 · N`（error，`errored`；N=1 时不显示计数）。
- settled：只留 `{summary}`（muted）——「已完成」由左侧对勾圈说（2026-10-03；05-12 选的 `已完成 · ` 前缀当时只与「第 N 步 · 」和完成徽章比过，没测过不加前缀）。只有没跑完的才带词：cancelled `已中止 · {summary}`——用户主动中止的会话不得声称完成；步数上限暂停 `已暂停 · {summary}`（空心环）。标记例外、不标记常态，同「· 1 是噪音」。

计数（error）折进 subline，不再单设角标行，且**仅 N>1 时显示**（`· 1` 是噪音）。`{summary}` 在 running→settled 间保持稳定，只换前缀，给用户视觉连续性。legacy `第 N 步 · ` 前缀在渲染时 strip，无需 DB migration。时间桶（今天 / 本周）跨午夜自动重算（`useDayStamp`），常开监控不再停留在昨天的分组。

##### 4. 标题字重 + 入场 pop

- 标题 13px Inter，进行中 / 未读 / 各 blocking 状态 `font-semibold`，其余 `font-medium`。
- **截断用渐隐，不用省略号**（2026-10-08）：标题与状态行排到 18px 文字边为止，真被截断时最后 22px 淡出（`.truncate-fade` + `lib/truncation-fade.ts` 维护的 `data-truncated`；放得下的行不渐隐，免得末字落进渐隐区像被截了）。浏览器的 `…` 只能在整字处截断，汉字 13px 一个，截断的行右缘散在约 10px 的带里，截在全角逗号后还会出现浮着的「，…」。遮罩只加在文字上，选中 / 悬停底色不受影响。
- 标题与状态行截断时用原生 `title` 补全文（§4.1 icon-only 不用原生 `title` 的例外），且**只在确实截断时**挂：悬停时量 `scrollWidth > clientWidth`（`lib/truncated-title.ts`），放得下的文字不再弹一个重复自己的系统提示框（2026-10-03）。悬停时量是有意的：悬停时行右侧给 ⋯ 让出 28px，静止时放得下的标题悬停时可能被截。
- **一次性入场 pop**（`sidebar-state-pop`）：进入 error / ask / unread 时图标弹一下（keyed on `attentionKey`，replay on entry，不在 in-state 时循环）。强 overshoot（scale 0.42→1.38→0.94→1，0.44s `cubic-bezier(0.22,1,0.36,1)`）确保在繁忙状态板上是明确的「看这里」一拍。**running 不 pop**（它已有呼吸 rail + 旋转图标）。**挂载不 pop**（2026-07-05）：entry 指状态迁移；启动时全列齐射「看这里」不是信息，是噪音。
- 所有 sidebar 状态动效都遵守 §2.7 与 reduced-motion：呼吸 rail 属外围 liveness 例外保留；pop / step-tick 是一次性入场，禁止无限闪烁 / shimmer / 大面积背景呼吸；`prefers-reduced-motion` 下 `sidebar-liveness-rail` / `sidebar-liveness-tick` / `sidebar-step-tick` / `sidebar-state-pop` 全部关停。
- **Desktop Pet**：Cat icon 是 session status badge，仅在绑定 session 出现。
- **Supervisor 来源徽标**：`origin.via === "supervisor"` 的 session 在标题右侧显示 `PlugsConnected` 小徽标，tooltip / aria 为「Supervisor 创建」。这是 provenance，不是运行状态；不得参与排序，也不得覆盖 running / waiting / error 的 rail、icon、subline。

#### Project 组行

2026-10-08 起项目是侧栏里的「项目」分区，每个项目一行可折叠的组（[devlog](../devlog/2026-10-08-sidebar-project-groups.md)），取代 Project Review 的项目行与抽屉。

##### 项目分区

- **位置固定**：置顶之下、今天之上（JC 真机定；「置顶之上」与「组行混排进时间桶」落选）。项目有固定的位置，不随最近活动在时间桶之间跳动。
- **分区头**：时间桶标题同款（10px 标签 + 右侧计数，同一网格），计数后跟 caret，展开时朝下。caret 伸进按钮右侧的内边距（`-mr-[11px]`，caret 9px + 间距 2px），计数右缘与时间桶计数落在同一条 18px 线上；「更早」入口同样处理（2026-10-09；此前 10-08 起计数偏左 11px）。计数 = 列出的项目数，为 0（只剩「更多项目」）时不显示数字。不放「+ 新建项目」（右侧是计数；新建项目在书眉与 ⌘K）。
- **可折叠，跨重启记住**（JC 真机定，「只是标签」落选）：默认展开；折叠状态存 pref `sidebar_projects_collapsed`。启动时读回偏好之前就点了折叠的，以用户这一下为准。新建项目 / 「查看项目」遇到分区折叠会先展开它，这次展开照样记住。展开 / 折叠是瞬时的，没有高度动画：折叠时组整个卸载，保证每个会话只挂一份。
- **只有项目分区可折叠，置顶与时间桶不折**（2026-10-08 讨论定）：容器才折，刻度不折。项目分区能折，靠三条同时成立：在「今天」之上且高度不定；内容是长期存在的对象，又常是副产品（回归批次、Supervisor 拆出的子会话）；折叠时有挂出兜底。今天 / 本周 / 本月是同一条时间线上的刻度：折「今天」等于折掉状态板最常看的一段（挂出规则不露正在工作），折叠状态跨重启记住时，次日新建的对话还会落进折着的桶、切走就不见；本周 / 本月在主要内容之下，折了不会把任何东西提上来，「本月」又是「上次那个任务」最常落的区间（09-09）。置顶算容器，但内容是用户逐条挑来放在手边的，折它等于撤销置顶；JC 库 10-08 置顶 0 条，没有折的理由。
- **折叠后与「更早」入口同形，不改**：分区折叠后是「项目 N ›」，与「更早 N ›」同一写法，一个就地展开、一个开对话框。不改的理由：这个形态只在用户亲手折过分区后出现，误判的代价是一个能关掉的对话框；caret 在右、悬停才有反馈是 mac 侧栏的惯例（Finder 悬停分区名时箭头出现在名字右边，[Apple 支持 127254](https://support.apple.com/en-gb/127254)），挪到标签左边是 IDE 的惯例，还要在网格外多一个元素。比 Finder 好的一点要保持：caret 与计数常显，折起来也看得出里面有几个（Finder 折叠后只剩灰字标题，有用户以为收藏夹丢了）。回看信号：有人反馈点「更早」以为会就地展开，或折了项目之后找不到。
- **分区折叠时，需要你的会话挂在分区头下面**：出错、等你回复的项目会话与选中的项目会话，作为普通会话行直接列在分区头下（不缩进、不带引导线，它们可能来自不同项目），同时间桶列行的方式。正在工作与未读不露。
- **列哪些项目**：置顶项目、30 天窗口内有未置顶会话的项目、窗口内新建的空项目；窗口内会话全部置顶、又没置顶的项目不列。没有任何项目时不出现分区。
- **更多项目**（2026-10-09 起；同日上午叫「其他项目 N ›」、写成分区头样式的折叠行，下午 JC 真机改定，[devlog](../devlog/2026-10-09-project-group-show-more-and-one-line-rows.md)）：其余项目是同一个按活跃度排的列表的后半截，所以控件在列表末尾：收着时最后一行「更多项目 N」（列表行样式，见组行「显示更多」），点开后这些项目的组行接在后面、同序，最末一行变「收起」；展开状态只在本次运行内记住。收着时，某个沉底项目里有出错 / 等你回复 / 选中的会话，**借位露出整个项目组行**（在「更多项目」上方），那条会话按组的规则缩进挂在组行下——项目列表借项目行、会话列表借会话行，挂出来的会话看得出属于哪个项目（「其他项目」时代直接把会话挂在那一行下、不缩进，看不出归属）；N 不含借位的项目。分区折叠时，这些会话照旧直接挂在分区头下。这些项目的旧会话同时也在「更早」里，「更早」入口不再借位挂它们（`groupedSessionIds`）。只剩这些项目时分区照样出现。将来加项目数量上限（deferred），溢出的项目并进这一行。
- **顺序**：置顶项目在前，再按内容活跃度（`sortProjectsForNavigation`；「更多项目」里同序）。不按时间桶拆分：一个项目只出现一次。
- **置顶会话不进组**：项目里置顶的会话作为普通会话行留在置顶区（置顶优先于日期）。置顶区因此只放会话，置顶的项目在分区顶部。

##### 组行

- **一律折叠**：只有一个会话的项目也是组（JC 真机定，「≥2 才折」落选）——项目会话永远在项目行下面，行的形态不随数量变。启动时全部折叠，展开状态只在本次运行内记住（「默认展开」落选）。
- **组内平铺，只显示最近 5 条**（2026-10-09 JC 定，此前按 30 天窗口分界）：未归档、未置顶的会话按最近活动排序，显示前 5 条（`PROJECT_GROUP_RECENT_COUNT`），其余的收在组末一行「显示更多 N」后面。为的是 JC 的常见场景：同时开着三个项目、每个都有会话在推进，历史会话多时，上一个组的历史会把下一个组正在推进的那条挤出小屏（三组各 15 条时，第二、三条活跃会话在第 17、33 行左右；K = 5 时三组约 980px，比 K = 3 的约 690px 多，JC 取 5）。分区列哪些项目仍按 30 天窗口。不分时间组，所以分界改成按条数不打破任何时间标签；尾行里 30 天前的会话同时也在「更早」入口里。空项目展开显示 `+ 新建项目对话`。
- **「显示更多 / 收起」在组末**（2026-10-09，JC 真机定，[devlog](../devlog/2026-10-09-project-group-show-more-and-one-line-rows.md)）：尾部是同一个列表的后半截（同一个项目、同一个排序，只是截在第 5 条），所以控件在列表末尾：收着时组末一行「显示更多 N」，点开后其余会话接在最近 5 条后面，这一行移到组的最末变「收起」；收起时补偿滚动，让这一行留在鼠标下（上面十几行一起消失，WebKit 系 WebView 的 CSS 滚动锚定不可依赖）。N 是隐藏条数，不含借位露出的。此前（10-08 起）是一行「更早 N ›」：分区头样式（10px 标签 + 计数 + caret）读成组里的小节头，展开后停在第 5、6 条之间把一个项目切成两段；10-09 分界改按条数后尾部可能是本周的会话，而「更早」在时间桶里的意思是 30 天前、点了开对话框——同一个词两个意思两种行为。判据：折起来的是另一类东西（Gmail 左栏 More / Less，Less 留在主列表与隐藏标签之间，因为隐藏的是用户挑出去的另一类标签），开关留在原地当分隔；是同一列表的后半截，开关在末尾。落选：「无收起」（A′，靠点项目行收起整组、下次从 5 条开始；长组想缩回要滚回顶上点两下）。
- **「显示更多」行的样式**：列表行，不是小节头——图标列一个 10px ⌄ / ⌃（regular、60% 不透明度），文字列 11px `ink-muted`「显示更多 / 收起 / 更多项目」，右侧隐藏条数，行高 28px（JC 嫌 12px / 32px 那版不够安静；颜色不再降，10.5px + 75% 淡墨曾被社区反馈看不清，汉字最小 11px）。侧栏里于是只剩两种折叠形态，各管一件事：小节头样式（「项目」可折叠、「更早」开对话框）、列表末行（「显示更多 / 收起」，就地接续）。
- **子会话单行，引导线从文件夹图标接下来**（2026-10-09，JC 真机定，[devlog](../devlog/2026-10-09-project-group-show-more-and-one-line-rows.md)）：组内的子会话（展开的抽屉、组折叠时挂出的、借位露出的）只留状态图标 + 标题，行高 32px；分区头折叠时挂在分区头下的会话、时间桶里的会话仍是双行。引导线在 25.5px（文件夹图标中心），展开且有会话或有挂出行时从图标下方接到组行底；子会话的状态图标对齐父行项目名的 42px 线。此前（Project Review 抽屉原样）是 `ml-6` + `border-l`：线在 24px、子会话图标在 47px，都没对上网格，三种行同为 48px 双行、同字号同字色，展开后看不出组从哪开始到哪结束。真机比了四档：对齐（V1）/ 对齐 + 整组淡底托（V2）/ 对齐 + 子会话单行（V3）/ 有状态的子会话保留副行（V3′）。JC 定 V3。代价：子会话丢掉状态行，「第 N 步 · …」「等你回复」「出错」的字看不到，状态靠图标、竖条、底色、字重；V3′ 落选的理由是行高随状态伸缩（一条会话跑完就从 48px 缩到 32px，下面整片跟着跳），状态板上更难受。
- **单行 + 右侧总数**（2026-10-09，JC 真机定，[devlog](../devlog/2026-10-09-project-group-show-more-and-one-line-rows.md)；10-08 两轮真机定的是双行）：与会话行同网格（16px 图标列、42px 文字列），行高 36px（比单行子会话高一档）。`Folder`（展开时 `FolderOpen` + `text-brand-strong`）+ 项目名 + 置顶图钉，右侧 11px 淡色总会话数（含尾部的旧会话），落在右侧 18px 文字边上，悬停 / 菜单打开时让位给 `+` 与 `⋯`。Mail 在邮箱名右侧放数字是同一类 mac 写法。为什么翻 10-08：空闲是常态，第二行这时只有「共 19 个对话」；等你回复 / 出错的会话本来就挂在组行下面，第二行的「1 个等你回复」与它重复。10-08 第二轮否掉的正是「单行 + 右侧计数」，但那时子会话是 48px 双行，单行项目行比自己的子会话还矮、层级倒挂；子会话改单行后条件变了，重比。代价：收起的组里「几个正在工作 / 几个未读」的数字没了，只剩呼吸竖条与加粗的项目名（JC 开演示状态真机看过，够用）。落选：右侧数字随状态换成状态图标 + 计数（B′，同一位置的数字含义会变）、双行但空闲时第二行写「最近：某会话」（D，加字而不是减字）、空闲单行有状态双行（行高伸缩，同 V3′ 的理由）。
- **状态汇总**：优先级 出错 > 等你回复 > 正在工作 > 未读 > 空闲。左侧 3px 状态条同会话行（running 呼吸 / waiting 琥珀 / error 红），有任何非空闲状态时项目名 semibold；进入 error / ask / unread 时文件夹图标 pop 一次，挂载不 pop。2026-10-09 起没有文字汇总行（见上一条）。
- **组行永远不用 `bg-selected`**：侧栏里恰好一处在说「你在这里」：选中的会话、新对话行（项目的空白新对话也是它），或开着助手时的助手卡片；展开只靠 `FolderOpen` 表达。悬停 `bg-hover`。（2026-10-14 前，有主对话时项目新对话按下的是这一行自己的加号，票 13，随票 18 撤掉。）
- **折叠时，需要你的会话露出来**：出错或等你回复的子会话、以及选中的子会话，作为普通会话行挂在组行正下方（同样的缩进与引导线），每个只挂这一份——折叠的抽屉里不再挂它。正在工作与未读不露，交给组行的竖条与字重。规则：需要你处理的会话永远不会被折叠藏起来。展开时「显示更多」收着，尾部里出错 / 等你回复的会话与选中的会话借位挂在「显示更多」上方（同「更早」入口的借位；2026-10-09 起不只选中的——尾部也是折叠，分界改成第 5 条之后，最近几天的子会话也会落进尾部）。

- **删除项目：确认框里带「同时归档」**（2026-10-08，[devlog](../devlog/2026-10-08-sidebar-project-groups.md)）：删除项目不删除对话，对话脱离项目、按最后活动时间回到今天 / 本周等分组（外键置空），这一步撤不回来，重新归组只能逐条「移到项目」。这与「删文件夹连内容一起删」的直觉相反（ChatGPT 删项目即连对话一起删），想清理的人选了最彻底的红色按钮，得到的却是被刷满的时间桶。所以确认框把分叉摆成一个选择：标题「删除项目「名」？」，下面一行「项目删除后无法恢复。」，再是一块下沉勾选框（ArchivedDialog「清空」勾选框同款）「同时归档里面的 N 个对话」，**默认勾上**，勾选框里第二行说当前选择的后果——勾上：「归档后可以在「已归档」里恢复，但不会再回到这个项目。」（有运行中的会话时接上归档全部对话的同一句提醒）；不勾：「对话会回到侧栏，按最后活动时间排进今天、本周等分组。」N 与归档全部对话同一组（`archivableProjectSessions`：未归档、未置顶），置顶的会话留在置顶区；N 为 0 时没有勾选框。确认按钮始终是「删除项目」。默认勾上是推测：删项目的人多半想让它消失；库里不记删除动作，没有数据。被否：菜单项改名「解散项目」单做（一个词说不清对话去哪，确认框照样要写）；项目整体归档（要动 Core 数据结构与 CLI 契约，进 deferred）。
