## Dialog 关闭按钮（2026-08-07 裁决）

统一承载组件是 `ui/dialog-close-button.tsx` 的 `DialogCloseButton`——
新 Dialog 不许手拼 `Dialog.Close + IconButton + X`。规则：

- **内容型 Dialog 右上角必有 X**（浏览 / 表单 / 工作台类：Earlier /
  Archived、Create/Edit Project、Prompt Manager、Scheduled Tasks、
  Tutorial、Settings、图片预览）。
- **确认型 / 强制选择型不放 X**：关闭语义走 footer 按钮 + Esc
  （ConfirmActionDialog 一族、FirstClose）。给 confirm
  加 X 会制造第二条模糊的"取消"路径。
- 两个变体：`inline`（默认，ghost，进 header row）；`floating`
  （同为 ghost 气质 + `bg-elevated/80` 半透明垫 + backdrop-blur，浮在
  可滚动内容或图片上，定位由调用方给，如 Settings 的
  `absolute right-3 top-3`）。真机 A/B（2026-08-07）否掉了 floating 用
  secondary 边框凸起的旧样式：关闭按钮语义上应安静，"能见"是版面的
  责任，不靠按钮自我防卫——见下条。
- **X 浮在滚动内容上的面，版面必须给 X 让出安静背景**：Settings 右栏
  顶部 48px 安全区（内容 `pt-12` 起步，静止零重叠）+ 同色渐变层
  （`--color-app` → 透明，`pointer-events-none`，静止隐形、内容上滚时
  文字在钻到 X 底下前淡出，无需滚动监听）。诊断记录：X 与右对齐控件
  抢角落是结构问题，皮肤解不了。
- 图标一律 `X` 14/thin（28px 按钮）；`size="md"`（32px、图标 17）是
  记录在案的唯一例外，只给沉浸式全出血面（图片预览）。
- X 一律不带 tooltip，aria-label 统一 `common.close`。
- 关闭只走 Radix `Dialog.Close` → `onOpenChange(false)` 单一路径，
  不在关闭按钮上另挂 onClick。

## 确认弹窗（2026-10-14 立节）

确认型弹窗共用一个 shell：`ui/confirm-action-dialog.tsx` 的 `ConfirmActionDialog`。

- 压过父 modal 的二级层（`z-60`，见 [onboarding-and-cards](./onboarding-and-cards.md)「Overlay 层级」），
  420px 宽、`bg-elevated`；不放 X，关闭走「取消」与 Esc（见上节）。
- 「取消」默认聚焦，回车不会误触执行；确认键在它右边。
- 正文写全删什么（例：渠道的解除接入，见「Channels」）；正文是块，可以放段落与列表。
- 主对话里删一条消息不弹确认，用撤销提示条（[主聊天 PRD](../../.scratch/main-chat/PRD.md) 裁决 85，票 38；推翻裁决 83 的「只删一条、标题已说全时确认框可以没有正文」：JC 真机嫌它像正文被删了、空间浪费）：气泡立刻藏起，提示条给 5 秒「撤销」，走掉才真删，见 [conversation](./conversation.md)「助手的对话」的「消息菜单」与 [onboarding-and-cards](./onboarding-and-cards.md) 的提示条。`ConfirmActionDialog` 的正文仍可省略，现在没有调用方这样用。

**做了收不回的，用长按确认**（2026-10-14，[主聊天 PRD](../../.scratch/main-chat/PRD.md) 裁决 59，票 15；
目前只有「重置主对话」用）：确认键换成一颗要按住 5 秒的按钮（`ui/hold-to-confirm-button.tsx`；时长是
`lib/hold-to-confirm.ts` 的 `HOLD_TO_CONFIRM_MS`，计时与规则也在那里，带单测）。

- 按下开始，按钮内从左到右填充 error 色，线性，填满即执行。满没满按时间戳判断，不看动画。
- 松手、指针移出按钮、窗口失焦、按 Esc 都是取消，填充退回（票里写约 200ms；新代码不写时长字面量，取
  `--motion-base` 160ms）。不到 5 秒就松手，按钮下出一行「要按住不放」，下次按下时收起。按住时的 Esc
  只取消这次按住，弹窗留着；再按一次才关。
- 只认鼠标：按钮只有 pointer 事件，没有 click 和键盘处理，回车、空格都不触发；不用 pointer capture，
  移出按钮就算松手。
- 按住时界面不能动：提示行绝对定位在按钮下，弹窗底部为它多留 8px（`pb-7`）。按钮在指针下挪开，等于替
  用户松了手。
- 执行中按钮写「正在重置…」，填充留满、禁用，弹窗关不掉；失败在弹窗里写原因，带「复制详情」。
- `prefers-reduced-motion` 下填充照常：它是状态，不是装饰；只有退回变成瞬时。
- 理由：Galley 鼠标优先（[layout-and-chrome](./layout-and-chrome.md)「交互输入模型：鼠标优先」），打字确认
  要把手挪去键盘；误触不会超过一两秒，余下的时间是松手就能反悔的时间。被否：输入「重置」二字（票 15 初稿，
  JC 2026-10-14 改为长按）；撤销（指的是重置：删的是对话、长期记忆和备份，票 15 定为不做；删一条消息的撤销是另一回事，见上一节）。
- 只给做了收不回、而且波及眼前这一条以外的动作。永久删除一个对话、解除一个渠道，确认仍是点一下：长按会
  把日常的删除拖慢，用多了也就不再是一道少见的关。

## 8. Command Palette（⌘K Overlay）

### 触发与形态

- `⌘K` 开 / `Esc` 或点遮罩关
- `⌘F` 与顶栏标题菜单的「查找聊天记录…」带范围打开：只搜当前对话（2026-10-15，票 28，见下「范围：在一个对话里查找（⌘F）」）；没有打开对话时 `⌘F` 等于 `⌘K`
- **居中 overlay**（不贴顶；居中更聚焦，不遮 Top Bar 状态）
- 宽度 **920px**（内容工作台档，与 Prompt Manager 同档，见本文件开头的
  overlay 尺寸阶梯）
- 高度自适应，max 680px，超出 scroll；小窗口下钳到
  `min(680px, calc(82vh - 24px))`（窗口 minHeight 600 时不越出下沿）
- 背景 `surface-elevated` + `shadow-elevated` + 圆角 14px
- 触发后页面其余加 `surface-overlay` 遮罩，**无模糊**（模糊太花）

### 不加 ⌘P 别名

只 `⌘K`，少而精（VS Code/macOS `⌘P` 习惯不引入）。`⌘F` 不是别名：它打开的是带范围的面板（见下）。

### 内容范围（V0.1 收敛）

#### Session 类（主轴）

- 最近 8 个 session（按 `lastActiveAt` 倒序）
- 搜索（2026-09-08 改）：**不分大小写子串匹配**，不再用 cmdk 的模糊子序列——行内要给命中的字面词打 mark，模糊命中（"部署文档" 匹配 "文档部署方案"）会出现"这行匹配了却没东西亮"的怪状；与下方 FTS 组同一种包含语义。候选池：无查询时最近 8 条；有查询时在**全部**会话的标题 + 摘要里找，最多显示 8 条（"按标题找那个老会话"必须能越过最近窗口）。标题 / 摘要 / FTS 片段里的命中统一用 `.cmdk` 的搜索 mark（`bg-brand/[var(--opacity-strong)]`），和落地后对话内的 `::highlight(galley-locate)` 同一寄存器：用户敲的那个词从候选到落点长得一样。
- "New chat" 永远固定在第一项

### 视觉细节

- **Input row**：48px 高 / 17px Inter / placeholder italic muted "搜索 session 或输入命令…" / 左侧 16px Phosphor `MagnifyingGlass` thin / 右侧 `Esc` shortcut hint（13px muted）
- **Divider**：1px `border-default`
- **Result row**：36px 高 / 13px Inter / 左侧 16px Phosphor icon / 中间 label / 右侧 keyboard shortcut（如 `⌘N`）灰色 hint
- **Section header / 分组**（2026-08-13 裁决，推翻「结果少时不显示」）：root
  列表已长成四种语义（新建 / 最近会话 / 对话内容命中 / 操作），默认态即
  15 行——V0.1「结果少时 header 是噪音」的前提不再成立。现规则：
  - New chat / New project 裸置顶不进组（"New chat 永远第一项"不变）
  - 其余三组走 cmdk `Command.Group`，组头**始终显示**：`最近会话` /
    `在对话内容中` / `操作`（10px semibold uppercase tracking 0.08em
    muted，即原「对话内容」手写头规格；搜索过滤后空组连头自动隐藏）
- **Hover / 键盘选中态**：背景 `hover-tint`，左侧 2px charcoal 竖条
- **Empty state**：输入有内容但无匹配 → 中央一行 muted "没找到。Enter 直接发问？" + Enter shortcut（**做** —— 输入框里写的字 Enter 直接 new chat + 把它当第一句 prompt，是对"文档对话工作台"心智的延伸）

### 关键交互

- ↑↓ 选 / Enter 执行 / Tab 进二级（如「切换模型」子菜单）
- **对话内容命中 → 定位到那条消息**（2026-09-08，issue #27）：选中一条
  FTS 命中不只是打开会话，而是把命中的那条消息停在对话区的统一锚线
  （`USER_MSG_ANCHOR_TOP_PX`，与提交置顶 / ⌥↑↓ / rail 跳转同一根线），并给
  该消息块一个 1.4s 衰减的品牌色洗染（`message-locate-flash`，只有底色
  与同色外圈，不抬升不描边——它表达「就是这里」，不是新元素）。锚点是
  `data-message-id`（`msg_<会话>_<绝对轮次>_<角色>`，Core 定义的行 id；恢复
  的会话从行取，实时 agent 轮次按同一格式算出）。定位请求存 ui store，
  会话切换时的「回到底部」看到待定位请求就让位；节点 30 帧内没出现
  （被折叠吃掉、或旧数据没有 id）则静默放弃、会话停在原位。
  **词级高亮 + 停到词所在行**（同日第二轮）：搜索词随定位请求带过去，在
  定位到的块里按不分大小写子串扫文本节点（与 FTS 三元组 / LIKE 同语义），
  用 CSS Custom Highlight API 注册 `galley-locate`——不改 DOM，react-markdown
  的树不受影响；样式是 brand `--opacity-strong` 填充（与面板行 mark 同一
  寄存器），取 strong 而非 soft/medium 是因为它要在用户消息的 brand-tint
  气泡底上也读得出。锚线停的是**第一个命中
  所在行**而不是块顶（长回答里词可能在块顶几百像素之下），块级洗染照旧。
  例外（2026-10-16，工作台对话票 01）：命中的是你的消息、它正上方挨着
  一条时间条时，照其他跳转的同一条规则停：时间条上缘停在视口顶下 16px，
  气泡在它下面 30.5px（见 conversation「Scroll behaviour」的「停一条你的
  消息」）；你的话短，词照样在视口里。
  生命周期：停留到下一次定位、切会话或 Esc（用户落地后要在附近上下读，
  1.4s 太短；它不改 DOM，留着零成本）。API 不可用时退回块级洗染。
- 输入"#"前缀强制只搜 session（V0.2 留）；输入">"前缀只搜 action（V0.2 留）
- **没有最近搜索历史持久化**（V0.1 简化）

### 范围：在一个对话里查找（⌘F）

2026-10-15，[主聊天 PRD](../../.scratch/main-chat/PRD.md) 裁决 77，票 28。先例：Slack 的 ⌘F（搜索框里自动带 `in:` 当前频道）、微信的查找聊天记录。

- **入口**：任何打开的对话里按 `⌘F`（Windows / Linux `Ctrl+F`），或点顶栏标题菜单的「查找聊天记录…」（[layout-and-chrome](./layout-and-chrome.md)「标题菜单里的查找与重置」）。没有打开对话时（新对话的空状态、设置开着、引导页）`⌘F` 等于 `⌘K`。同 `⌘K`：输入框、设置里的文本框有焦点时也生效；输入法组字时的按键交给输入法。范围就是这个对话的面板开着时再按 `⌘F` 关掉它（同再按 `⌘K`）；开着不带范围的面板时按 `⌘F`，给它加上范围。
- **范围标签**：输入框前一个标签，主对话写「在主对话里」，普通会话写「在这个对话里」（英文「In main chat」「In this chat」），带一颗 ×（无障碍名「改为搜索全部」，样式同新对话输入框下项目标签的那颗）。标签 24px 高、`border-line` + `bg-app`、12.5px；它所在的格子 48px 高、带与输入框同一条底线，输入框接在后面占满余下的宽。占位文字「查找主对话…」「查找这个对话…」（英文「Find in main chat…」「Find in this chat…」）。
- **只有对话内容的命中**：不显示新对话、新建项目、最近会话、操作；组头「在对话内容中」照旧。Core 的 `search_messages` 带 `sessionId` 只回这个对话的命中，按对话里的先后从新到旧（不带时同今天：全部对话、会话最近活动的在前），最多 20 条（⌘K 里 8 条，旁边还有会话与操作）；cmdk 不再过滤、不重排。
- **每条第一行是日期**：范围里会话标题都一样，换成这条消息说的时间，格式照对话里的时间条并保留今天 / 昨天：「今天 21:40」「昨天 09:12」「10月13日 21:40」，跨年带年份；英文 12 小时制（`lib/message-time.ts` 的 `formatMessageTime`）。没有尽头的对话里，什么时候说的才是线索。第二行照旧是片段，你 / 它的图标照旧。
- **空的时候**：不到两个字（还没开始查）一行安静的提示「输入至少两个字开始查找」；查询在路上时什么都不显示，不闪「没找到」；查回来没有，写「没找到。」，不带「Enter 直接发问？」：这里的回车是查找，不开新对话。
- **回车 / 点击**：同 ⌘K 的命中，定位到那条消息（分页历史逐页加载、锚线、洗染与词级高亮，见上「关键交互」）。
- **退格去范围**：空输入框里按退格（或点标签的 ×）去掉范围，变回普通的 ⌘K（最近会话、操作、全部会话的命中）；输入法组字时的退格不算。
- 规则是 `lib/palette-scope.ts` 的纯函数（带单测）；范围存在 UI store 的 `paletteScope`，面板每次关掉、或从别处（`⌘K`、侧栏的搜索）打开都清掉。
- 不做浏览器式的查找条（裁决 77）：分页的历史不在页面上，要覆盖全部得接 Core 搜索再配逐页加载，等于做两遍；在 markdown、代码块、折叠的长消息、收起的过程卡片里原地高亮细节多；又是一个新容器。

- Session 类按 lastActiveAt

## 9. Settings（modal overlay）

### 形态决策

当前实现是 **Radix Dialog modal overlay**，1040 × 680px，左侧 tab list + 右侧内容区。独立 settings window 是历史方向，已从当前基准移出。

理由：

- Tauri 多窗口需要第二 React entry + WebviewWindow 生命周期，成本不应压过 v0.2 beta 的核心任务。
- 当前 settings 多数是即时保存的低频配置，modal 的短暂停留成本可接受。
- 用固定 overlay frame 先统一 Settings 内部信息架构，未来若升级为独立窗口，tab/content API 可以保留。

### 规格

- **1040 × 680px / centered modal / `bg-overlay` scrim**
- 左侧 180px Tab list（垂直），右侧主内容区
- 右上角 28px close icon（floating `DialogCloseButton`；右栏顶部 48px
  安全区 + 同色渐隐给它让位，见「Dialog 关闭按钮」节），Esc 可关闭

  contenteditable）时，第一下 Esc 只离开输入框（字段自己有 Esc 规则的照它的来，如外部 GA 路径框还原
  草稿），第二下才关设置；输入法组字中的 Esc 不处理。全设置页生效，实现在 `Settings.tsx` 的
  `onEscapeKeyDown`——Radix Dialog 在捕获阶段处理 Esc，字段自己的 keydown 走不到。

  标题「没有手机在线」；Core 的 relay 连接断开 →「正在连接」中性转圈，标题「暂时连不上网络」。
  说明行是「上次连接 {时间}」（日期格式同绑定时间），没有时写「手机打开 Galley 时会自动连上」。
  上次连接时间只记本次 Core 进程内的，Core 重启后归空。
- **二维码**：Core 画成 SVG 交给页面（`<img>` 的 data URL），二维码串带配对主密钥，不以文字
  形式进 JS；**不做**「复制配对码」按钮。只在点「显示配对码」后出现，几何同微信卡（168px 框、
  148px 图，SVG 自带白底与 4 格静区，深色模式也能扫）。旁边两句步骤 + 一句安全提示（这个码等于
  这台电脑的使用权）；配对中的码在步骤后多一句「配对码 10 分钟内有效。」（英文「This code works
  for 10 minutes.」），「添加手机」的码是存下的那把，不过期，不写这句。
- **二维码何时收起**：
  - 配对中的码随 Core 的 `pairing`：第一台手机连上（切到已配对版式）、10 分钟没人扫（Core 自己
    取消）时收起。超时后按钮回到「显示配对码」，不另提示：码下已写明有效期，回来的人看到按钮就
    知道再点一次。
  - 「添加手机」的码：有手机连上（上次连接时间变了）就收起。
  - 两种码都在点「收起配对码」、离开「手机」页、关闭设置时收起，同时调 `cancel_remote_pairing`
    让 Core 断开并丢掉没扫的码；已配对时这是空操作，已配对的手机不受影响。
  - 命令的回应可能比 Core 的「配对中」状态先到，所以码在看到 `pairing` 变真之后才跟着它收起。
- **存不进去**：第一台手机握手后密钥写不进凭据存储时，Core 不放这台手机进来（它收不到握手回应），
  码仍有效，卡下出一行错误「配对没能保存，手机没有连上：{原因}」（英文「Couldn't save the
  pairing, so the phone didn't connect: {原因}」），配对结束或成功后消失。
- **不提 relay**：JC 裁定用户不需要知道有中转，文案里没有 relay / 中转 / 服务器；relay 连接断开
  一律说成网络暂时连不上。也不写「直接连到电脑」，那不是实情；只说手机连上这台电脑。
  （用户唯一会读到「中转」的地方是隐私说明，见远程协议设计稿第 12 节第 3 点。）
- **后台运行检查**（PRD 裁决 10）：「关闭窗口时保持后台运行」关着时，卡下出一条 warning 横条
  （同聊天软件的旧配置横条）+「打开」，打开的就是通用页那个偏好。「接通电源时保持唤醒」属票 04，
  本页还没有。

生效一次，与 `⌘N` / `⌘,` 同一机制：AppKit 先拿到就由菜单处理，webview 收不到；
webview 先拿到则 JS 处理器 `preventDefault`，WebKit 不再把它转给菜单（见
`useGlobalShortcuts.ts`）。两条路径做的是同一件事（一档 / 复位），哪条先到
结果都一样。阅读宽度**不给快捷键**：没有约定俗成的键位，
